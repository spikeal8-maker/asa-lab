## Подтверждённый путь лишнего расчёта в исходниках

В `apps/web/src/electronics/use-electronics-workbench.ts` stopped
`staticPreflightResult` вызывает `calculateSimulationPreflight` синхронно внутри
`useMemo`, зависящего от всего `document`. Эффект подготовки LED спустя 120 ms
вызывает тот же preflight прежде проверки наличия нужного LED. Таким образом,
изменение документа может вызвать два предварительных анализа при Stop.

`apps/web/src/electronics/live-simulation.ts` направляет preflight в настоящий
`analyseCircuit`. Остановленный `calculateLiveSimulation` только проверяет и
возвращает сохранённый результат; solver там не запускается.

Граница существующего Worker нуждается в отдельном контроле: evaluator сначала
вызывает `analyseElectronicsSnapshot`, который сам вызывает `analyseCircuit`,
затем `calculateSimulationPreflight`. Поэтому один Worker request не равен
одному выполненному расчёту. Счётчики стенда отдельно наблюдают оба API и
фактические `analyseCircuit`, по main/Worker. В R00 runtime не редактируется.

## Методика

`apps/web/src/electronics/testing/stopped-preflight.browser.mjs` собирает настоящий
полный `SchematicEditor`, dedicated Worker и каталог в production-режиме esbuild.
API открытия/сохранения направлен на одноразовую тестовую копию. Сохранение
проверяет parser и ревизию, но не запускает дополнительный solver. Это
**instrumented candidate full editor**, а не установленная версия asa-lab.ru.

Четыре точных наблюдательных transform сохраняют return/exception результата:
preflight, `analyseCircuit`, read-only diagnostic reference и `useLayoutEffect`
полного редактора. Точные original/transformed SHA-256, итоговый UI/Worker/CSS,
дерево compilation inputs и SHA фактически измеряемого source лежат в receipt.
Worker duration измеряется его собственными часами; связь с main определяется
requestId и main send/receive, без вычитания часов разных контекстов.

Для S3/S4 × код закрыт/открыт × четыре действия — три прохода по 30 фиксированным
секундным слотам, **90 проб на профиль**. Все пробы сохраняются, включая
превышения срока слота. При медленном действии окно может выйти за 30 секунд:
`actualElapsedMs`, `startDeadlineMissMs`, `harnessWallMs` явно отражают это.

1. Добавить ранее загруженный резистор через каталог и сцену; Undo восстановления
   вынесен из измеряемого интервала. При открытом коде выбор каталога происходит
   до измерения, затем панель кода открывается снова и выполняется размещение.
2. Перетащить Uno без изменения связей. Задержка здесь означает **pointer release
   → соответствующий DOM commit**; весь drag присутствует в отдельной видеозаписи.
3. Изменить 220↔330 Ω. Smoke проверяет доступность поля при открытом коде и
   штатное изменение ширины панели. Если поле недоступно, оба профиля используют
   настоящий Undo/Redo заранее введённого номинала; это не задержка набора текста.
4. Изменить скетч: первый `delay(100)` заменяется на `delay(101 + i)`, i=0…89.
   Полный текст и hash программы каждой пробы сохранены. Для закрытого кода
   сценарий явно `открыть → ввести → закрыть`; input latency начинается после открытия.

Граница основного времени — native event до соответствующего документа и
DOM-свидетеля в layout effect. Отдельно измеряется готовность актуальной
диагностики. RAF сохраняется только как событие планирования и не называется
доказанным paint. До завершения пробы ожидается stopped resource timer и
отсутствие pending Worker. Warmup/reset/Undo сохраняются отдельно от действий.
Сохраняются p50/p95/max, фактические solver counts/durations и long tasks
(число, сумма, максимум). Паузы harness не входят в задержку действия.

Численные проходы выполняются без video/trace. Отдельный одинаковый replay
записывает полный редактор в WebM, Rendering/Paint trace и PNG; дополнительно
проверяет 1366×768 и 390×844. Главный профиль 1920×1080, DPR1, новый контекст
Chromium, браузерный масштаб 100%. Сцена/панель/вариант заранее загружены.
CPU/RAM/OS/Node/браузер/GPU/viewport/zoom/visibility записываются по факту.
Headless CI не равен компьютеру владельца и дисплею 60 Гц. Холодное открытие —
`NOT_CHECKED`; это ограниченный тёплый Stop сценарий.

## Воспроизведение и артефакты

Workflow `Electronics recovery performance` автоматически запускается только
для ветки `codex/electronics-recovery-r00-1111` при изменении runner/fixtures/workflow:
сначала smoke `NOT_ACCEPTANCE`, затем полная baseline при его успехе. Отдельный
`workflow_dispatch` позволяет повторить before и разрешённый R10 candidate
последовательно на одной машине, одним runner и одними сценами.
Push и default dispatch закрепляют before source
`cb15c700253f26bf276ad69d5e45ca27c2306787`; runner проверяет запрос полного SHA
до компиляции и сохраняет его рядом с фактическим source SHA в receipt.

```bash
node apps/web/src/electronics/testing/stopped-preflight.browser.mjs --build-only
NX_SKIP_NX_CACHE=true node control/apps/web/src/electronics/testing/stopped-preflight.browser.mjs --source-root=before --phase=before --smoke --output=reports/smoke
NX_SKIP_NX_CACHE=true node control/apps/web/src/electronics/testing/stopped-preflight.browser.mjs --source-root=before --phase=before --output=reports/before
```

Browser runner разрешён только внутри GitHub Actions. Артефакт содержит
`index.html`, `report.json`, отдельные сырые pass JSON, build receipt, compile inputs,
initial diagnostics для численного сравнения, WebM/PNG/trace и ошибки при сбое.
Срок хранения CI — 90 дней; этот срок не заменяет закрепление итогов в GitHub.

создания истории 220→330→Undo. Полное равенство документа и электрического digest
проверяется после resize, доступность Undo/Redo — перед измеряемым жестом.
Способ nominal и ширина панели обязаны совпадать в paired before/after.

Первый screenshot подтверждает перекрытие поля номинала даже при панели 620 px.
Существующий keyboard resize/nudge дефект продукта остаётся **OUT_OF_SCOPE**:
R00/R10 его не чинит. Для полного вида стенд также отдаёт исходный
`/asa-lab-mark.svg` из public без изменения самого asset. На момент этой поправки повторный smoke и
полный baseline были PENDING; затем оба успешно выполнены, итог приведён ниже.

## Единственная финальная конвергенция контроллера

GitHub отклонил merge1116 после SUCCESS исходного General: обязательный ASA / required ожидается на актуальной базе, PR имеет mergeable_state=behind. Контроллер объединяет exact8ee с main e04d443360703db98a6d98fbd591dfbbc7823734 без конфликтов. В этом же документационном переходе принимает неизменённый одобренный checkpoint007 и выбирает R10; runtime и измеренный harness остаются прежними. Повтор required CI нужен на объединённом SHA. Новый автор R10 получает право продуктовой записи только после принятия этого выбора в main; feature-ветка и автор R00 задачу не выбирают.
