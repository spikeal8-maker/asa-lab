# #464: карта существующих live-настроек первого среза

Все изменения в таблице относятся к уже открытому и работающему редактору. При Run экран передаёт изменение через `runtimeOverrides`; исходный `document` и autosave не меняются. При Stop override очищается. Изменение при остановленном расчёте записывается в документ обычным `commitDocument`. Следующий Start всегда начинает новую физическую историю с нулевого времени.

| Прибор и ввод | Единицы и диапазон | Во время Run: путь и применение | Наблюдаемый результат | Сохранение и Stop/Start |
| --- | --- | --- | --- | --- |
| Источник: `voltageSetpointVolt` | В, 0…30 | `runtimeDocument` → Worker `voltageSetpointVolt` → canonical timed event → scheduler `stateProperties` → модель источника в точке события | Напряжение и ток новой рабочей точки; прежний заряд, нагрев и время сохранены | Только runtime; при Stop прежнее документное значение. После Stop можно записать новое, затем Start с нуля. |
| Источник: `currentLimitAmp` | А, 0…5 | Тот же timed path; лимит применяется моделью источника | CV/CC и ток нагрузки по новому пределу | То же. |
| Источник: `outputEnabled` | boolean | Тот же timed path; явное значение свойства приоритетнее начального `state` | Выход включён или выключен в новом расчёте | То же. |
| Генератор: `waveform` | sine/square/triangle | `runtimeDocument` → Worker event → scheduler → модель генератора | Форма физического сигнала при новом времени; square проверен статическим и timed расчётом | То же. |
| Генератор: `frequencyHz` | Гц, 1…1 000 000 | Тот же timed path | Новая частота/фаза физического сигнала | То же. |
| Генератор: `amplitudeVpp` | Vpp, 0…10 | Тот же timed path | Амплитуда физического сигнала | То же. |
| Генератор: `dcOffsetVolt` | В, −5…5 | Тот же timed path | Смещение физического сигнала | То же. |
| Генератор: `outputEnabled` | boolean | Тот же timed path; явное свойство приоритетнее `state` | Выключенный выход даёт нулевой сигнал | То же. |
| Осциллограф: `voltsPerDivision` | В/дел, >0…100 | Timed event → scheduler; масштаб только представления, входные 10 MΩ остаются в электрической модели | Новая вертикальная шкала, без новой генерации | То же. |
| Осциллограф: `timePerDivisionMs` | мс/дел, >0…10 000 | Тот же timed path; только представление | Новая горизонтальная шкала, без новой генерации | То же. |
| Осциллограф: `triggerLevelVolt` | В, −100…100 | Тот же timed path; только представление | Новый уровень триггера | То же. |
| Осциллограф: `displayEnabled` | boolean | Тот же timed path; управление экраном, а не сопротивлением входа; явное свойство приоритетнее `state` | Экран включается/выключается, физический вход остаётся подключённым | То же. |
| Мультиметр: `meterRange` | Только внутреннее свойство представления; отдельного live-органа UI нет | `runtimeDocument`, исключено из сравнения канонической структуры; физическая модель не читает поле | Диапазон показания; электрическое включение не меняется | Runtime только при программном вызове; Stop очищает. |
| Мультиметр: `measurementMode` | dc-voltage/dc-current/resistance | `runtimeDocument` → Worker `measurementMode` → canonical timed event → scheduler `stateProperties` → физическая модель A/V/R в точке события; clock profile выбирается по неизменному составу источников, включая Arduino GPIO, и накопителей, поэтому переход режима не меняет профиль | Шунт, вход 10 МОм или ограниченный сигнал омметра реально участвуют в новом расчёте; история предохранителя остаётся | Только runtime; Stop возвращает документный режим. После Stop обычная запись в документ; новый Start с нуля. |

Worker исключает только перечисленные свойства из `sameCanonicalStructure`; для источника, генератора, осциллографа и режима мультиметра это допустимо потому, что каждое изменение превращается в валидированный timed event и реально применяется scheduler к рабочему документу. Недопустимые значения возвращают fault без продвижения committed horizon. Электрический вход осциллографа 10 MΩ участвует в KCL и power balance с прежними допусками.

Предел доказательства: timed наблюдение пока не возвращает график `oscilloscopeTrace`, поэтому этот срез подтверждает шкалу, статус и физическое значение входа, но не заявляет проверенный график на экране. Пассивная схема без независимого источника остаётся в алгебраическом профиле: A/V показывают `no_source`, а R использует собственный ограниченный тестовый сигнал. Новые live-настройки обычного резистора и количества батарей здесь не затронуты.
