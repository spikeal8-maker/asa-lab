# ASA Lab Electronics — исполняемое ТЗ и очередь 23 замечаний

**Редакция 1.0 · 24 октября 2026 · программа #452 · реестр #703**

Это рабочая инструкция для программного контролёра и отдельных ботов-исполнителей. Она устанавливает порядок, ожидаемый пользовательский результат, границы изменений, зависимости и критерии приёмки **23 замечаний**, полученных от учителей и учеников. **Она не является текущим execution state и сама по себе не активирует ни одну задачу.**

## 1. Единственные источники истины и вход

1. Политика: [AGENTS.md](../../../AGENTS.md) и [START_HERE_FOR_AI.md](../../../START_HERE_FOR_AI.md).
2. Маршрут Electronics: [START_HERE.md](START_HERE.md), действующие [ТЗ стабилизации 2.1](ASA_ELECTRONICS_STABILIZATION_SPEC_V2.md) и [реестр E01–E35](ASA_ELECTRONICS_OWNER_REPAIR_PRIORITY_20261008.md).
3. **Программа:** [Issue #452](https://github.com/spikeal8-maker/asa-lab/issues/452). **Единая матрица симптомов и статусов:** [Issue #703](https://github.com/spikeal8-maker/asa-lab/issues/703). Здесь нет второго списка live-статусов.
4. **Текущая исполняемая задача, активные параллельные lanes, checkpoint, SHA и разрешения:** только [docs/execution/current.yaml](../../execution/current.yaml). Не выбирать работу по одному порядковому номеру из этого плана.
5. **Подробная task card:** существующая карточка в `tasks/`, или новая ровно при формальном выборе нового среза. Перед кодом — `pnpm agent:preflight --scope electronics --check` либо preflight узкой выбранной lane и `pnpm validate:electronics-agent-docs --task <selected-id>`. Токен `<selected-id>` означает фактический ID уже выбранной задачи в `current.yaml`, а не произвольное название.
6. **Код, PR, issue, CI и merge проверяются заново на актуальном SHA.** Завершённая Issue, merged PR и старый green CI не доказывают, что исправление установлено в школе.

**Статусы существуют отдельно:** код в `main` → продуктовая техническая приёмка → развернуто на нужном сервере → проверено пользователем. Не повышать статус по косвенной информации. Даты, SHA, ветки, исполнители и текущие состояния фиксируются в Issues / `current.yaml`, но **не в этом стабильном плане**.

**Нулевое действие P0:** одновременно с запуском очереди провести read-only диагностику инцидентов **№19 и №21**. Потеря работ, коррупция сохранения или раскрытие чужих проектов немедленно прерывают обычную очередь, даже если ремонт сложный. Персональные данные учащихся, схемы, токены, ID аккаунтов и сырые школьные логи НЕ публиковать в GitHub.

**Основной порядок:** сначала недостающая приёмка уже опубликованного результата; затем маленькие независимые визуальные изменения; далее editor/Blockly; затем новые компоненты; затем Worker, физика и сложная функциональность. Уже активные задачи не переключать и не перезапускать: контролёр продолжает их независимо, согласуя пересечения путей и выделяя очередной новый срез только когда он действительно свободен.

## 3. Алгоритм контролёра: выбрать ровно один следующий срез

1. Проверить `origin/main`, изменения, открытые Issues/PR, соответствующие CI на **точном HEAD**, текущую [#703](https://github.com/spikeal8-maker/asa-lab/issues/703) и уже выбранные Electronics lanes из `docs/execution/current.yaml`.
2. Отметить уже существующие merged/closed результаты и оставшиеся условия; **не** повторять продуктовую работу #688/#543/#679 и **не** путать merged тестовый PR с исправленной физикой. Старые `in_progress` записи для закрытых задач требуют точного reconciliation, а не слепого запуска.
3. Проверить P0. Пока P0 не классифицирован, разрешены только безопасная read-only диагностика и независимые изменения, которые гарантированно не затрагивают save/API/identity; подтверждённая потеря данных получает приоритет на исправление.
4. Для нового исполнения идти по таблице **сверху вниз**. Пропускать уже технически принятые, занятые другим ботом, требующие unavailable evidence и запрещённые на данный момент dependencies. Указывать конкретную причину пропуска в #703 и определённый unblocker — без бесконечного ожидания одного пункта.
5. Если соответствующая Issue/card уже существует, **использовать её**. Для `новая карточка` открыть одну узкую Issue и одну concrete task card только в момент назначения. Присвоить ID, owner-visible результат, files/surface, allowed diff, negative cases, тесты, prerequisite, risks и критерии остановки. Никогда не запускать два пишущих агента на пересекающиеся пути.
6. Прежде чем разработчик пишет код, контролёр корректно выбирает эту конкретную карточку в `current.yaml` **на main** (существующую Electronics lane либо разрешённую параллельную). Feature-ветка не может авторизовать себя сама. Бот исполняет только выбранный срез и его реальные blockers.
7. Исполнитель: preflight → native BEFORE → установление причины → минимальный кодовый diff → focused/unit/browser AFTER → обязательный exact-SHA CI → независимый reviewer. Если нет доказанной причины, сделать только диагностику, не маскировать баг «упрощением» физики/проверок.
8. Контролёр сверяет результаты на актуальном main, сохраняет чужие изменения, вносит принятый срез по действующей политике `direct_main` (PR необязателен, чужой Draft без разрешения не merge), обновляет Issue/#703 и execution checkpoint. **Контролёр продолжает программу**, когда один исполнитель закончил свой срез.
9. Установленная версия / USER_VERIFIED идут отдельной задачей выпуска, а не получаются автоматически после push. Не смешивать `SOURCE_APPROVED`, `CI_PASS`, `IN_MAIN`, `DEPLOYED` и `USER_VERIFIED`.

## 4. Обязательный шаблон любой concrete task card

Каждый новый срез должен иметь в самом Issue и карточке все следующие поля:

- **Идентификация:** № из 23, parent #703/#452, живые связанные Issue/PR, сложность, P0–P3, выбранная lane, owning surface, текущий baseline SHA.
- **Результат для ученика/учителя:** одна проверяемая история «БЫЛО → СТАЛО». Для UX — фото/видео native браузера. Для Worker/physics — готовые вычислительные результаты и фронты времени. Для persistence — прочитанные после SaveCAS ревизии и полные документы.
- **Правильный BEFORE:** скетч/схема/разрешение/действия пользователя/ожидаемое и наблюдаемое; при отсутствии воспроизведения честно обозначить `UNCONFIRMED`.
- **Минимальная граница:** точные production/test paths, совместимость с соседними открытыми карточками, ни одного постороннего cleanup.
- **Функциональная приёмка:** один положительный, минимум один физически/логически отрицательный случай и действительные Save/Undo/Reset тесты только там, где эта функциональность затронута.
- **Доказательства:** источник SHA, реальный browser/unit/Worker/PostgreSQL по классу риска, CI run/job IDs, независимое code/product review и отдельный integrated-main SHA.
- **Остаточное:** что не исправлено, что требуется от владельца, что не проверено на школе, следующая готовая карточка для контролёра.

Нельзя закрывать карточку фразой «локальные 1000 тестов PASS», если пользовательский AFTER не показан и точная интеграция не подтверждена.

## 6. Блокеры, безопасность, компактность, размер сборки

- Только Electronics/Arduino. **Не менять** другие продуктовые направления: Курсы, Публикации, Scratch, ИИ, Auth, Portal. Отдельный foreign blocker заводится владельцу области.
- **Без** school deployment, активных школьных БД, бэкапов, изменения FRP/DNS/сертификатов, доступа к живым данным детей и сетевой конфигурации без отдельного согласованного задания.
- Текущий лимит editor bundle `218000` байт НЕ повышать. Старое наблюдение `217993` оставляло 7 байт лишь на историческом SHA. Перед каждым UI изменением повторно проверять реальный fresh `bundle:check`. [PR #685](https://github.com/spikeal8-maker/asa-lab/pull/685) нельзя автоматически притягивать только ради размера.
- На телефоне не добавлять крупные карточки/модальные панели там, где достаточно компактного контролла. №23 уплотняет видимые интервалы, но не разрушает минимальные интерактивные цели и a11y; №17 не должен превращать canvas в панельную ленту.
- Существующие `current.yaml`/Issues могут временно не совпадать (например, closed Issue и historical lane `in_progress`). Контролёр обязан восстановить actual status, а не плодить вторую систему флагов в этом документе.
- Изменение `main` другим ботом на пересекающихся файлах, non-fast-forward, отсутствующий BEFORE, потеря семейства инвариантов или независимый `REQUEST_CHANGES` = STOP **конкретного исполнителя** с evidence и unblocker. Контролёр продолжает другие независимые задачи.

## 7. Приёмка программы

Все 23 строки #703 имеют чёткое состояние; №18 и №22 закрываются одним совместным доказанным сценарием. Для каждого пункта указаны точный источник, результаты проверки и статус установки. Четыре уровня отчётности раздельны: `IN_MAIN / TECHNICALLY_VERIFIED / DEPLOYED / USER_VERIFIED`. Система не объявляется полностью исправленной, пока `P0` не принят и не выполнена разрешённая итоговая школьная проверка.

**Единственная точка старта нового бота:** корневой `START_HERE_FOR_AI.md` → `docs/product/electronics/START_HERE.md` → этот документ → #703 → `current.yaml` → конкретная card. Этот документ редактируется при новых решениях владельца или изменении устойчивой очередности; live-SHA и результаты обновляются только в GitHub Issues и `current.yaml`.
