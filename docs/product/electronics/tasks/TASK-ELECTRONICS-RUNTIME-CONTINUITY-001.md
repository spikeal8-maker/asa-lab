# Непрерывность уже работающих live-настроек

Программа: [#452](https://github.com/spikeal8-maker/asa-lab/issues/452). Четвёртый рубеж: [#464](https://github.com/spikeal8-maker/asa-lab/issues/464). Это первый ограниченный срез #464: существующие органы регулируемого источника и приборов. Новые live-правки сопротивления резистора и количества установленных батареек не входят в этот срез: их поведение после Stop/повторного открытия ещё требует ответа владельца.

## Один пользовательский результат

Разрешённая настройка уже работающего источника или прибора меняет фактический расчёт либо только отображение прибора по назначению, но не запускает незаметно новую физическую генерацию с нулевого горизонта. Время, нагрев, заряд конденсатора, состояние двигателя, повреждения и Arduino остаются непрерывными при таком live-действии. Владелец отдельно утвердил: намеренный Stop и новый Start начинают физическое состояние с нулевого времени.

## Вход и граница

Перед записью восстановить свежие `origin/main`, Electronics lane в `docs/execution/current.yaml`, Issue #464, CI текущего SHA и незавершённые изменения других исполнителей. Выполнить `pnpm agent:preflight --scope electronics --check` и `pnpm validate:electronics-agent-docs --task TASK-ELECTRONICS-RUNTIME-CONTINUITY-001`. При `RECOVERY_REQUIRED`/`WAITING_HANDOFF` сначала классифицировать diff, процессы и пересечения; чужие файлы не менять.

Маршрут: `docs/product/electronics/COMPONENT_MAP.yaml` → `components/engine-worker-clock.yaml`, `electronics.worker.live-controller`, `electronics.engine.public-api`; для конкретного прибора — его компонентная карта. Исходные факты ТЗ: runtime overrides поступают в runtime document, а `sameCanonicalStructure()` исключает лишь часть динамических полей. Простое добавление поля в исключения без канонического применения значения запрещено.

## Ограниченный scope

1. Составить техническую таблицу для каждого уже разрешённого live-control: ввод → единицы/границы → canonical event или display-only правило → применение → новый результат → история/сохранение → Stop/Start. Сверить регулируемый источник (напряжение, ограничение тока, выход) и существующие настройки мультиметра, генератора и осциллографа. Сохранять действующую семантику записи этих органов; не добавлять незаметное сохранение runtime overrides.
2. На каждом доказанном скрытом `beginGeneration(document, 0)` минимально провести параметр через существующий канонический timed path либо корректно отделить только масштаб/отображение прибора от физики. Не менять электрическую модель, чтобы получить удобный UI-результат. Если механизм для конкретного контроля требует новой физической модели или отдельного продуктового решения, зафиксировать его как предел среза, не выдавать UI override за расчёт.
3. Не разблокировать в этом срезе обычный резистор, не менять количество/вместимость/вариант батарейного отсека, не расширять структурные жесты, не трогать owner images, соединения и ID схемы, autosave, авторизацию или рабочую установку.

## Acceptance

- Для выбранных существующих controls подтверждён путь значения до канонического расчёта или доказано, что control меняет только представление прибора. Время не идёт назад; capacitor/motor/temperature/Arduino state не обнуляются из-за настройки. Настоящий Stop/Start начинает новый runtime согласно решению владельца.
- Mapped unit/regression tests проверяют отсутствие скрытого `beginGeneration(..., 0)`, применение значения и сохранение инвариантов solver. Реально собранный браузерный редактор проверяет как минимум один физический live-control и один display-only control на до/после без перезагрузки и без изменения схемы.
- `pnpm gate:electronics-m1`, `pnpm gate:electronics-m1:browser`, `pnpm gate:repository` и `git diff --check` имеют exact-head evidence; независимый агент проверяет фактический diff, GitHub state и браузерный результат. Unrelated CI классифицируется по `AGENTS.md` §2.1 без расширения текущего ремонта.

## Остановка

Исполнитель реализует только этот bounded срез, выполняет focused gate и self-review, сообщает точный SHA и STOP. При замечании review отдельный исполнитель делает ограниченный repair. Контроллер проводит integration и closeout этого среза; оставшиеся новые resistor/battery controls требуют отдельного bounded решения после ответа владельца. Owner acceptance, deployment и classroom test не заявляются этим результатом.
