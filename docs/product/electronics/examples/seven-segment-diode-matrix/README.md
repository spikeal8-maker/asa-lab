# Семисегментный индикатор: десять кнопок и диодная матрица

Функциональный пример ASA Lab по работе ученика из Tinkercad. Arduino и код
не используются. Снимок не позволяет достоверно прочитать все номиналы и
соединения; здесь сохранён принцип схемы, а выбранные значения указаны явно.

## Схема

- Батарейный отсек **2×AA, 3 В**, существующая модель с внутренним
  сопротивлением 0,45 Ом.
- Семисегментный индикатор с общим катодом; оба общих вывода соединены внутри.
- Десять кнопок слева направо соответствуют цифрам **0–9**.
- 49 диодов DO35 распределяют питание каждой кнопки на необходимые сегменты.
  Диод направлен от выхода кнопки к сегментной шине.
- Каждая диодная ветвь содержит резистор **220 Ом**. Каждая из семи сегментных
  шин подключена к индикатору через дополнительный резистор **100 Ом**.
- Точка не подключена. Всего **117 компонентов**.

Удерживайте кнопку: появляется её цифра. Отпустите: индикатор гаснет.
Диоды препятствуют обратному питанию соседних кнопочных ветвей. Одновременное
замыкание двух кнопок даёт объединение соответствующих сегментов с рассчитанным
распределением токов; программного приоритета цифр нет.

Пример использует существующие физические модели. При одной нажатой кнопке ток
сегмента около **1,52 мА**; яркость вычисляет движок. Для независимой проверки
использована формула последовательной цепи:

`I = (3 − 0,58 − 1,9) / (220 + 12 + 100 + 8 + 0,45 × N)`

Здесь 0,58 В / 12 Ом — рабочий участок модели DO35, 1,9 В / 8 Ом — модель
красного сегмента, N — количество включённых сегментов. Это проверка выбранных
моделей ASA, а не обещание точных параметров любой реальной детали.

## Файл схемы и проверка

[circuit.json](circuit.json) — сохранённый **ASA emergency circuit document**,
тот же формат ElectronicsDocument, который экспортирует существующая команда
аварийной копии. В файле нет рассчитанных токов или принудительной яркости.
Нативный тест открывает его через существующий project/document pipeline и
проверяет повторное открытие. Отдельный пользовательский UI импорта JSON,
серверное сохранение и основная установленная версия здесь **не проверялись**.

Воспроизведение из корня репозитория:

```text
pnpm exec vitest run contexts/electronics/testing/seven-segment-diode-matrix.spec.ts
node apps/web/src/electronics/testing/servo-runtime.browser.mjs --seven-segment-buttons-only
```

- 16 focused domain tests: десять цифр и разомкнутое состояние, аналитический
  ток, нулевой ток неактивных диодов, четыре пары кнопок, повторные нажатия и
  отпускания, parse/serialize/reopen без изменения топологии и результата.
- Реальный Chromium, Worker, hook и production Stage, ширины 1440 и 390:
  **20 нажатий и 20 отпусканий** мышью/нативными touch-событиями, все цифры 0–9.
  Каждый видимый рисунок связан с session/generation/input digest/committed frame
  рассчитанного результата, а DOM opacity сравнивается со всеми восемью ветвями.
- Повторное открытие проекта сохраняет компоненты, соединения и отпущенные кнопки.
- Focused lint, форматирование и targeted TypeScript проверки выполнены отдельно.
  Product code не изменён; предыдущие полные gate/build/budget доказательства
  подсказок 751 переносятся, новая полная сборка не заявляется.

[native-receipts.json](native-receipts.json) содержит полные scoped результаты.
Скриншоты: [desktop](desktop.png), [mobile](mobile.png). На телефоне общий вид
большой схемы требует увеличения для комфортного редактирования. Эта проверка
не закрывает всю матрицу удобства мобильного интерфейса и не доказывает
одновременное удержание нескольких кнопок через multi-touch.

Проверка счётчиков и эффектов Arduino остаётся отдельной частью пункта 2.
Сервер, Docker, база данных, artwork, solver, параметры сходимости и лимиты
не изменялись.
