# ASA Lab — общие вкладки и системные уведомления (решение владельца, 15.10.2026)

Этот документ фиксирует **нормативное правило для всего продукта**, в том числе для страниц, созданных в будущем. Нельзя создавать новый уникальный стиль вкладок или уведомлений без осознанного продуктового исключения. Этот документ не выдаёт разрешения на deployment, не меняет execution state и не заменяет product acceptance.

## Вкладки: одна система ASA Lab

Эталон — компактные вкладки страницы «Классы», с немного более чистым выделением активной секции. Канонический компонент для переключения разделов — `SystemTabs` (`apps/web/src/components/SystemTabs.tsx`), стиль — `system-tabs.css` (корневой класс `asa-system-tabs`). Если экран уже использует полноценные `role=tablist/tab/tabpanel`, **не ломать его доступность** и подключать то же оформление по CSS-классу, сохраняя все id/aria-controls/aria-selected и текущую клавиатурную модель.

- Контейнер: светлая нейтральная поверхность, тонкая граница, радиус около 12 px, компактные внутренние зазоры. Активная вкладка: белая поверхность, синий акцент снизу, контрастный текст. Не использовать огромные кнопки, многоцветные плашки или чрезмерные тени.
- Нативные кнопки (не ссылки без действия), минимальная зона нажатия 44 × 44 CSS px, видимый focus-visible, доступный текст. Никаких переносов **внутри слова** и скрытого за экраном активного раздела.
- Длинная навигация: при достаточной ширине компактные строки; на телефоне — понятное переносимое представление без горизонтально отрезанных действий. Там, где исторически используется mobile select («Классы», «Настройки»), допустим тот же паттерн, но подписи и активная секция должны совпадать.
- `aria-current=page` — для переключения разделов без полноценной ARIA-tabpanel-модели; `role=tablist` и `aria-selected` — только при сохранении корректной tabpanel-структуры и клавиатурных взаимодействий. **Не заменять семантику ради CSS.**
- Группы фильтров со своими `aria-pressed` — тот же визуальный язык, но остаются фильтрами, а не панелями. Меню редакторов, вкладки документов и инструменты черчения не превращать в разделы страниц.
- Все новые страницы обязаны использовать компонент либо общий класс `asa-system-tabs` с осознанной модификацией (например, `--vertical`). Не копировать новые самостоятельные CSS-реализации.

## Уведомления: один канал

Для действий с подтверждённым сервером (сохранено, удалено, добавлено, отправлено, скопировано **после успешной записи в буфер**) используется `systemFeedback.success(text)`; при подтверждённой неудаче действия — `.error(text)`; для предупредительных ситуаций — `.warning(text)`, для сведений — `.info(text)`.

Канонический код: `apps/web/src/components/system-feedback.ts`, единственный глобальный рендерер: `SystemToastViewport` в `main.tsx`, оформление: `system-feedback.css`.

- На компьютере уведомление справа сверху, **ниже системной шапки**. На узком телефоне — снизу по центру, с учётом безопасной зоны. Не перекрывать ввод, вкладки, основные действия и экранную клавиатуру.
- Вид: компактная белая карточка, заметная **цветная левая граница и иконка**, не яркая заливка всей страницы. Успех — зелёный, ошибка — красный, предупреждение — янтарный, информация — синий. Текст конкретен и понятен, без технических кодов для ученика.
- Сообщения об успехе и информации закрываются автоматически через 4.5 секунды, предупреждения через 7 секунд, **ошибки не исчезают до ручного закрытия**. Кнопка закрытия 44 × 44 px доступна клавиатуре. Одновременно показывать максимум 3 карточки; последующие сообщения стоят в очереди.
- Доступность: `role=status` для штатных сообщений и `role=alert` для ошибок, с сохранением фокуса в текущем действии. Не показывать уведомление до подтверждения сервера и не обещать успех, если сохранение отложено/не получило подтверждения.
- **Никаких паролей, Student Code, QR-токенов, секретных ссылок и персональных данных в текстах всплывающих уведомлений, логах или тестовых скриншотах.** При выходе из учётной записи сбрасывать остаточные сообщения.
- Ошибки встроенной проверки поля, прогресс «сохраняем…», длительная загрузка, inline-retry и контентные оповещения от преподавателя остаются **на своих местах**: глобальный toast их не заменяет. Не дублировать один и тот же успешный результат и внутри формы, и во всплывающем окне.
- Действия удаления требуют прежнего подтверждения и проверки прав. Toast об успешном удалении появляется только после подтверждённого результата, а не в момент нажатия.

## Масштаб внедрения

Первый технический срез создаёт общий компонент, стили, глобальный viewport и переводит на единые правила ключевые разделы: классы, учебные материалы, настройки, профиль, проекты и админку. Оставшиеся модульные поверхности должны подключаться по мере разработки без копирования компонентов. Документ — **задание и правило**, не утверждение, что визуальная приёмка каждого экрана завершена.

Критерии приёмки: exact-SHA build + lint + typecheck, проверка снимков на 320/390/768/1024/1440 px, работа мышью/клавиатурой, масштаб 200%, случаи 0/1/3+ сообщений, ошибки не исчезают, server-authoritative notifications не теряются при переходе между страницами, и нет доступа к чужим аккаунтам или данным при переключении.
