# ASA Lab — ученический интерфейс и доступ, редакция 1.0

**Статус:** supporting UI contract; не отчёт о готовности.
**Основные нормы:** Access 2.2 §9/33; Integrated V1.5 §4; Learning Master 2.2.
**Публичный ресурс:** https://asa-lab.ru/.
**Маршрутизация:** `docs/execution/current.yaml` и Document Registry. Этот файл не выбирает задачи и не вводит второй identity/runtime.

## 1. Два постоянных ученических сценария

Account-ученик имеет личный Account и может учиться в нескольких разрешённых контекстах. StudentSeat — постоянный учебный профиль конкретного класса без обязательной регистрации Account. Сессии и права различны. TemporaryLearningAccess для отдельного оценивания относится к E2 и не переопределяет StudentSeat.

## 2. Первые действия после входа

Ученик понимает, в каком классе находится, что делать дальше, где продолжить проект, сохранён ли последний ввод, есть ли feedback и как выйти. Login сам по себе не отмечает задания пройденными. Нельзя показывать чужие работы или фиктивные оценки ради заполнения экрана.

## 3. Оболочка и навигация

Пункты StudentSeat: «Главная», «Моё обучение», «Мои учебные работы», «Помощь», «Мой учебный профиль». Выход доступен явно; бренд не заменяет пункт «Главная». Главная переиспользует существующий разрешённый learner home. Ученику не показываются staff-roster, общий список credentials, platform admin и управление чужими профилями. Account-ученик сохраняет свои личные области по server entitlements.

## 4. Вход и карточка

Ручной путь: код класса → код ученика → Войти. QR карточки сразу разрешает класс и оставляет только ввод кода ученика; без лишнего «Продолжить». Страница не требует имя, email, длинный secret, выбор роли или видимую CAPTCHA. Код ученика — 6 случайных различимых символов, регистронезависимый; отображаемое имя не credential.

Preview содержит название класса и canonical public имя преподавателя, никогда его email. Если имени нет — нейтральное «Преподаватель». Ошибка кода не раскрывает наличие конкретного ребёнка. Сетевой сбой, invalid/rotated class code и rate-limit различаются понятными сообщениями. Разрешённый ручной вход остаётся доступным после ошибки QR.

Карточка печатается преподавателем повторно: ASA Lab / asa-lab.ru, имя ученика, класс, Class Code, Student Code, справа class-only QR. Видимый текст не содержит hash-route/query. QR имеет origin https://asa-lab.ru и не содержит Student Code. Коды/печать не меняют историю. Потерянная бумажка — повторная печать; компрометация — отдельная явная ротация.

Mass-entry acceptance: 30 учащихся за одним IP входят обычным и QR-путём; успешное разрешение кода класса не исчерпывает бюджет всех учеников. Защита от перебора остаётся серверной, незаметной при обычном входе и проверяется отдельным negative test.

## 5. Главная

Показывает настоящее продолжение работы, ближайшие сроки, доработки и feedback в доступных контекстах. Ошибка загрузки — не пустая история. «Открыть», «Продолжить» и «Посмотреть отзыв» ведут к конкретным объектам. Неподдержанные блоки будущих этапов не подставляются как работающие.

## 6. Мои классы

Доступные memberships отображаются внутри «Моего обучения», не staff shell. Видны разрешённые название/преподаватель/статус/назначения, а не общий roster, приглашения преподавателей или чужие Student Codes. Вышедшее/архивное участие сохраняет историю согласно policy и не даёт Start вне разрешённого состояния.

## 7. Список назначений

Карточка показывает название, класс, модуль, workflow, срок/timezone, сохранность и основной следующий шаг. «Не назначено», «Не начато», «В работе», «Сдано», «На доработке», «Завершено», «Без оценки» не смешиваются. Поиск/фильтр не пересекает разрешённый scope. Последняя оценка может отображаться рядом с новой попыткой доработки без её перезаписи.

## 8. Условия задания

До Start доступны exact statement, инструмент, версия, сроки/окно, attempt allowance, режим результата и правила сдачи/feedback по реализованной policy. Effective overrides относятся к точному ученику/назначению. Не показывать ответ/hidden tests. Нельзя выдавать кнопки неподдержанного quiz/programming runtime за E1-функции.

## 9. Контекст редактора

Electronics/3D открываются как реальные редакторы, связанные с той же Attempt. Видны название/задание, back path, состояние сохранения и Submit. Read-only review/preview не редактирует сдачу. Start и Resume различаются; Resume не создаёт новую Attempt. Поздний ответ чужого context не попадает в открытый проект.

## 10. Сдача

Submit фиксирует последнюю подтверждённую сервером exact revision/digest. При незавершённом сохранении нужно дождаться подтверждения либо объяснить отказ; unsent локальный текст не называется сданным. Повтор после потерянного ответа возвращает тот же Submission, не дубликат. Последующее редактирование draft не меняет сданный снимок.

## 11. Отзыв и пересдача

Опубликованный review показывает реальное решение, комментарий и оценку только в соответствующем resultMode. Ungraded/completion не получают искусственных баллов. Возврат при разрешении создаёт новую связанную Attempt; прежняя сдача доступна в истории. Result correction является новой ревизией; ученик и преподаватель видят один выбранный результат.

## 12. Учебные проекты

Account сохраняет личные проекты независимо от школы. StudentSeat хранит свои учебные работы в разрешённом контексте; safe modules для свободной практики выбираются policy. Смена кода не меняет владельца и не создаёт второй список работ. Публикация/экспорт не появляются без соответствующего права и safety policy.

## 13. Достижения

Badges и ProjectFeedback — отдельная обратная связь, не официальная AssessmentResultRevision и не источник Gradebook. Пустой список достижений не заполняется выдуманными наградами. Нет общего рейтинга детей без отдельного разрешённого продукта и политики.

## 14. Профиль и Safe Mode

Минимальные имя/класс/teacher/safety, поддержанный avatar, помощь и logout. Нет обязательного email, публичного профиля и биографии у Seat. Safe Mode наследуется от класса/профиля и не снимается произвольным клиентским переключателем. Настройка личного Account не выдаёт новых прав StudentSeat.

## 15. Уведомления

Реальные события назначения/условий/проверки/доработки/результата/сроков. OFF меняет доставку, не работу и не очередь. Read/unread не является completion. Внешние каналы доступны только при подключённом и разрешённом провайдере; отсутствие email не блокирует обучение.

## 16. Ошибки, сеть и отзыв доступа

Offline/reconnect: не выдумывать серверное сохранение; вернуть ту же Attempt и сохранённый draft по policy. Две вкладки получают conflict вместо silent overwrite. Отзыв code/session прекращает будущий доступ, не удаляет историю. Нет бесконечного повторного reset. Logout очищает scoped данные и subscriptions на общем устройстве; следующий ученик не видит локальный draft предыдущего.

## 17. Читаемость и доступность

Понятные русские подписи, keyboard/focus/labels, semantic errors/status, состояние не только цветом, reduced motion. Проверки 1440/1024/390/320 с длинными именами/названиями, error/loading/disabled/empty/populated. Коды не разбиваются неоднозначно. Нет overlap, page overflow, inaccessible CTA. Сохранность и читаемость обязательны до visual pass; окончательная плотность/цветовая композиция доводятся после функционального закрытия.

## 18. Визуальные доказательства

Снимать именно изменённые экраны: manual join, QR second step, learner menu/home, работа/save/submit, feedback/history, карточки и A4 print-preview. У каждого артефакта synthetic identity, exact SHA и viewport. Screenshot без просмотра/сравнения не доказывает отсутствие дефекта. Реальное сканирование камеры и печать имеют отдельную manual отметку; наличие SVG не доказательство QR.

## 19. Сквозная и отрицательная приёмка

StudentSeat: учитель создаёт synthetic класс/ученика через продукт → печатает/reopens card → QR правильного origin → один Student Code → Главная → назначение → реальный редактор → save/reload → immutable submit → review/return → новая Attempt → resubmit/result. Отдельно ручной массовый NAT-вход, invalid/revoked code, второй ученик без доступа к первому, logout на общем устройстве, rotated class QR и недоступный endpoint.

Account-ученик: normal auth → законное join/approval → тот же учебный runtime → личные проекты не исчезают. E2 временный доступ/timer и E3 linking проверяются только после отдельной реализации и не объявляются частью пройденного E1.

## 20. Definition of Done

Требование, реализация, executed tests, exact CI и live/owner evidence разделены. Продуктовое PASS невозможно при известной потере draft, блокировке класса, неправильном QR origin или утечке credentials. Без разрешённого доступа private live journey на asa-lab.ru остаётся not_run. Doc-only правка не обновляет сервер и не исправляет код. Окончательная visual convergence следует после функциональной приёмки по Integrated V1.5.
