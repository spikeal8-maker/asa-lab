# Допуск модулей публикатора — игры остаются в «Играх»

Прямое решение владельца DEC-PROJ-117, программа #211. Активное состояние —
только current.yaml. Компоновка принята #780; следующая зависимость перед
public-artifact/viewers — серверное соблюдение границ модулей.

## Один срез

Публикатор допускает только `three-d`, `electronics`, `blocks` (Scratch).
Убрать шахматы/шашки и прочие игровые варианты из выбора публичного каталога.
Сервер запрещает новое опубликование игровых Project и публичное чтение старых
игровых публикаций через canonical readability. UI-only запрет недостаточен.

Новая forward SQL миграция следует фактическому опубликованному frontier;
старые миграции не переписываются. Использовать существующую publication policy,
не добавлять вторую систему владения/видимости. Причина отказа понятна автору,
без SQL/личных данных. Прямые HTTP и legacy пути не обходят запрет.

## Сохранность и границы

Не удалять игровые Project/Draft/Version/publication/history и не менять раздел
«Игры», его партии, рейтинги или авторизацию. Остальные safety guards и допуск
владельца остаются прежними; права StudentSeat — отдельный DEC118 срез.
Администратор сохраняет метаданные ранее сохранённых публикаций для контроля,
но игровые работы не становятся доступными публике через admin actions.

Только publication SQL/policy, public module presentation/API validation,
целевые PG/API/browser/unit и необходимые строгие migration-history fixtures.
Без артефактов, runtime, скачивания, лайков, жалоб, общего CI и чужих редакторов.

## Проверка

- Реальная PG: попытка публикации игр запрещена; сохранённые до новой миграции
  игровые публикации недоступны публично, исходные данные/история сохранены.
- Личные 3D/Electronics и допустимый static Blocks не получают регрессию;
  запреты private/Learning/несовпадающего actor/Seat не ослаблены.
- API: прямые публикация/read/image/copy и legacy paths не обходят policy;
  фильтр каталога не предлагает игры. Games API не меняется.
- Все строгие migration fixtures сохранены и дополнены; суммы сверяются с LF
  Git blobs окончательной SQL, не Windows working-tree bytes.
- Exact-SHA профильные PG/API/browser и обязательный General, отдельные
  независимые Code/Security review, отсутствие high/critical замечаний.
- Обычная интеграция в Main после приёмки. Не менять рабочий Docker или базу.
  Исполнитель завершает один срез и останавливается; контроллер затем выбирает
  R7-03A и ведёт основной сценарий просмотра/скачивания дальше.
