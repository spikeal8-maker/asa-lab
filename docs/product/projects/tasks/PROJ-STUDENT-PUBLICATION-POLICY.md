# Права класса и ученика на публикацию и скачивание

Программа #211, второй пункт поручения владельца от 28 октября 2026 года.
Один ограниченный prerequisite-срез; после его принятия контроллер продолжает
экспорт и лайки, затем отдельно обновляет действующий сайт.

## Результат

В существующих настройках класса учитель управляет двумя независимыми флагами:
«Публикация проектов» и «Скачивание проектов». Оба выключены по умолчанию;
для каждого StudentSeat независимо доступны «Как в классе», «Разрешить»,
«Запретить». Действующий ученик может смотреть допустимые публичные работы
независимо от флагов; будущие лайки также от них не зависят.

Решение владельца: выключение публикации запрещает новые публикации и
обновление опубликованной версии, но НЕ скрывает уже опубликованные работы.
Включение флага само ничего не публикует. Отзыв, модерация, недоступный/заблокированный
участник и защищённое учебное происхождение сохраняют прежнюю защиту.

Ученику с эффективным разрешением доступна явная публикация СВОЕЙ допустимой
не-Learning/non-assignment работы с актуальной неизменяемой ProjectVersion,
frozen preview, безопасной публичной подписью и существующей модерацией.
Ни чужая работа, ни задание, ни durable Learning origin не становятся публичными.
Самостоятельные личные проекты Account не подчиняются школьному флагу глобально.

## Реализация и границы

- Existing Account/Principal/StudentSeat/class/teacher authority, без второго аккаунта.
- Отдельные versioned class defaults и per-Seat overrides; строгий CAS, append-only
  административный аудит actor/target/before/after/requestId, существующий стиль API.
- Сервер вычисляет эффективное право из действительного ресурса и сессии, не из UI.
  Защита от cross-class/tenant/teacher/Seat substitution и конкурентного revoke/publish.
- Разделить publication write admission и readability старой явной публикации:
  выключение флага не отменяет уже сделанную публикацию. Не расширять legacy/raw
  Gallery доступ вследствие допуска Seat; проверить все совместимые read paths.
- Сохранить один канонический immutable publication writer и текущие RLS/locks,
  moderation/pins/reports, exact-version/dedup и user-safe errors. Старые опубликованные
  SQL не переписываются: одна новая forward migration после проверки текущего frontier.
- Эффективное download admission сделать каноническим server seam для следующего
  export-среза. Не показывать фиктивную download кнопку и не объявлять архивы готовыми.
- Компактный teacher UI без новых экранов аккаунта/кодов; адаптивность320/390/1440,
  доступные названия, pending/error/conflict/reload; students не управляют настройками.
- Не менять Games, личный вход, пароль, чужие WIP, solver, Scratch upstream, конфиги
  рабочего сервера или рабочую БД. Просмотр Scratch/электроники и компактная страница
  PR814 сохраняются. Рейтинг, бонусы, жалобы и новая модерационная система вне среза.

## Обязательная проверка

Один автор: узкие unit/types/format, bounded self-review; независимые Code/Security
точного SHA. Реальные PostgreSQL/API/browser в существующем GitHub focused workflow:
class defaults OFF, оба override и inherit, активный/blocked/removed Seat, teacher ACL,
CAS/concurrent publish-policy, неподделываемый audit, protected origins, personal Account,
Seat без Account, exact frozen version, право отменено -> новые publish/republish denied,
старая публикация всё ещё доступна, revoke/moderation всё ещё скрывают её.
Скриншоты реальных teacher/Seat интерфейсов. Старые миграции, legacy reads, RLS и
существующие personal publisher/viewers не ослаблять. General и affected focused
на финальном SHA перед Main; не гонять неизменённые тяжёлые проверки локально.

После отчёта автор STOP; контроллер ведёт дальнейшие экспорт/лайки, не считая этот
prerequisite завершением всего второго пункта. Deployment только после всей программы.
