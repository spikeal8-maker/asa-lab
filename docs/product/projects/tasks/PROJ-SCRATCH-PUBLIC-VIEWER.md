# Официальный Scratch player в публикациях

Программа #211. Прямое поручение владельца: применить готовый официальный
просмотрщик Scratch; для лайков и скачивания использовать его решения как
образец. Этот цельный срез даёт работающий player; правила DEC118 для учеников
и отдельная реализация реакций/разрешённого экспорта сохраняются.

## Пользовательский результат

Публичная страница опубликованного Scratch-проекта открывает официальный
закреплённый Scratch player: настоящая сцена и ресурсы, зелёный флаг, остановка,
штатный полноэкранный режим, телефон и клавиатура. Подключение идёт через
существующую ASA iframe/host boundary. Исходный проект остаётся неизменным.
Сначала показать действительный визуал, затем провести финальные проверки.

Не создавать собственный интерпретатор, второй редактор или замену scratch-vm.
Не обновлять upstream pin и не добавлять upstream patch. GUI/VM не становятся
зависимостями основного apps/web. Сохранить лицензии, штатную механику Scratch
и работающий editor/storage/recovery. Режим player не имеет прав записи.

## Точный источник и безопасность

- Использовать каноническую текущую PublicationRevision и связанную immutable
  ProjectVersion. Working Draft, старый Gallery work и tenant-wide доступ не
  являются источником публичного просмотра.
- Реальный гость и активный ученик могут смотреть допустимую публикацию.
  Private/unlisted/revoked/trashed/Learning/stale не обходятся.
- Переиспользовать existing runtime capability/session/storage primitives.
  Публичная authority привязана к publication/revision/version; её нельзя
  подставить в editor/draft/save/asset-upload endpoint. Проверять актуальное
  право при выдаче, обновлении токена и чтении данных/ресурса, включая cache hit.
- Ресурсы остаются в частном bucket. Чтение разрешено только для канонического
  asset ref точной опубликованной версии с совпадающими hash/size/format и
  tenant alias/blob metadata. Без утечки внутренних object keys или доступа
  ко всем ресурсам автора. Не выдавать Account cookie в качестве authority iframe.
- Применить существующие ограничения JSON/assets/count/bytes и capability TTL,
  in-memory nonce/token lifecycle, проверку origin/source сообщений. Не хранить
  секреты в URL, localStorage, логах или публичном artifact.
- Неподдерживаемый документ/ошибка показывают честную обложку и короткое
  сообщение. Не заменять выполнение фиктивной анимацией.
- Публичная выдача пользуется безопасной проекцией общего artifact или явно
  типизированной совместимой capability; не возвращать private editor DTO.

## Ресурсы и интерфейс

Lazy iframe только на странице Scratch-публикации, штатный isPlayerOnly.
Не загружать Scratch в каталог/карточки/электронику и не монтировать editor UI.
Освобождать iframe, обработчики, refresh timers и выполнение при уходе,
смене revision и отзыве. Ограничить bootstrap/payload/asset requests, не создавать
цикл загрузки/обновления. Не обещать 5000 одновременных пользователей без замера.

Вписать сцену в принятую полноширинную рабочую область. Проверить реальные
1440/1024/390/320, без горизонтальной прокрутки, с видимыми запуском/остановкой.
Полноэкранный режим и выход должны реально работать. Loading/error/fallback
не мигают и не перекрывают действия. На мобильном управление не требует hover.

Лайки/избранное/скачивание из scratch-www служат образцом пользовательского
поведения; их серверные вызовы Scratch не подключать к нашим аккаунтам.
Не добавлять пока фиктивные кнопки. Публикация/скачивание ученикам разрешаются
только будущим серверным применением DEC118; просмотр этим не ограничивается.

## Проверка и выпуск исходного кода

1. Один автор реализует bounded slice и POST_STEP_REVIEW. Сначала локальные
   узкие unit/type/contract проверки, без установки/перелинковки неполного
   node_modules и без тяжёлой локальной Scratch сборки.
2. Реальные PG/HTTP: anonymous и Seat, exact version/assets, draft V2 не влияет
   на V1, републикация/отзыв/старые ссылки, asset ID substitution, истечение и
   несовместимость player token с записью. Без небезопасных SQL grants/RLS bypass.
3. Реальный pinned Scratch в браузере запускает опубликованную программу с
   настоящим costume/sound asset; stop/fullscreen/повторное открытие работают.
   Проверить отсутствие save/upload/mutation и неизменность оригинала, teardown,
   гостя и ученика. Сохранить actual screenshots и receipts в загружаемом artifact.
4. Сохранить Public Projects/Electronics и Scratch editor regressions. Использовать
   существующие GitHub focused gates и окончательный General; повторять только
   затронутые проверки при новом diff/ошибке. Не чинить независимые чужие дефекты.
5. Независимые Code/Security и structural boundary review точного окончательного
   SHA, визуальная инспекция контроллером. После требуемых PASS — обычная отправка
   в Main и отчёт. Никаких фиктивных GitHub APPROVE/обхода защиты.

Рабочий сайт, Docker, рабочая БД и внешние настройки не меняются этим поручением.
Остальные части #211 не объявляются завершёнными из-за готовности player.

## Уточнение владельца: компактная страница публикации

Страница следует структуре официального Scratch preview: компактные название и
публичное имя автора, настоящая сцена слева и описание справа на компьютере,
сцена первой на телефоне. Ориентир:
https://github.com/scratchfoundation/scratch-www/blob/develop/src/views/preview/presentation.jsx.
Публичная кнопка «Обновить публикацию», открытие отдельной картинки и лишняя
полоса над Scratch удаляются. Полноэкранное действие остаётся компактной кнопкой
с доступным названием. Ссылка копируется без открытия поля при успехе;
выделяемое поле появляется только при отказе clipboard. Недоступное копирование
скрыто по существующему серверному canCopy, доступное остаётся компактным.
Лицензия и даты доступны в раскрываемых сведениях. Имя автора берётся из
существующего безопасного публичного authorLabel, без раскрытия почты или
закрытого профиля. Реальные сохранение, права и native player не заменяются.
