# Ручной журнал по датам — КЛ-14 и КЛ-15

Дополнение владельца от 09.10.2026 выбирает отдельные ручные наблюдения по
дате и категории. Они не являются результатом задания, попытки или сдачи и
не включаются автоматически в результаты курса, среднюю оценку или рейтинг.
Существующий канонический журнал заданий и immutable review доступны в режиме
«Задания», включая старые ссылки `assignment` / `learner` / `attempt`.

Матрица и ученический список проецируют одни `classroom_journal_revisions`.
`seat_id` обозначает точное место в классе, `learner_identity_id` разрешается
существующим `learning_audience_ensure_seat_identity` только при отсутствии
связи Seat. Существующую неактивную связь команда не воскрешает. Principal используется
только для авторства и проверки доступа. Связанный Account получает ту же
историю, что StudentSeat; поиск/слияние по имени не используется.

Шкала закрепляется в неизменяемом столбце через `scale_id`. Будущий default:
`five` = 0..5, `hundred` = 0..100, `three_five` = только 3/4/5,
`smileys` / `symbols` = возрастающие уровни 1..5. Ноль является оценкой.
Очистка существующей оценки — новая ревизия со значением NULL; первые пустые
ячейки не создают ревизий. Исправление и очистка требуют причины и
`expectedRevision`. История содержит автора, время и ссылку на предыдущую
ревизию, UPDATE/DELETE запрещены триггерами и runtime grants.

API описан в `schemas/openapi.yaml`. Teacher read/write требует действующей
educator capability и точного owner/co_teacher membership. Идентичность
выводится из сессии. Учительские методы и `/api/learning/journal/results`
разрешают только Account cookie. `/api/class-join/journal/results` разрешает
только StudentSeat cookie и не запускает Account refresh. Две cookies не
смешиваются и не дают fallback. Компонент получает явный scope из SeatResults
или AttendedClassesPage; повторная проверка по focus/visibility, logout и
кнопке обновления очищает старую выдачу и отбрасывает устаревшие ответы.
Результаты ученика разрешаются только для его активного/выданного Seat;
неодобренная/отклонённая заявка не даёт доступа. Проверяются активная identity
самой оценки, активные канонические связи Seat и Account и tenant/school/class
lineage. Одного устаревшего `seat.account_id` недостаточно. Отзыв любого
субъекта скрывает результат и inbox для этого субъекта, не переносит историю
и не скрывает результат от другого всё ещё разрешённого субъекта.
Архив позволяет чтение и replay ранее
сохранённого receipt, но запрещает новые mutations; удалённый класс скрыт.

Команды сериализуются блокировкой строки класса. После текущей авторизации
receipt ищется до проверки stale revision. `requestId` scoped по классу и
автору; повтор с другим payload возвращает 409. Receipts хранятся вместе с
историей без срока автоматического удаления. Клиент не показывает сохранение
до ответа сервера; ошибка сети сохраняет requestId для точного повтора, конфликт
требует обновления данных.

Ручные результаты используют существующие learning_notifications:
`journal_revision_id`, `NF04`/`NF05`, `NC03`. Фиктивных FK на сдачи нет.
Существующие настройки общего выключателя, категорий и правил класса
применяются к доставке, а не к результату. Оба разрешённых субъекта получают
по одному событию в своём штатном inbox. Общий `learning_notification_emit`
делает ранний return по legacy `seat.account_id`; его resource access нельзя
использовать как authority канонической ручной оценки. Поэтому узкий закрытый
`classroom_journal_notification_emit` проверяет точную journal identity, затем
использует тот же advisory lock, `learning_notification_enabled`, NC03 и ту же
таблицу inbox. OFF создаёт явную suppressed запись. Реальная ошибка emission
откатывает оценку, уведомления, receipt и audit; HTTP 500 допускает точный retry.
Пропущенное INSERT тоже является ошибкой, а не успехом. Journal-ветка access
проверяет точную identity; прежнее тело access/course revocation оставлено в
ELSE без ослаблений. Unread/mark-read продолжают применять эту же функцию.
Нового polling нет.
Student Code: `#/join-class?code=…` → штатный вход → `#/learning`, компонент
SeatResults. Account: `#/learning` / `#/attending`, AttendedClassesPage.
Inbox: существующий раздел `#/account/notifications` →
`#/learning?journal=1&journalMonth=YYYY-MM&journalColumn=UUID`. Это focus hint:
колонка фильтруется внутри авторизованного SQL, не даёт доступа. Открывается
последнее опубликованное состояние этой ячейки, включая очистку, и прежний месяц.

Начальная страница — текущий календарный месяц. SQL и API ограничивают
включительный диапазон 93 днями, limit — 1..50, offset — 0..1000000.
Матрица загружает до 50 столбцов и только их оценки; список ученика — до 20
результатов по умолчанию, история — до 20 изменений с exclusive revision cursor.
Навигация месяца, выбор любого прежнего месяца и следующие/предыдущие страницы
есть в UI. Нет fetch-all или запроса истории каждой ячейки: авторы соединяются
в SQL страницы, история запрашивается только для открытой ячейки. Настройки
используют отдельный маленький `/journal/settings`, без загрузки матрицы.

Первый scale snapshot закрепляет валидную сохранённую IANA timezone владельца
класса (если её нет, UTC). Новые scale versions сохраняют эту же timezone;
профиль другого преподавателя/устройство не сдвигают календарные даты. Server
возвращает today/range в этой timezone; исторические даты хранятся как DATE.
Ученический результат несёт timezone своего класса для времени публикации.
При нескольких классах начальный месяц берётся из timezone первого доступного
класса по UUID; выбранный пользователем месяц одинаков для всего списка.

Реальные PostgreSQL проверки включены общим Vitest через
`tests/courses/classroom-manual-journal.pg.spec.ts` и требуют изолированную
`*_test` БД и restricted runtime role. E2E:
`e2e/classroom-manual-journal.spec.ts`, без synthetic API. Инъекция сетевого
сбоя исполняет реальный POST и теряет его первый ответ для безопасного повтора.
Реальный PG тест устанавливает временный class-scoped trigger отказа INSERT
уведомления, проверяет полный rollback, удаляет инъекцию и повторяет тот же
requestId без дубля. Дополнительно покрыты отзыв Account/Seat/identity,
каноническая связь с устаревшим полем, прежние course/class/requester правила,
границы диапазона/страницы, timezone snapshot и реально смешанные cookies.
