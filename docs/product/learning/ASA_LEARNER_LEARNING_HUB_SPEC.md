# ASA Lab — ученический центр обучения и путь к учебной работе

**Идентификатор:** LRN-LEARNER-HUB-01  
**Статус:** нормативная детализация E1  
**Дата:** 21 сентября 2026 года  
**Связанные требования:** PRODUCT-INTEGRATED-V15 §4.5.1, E1-FIX-13, E1-FIX-14  
**Связанные документы:** ASA_LEARNING_WORK_SHELL_SPEC.md, ASA_LEARNER_WORK_LIFECYCLE_SPEC.md, ASA_LEARNING_WORK_ARCHITECTURE_PLAN.md

## 1. Основной принцип

ASA Lab не превращает обычный Account в отдельный «аккаунт ученика».

Личный пользователь по-прежнему может:
- создавать собственные проекты;
- открывать лаборатории для экспериментов;
- хранить личные проекты;
- пользоваться Сообществом/публичными возможностями по обычным правилам.

Учебные группы, курсы и задания являются отдельным контекстом внутри того же Account и находятся в **«Моём обучении»**.

StudentSeat использует ту же учебную модель, но scoped к своему классу/группе и без личных Account-функций, которых у Seat нет.

## 2. Полный путь ученика

Нормативный основной путь:

~~~text
Вход в ASA Lab
      ↓
Главная / учебное внимание
      ↓
Моё обучение
      ↓
группа / курс / отдельное задание
      ↓
карточка/страница конкретного задания
      ↓
Начать работу / Продолжить работу
      ↓
предметная лаборатория
      ↓
постоянная бирка «Задание»
      ↓
по нажатию открывается плавающая панель задания
~~~

Ученик не обязан сначала открывать «Мои проекты», чтобы найти работу преподавателя.

Учебный Project является следствием Start учебного задания, а не навигационной сущностью, через которую ученик должен угадывать, что ему было задано.

## 3. Что ученик видит сразу после входа

### 3.1 Account с учебными контекстами

Личная Главная остаётся личной. Учебный контекст не захватывает весь Account.

Если есть актуальные учебные действия, на Главной показывается компактный блок **«Учебные дела»**:

~~~text
┌ Учебные дела ──────────────────────┐
│ ↩ Закон Ома · нужна доработка      │
│ ⏱ 3D-модель · до завтра            │
│ ◆ Схема цепи · доступно            │
│                                    │
│ [Открыть Моё обучение]             │
└────────────────────────────────────┘
~~~

Показываются максимум несколько наиболее важных действий и общий переход в «Моё обучение». Блок не заменяет личные проекты/лаборатории.

Если actionable learning нет, блок может быть компактным либо отсутствовать.

### 3.2 StudentSeat

Для StudentSeat Главная делает учебное продолжение более заметным, потому что Seat существует именно в scoped learner context. Однако основной экран заданий всё равно остаётся «Моё обучение», а не отдельная вторая платформа.

## 4. Два независимых индикатора внимания

### 4.1 Колокольчик

Колокольчик показывает **непрочитанные учебные события**.

Примеры:
- назначено обучение;
- изменены условия;
- нужна доработка;
- опубликован результат;
- скоро срок;
- срок прошёл;
- курс завершён.

Badge колокольчика = число непрочитанных notification events.

Нажатие на learner notification ведёт в «Моё обучение» к конкретному assignment/course context, **не обязано сразу открывать editor**.

### 4.2 Badge «Моё обучение»

Badge рядом с «Моё обучение» = число **уникальных учебных работ, требующих текущего действия ученика**.

Сюда входят:
- available not started;
- in progress;
- changes requested;
- overdue, если сдача ещё разрешена.

Не входят:
- scheduled/locked;
- submitted waiting review;
- completed;
- closed без разрешённого learner action.

Одна работа считается один раз независимо от количества notification events.

## 5. Несколько учебных групп

Account может одновременно учиться в нескольких Classroom/учебных группах.

Backend сущность остаётся Classroom; UI может использовать нейтральное понятие «учебная группа» там, где слово «класс» слишком школьное.

~~~text
Моё обучение

Сейчас

Группа «Робототехника 8А»
  Основы электроники
  2 актуальные работы

Группа «3D по субботам»
  Основы моделирования
  1 актуальная работа
~~~

Нельзя переключать весь Account в одну «активную школу/класс» только ради обучения. «Моё обучение» агрегирует все разрешённые learner contexts.

StudentSeat видит только свой scoped Classroom.

## 6. Информационная архитектура «Моего обучения»

Целевой E1 экран:

~~~text
Моё обучение

[Сейчас] [Группы и курсы] [Завершённое]
~~~

Самостоятельное обучение становится отдельной полноценной ветвью на E3; до этого открытые материалы остаются в «Знаниях».

### 6.1 Сейчас

Это агрегированный список по всем группам Account.

Секции по приоритету:

1. **Требует внимания**
   - changes requested;
   - просрочено, но ещё можно сдать;
   - срок скоро.

2. **Продолжить**
   - in progress.

3. **Доступно**
   - open/not started.

4. **Ждёт проверки**
   - submitted/evaluating.

5. **Скоро**
   - scheduled with future opensAt.

Выполненные не засоряют «Сейчас».

### 6.2 Группы и курсы

Показывает группы, в которых учится пользователь.

Внутри группы:
- преподаватель/группа;
- активные CourseRuns;
- отдельные direct assignments;
- количество актуальных работ;
- upcoming;
- завершённое.

Внутри курса сохраняется структура:
~~~text
раздел
→ урок
→ материал
→ конкретный Activity block
~~~

Если в одном уроке три практики, это три отдельные учебные работы/occurrences с собственными состояниями.

### 6.3 Завершённое

Показывает академическую историю:
- выполненные практики;
- завершённые курсы;
- опубликованные результаты;
- переход к ранее выполненной работе.

Этот список не зависит от того, убрал ли ученик сам Project в «учебный архив» списка проектов. Academic history и project-list organization — разные вещи.

## 7. Карточка задания в списке

Минимально:

~~~text
┌──────────────────────────────────────┐
│ Закон Ома                            │
│ Основы электроники · Робототехника 8А│
│                                      │
│ Доступно · до 25 сентября            │
│                                      │
│ [Открыть задание]                    │
└──────────────────────────────────────┘
~~~

Состояния карточки:

~~~text
🔒 Откроется 25 сентября, 09:00
◆ Доступно
● В работе
↩ Требуется доработка
✓ Сдано · ждёт проверки
✓ Выполнено
⏱ Просрочено · сдача разрешена
— Закрыто
~~~

Статус определяется сервером, не вычисляется из текста кнопки.

## 8. Планирование и открытие задания преподавателем

Нужно различать три вещи.

### 8.1 Авторский draft

Учитель только подготовил материал/задание, но ещё не выдал его группе.

Ученик **ничего не видит**.

### 8.2 Выдано, но opensAt в будущем

Задание уже назначено ученику, но период выполнения ещё не начался.

По умолчанию E1 ученик видит:

~~~text
🔒 Закон Ома
Робототехника 8А · Основы электроники
Откроется 25 сентября в 09:00
Сдать до 30 сентября
~~~

До opensAt:
- видны title, group/course context, open time, due time;
- полный текст/медиа задания не раскрываются;
- Start/Continue запрещены;
- editor не открывается.

Это и есть нормативный смысл «учитель запланировал, но ещё не открыл».

### 8.3 Доступно

После opensAt:
- открывается полный task snapshot;
- появляется Start/Continue;
- учебная работа становится actionable и учитывается badge «Моё обучение».

### 8.4 dueAt и closesAt

dueAt — срок, но не обязательно жёсткая блокировка.

Если dueAt прошёл, а policy разрешает позднюю сдачу и closesAt ещё не наступил:

~~~text
⏱ Просрочено · можно сдать
~~~

После effective closesAt:
- Start/Submit запрещены;
- существующая история доступна;
- teacher unlock/override может вернуть разрешённое действие.

Нельзя клиенту самостоятельно трактовать dueAt как closesAt.

## 9. Экран конкретного задания до лаборатории

Клик «Открыть задание» сначала открывает learner assignment detail.

~~~text
Закон Ома
Робототехника 8А
Основы электроники · Урок 4

Цель
Исследовать зависимость тока...

Что сделать
1. Соберите...
2. Измерьте...
3. Запишите...

[схема / изображение]

Срок: 30 сентября

[Начать работу]
~~~

Это основной reader exact task snapshot.

Не создавать Project только от просмотра задания.

### 9.1 Кнопка действия

Состояние → действие:

~~~text
not started      → [Начать работу]
in progress      → [Продолжить работу]
changes requested→ [Продолжить доработку]
submitted        → [Посмотреть работу] + «Ждёт проверки»
completed        → [Посмотреть работу]
scheduled        → disabled «Откроется …»
closed no action → только просмотр доступной истории
~~~

При первом Start целевая архитектура использует atomic StartLearningWork.

## 10. Вход в лабораторию

После Start/Continue открывается subject editor.

Ученик только что видел полное задание на предыдущем экране, поэтому нормальный editor entry **не обязан снова занимать экран раскрытой карточкой**.

Целевой desktop entry:

~~~text
┌──────────────────── лаборатория ─────────────────────┐
│                                                      │
│                рабочая среда                         │
│                                                      │
│                                                      │
│ [▣ Задание  ˄]                                      │
└──────────────────────────────────────────────────────┘
~~~

Бирка задания остаётся постоянной платформенной точкой доступа.

## 11. Бирка и панель задания в лаборатории

### 11.1 Anchor / бирка

На desktop:
- по умолчанию у нижнего безопасного края;
- показывает «Задание» и при достаточном месте короткое название;
- содержит понятный индикатор открыть/закрыть;
- остаётся доступной, пока panel open;
- не перемещается вместе с содержимым задания случайно.

Пример:

~~~text
[ ▣ Задание · Закон Ома   ˄ ]
~~~

### 11.2 Открытие

Нажатие на anchor:

~~~text
             ┌──────────────────────────────┐
             │ Закон Ома                    │
             │ Цель...                      │
             │                              │
             │ [схема]                      │
             │                              │
             │ Сохранено       [Сдать]      │
             └──────────────────────────────┘
[ ▣ Задание · Закон Ома   ˅ ]
~~~

Panel открывается **над anchor**, а anchor остаётся toggle.

Повторное нажатие сворачивает panel обратно к бирке.

### 11.3 Desktop panel

Начальный размер открытой panel:
- около 360–400 px шириной;
- content-fit height с разумным максимумом;
- body scroll при длинном задании.

Ученик может:
- перетащить panel;
- вручную изменить width/height;
- использовать expand preset;
- вернуть безопасное положение.

Anchor при этом остаётся постоянным способом спрятать/вернуть panel.

### 11.4 Работа со схемой/картинкой

Если задание содержит reference image/schema:
- изображение адаптируется к panel;
- пользователь может увеличить;
- изменить окно так, чтобы оставить видимой только нужную часть/схему;
- позднее pinned reference позволяет отделить схему от полного текста.

Цель — ученик может разместить reference рядом с Electronics/3D/Scratch и работать по нему, а не постоянно переключаться между страницами.

## 12. Mobile

На телефоне anchor находится в safe bottom area.

Нажатие открывает bottom sheet.

Никакого desktop drag/resize.

Состояния:
- anchor collapsed;
- medium sheet;
- large sheet.

Возврат к anchor не закрывает и не перезагружает лабораторию.

## 13. Уведомления и destinations

Learner notification ведёт на соответствующий экран «Моего обучения».

Примеры:

~~~text
Назначено обучение
→ assignment/course detail

Нужна доработка
→ конкретное задание, state changes requested

Срок скоро
→ конкретное задание

Результат опубликован
→ completed/result context
~~~

Notification mark-as-read и academic/workflow state независимы.

Прочитать уведомление ≠ начать задание.

## 14. Сортировка «Сейчас»

По умолчанию:

1. changes requested;
2. overdue but actionable;
3. due soon;
4. in progress;
5. available not started;
6. submitted waiting review;
7. scheduled upcoming.

Внутри одной группы приоритета — ближайший effective dueAt, затем стабильный идентификатор.

UI допускает фильтр по группе/курсу без изменения canonical order semantics.

## 15. Что уже существует и переиспользуется

Текущая система уже имеет:
- «Моё обучение»;
- Account с несколькими attended Classroom;
- Seat scoped class journey;
- SeatCourses;
- SeatAssignments;
- LearningInbox;
- unread notification badge;
- notification destinations в learning/classroom;
- unfinishedCount badge рядом с Learning.

Эта спецификация **конвергирует существующие поверхности**, а не создаёт второй learner dashboard.

## 16. Что требуется изменить

Нужно довести существующие поверхности до одного coherent journey:

1. «Моё обучение» получает агрегированный default «Сейчас».
2. Multi-class Account видит задания по всем группам без смены Account workspace.
3. Scheduled future assignment имеет locked visible state.
4. Assignment detail становится обязательным шагом чтения перед Start.
5. Notifications открывают assignment detail, а не заставляют искать проект.
6. Learning badge считает unique actionable work.
7. Editor использует постоянный anchor + toggle panel.
8. Academic completed history не смешивается с project learning archive.

## 18. Не включать ложные доказательства

Не считать реализованным multi-group learner hub, если тест:
- создаёт только один Classroom;
- открывает assignment напрямую query-параметром, обходя «Моё обучение»;
- показывает notification, но destination не приводит к task detail;
- показывает future assignment как доступное;
- создаёт Project до нажатия Start;
- открывает editor без постоянного assignment anchor.
