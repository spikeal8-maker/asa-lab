# ASA LAB — коррекция интерфейса профиля и платформенных сценариев

**Decision ID:** `SP-OWNER-UX-20261116-V1.1`  
**Инициатор:** владелец ASA Lab, обратная связь по трём фактическим экранам от 16.11.2026.  
**Область:** главная Account/StudentSeat, левый блок профиля, «Моё обучение», рейтинг группы, выбор аватара; отдельно — проект будущих платформенных прав.  
**Статус:** нормативная корректировка композиции **после принятия данного документа в main**. Наличие ТЗ не является исполнением кода/CI/деплоя.  
**Точка входа:** [основное ТЗ](MASTER_SPEC.md), [UI-контракт](UI_CONTRACT.md), [приёмка](ACCEPTANCE.md).  
**Исполнение:** [P0 — профиль и группы](tasks/SP-UX-REVISION-P0.md), [P1 — аватары](tasks/SP-AVATAR-CHOOSER-P1.md), [будущие права v2](tasks/SP-PLATFORM-RATING-ACCESS-V2.md).

## 1. Продуктовое решение

**ASA Lab — платформа проектов и самостоятельной работы. Обучение — дополнительный полноценный контекст, а не обязательная главная роль пользователя.** Нельзя предполагать, что каждый Account — ученик. Единственный надёжный признак учебного контекста — подтверждённое участие/доступное учебное действие от сервера, а не сам факт регистрации, наличие имени или роль интерфейса.

Две штатные точки аватара сохраняются: профиль в левом меню и действующий аватар в правом углу верхней панели. Третье крупное изображение того же лица в контенте запрещено. Нельзя создавать вторую большую «шапку» ради трёх чисел.

Для desktop метрики интегрируются **слева от существующего аватара в левом профиле**, без сдвига основного каркаса. На мобильном — компактно около видимого аватара профиля или внутри доступной по нажатию панели профиля, без третьего изображения и перекрытия действий.

## 2. Desktop: точное расположение

1. Сохраняется существующая высота header, текущая навигация и допустимая ширина sidebar. Изменяется только локальная внутренняя область профиля, а не весь портал.
2. Аватар остаётся на своём месте и остаётся кнопкой перехода к существующему выбору изображения. Имя — под аватаром, с корректным обрезанием и доступным полным текстом.
3. Слева от аватара — колонка компактных `иконка + число`, по вертикали сверху вниз:
   - **Общий личный рейтинг**, визуально главный небольшой бейдж у верхнего левого края аватара, но только при серверно подтверждённом расчёте SP-06/SP-07.
   - **Опубликованные работы** — число подтверждённых уникальных публикаций автора.
   - **Нравится** — текущее число действительных лайков его работ.
   - **Добавили к себе** — число успешных созданных копий его публичных работ; это **не скачивания** и не число уникальных людей.
4. Текущие реальные нули должны быть корректны: в компактном sidebar нулевые вторичные счётчики можно свернуть, но их полные значения доступны в профиле/подсказке. `unknown`, `loading`, `error`, `disabled` не превращаются в `0`. Если все вторичные показатели нулевые, отдельная пустая полоса/карточка не появляется.
5. Общий рейтинг не подменяется баллом группы и не выводится из суммы лайков. Пока серверного журнала рейтинга нет, **числовой бейдж общего рейтинга не отображается**; при необходимости краткий статус — только внутри профиля.
6. Каждый значок имеет доступное название для клавиатуры и скринридера; по нажатию метрики открывают существующую работающую страницу/объяснение, **не декоративную пустую ссылку**. Никакой обязательной навигации при наведении.
7. В центральном контенте главной не отображается второй крупный блок «Мой прогресс», второе имя/аватар и отдельная пустая карточка «О показателях». Краткое объяснение чисел доступно рядом с ними в профиле.

Нужная информационная иерархия на desktop: **штатная панель профиля + проекты и направления в основном поле**; компактный учебный контекст вставляется только когда действительно имеет смысл.

## 3. Три состояния пользователя

| Состояние | Главная | «Моё обучение» |
| --- | --- | --- |
| **Account без подтверждённого участия в группах и без учебного next-action** | Нет «Мои группы», «Открыть обучение», пустых назначений/результатов. Сразу направления, проекты, создание и релевантные личные материалы | Раздел доступен добровольно через штатную навигацию; не навязывается и не открывается автоматически |
| **Account с подтверждённой группой или реальным учебным действием** | Одна компактная сводка реальных групп/действия, без двух вложенных шапок и пустой карточки. «Продолжить» только для реального действия с корректным маршрутом | Полный учебный обзор с assignments/courses/results и безопасным рейтингом |
| **StudentSeat** | Его собственная область учебных групп и разрешённых действий; проекты доступны по существующим правилам. Никакого раскрытия приватного Account | Доступный этому Seat обзор, без посторонних классов/проектов |

Проверка `next-action` не должна подставлять «Открыть обучение» как fallback после пустого результата, ошибки или отсутствия групп. При ошибке учебного API не скрывать рабочие направления и проекты. Пользователь может сам открыть «Знания» или «Моё обучение» через существующую навигацию.

На главной учебная сводка показывается **только при фактическом участии**, не более двух групп; «Все группы» ведёт в обучение только при наличии групп. На экране обучения не повторять общий профиль/аватар/имя — там только контекстные учебные данные.

## 4. Рейтинг группы: использовать ширину, но не разглашать данные

1. На desktop ряд рейтинга занимает **всю доступную ширину контейнера**, без искусственно пустой правой половины.
2. Сам участник закреплён слева как компактный элемент `Вы · место · балл`, без третьего полноразмерного дубликата профильного аватара. Место остаётся серверным; «закреплён слева» **не означает первое место**.
3. Одногруппники идут справа в **одну строку** по серверному ранжированию. У каждого аватар; место на верхнем левом углу изображения, балл в правом нижнем. Имен, фамилий, кодов, контактов нет ни в DOM/aria/title/tooltip, ни в ученическом API.
4. Количество peer-аватаров рассчитывается из измеренной ширины строки `ResizeObserver`, с учётом ширины `Вы`, безопасных отступов, числа знаков/балла и touch target. Использовать пространство до края; **фиксированного потолка 5 на широком экране нет**. Максимум одного начального запроса — ограниченное значение, например 20 peers; точная граница фиксируется в тестах и согласуется с API-cap.
5. Нельзя загрузить весь класс и скрыть DOM через CSS. Запросы/изображения получают только нужную ограниченную порцию; при расширении контейнера — адресная догрузка или корректный кеш, без fan-out и polling. При сужении — не возникает горизонтальный scroll страницы.
6. Непоместившиеся участники доступны по действующей кнопке `Все`, которая открывает **настоящий серверно-пагинируемый рейтинг** выбранной группы. Если группа полностью помещается, действие можно скрыть или заменить на ненавязчивое «Весь рейтинг», только если оно действительно работает.
7. На 1024/390/320 число peers уменьшается **по фактической ширине**, но сами значки и цифры не становятся нечитаемыми. Предусмотреть длинное название, дробные баллы, трёхзначные места, 200% zoom, null score/rank, loading/error, повторную загрузку и смену identity.
8. Два контекста — домашняя сводка и обучение — могут иметь разную ширину, но один алгоритм расчёта ёмкости и одинаковую приватную семантику; не дублируют запросы между поверхностями при одинаковом scoped-key.

## 5. Выбор аватара: отдельно после P0

Существующую диалоговую панель сохранить, но убрать обязательную последовательность `выбрать → отдельный экран большого превью → назад`.

- Desktop: изображение увеличивается при **наведении** рядом с сеткой и при клавиатурном фокусе, без изменения выбранного значения; один клик по миниатюре помечает выбор, отдельное **Сохранить** подтверждает его.
- Touch: касание выбирает и раскрывает встроенное увеличенное изображение без отдельного полноэкранного экрана; **Сохранить** подтверждает.
- Предпросмотр не меняет аватар автоматически, не требует повторного открытия каталога и не вызывает дёрганье размера модалки; пользователь видит текущий и выбранный варианты.
- Сохраняются загрузка собственного файла, server save, ошибки, запрет записи в чужой контекст, обработка отмены, клавиатура/Escape и reduced motion.

Это UX существующего `AvatarChooser/AvatarSelection`, **не новый графический редактор аватаров**.

## 6. Отдельное решение о правах по общему рейтингу

Владелец предложил открывать платформенные возможности — например, ИИ и игры — на основании **общего личного рейтинга даже у Account без класса**, с настройками в админке. Это **новый контракт v2**, а не скрытая правка SP-05 или действующих полномочий.

- В текущем v1 общий рейтинг **не управляет разрешениями**; существующие игры/ИИ и групповые режимы не менять при визуальном P0/P1.
- Новую `platform-rating access v2` внедрять отдельным L3-этапом **после реально работающего SP-06**, серверного подтверждения счёта и явного controller selection.
- Администратор задаёт по каждой возможности `inherit_existing / allow / deny / min_global_rating`, порог и область Account. По умолчанию `inherit_existing`, что сохраняет поведение существующих пользователей.
- Для `min_global_rating` решение серверное и динамическое, при каждом защищённом действии; нет автоматического бессрочного grant. Сохранённый grant можно вводить только отдельным принятым решением.
- Платформенные ограничения, права на ресурсы/модуль, реальные запреты, tenant и безопасная личность имеют приоритет. Групповой рейтинг не заменяется общим; StudentSeat не получает Account-only право через совпадение имени.
- UI выводит краткую причину и корректный остаток до порога, только когда существует проверенный рейтинг, scope и threshold. Если рейтинг недоступен, не показывать фиктивные нули/права.
- Код, схемы, admin UI, серверный resolver, отрицательные тесты — отдельный контракт [v2](tasks/SP-PLATFORM-RATING-ACCESS-V2.md). **Никакой live activation без собственной приёмки и релизного решения.**

## 8. Что НЕ затрагивать

Нельзя изменять формулу группы, канонические баллы, произвольные учебные оценки, C3/0323, выбранную модель `SP05-B-1.0.0`, её checksum, старые микросервисы или ID/RLS, глобальную навигацию/шапку, существующие rights semantics игр и ИИ, принудительно подключать SP-06 или выполнять production deployment.

**Важно:** данное исправление может быть принято как новый UI-correction milestone, но оно не отменяет `done` для SP-00…SP-05 и не делает публичный общий рейтинг готовым. Статусы меняет только `current.yaml` по действующим правилам.
