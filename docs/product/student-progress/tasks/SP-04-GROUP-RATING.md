# SP-04 — безопасная аватарная лента группы

**Зависимость:** SP-03. **Класс:** L3 learner read permissions + UI.\
**Нормы:** MASTER SP-D04, SP-D06…SP-D09, SP-D21…SP-D24; UI/DATA contracts.

## Результат

Ученик видит собственный закреплённый аватар и разрешённые аватары участников своей группы с местами и баллами. Полный список открывается ограниченными порциями. Принятый референс реализован на настоящих данных.

## Серверная граница

Отдельная learner-safe проекция: opaque peer key, безопасный avatar reference, score, rank, isSelf, период/версия расчёта, cursor/hasMore. Она не возвращает teacher roster, имена, credentials, last-active, оценки, private work IDs и чужие access reasons. Защищается и выдача пикселей аватара, а не только JSON.

Own profile и peers используют один согласованный результат расчёта. Сохраняются формула и `rank()`; точность до двух десятичных знаков. Stable paging привязан к actor/class и версии результата. Новая версия не должна создавать дубли и пропуски незаметно: клиент начинает согласованную порцию заново.

## UI

Own слева крупнее, тонкий разделитель; peers по server rank без own-дубля. Desktop — до пяти peers, narrow — столько, сколько помещается с трёхзначным местом и дробным score без сокращения значения. «Все» доступно с клавиатуры и touch. Никаких знаменателей и имён, включая скрытые подписи.

## Приёмка

Не участник/removed/revoked/cross-tenant не читает ленту, связь участника с аватаром и приватные изображения. Общие стандартные ассеты `/assets/avatars/default/*.webp` остаются публичными. Account видит только группы с действующим разрешением. Проверены ties `1,2,2,4`, все нули, null, own вне верхней порции, повторяющиеся аватары, смена версии при paging, длинные названия, недоступное изображение и logout.

Серверные отрицательные тесты выполняются в реальном PostgreSQL; browser evidence — в built ASA Lab на 1440/1024/390/320. Независимый challenge review обязателен.

## Выход

Лента подключена к главной и обучению; реальный ученический API даёт только разрешённые поля. Выдача всего staff DTO с последующим скрытием имён CSS не принимается.
