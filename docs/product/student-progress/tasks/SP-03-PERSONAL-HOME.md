# SP-03 — личный блок и собственный прогресс групп

**Зависимости:** SP-01, SP-02. **Класс:** L1 UI.\
**Нормы:** MASTER SP-D01…SP-D08, SP-D12, SP-D21…SP-D24; UI_CONTRACT.

## Результат

Главная содержит собственный аватар и реальные показатели работ. В главной и обзоре обучения видны собственные место, балл и период каждой разрешённой группы в компактном виде. Обычный Account с учебными memberships получает тот же учебный контекст.

## Scope

- `CreatorHomePage.tsx`, `LearningPage.tsx`.
- Новые локальные progress components, API adapter и scoped CSS.
- Существующие данные аватаров, достижений и доступного следующего действия.
- Необходимые addressed component/browser tests.

Не монтировать целиком `StudentParticipantSummary` в hero. Не переносить туда учительские grades/roster/credentials. В этом этапе peers ещё не показываются: они появляются через безопасный SP-04. Общий рейтинг остаётся отсутствующим до SP-07, а не равным макетному числу.

## UI

Собственный аватар, «Мой прогресс», компактные иконки и три настоящих значения. До двух групп на главной, остальные доступны в существующем обучении. Место и рейтинг размещены поверх своего аватара по референсу. Один следующий учебный шаг определяется существующим actionable state; нет фиктивных заданий или обещанного точного прироста.

Empty, partial, loading, error, disabled и long-content имеют отдельные состояния. Разрешённые направления без проектов остаются видимыми. Account без группы сохраняет полезную личную главную. Поздний ответ прежнего actor не попадает новому после logout/login.

## Приёмка

StudentSeat, Account с двумя и более группами, самостоятельный Account; rating null/zero/fractional; missing avatar; запрет действия; ошибка запроса; long title. Проверка обеих реальных поверхностей на 1440/1024/390/320, сравнение header/sidebar before/after и работа primary action.

## Выход

Первый личный экран работает с настоящей сводкой. Нет client aggregation из частично загруженного каталога, нового polling или страницы из одних нулевых карточек.
