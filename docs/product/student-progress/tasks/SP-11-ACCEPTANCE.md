# SP-11 — сквозная приёмка программы

**Зависимость:** завершены применимые SP-01…SP-10. **Тип:** независимая продуктовая приёмка.\
**Нормы:** MASTER, ACCEPTANCE, `docs/agent/review-protocol.md`, `ASA_UI_LAYOUT_ACCEPTANCE_SPEC.md`.

## Результат

Один точный объединённый кандидат подтверждает согласованный путь StudentSeat и Account. Карта требований указывает действительные исходники и выполненные проверки, а не только наличие новых компонентов.

## Сценарии

1. Учитель создаёт synthetic группу и ученика; штатный вход ученика ведёт в настоящую главную.
2. Главная → обучение → разрешённая группа → конкретное задание → работа → сохранённый/принятый результат → возвращение в личный прогресс.
3. Account с несколькими подтверждёнными группами видит корректные собственные результаты без двойного начисления.
4. Собственная публикация и чужая разрешённая реакция отражаются в сводке и рейтинге согласно версии правил.
5. Ниже порога / точное достижение / сохранённый grant / последующее снижение / явный запрет / отзыв проходят через реальный API.
6. Logout и вход другого ученика на общем устройстве не раскрывают данные предыдущего.
7. Полная матрица применимых negative, retry, identity и compatibility случаев имеет evidence.

## Визуальные доказательства

Built UI на 1440/1024/390/320; главная, обучение, группа, раскрытие рейтинга, настройки учителя и unavailable states. Изображения действительно просмотрены. Сравнение header/sidebar до/после, проверка fractional scores/трёхзначного места/длинного названия/200% zoom. В публичных artifacts только synthetic identities и безопасные данные.

## Технические доказательства

Точный source SHA, green applicable `ASA / required`, заявленные focused/data/browser gates, independent challenge review для permissions/ledger, отсутствие известных открытых дефектов данного scope. Результат из кеша не выдаётся за новый owner evidence run.

## Выход и граница

Отчёт отдельно называет implementation, CI, visual acceptance, owner acceptance и deployment. Отсутствующий live deployment не маскируется screenshot fixture. Обновление существующего стенда выполняется только при отдельном поручении владельца по штатному updater; эта карточка не разрешает новый сервер или изменение рабочей БД.

Продуктовая проверка доказывает корректную поддержку видимого прогресса. Рост качества обучения оценивается отдельно по выполненным/принятым работам и продолжению обучения; числа рейтинга и посещений не объявляются доказательством учебного эффекта.
