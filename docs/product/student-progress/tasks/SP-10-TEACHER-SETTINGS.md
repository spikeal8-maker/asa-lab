# SP-10 — настройки учителя и объяснения ученику

**Зависимости:** SP-08, SP-09. **Класс:** L1 UI над принятыми permissions.\
**Нормы:** UI_CONTRACT, ACCESS_CONTRACT; MASTER SP-D15…SP-D20.

## Результат

Преподаватель в компактной таблице видит возможность, режим, условие и индивидуальные исключения. Ученик получает короткую понятную причину и доступный следующий шаг.

## Scope

Существующий `ClassroomProjectSettings.tsx` и локальные связанные controls/CSS. Игры/ИИ можно представить в общей иерархии, сохранив их действующие API и динамический смысл. Не переделывать весь кабинет преподавателя, список классов, header или navigation.

## UI

- Для новых действий: разрешено, недоступно, после достижения; источник явно «Рейтинг в этой группе».
- Порог и объяснение появляются только для соответствующего режима.
- Сохранение/отмена располагаются рядом; dirty state и revision conflict читаемы.
- Индивидуальные allow/deny показываются отдельно от группового правила.
- Отзыв постоянного grant — отдельное явное действие, а не скрытый эффект изменения числа.
- «Ученик увидит…» использует фактическую reason model.
- Remaining points выводятся только для единственного невыполненного рейтингового условия. Запрет, отсутствие рейтинга и transport error не подменяются остатком.
- Термины «Добавили к себе», «Скачать файл», «Опубликовать» соответствуют реальным операциям.

## Приёмка

Учитель сохраняет правило → reload показывает те же данные → синтетический ученик видит тот же effective decision → действие действительно допускается/отклоняется. Две вкладки настроек не перезаписывают друг друга. Старые настройки после обновления имеют тот же эффект. Проверены keyboard/focus/touch и 1440/1024/390/320 с длинными русскими подписями.

## Выход

Настройки и ученические объяснения подключены к серверу; декоративная таблица или клиентский расчёт доступа не принимаются.
