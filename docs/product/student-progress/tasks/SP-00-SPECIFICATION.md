# SP-00 — регистрация системы ТЗ

**Программа:** ASA-STUDENT-PROGRESS-001. **Тип:** документация/governance.

## Результат

Принятая композиция, смысл данных, условия доступа, зависимости и приёмка сохранены в GitHub и доступны по одному router. Следующий исполнитель получает однозначную карточку и не восстанавливает решения по пересказу чата.

## Scope

- `docs/product/student-progress/`: основной контракт, UI/data/access, приёмка, план, task cards и референс.
- Компактный контракт и Document Registry.
- Ссылки из существующих student experience/learning hub specs.
- Добавление отдельного lane в `current.yaml` с сохранением остальных selections.

## Проверки

1. Полный planned-path preflight, clean baseline и отсутствие чужих пересечений.
2. Все относительные ссылки разрешаются; IDs требований и сценариев уникальны.
3. Нормативные документы не противоречат identity/learning/runtime и не заявляют уже выполненную реализацию.
4. Референс содержит явные условные данные; его SHA-256 и происхождение указаны в UI contract.
5. `pnpm gate:governance`, формат изменённых текстов и `git diff --check`.
6. Независимое чтение финального пакета: принятому визуалу и порогам соответствует ровно один вариант.

## Выход

Проверенный пакет находится в GitHub, applicable protected CI известен. Product implementation начинается после принятия канонического выбора на main. Документационная регистрация не изменяет серверы, БД, разрешения и пользовательские баллы.
