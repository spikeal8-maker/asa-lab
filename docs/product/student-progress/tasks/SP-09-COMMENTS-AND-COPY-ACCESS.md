# SP-09 — комментарии и получение чужих проектов

**Зависимость:** SP-08. **Класс:** L3 permissions.\
**Нормы:** ACCESS_CONTRACT и existing discussion/copy contracts.

## Результат

Тот же проверенный механизм группового порога и постоянного grant применяется к разрешённому созданию комментария и получению копии чужого публичного проекта. У каждого действия собственное условие и причина ограничения.

## Ограниченные подэтапы

Контроллер выполняет последовательно SP-09A (comments) и SP-09B (copy admission), с отдельным focused evidence. Один исполнитель не переходит между подэтапами без новой selection. Они используют общий принятый resolver SP-08, а не независимые копии алгоритма.

## Семантика

- Comment create проверяет current publication/discussion/platform state и scope автора комментария. Запрет новых комментариев не удаляет старые; прежние права редактирования/удаления сохраняются по существующей модели.
- Copy admission учитывает destination scope текущего actor, source readability/license и поддержку модуля. Учительское allow не добавляет поддержку нового формата и не отменяет запрет автора.
- Групповой контекст назначения/получателя определяется сервером. У personal Account destination личная политика; у Seat — действующий scoped учебный контекст.
- Нажатие кнопки и неуспешная операция не считаются успешной копией.
- Уже созданная копия не удаляется при последующем запрете новых действий.
- Экспорт собственной работы и получение учебного материала не захватываются порогом копирования чужой публикации.
- Существующий boolean download/distribution сначала картируется по реальным handlers. Новая policy не может тихо расширить его смысл. Если одна legacy настройка покрывает разные операции, compatibility mapping фиксируется до migration.

## Приёмка

Прямые API вызовы, два actor scopes, revoked policy, threshold boundary, explicit deny, stored/revoked grant, unsupported module/license и одновременно обновлённая настройка. Проверить текущие comments/copy tests и отсутствие регрессии игр/ИИ.

## Выход

Два действия используют одну понятную семантику, но разные source/destination boundaries. Нет нового балла за raw копирование, новых форматов копии и автоматического удаления исторических данных.
