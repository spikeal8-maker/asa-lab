# SP-01 — единая карточка публикации

**Зависимость:** SP-00 принят в main. **Класс:** L1 UI.\
**Нормы:** MASTER SP-D01, SP-D10…SP-D13; UI contract, раздел карточек сообщества.

## Пользовательский результат

Главная показывает те же узнаваемые карточки публичных работ, что каталог: предпросмотр, автор, направление, существующие отметки, лайки и добавления к себе. Рядом с «Проекты сообщества» находится вторичная подпись «Работы пользователей платформы».

## Точки реализации

- `apps/web/src/projects-public/PublicProjectsPage.tsx` — извлечение существующей карточки.
- Новый `apps/web/src/projects-public/PublicProjectCard.tsx` — общий презентационный компонент.
- `apps/web/src/creator-portal/HomePublicShelves.tsx` — использование компонента.
- `apps/web/src/projects-public/public-projects.css`, `apps/web/src/creator-portal/home-workspace.css` — только относящиеся к карточкам selectors.
- Существующие `PublicationPreview`, `PublicAuthorAvatar`, module artwork и preview lifecycle переиспользуются.

## Границы

Не менять API, авторизацию, сортировку каталога, политику копирования, hover runtime или глобальную оболочку. Не вычислять общий рейтинг и авторские итоги из этой полки. Существующий `copyCount` подписывается как «Добавили к себе». Компонент не создаёт вложенные ссылки/кнопки и не запускает WebGL сразу для всей полки.

`home-public-card` также используется карточками курсов в `HomePublicShelves.tsx`: общий компонент публикации не должен менять их ширину и содержание. Сохранить существующую горизонтальную полку, её ленивую загрузку, класс `.public-project-card`, необходимый для preview lifecycle, и семантически правильный уровень заголовка в каждом consumer.

## Приёмка

- Одинаковая публикация имеет одинаковые значки, данные и destination в обоих consumers.
- Все поддержанные направления, отсутствующий preview, длинное название и нулевые метрики отображаются корректно.
- Existing catalog/home tests продолжают проходить; адресно расширяются `PublicProjectsPage.spec.ts` и `tests/portal/creator-home.spec.ts`, если затронута их проверяемая семантика.
- Проверка модели `creator-home.spec.ts` не доказывает рендер полки. Сценарий одной реальной публикации на главной и в каталоге добавляется в существующий `e2e/public-projects.spec.ts`, входящий в publication browser gate. Его helpers создают данные через настоящий API в изолированной тестовой БД.
- Реальный built UI проверен на 1440/1024/390/320; нет horizontal page scroll, перекрытия автора/значков и сдвига шапки.
- Сохранены выдача public-only и cleanup интерактивного preview.

## Выход

Общий компонент подключён к двум настоящим поверхностям, required CI и layout evidence относятся к точному SHA. Новая карточка, оставшаяся без consumers, не является выполнением этапа.
