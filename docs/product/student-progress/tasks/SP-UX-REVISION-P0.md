# ASA LAB — SP-UX-REVISION-P0: устранить дублирование и учебный перекос

**Класс:** L1 UI; адресная проверка безопасного API чтения peers при необходимости.  
**Основание:** [owner decision](../OWNER_PLATFORM_PROFILE_UX_2026-11-16.md).  
**Цель:** один профиль пользователя в штатной оболочке, компактный learner-context только по настоящим данным и рейтинг группы, заполняющий доступную ширину.

## 1. Обязательный пользовательский результат

- **Обычный Account без участия:** главная начинается с проектов/направлений; нет большой карточки «Мой прогресс», дублированного фото, пустых учебных панелей и «Открыть обучение» fallback. Существующая навигация обучения остаётся.
- **Account в группе:** показатели публикаций/отклика видны около аватара слева; на главной только компактная учебная группа/настоящее следующее действие. В «Моём обучении» — группа, задания, курсы и результаты без ещё одной героической шапки.
- **StudentSeat:** только его доверенный учебный scope, без приватных данных связанного Account.
- Все пользователи: корректные реальные числа или честный unavailable; сохранённые header/right avatar/sidebar, проекты, создание и уже работающие маршруты.

## 2. Границы реализации

Сначала read-only preflight по `AGENTS.md`, получить выбранный task и актуальный main. Не записывать продуктовый код до принятия нормативной версии и явного controller selection.

Кандидаты на изменение, точный путь проверить по фактическому `main` до записи:

- `apps/web/src/creator-portal/PersonalProgress.tsx`, `personal-progress.css`, `personal-progress.ts` — разделить `ProfileMetricStrip` и `CompactGroupRating`; убрать второй `OwnAvatar` в hero, заменить `groupRatingPreviewLimit(width)` на ширинно-измеряемый расчёт.
- Существующий **компонент боковой панели профиля** и его локальный CSS — найти по действительным consumers, интегрировать статистику слева от его аватара; не вводить второй источник avatar/score.
- Существующие `GroupRatingPageV1`/безопасная выдача peers — если лимит API мешает вместимости desktop, изменить только ограниченный параметр `limit` с тестами авторизации и pagination, без имён и unrestricted fetch.

До реализации зафиксировать в `current.yaml` **точные owned paths**, владельца ветки и согласование shared sidebar paths; сохранить чужие worktree. По необходимости разделить один документированный UI-срез и отдельный bounded API-срез.

## 3. Layout/данные

**Профиль:** desktop метрики в колонке слева от существующего sidebar avatar, верхний бейдж общего рейтинга только при достоверном серверном total; mobile — возле активного аватара/в раскрытии профиля. Никакой третьей картинки.

**Метрики:** подтверждённые unique public works, active likes и созданные public copies; не Downloads. Нули в подробностях допустимы; не показывать отдельные три декоративных `0` на пустой главной. `unknown !== 0`; errors не скрывать под нулями. Сохранять typed API, lifetime/cancellation и identity scope.

**Обучение:** наличие группы либо настоящего `next.action` — единственное основание для CTA. Не создавать fallback ссылку «Открыть обучение» при `next.action=null`; не закрывать самостоятельные возможности `Знания`.

**Группа:** компактная `Вы`-ячейка слева (место/балл), далее столько аватаров peers, сколько влазит по ширине одной строки. Нет константы 5 для desktop. Расчёт через measured container width + actual slot widths, bounded max server limit; дебаунс, кеш и отсутствие запроса на каждый пиксель ResizeObserver. При недоступности API — читаемая локальная ошибка. `Все` — server-paginated real action, не CSS overflow.

## 4. Запрещённые регрессии

- Не менять формулу группы, `rank`, точность балла, tie semantics и период.
- Не показывать имена/полные имена/ID peers ни в DOM, ни в API (включая aria/title/alt).
- Не раскрывать Account-private информацию в StudentSeat/соседних группах.
- Не добавлять polling, N+1, WebGL preview, новый сервер или общий sidebar redesign.
- Не менять аватарный редактор и платформенные права в P0.
- Не трогать C3, SP-05, SP-06, production DB/deployment.

## 5. Условия PASS

1. Desktop Account без групп: центральный контент начинается с направлений/проектов; нет профильного hero и учебной подсказки-fallback; sidebar содержит один текущий профильный аватар, правый верхний — штатный.
2. Desktop Account с тремя реальными метриками: все метрики читаемы слева от sidebar avatar и не накладываются на фото/имя.
3. Реальный ноль, unavailable, partial, loading/error визуально и семантически различимы.
4. Account с одной/несколькими группами и StudentSeat: правильное число групп, безопасная сводка и реальное учебное действие; без лишних карточек.
5. Desktop 1440: peers занимают широкую доступную область, а не останавливаются после 5, когда есть ещё допустимые участники; диапазон ограничен серверной порцией.
6. Компактный 1024 и mobile 390/320: лимит рассчитывается из контейнера, не ломает числа, не создаёт горизонтальную прокрутку страницы; есть рабочее «Все».
7. При смене Account/Seat, logout/login, смене группы и async retry старые приватные данные не остаются в UI.
8. Скриншоты **всех 4 viewport** для populated/empty и применимых ошибок/long-content, 200% zoom, плюс сравнение до/после на идентичных данных.
9. Адресные unit/DOM/browser tests, build/types и требуемый exact-SHA GitHub CI — SUCCESS; независимый visual/layout reviewer проверяет каждую затронутую surface и consumers.

**Финал P0:** один ограниченный PR, screenshots/evidence, independent review, защищённый merge **только после отдельного разрешения владельца**. `main` не редактировать как побочное действие документационного PR.
