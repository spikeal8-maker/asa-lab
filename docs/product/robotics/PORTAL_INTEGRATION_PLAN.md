# Подключение робототехники к основному ASALab

Этот план задаёт пользовательский результат и границы реализации. Состояние, Issue, branch, SHA и blockers находятся только в [current.yaml](../../execution/current.yaml). Карточка исполнения: [Robotics Portal](../electronics/tasks/TASK-ELECTRONICS-ROBOTICS-PORTAL-001.md).

Базовый путь проекта и публикации выполняется перед новыми аппаратными возможностями и 3D. Уже работающие электрическое ядро и редактор используются повторно.

## Пять видимых результатов

| Шаг                              | Видимый результат                                                                       | Проверка                                                                                                                 |
| -------------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 1. Общий сервис проектов         | Создаётся проект аккаунта; схема, программа, конструкция и поле сохраняются вместе      | Реальный API и test PostgreSQL; whole-document validation, права, optimistic concurrency, сохранение незавершённой схемы |
| 2. Основной редактор и навигация | «Создать → Робототехника» открывает среду в обычном ASALab; работают возврат и переходы | Основной App/ModuleEditorHost и production build; переходы, flush pending программы, Leave/Save                          |
| 3. Главная и «Мои проекты»       | Карточка с названием и превью; повторное открытие после выхода и на другом устройстве   | Новый browser context без локального draft получает тот же серверный проект                                              |
| 4. Публикации                    | Проект виден в общей ленте и категории; другой пользователь открывает просмотр          | Immutable version/provenance, строгий публичный артефакт, нет private source/Blockly/прав                                |
| 5. Полный путь                   | Первый пользователь создаёт/сохраняет/публикует; второй просматривает                   | Обычные построенные Web/API, настоящая изолированная PostgreSQL, снимки и независимый review точного SHA                 |

## Один документ, одно ядро

Общий документ содержит circuit с программами существующих Arduino и world с исходными объектами, конструкцией и привязками. Серверный provider умеет создать, проверить и описать превью документа без браузерного runtime. Существующая математическая модель мира переносится в browser/server-safe контекст без поведенческой переработки.

Электрический solver, Arduino runtime, Blockly generator, каталог и Worker остаются общими. Робот получает committed обороты и время; HC-SR04 использует прежний timed-input контракт. Новых моделей двигателя или другого физического времени этот этап не вводит.

Source field и runtime motion разделены. Сохранение проекта не закрепляет случайную конечную позу опыта. Старые локальные проекты остаются читаемыми; автоматическое смешивание локального документа одного пользователя с серверным проектом другого запрещено.

## Серверное сохранение

Используются Project Core, существующие права, версии, baseRevision/mutationId и snapshot pipeline. Ошибки API, конфликт версий и отказ доступа показываются пользователю; локальная копия не называется серверным сохранением. Поле, схема и программа относятся к одной операции сохранения.

Незавершённая электрическая схема остаётся редактируемым сохраняемым документом. Проверка возможности запуска отдельно запрещает missing bindings/unsupported topology. Заголовок проекта берётся из общей metadata; сохранность его длины не ограничивается legacy локальным заголовком.

История программы сохраняет исправления M1: синхронная публикация перед операцией, единая host history boundary, защита от устаревшего callback, правильная целевая Uno при замене примера.

## Публичное представление

Публикуется конкретная неизменяемая версия. Public artifact имеет явный schema/provenance и ограниченную геометрию поля и конструкции. Он не передаёт исходный Arduino код, блоки, электрические bindings, приватный черновик или authorization metadata.

Просмотр показывает опубликованную сцену через существующий renderer. Доступные действия относятся к отображению; пользователь не получает ложные live показания или скрытый запуск программы. Копирование и скачивание приватного проекта не включаются. Политики StudentSeat, прав публикации, hide/revoke и защищённого кода остаются общими.

## Сборка и проверка

Обычный портал лениво загружает робототехнический редактор по projectId. Отдельный dev-вход сохраняется для разработки, но не является пользовательским маршрутом или доказательством завершённой интеграции.

Миграции только новые forward; существующие данные и выпущенные файлы миграций сохраняются. Test PostgreSQL изолирована, runtime role не получает superuser/BYPASSRLS. Продуктовые проверки используют штатный publication gate, а не подменённый API или PGlite вместо требуемой real PostgreSQL.

Сквозной сценарий включает две независимые browser sessions, повторное открытие без локального состояния, создание preview, публикацию, изменение draft после публикации, просмотр другим аккаунтом и отказ в доступе к private/revoked содержимому. Основные действия проверяются на desktop и телефоне. Реальные промежуточные экраны показывают прогресс каждого шага.

## Граница завершения

Регистрация, статические тесты, сохранение только в браузере или Draft PR не закрывают программу. Должен быть доказан полный путь через основной ASALab на одном итоговом SHA. Required CI, независимый review, owner acceptance и deployment обозначаются отдельно; существующие чужие CI отказы не исправляются в этом срезе и не объявляются закрытыми.
