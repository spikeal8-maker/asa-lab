## Где читать состояние

Единственный источник выбранной задачи и её статуса — [current.yaml](../../execution/current.yaml),
направление robotics. Эта страница описывает маршрут, а не заменяет execution state.
Документационная регистрация начинает действовать только после принятия в main.
Принятие ТЗ не означает, что новая физика реализована или прошла испытания.

## Сохранность перед новой работой

Датированное [свидетельство E0](evidence/field-core-e0-20261111.json) содержит исходные
SHA, hash manifest локальной работы, архивную ветку GitHub и проверку восстановления.
Архивная ветка нужна для восстановления, не для слияния целиком с main.
В ней намеренно сохранён непроверенный timeout старого E2E-теста; не переносить его
автоматически в продукт. Не удалять исходные локальные PNG/JSON и не принимать их
старые PASS за доказательства нового кандидата.

Действующий порт 4630 продолжает обслуживать прежнюю рабочую папку.
Новая чистая копия исходников не запускает второй сервер, не подключает рабочую БД
и не меняет пользовательские проекты. Переход интерфейса на новый кандидат требует
отдельной проверенной передачи изменений; не подменять его при подготовке harness.

## Рабочий порядок

Сначала scoped preflight и актуальный main; затем только выбранный срез E1.
Шесть TEST_ONLY физических сцен и доступные runtime API проверяются отдельно от UI.
D01 требует измерений; D02 — честного описания возможностей и недостающих контрактов.
Камера/панели могут выполняться отдельным UI_ONLY срезом по зависимостям ТЗ,
но не являются доказательством работоспособности 3D-привода.

После каждого среза: адрес результата, exact SHA, коммит/push, реальные команды,
результаты и ограничения. Сохранение в GitHub, приёмка реализации и deployment —
разные события. Исторические задачи и их незакрытые замечания остаются видимыми.
