## 1. Продуктовая цель и граница текущей реализации

Пользователь может: **(1) выбрать готового робота; (2) собрать собственного из библиотеки реальных деталей; (3) загрузить собственную 3D-деталь; (4) сохранить личную сборку как версионную заготовку; (5) перейти к электронике, программе и полю без потери структуры, проводов и кода.**

В текущей реализации уже есть четыре вкладки «Поле / Робот / Электроника / Код», совместный host проекта, RobotAssemblyPanel с 2D-видом сверху, назначением Arduino/двух gearmotor/датчика, параметрами шасси, реальной электрической схемой, инспектором и кодом Arduino. **Нет подтверждённого полноценного редактора 3D-сборок, личной библиотеки произвольных деталей, произвольных шарниров или готовой поддержки всех перечисленных моделей роботов.** Их нельзя показывать как завершённые функции.

Нельзя создавать второй редактор Arduino, второй электрический solver, независимый физический clock, дубликат электронного каталога, новый отдельный портал для конструкторов или заменять текущий RobotAssemblyPanel невыполненной 3D-витриной.

## 2. Навигация и страница «Робот»

### 2.1. Три области на desktop

**Единая шапка:** название проекта, четыре существующие вкладки «Поле / Робот / Электроника / Код», сохранение и статус; один контроллер запуска/паузы/остановки. Не дублировать общую шапку и сохранение.

**Слева — наблюдение (начальная ширина 240 CSS px, допустимый диапазон 200–360 согласно REQ-UI-02):**
- компактный реальный вид мини-поля со стартом/позой/объектом, кнопка «Открыть поле»;
- мини-просмотр существующей электрической схемы из того же project circuit, без редактирования из превью;
- компактная информация об активной программе (тип: блоки или текст, целевая Arduino, статус), переход «Открыть код»; по необходимости выдвижной штатный ArduinoCodePanel;
- телеметрия поддержанных моторов, датчиков и статуса привязок; неподдержанные показывают ограничение, а не вымышленные значения.
Не размещать второй постоянно активный экземпляр Blockly или электрической схемы.

**Центр — главный холст робота:**
- интерактивная **3D-сборка** (орбитальная камера, pan, zoom относительно курсора, «Вписать», «Сверху», «Сбоку», «Изометрия», «К выбранному»); опциональный ортографический инженерный вид;
- выбор отдельной детали, подсветка совместимых креплений, визуальный ghost перед установкой, совместимые соединения/оси, габариты и направление осей;
- отдельные режимы «Просмотр» (доступен в простом режиме) и «Сборка» (разрешён в расширенном режиме);
- единицы и линейка, основная точка робота и направление X вперёд, Y влево, Z вверх (как в FIELD_CORE_SPEC §5/REQ-GEO-02);
- без полос прокрутки внутри сцены и без полной перезагрузки GLB при выделении детали, изменении её свойств или переключении LED;
- первая поставка может показывать точный 2D-вид + read-only 3D-preview, но должна честно обозначаться **неполным конструктором**.

**Справа — один адаптивный dock** (ширина 300 CSS px, 280–420; не четвёртая колонка):
- вкладка «Готовые роботы»: категории, поиск, карточки с видом, размерами, мотором, платой, готовностью и действием «Выбрать»;
- вкладка «Компоненты»: дерево механики — корпуса/колёса/моторы/приводы/крепёж/Arduino/драйверы/датчики, поиск/фильтр совместимости;
- вкладка «Мои сборки»: личные версионные заготовки, «Сохранить как сборку», копирование, переименование;
- вкладка «Мои детали»: собственные импортированные 3D-ресурсы, сведения о масштабе, оси, лицензионное происхождение, статус проверки;
- при выборе узла dock показывает инспектор: размер, масса (известно/неизвестно), позиция, поворот, привязка, совместимые крепления, разрешённые диапазоны суставов, электрические терминалы, происхождение.
Одновременно открыт ровно **один** инспектор/dock. Не допускать перекрытия выбранной детали.

### 2.2. Сценарии использования

**Новый проект:** показ карточек «Готовый робот» / «Собрать своего» / «Мои сборки». Готовый робот создаёт проект с разрешённым, версионным ready kit; программирование возможно без изменения механики в режиме «Простой». «Редактировать конструкцию» — явный переход в «Расширенный» только после сохранения контрольной версии по REQ-MODE-03.

**Выбор другого робота:** не стирать автоматически поле, программу, сохранённые соединения или историю. При смене kit показать конфликтующие bindings, функциональные ограничения и явное подтверждение; несовместимая программа сохраняется, но запуск блокируется, как REQ-KIT-04.

**Сборка своего:** начать с пустого доступного шасси либо копии готовой сборки; перетаскивание детали показывает 3D-ghost; притяжение только к совместимому механическому anchor; в инспекторе точные координаты и размеры; одно размещение — одна атомарная Undo-операция, содержащая физические и электронные связи (если затрагиваются), без записи незавершённого drag.

**Мои сборки:** «Сохранить как сборку» создаёт собственный immutable revision/clone-источник, отдельно от текущего проекта. Подстановка новой версии не перезаписывает ранее сохранённые проекты; пользователь явно принимает обновление. Экспорт готовой сборки — версия манифеста плюс разрешённые по правам asset refs, не только запечённый GLB.

**Простой/Расширенный** — один и тот же электрический, механический и программный документ, отличаются правами редактирования по §20; блоки/текст отдельно, без скрытого режима отдельной физики. Пользователь с правом выдачи заготовок может закрепить проверенный комплект; другой пользователь вправе создать собственную копию в пределах действующих прав.

## 4. R01 — круглая платформа miniQ и производственный чертёж

### 4.1. Не путать размеры разных вариантов

По официальной карточке **отдельной рамы miniQ** Amperka: прозрачный акрил **3 мм**, внешний диаметр **127 мм**, крепления микромоторов шириной 12 мм, колёса **42×19 мм**, шаровая опора 12 мм. У собранного продукта miniQ заявлен общий габарит **122 мм**, а не гарантированный диаметр той же отдельной рамы. Поэтому хранить **разные** physicalVariantId/измеренные корпуса; 122 и 127 не заменять друг другом. Источники:
- https://amperka.ru/product/miniq-base
- https://amperka.ru/product/miniq-deck
- https://amperka.ru/product/amperka-miniq

Массовые китайские круговые аналоги не считать геометрически одинаковыми с Amperka без точной посадки двигателя, отверстий и проставок. Для каждого — источник товара и документации, конфигурация посадок, отдельная качественная 3D/2D-геометрия.

### 4.2. Изготовление собственной платформы на лазере

Для каждого варианта минимум **две разные сущности**:
1. Визуальная 3D-модель (STEP либо геометрический master → оптимизированный GLB для браузера, отдельный collision mesh).
2. **Производственный векторный контур** (SVG/DXF **1:1 в миллиметрах**) для плоской акриловой/фанерной/ПЭТГ-пластины.

Требуемые слои/данные чертежа:
- CUT_OUTER — замкнутый внешний контур с проверенным диаметром;
- CUT_INNER — реальные сквозные отверстия и слоты для N20-креплений, стоек, шаровой опоры, Arduino, датчиков и дополнительной палубы; без придуманных центров;
- ENGRAVE — необязательные подписи/оси/маркировка, отдельные от резки;
- REFERENCE — неэкспортируемые вспомогательные линии/размеры;
- паспорт материала: толщина (первый вариант 3 мм), номинал/измеренный зазор/керф конкретного лазера, направление верхней стороны, применимость к пластикам и безопасности процесса;
- понятная единичная система mm, без перспективы и растрового контура; path замкнуты, нет дублей, самопересечений и перекрывающихся режущих линий.

**Из 3D можно автоматически получить SVG/DXF**, если есть достоверная CAD-модель и выбраны плоскость реза/нижняя и верхняя грани: берутся плоские замкнутые контуры, отверстия/слоты и реальные размеры. **Обычный скриншот 3D, силуэт GLB или вид сверху фотографии не являются пригодным для лазера производственным файлом.** Для многослойных плат отдельных плоскостей будет несколько отдельных деталей.

**Без подтверждённых координат всех монтажных отверстий и тестового образца нельзя маркировать производственный SVG как готовый для вырезания.** Папка amperka/hardware-drawings содержит 2D-иллюстрации компонентов, но при текущем просмотре **нет подтверждённого исходного cutting file miniQ**. Художественная SVG и производственная SVG — независимые артефакты.

Проверка производства: ревизия размеров → DXF/SVG просмотр 1:1 → тестовая пластина либо набор контрольных отверстий → физическая проверка N20, колёс, стойки и шаровой опоры → корректировка допуска → подтверждённая ревизия для библиотеки.

### 4.3. Показ внутри ASA Lab

Карточка платформы включает вкладки: «3D-модель», «Конструкция», «Электроника», «Чертежи для изготовления», «Материалы и крепёж». Скачать лазерный файл можно только для варианта с проверенной производственной геометрией и разрешением на распространение; иначе показывать «Чертёж уточняется». ## 5. Каталог отдельных деталей и сборочная модель

Классы: chassis/deck, wheel+tire, axle, DC motor N20/TT, mount/bracket, ball caster, fastener/spacer, servo, sensor, controller Arduino Uno/Nano, motor driver L298N / Shield / TB6612 и user mesh.

Каждая деталь имеет:
- immutable partId, version, sha256 арта, авторство/лицензию, источник, units, реальные dimensions;
- visual GLB (или допустимый иной формат после безопасной конверсии), optional LOD, простой collision shape/hull и невыдуманные массу/inertia/центр масс;
- локальные координаты детали; **engine** X вперёд, Y влево, Z вверх, метр; для glTF (обычно Y-up) — явная трансформация при импорте, а не молчаливая подмена оси;
- конечный набор механических anchors: ID, local position/orientation, тип сопряжения, размер/диаметр, допустимые повороты и соединения, joint limits (fixed, revolute, prismatic, planar linkage);
- электрические terminal refs только к реальному каталогу электроники, стабильные IDs и bindings по REQ-KIT;
- физический/электрический статус: verified / illustrative / simulation_unsupported / manufacturing_unverified — без догадок по картинке.

Деталь должна оставаться отдельным 3D-объектом в сцене сборки; собранный робот хранит граф частей и соединений. Колесо/вал и корпус — разные rigid bodies и joints при реальной физике. Смена модели колеса сохраняет anchor или явно показывает несовместимость; не телепортирует колесо и не меняет задним числом исходный мотор.

### 5.1. Загрузка своих моделей

**Первый разрешённый импорт для визуализации:** GLB с проверкой числа узлов/треугольников, размеров, ориентации и чистотой ресурсов. STL — в следующем узком этапе как статическая геометрия без материалов; STEP/F3D обрабатываются через безопасную контролируемую CAD-конверсию, а не прямо в браузере. Сначала локальный preview, потом явное подтверждение записи в приватную библиотеку.

Отклонять скрипты/HTML, внешние URL и ресурсы, неожиданные mime, разрыв пути, zip bomb, опасную геометрию и превышение размера/сложности. Проверить права и происхождение импортируемого файла. Только user-scoped хранилище и существующие авторизация/quotas/RLS; импорт не публикует модель и не делает её доступной другим пользователям автоматически.

У загруженной детали нет автоматически доверенных электрических контактов, массы, крепежа и физики: их авторизованно задают или подтверждают отдельным редактором паспорта.

## 6. Сохранение, структура, безопасность

Не менять действующий сериализованный RoboticsProject скрыто. В E2 по нормативному §17 требуется предложить versioned extension для assembly:
- robotAssembly: rootAssemblyId, parts/instances, transforms, anchors, joints, source catalogue/version/hash, mass/collision refs;
- kit reference+version, immutable resolved circuit, bindings и исходная схема;
- user assets через content-addressed immutable refs, права, размеры, provenance;
- separate authored initial state от временной pose/скоростей во время simulation;
- выбранный режим простого/расширенного доступа — не новый электрический алгоритм;
- для старого 2D проекта — обратимая совместимая migration или legacy viewer без потерь.

Автосохранение проекта — не чаще одного серверного запроса за 60 секунд при обычном редактировании, явное «Сохранить» сразу, без вызова API на каждый drag/камера/LED/физический тик (REQ-SAFE-04); атомарная история изменений и синхронная публикация Arduino source перед Save/Run. Не менять настоящие пользовательские данные для тестов.

**KIT-01:** после E2/D02 определить exact ready kit, физические component IDs, рабочую проверенную схему и default Arduino source. Только проверенная электрическая топология, без декоративного включения двигателя. Простой режим должен использовать готовый kit; расширенный — ту же схему и те же модели.

**ASSEMBLY-01:** разрешить добавить только несколько совместимых деталей (motor N20, wheel, caster, board) с проверенными anchors, фиксированными соединениями и корректным Undo/Redo. Сохранение и повторное открытие всей сборки.

**CUSTOM-01:** личная сборка и первая безопасная загрузка GLB; проверка личной области хранения, копирования и приватности.

**FAMILIES-01:** R02 вытянутый TT, далее R04 плоскопараллельный и R05 угловой — только после отдельной квалификации joints и owner acceptance. Шагающие и мобильный манипулятор позже; не подменять их визуальным движением.

Каждый срез требует отдельной канонической selection в current.yaml и focused gate. Нельзя переводить этот vision-документ в новый активный milestone самостоятельно. Не останавливать и не трогать активные E1/D01/D02/другие задачи; не менять текущий main без обычного безопасного допуска.

## 8. Критерии приёмки целевой страницы (пока NOT_RUN)

1. Пользователь видит три ясных пути: готовый робот, своя сборка, мои сборки; карточки показывают **реальную** готовность.
2. Выбор R01-A создаёт версионный ready kit с точным BOM/circuit/source; те же controller/physics в простом/расширенном режимах; отсутствие поддержанной физики блокирует запуск честно.
3. Редактор выбирает отдельную деталь/подсвечивает anchor; допустимое соединение атомарно; невозможное отклоняется без порчи сборки.
4. Два N20, колёса, опора, датчик, Arduino физически соразмерны; нет пересечений корпусов и ошибок осей; unit mm/m однозначен.
5. Переходы Поле/Робот/Электроника/Код не теряют программу, схему, сборку, Run generation и текущую камеру; один Worker/время.
6. Версия личной сборки и контент собственных деталей сохраняются/reopen; другие пользователи не получают доступ без соответствующих прав; публикация только по существующим ACL.
7. GLB неподдержанного либо опасного формата отклоняется, не создаёт запись и не запускает внешние ресурсы.
8. Laser SVG содержит подтверждённые внешний/внутренние контуры и mm/ревизию/лицензию, физически совпадает с пробным изготовлением; до того статус **NOT_FOR_MANUFACTURING**.
9. Поддержаны 1920/1440/1366/1024/390/320, доступный фокус/жесты, без перекрытия центра и без переполнения страницы.
10. Performance: измерить количество загружаемых GLB и их хеши, число draw calls/triangles и p95 отклика, потери FPS и сеть; базис и пороги подтверждаются в отдельной приёмке, не объявлять улучшение без измерения.
11. Browser и shared server engine обязаны согласоваться на одном immutable document; simulation-unsupported topology возвращает unsupported, не solved=true.
12. Финальная передача: MAIN_SHA, изменённые файлы, реальный browser evidence, тесты на точном SHA, независимый review, owner acceptance отдельно от deployment.

## 10. Инженерный паспорт первого комплекта R01-A (уточнение DOC-01)

**Статус: геометрическая квалификация не выполнена; NOT_FOR_MANUFACTURING.** Визуальный образ miniQ, схематичный SVG и производственный файл для лазера — три разных продукта. Утверждённая внешняя окружность **Ø127 мм** и толщина пластины **3 мм** относятся только к отдельной раме Amperka miniQ. До снятия остальных размеров это лишь опорные параметры, не готовый чертёж. Шасси DFRobot ROB0049 (Ø122 мм) и собранный Amperka miniQ с заявленным общим габаритом 122 мм не являются источником отверстий для R01-A.

### 10.1. Обязательные измерения перед CAD-ревизией

| Группа | Что фиксировать в паспорте, мм и источник доказательства | Готовность |
| --- | --- | --- |
| База | Ø127, толщина 3; центр O=(0,0); X вперёд, Y влево, Z вверх; контроль ориентации верхней стороны | Внешний диаметр и толщина из карточки, остальные привязки назначить в CAD |
| Отверстия и пазы | Для каждого: тип, центр X/Y, Ø либо габариты/радиусы, вращение, принадлежность CUT_INNER, допуск, способ измерения | **UNVERIFIED** |
| Два мотора | Точная модификация N20 и кронштейнов, посадка, отверстия, высота осей, положение выходных валов и расстояние между осями колёс | **UNVERIFIED** |
| Колёса и опора | Модификация ступицы/шины; рабочий диаметр, ширина, колея; X/Y/Z и высота шаровой опоры при нагрузке | **UNVERIFIED** |
| Электроника | Посадки платы Arduino, конкретного драйвера, аккумуляторов, датчиков, второго яруса и стойки; требования к доступу проводов и изоляции | **UNVERIFIED** |

| Динамика | Массы компонентов, центр масс, инерция, поддерживаемые моторные параметры и коллайдеры | **UNVERIFIED** |

В CAD-master хранить **номинальную геометрию**; компенсацию ширины реза применять осознанно на этапе подготовки производства и документировать настройки оператора, не делать двойной offset. Отдельно проверять Ø внешнего контура, замкнутость путей, отсутствие наложенных линий, размер 1:1, раздельность CUT_OUTER / CUT_INNER / ENGRAVE / REFERENCE и физическую посадку на тестовом экземпляре. SVG с одной окружностью или с ориентировочно нарисованными отверстиями **не маркировать как готовый miniQ-чертёж**.

### 10.2. Комплект артефактов для будущего ART-01

- **master** — исходный редактируемый CAD-файл с единицами, измерениями, контрольными базами и историей ревизий;
- **assembly.glb** — оптимизированные отдельные meshes рамы, двух моторов, колёс, опоры, крепежа и электроники; происхождение каждого asset; статусы частей; визуальный вид не выдавать за метрологический;
- **plan.svg** — ортографический план сверху для каталога, с измерительными ссылками и маркировкой иллюстративного статуса;
- **cut.svg + cut.dxf** — только после подтверждения всех рабочих отверстий и лицензии, в масштабе 1:1 и с контролем на тестовой резке; сначала недоступны для скачивания из продукта;
- **passport.json** — variantId, hardware revision, проверенные размеры/единицы, anchors, BOM, ссылки на источники, автора и лицензию, хеши, статус verified/illustrative/not_for_manufacturing и результаты проверки;
- **acceptance** — фотографии обмера и посадок, совпадение CAD с изготовленным экземпляром, таблица отклонений, независимая механическая ревизия.

Не включать чужие графические файлы или брендированные фото в assets ASA Lab без проверки условий лицензии. Название Amperka miniQ может использоваться для указания совместимости и источника, но графику торгового знака не следует копировать автоматически.

### 10.3. Проверка будущего готового Arduino-kit (KIT-01, не часть DOC-01)

Круглый робот становится **работающим kit**, а не только 3D-иллюстрацией, после верификации конкретных: двух моторов, напряжения и источника питания, драйвера (например, L298N либо подходящего совместимого решения), GND и проводов, входов направления и PWM, библиотечных component IDs, реально допустимых GPIO, программы Arduino, обратной связи датчиков, кинематики и ограничений симуляции. Нельзя автоматически назначать L298N, пины, токи или управляющие функции из одной фотографии рамы. Выбор драйвера учитывает электрические потери, допустимый ток и совместимость с указанными моторами. Если электрическая/физическая цепь не поддержана общим engine, карточка прямо показывает **«Модель доступна для просмотра; запуск не подтверждён»**.

Для UX-01 первая карточка «Круглый робот R01-A» может показывать проверенные физические характеристики и статусы **«3D-просмотр / Схема / Программа / Чертёж»**; нефункционирующие действия должны быть заблокированы с объяснением, а не симулировать успешное создание проекта. Каталог остаётся в правом dock, мини-поле/схема/программа — в левой области, сцена — в центре. Первый реальный end-to-end kit создавать лишь после предусмотренных §20 и E2/D02 контрактов, отдельной selection и exact-SHA приёмки.

## 12. Четыре раздела правой панели — состав карточек и логика

### 12.1. Готовые роботы

На первом открытии нового проекта видны пути **«Готовый робот» / «Собрать своего» / «Мои сборки»**, правая панель по умолчанию показывает «Готовые роботы». Категории: круглые 2WD R01, вытянутые 2WD R02, 4WD R03, манипуляторы R04/R05, шагающие R06–R08, мобильный манипулятор R09. Категория может иметь планируемые прототипы, но статус «Не готово» и отключённое создание обязательны.

Каждая карточка показывает: preview, имя и ID варианта, version, тип/число колёс или DOF, габариты, двигатель, плату, драйвер, основные датчики, мини-BOM, статус совместимости, готовности электрической схемы/физики/чертежа, источник и лицензию. Неизвестное значение — «Не определено», а не придуманное число.

Действия: **«Посмотреть»** (только preview; не меняет проект), **«Создать из набора»** (только проверенный kit, после подтверждения), **«Редактировать копию»** (только доступный расширенный режим), **«Чертежи»** (только квалифицированный manufacturing-файл). R01-A должен отображаться как стартовая карточка; до KIT-01 иметь статус **«Предпросмотр / рабочий комплект не готов»** и не запускать вымышленную электрическую схему. R01-B — отдельный вариант, не наследующий отверстия или посадки R01-A.

### 12.2. Компоненты

Категории: **рамы/палубы, колёса/шины, моторы N20/TT, крепления и стойки, шаровые опоры, сервоприводы/шарниры, Arduino, драйверы L298N/TB6612 (только по наличию реальных каталоговых компонентов), питание, датчики, модули расширения, свои детали**. Каждый элемент: preview, partId/version, dimensions/units, anchors, supported joints, электрические terminals (если подтверждены), material/mass (если измерены), совместимость, license/provenance, status. «Добавить» доступно лишь при допустимом сопряжении; кнопка и drag используют общую валидацию.

Первый механический состав R01-A: **рама (1), два реально подходящих мотор-редуктора N20 с креплением, два совместимых колеса, шаровая опора (1), стойки/крепёж, плата контроллера, выбранный по электрическим характеристикам драйвер, питание и проводка**. Датчики — по проверенному BOM. Это перечень классов деталей для квалификации, не заявка на готовые посадки, программные пины или verified-physics.

### 12.3. Мои сборки

Карточка: название, миниатюра, категория, revision, дата, количество деталей, статус. Действия **«Открыть», «Создать копию», «Переименовать», «Сохранить как новую версию», «Удалить»** (удаление с подтверждением и проверкой ссылок). Старая revision и уже созданные проекты остаются неизменны. «Сохранить как сборку» не является дублирующей кнопкой обычного Save проекта. Пустое состояние: **«Сохранённых сборок пока нет»**, действия появляются только по мере CUSTOM-01.

### 12.4. Мои детали

«Добавить 3D-деталь» → локальный выбор GLB → частный preview → явный выбор единиц и осей, визуальная проверка габаритов/сложности → тип детали («Колесо», «Шасси», «Кронштейн», «Другое») → подтверждение → приватная запись после server-side валидации. Новая деталь по умолчанию **только визуальная**: без доверенных массы, креплений, электрических контактов и физики. STL/STEP/F3D не принимать под видом подтверждённого GLB без соответствующего отдельного импортера; права, лимиты и RLS обязательны.

## 13. Состояния страницы и правило поведения

| Ситуация | Обязательный результат |
| --- | --- |
| Новый проект без робота | Справа категории, центр — приглашение/preview; выбор карточки сам по себе проект не меняет |
| Готовый подтверждённый kit | Один verisoned mechanical/circuit/source; активен законный запуск |
| R01-A только с иллюстрацией | Видимый «Не готово», кнопки создания/симуляции не активированы |
| Выбранная деталь | Подсветка, инспектор справа, «Назад к каталогу» |
| Drag детали | Полупрозрачный ghost и допустимые крепления; Esc отменяет без сохранения |
| Неподходящее крепление | Причина отказа; структура и электрические IDs не изменяются |
| Изменение при Run | Структурную правку отклонить или предложить Stop; runtime не меняется под ногами |
| Смена набора | Сохранить поле/программу; показать конфликт несовместимых пинов/команд, запросить подтверждение |
| Сохранение/повторное открытие | Версии деталей, сборка, схема и активная программа согласованы |
| Автосохранение | Не чаще одного обращения к серверу за 60 секунд; вращение камеры и каждый drag не делают Save |
| Нет WebGL | Честное 2D-представление с предупреждением; не считать 3D-симуляцию принятой |
| Нет сети/ошибка импорта/конфликт версий | Явное сообщение, нет тихой потери сборки или публикации чужих файлов |
| Экран 1024/390/320 | Сцена и поочерёдные выдвижные панели; доступны кнопки закрыть/назад/сохранить |

Клавиатура: **Esc** отменяет ghost или закрывает drawer; **Delete** удаляет выбранную доступную деталь только после проверки зависимостей; **Ctrl+Z / Ctrl+Shift+Z** применяют историю сборки только в расширенном режиме, если фокус не в редакторе кода. Для сенсорного интерфейса предоставить кнопочные эквиваленты операций. Размер области касания ≥44×44 CSS px. Статусы loading/empty/unsupported/error/conflict/saved различать текстом, не только цветом. Камера не отнимает ввод у полей размеров.
