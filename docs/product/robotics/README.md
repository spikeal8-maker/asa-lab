# ASA Lab Robotics

Робототехника связывает существующую электронику ASA Lab с полем, механикой робота и учебными задачами. Первый результат — управляемая программой двухколёсная тележка на 2D-поле с настоящей схемой из поддерживаемых компонентов.

Это вход в документацию модуля, а не журнал исполнения. Выбранная задача, ветка, checkpoint, ревизии и blockers находятся только в [execution state](../../execution/current.yaml). Конкретная граница первого среза задана в [карточке M0](../electronics/tasks/TASK-ELECTRONICS-ROBOTICS-M0-001.md); последовательность видимых результатов — в [плане реализации](IMPLEMENTATION_PLAN.md). Документы не объявляют этапы выполненными и не запускают следующий этап самостоятельно.

## Что пользователь должен увидеть первым

В одном рабочем пространстве доступны поле с роботом, электрическая схема и существующий редактор Arduino с блоками и текстом. Пользователь запускает программу, наблюдает движение и расстояние до препятствия, меняет программу или соединение и видит соответствующее изменение поведения.

У первого пресета два независимо управляемых колеса, Arduino Uno, два канала низкого ключа на поддерживаемых FET с защитными диодами и один HC-SR04. Источники питания, общая земля, защитные элементы и соединения входят в реальную схему. Пины не заменяются условными командами «ехать» внутри отдельного интерпретатора.

Эта схема допускает движение вперёд, свободный выбег и поворот за счёт разницы скоростей. Реверс, активное электрическое торможение и разворот встречным вращением колёс не заявляются: для них нужен отдельно проверенный драйвер двунаправленного двигателя.

## Один источник электроники

| Область | Источник и граница ответственности |
| --- | --- |
| Электрический документ, netlist, solver, Arduino runtime, мотор и датчики | Существующий пакет `@asa-lab/electronics`; robotics использует его публичный контракт и результат |
| Схема, провода, выбор компонентов и управление симуляцией | Существующие `useElectronicsWorkbench` и `WorkbenchStage` |
| Блоки, текст, генерация Arduino и состояние программы | Существующий `ArduinoCodePanel` и его штатные зависимости |
| Реальные компоненты и графика | Существующий каталог/manifest электроники; поддерживаемые элементы выбираются из него |
| Геометрия поля, поза робота, колёса и размещение датчика | Новый модуль robotics; метры и радианы внутри модели, миллиметры в настройках |
| Связь мира с электроникой | Явные привязки по стабильным component ID, чтение committed motor observations и штатные timed inputs датчика |
| Проект в отдельном dev-входе | Ограниченный локальный host существующего workbench; это не новый backend или второй каталог пользователей |

Robot world не вычисляет ток, напряжение, электрический момент двигателя или результат выполнения Arduino. Скорость колёс берётся из наблюдения канонической модели мотора, а положение робота — из кинематики колёс и размеров шасси. Документ схемы хранит исходные параметры; вычисленные токи, RPM и поза не становятся второй электрической истиной.

Dev-вход — `apps/web/robotics-dev.html`, UI и чистый доменный `world.ts` находятся в `apps/web/src/robotics`. World не зависит от React/DOM; размещение внутри существующего Web сохраняет Nx boundaries без нового пакета и исключений линтера. При появлении второго потребителя его можно отдельно перенести в `modules/robotics`. Вход использует существующие Vite, Worker, assets и зависимости Web, без отдельного сервиса, новой БД или production-активации.

## Честные границы M0

| Возможность | Граница первого среза |
| --- | --- |
| Поле | Вид сверху, метрический масштаб, несколько небольших пресетов, след, начальная поза и простые препятствия |
| Сборка | Готовая конфигурация и явные размеры/привязки; свободный механический CAD не требуется |
| Моторы | Реальный результат существующей электрической модели; кинематика плоского шасси |
| Контакт с препятствием | Геометрическое ограничение движения с явной учебной оговоркой; динамическая нагрузка, ток заклинивания и трение контакта не моделируются этим слоем |
| HC-SR04 | Геометрическое расстояние передаётся через существующий runtime input; Trig/Echo и питание остаются ответственностью ядра |
| Время | Только committed source time; частота кадров и скорость компьютера не задают физическое время |
| Сохранение | Явный локальный режим dev-host и повторное открытие своего документа; школьное/серверное сохранение подключается отдельно |
| Вёрстка | Функциональная, с `VISUAL_STATE=provisional`; обязательна доступность действий на 320/390/1024/1440 |

Подробный протокол частоты world/sensor, ограничения накопленной истории и поведения при исчерпании бюджета находится в [плане M0](IMPLEMENTATION_PLAN.md#протокол-времени-и-входов-m0). Рабочий цикл не скрывает fault и не обнуляет историю, чтобы продолжить демонстрацию.

## Категория Arduino и неподдерживаемые элементы

В robotics можно показать собственную категорию **Arduino** с явно отключёнными карточками будущих модулей: двунаправленного драйвера, датчика линии/цвета, энкодера. На карточке указан недостающий контракт или модель. Она не добавляется на схему, не участвует в пресете, не выдаёт показаний и не обещает загрузку рабочего кода для отсутствующей возможности.

Такие карточки принадлежат robotics UI. Они не изменяют общий `component-catalog`, manifest, registry электрических моделей или штатную палитру электроники. Уже поддерживаемые компоненты используются по существующему ID. При последующем добавлении настоящей модели она проходит обычный общий путь электроники; отдельная реализация «только для робота» не создаётся.

## Реальный робот и дальнейшее развитие

Параметры шасси, положение осей и датчика задаются явно. Это позволит связать виртуальный пресет с распечатанными деталями, картоном или другой простой конструкцией. Первый экран сам по себе не доказывает физическую воспроизводимость: для неё нужен отдельный результат с BOM, распиновкой, питанием, сборочным чертежом и проверкой на конкретном роботе.

3D станет другим представлением того же robot document и электрического состояния. До его подключения должны быть определены размеры, крепления, ограничения движения и роль печатной геометрии. Произвольный STL не превращается автоматически в шарнир, датчик или достоверную collision-модель.

## Вход исполнителя

### Запуск локального экрана

Из корня checkout с установленными зависимостями ASA Lab:

```bash
corepack pnpm dev:robotics
```

Открыть `http://127.0.0.1:4610/robotics-dev.html`. Это отдельный вход существующего Vite; API, PostgreSQL и вход в школьный аккаунт для него не нужны. В обычную production-навигацию и production HTML entrypoint он не добавляется.

Нажать **Запустить**: начальная программа подаёт GPIO HIGH на оба FET-ключа, а поле принимает RPM из общего Worker. HC-SR04 измеряет препятствие через настоящий Trig/Echo. Программа снимает питание заранее — при пороге 60 см — потому что низкие ключи дают свободный выбег, а не активный тормоз. Кнопки **Вперёд / Влево / Вправо / Выбег** отправляют F/L/R/S в Serial этой программы. Дистанционный запрет относится к движению вперёд; после автоматической остановки можно повернуть одиночным приводом. Пользовательский скетч сам решает, как реагировать на эти символы.

**Пауза / Продолжить** сохраняют текущую симуляцию; **Сбросить** возвращает исходное положение и время. Поле меняется при остановленной симуляции. **Сохранить / Открыть сохранённое** используют только локальное хранилище данного браузера. Рабочая схема, программа и блоки сохраняются вместе с полем; скачивание Blockly-проекта не добавляется. Штатная кнопка Arduino позволяет скачать `.ino`.

Учебный запуск ограничен 40 секундами модельного времени и 1000 входными событиями. Эти ограничения не скрывают действующий предел общего ядра. Контакт корпуса приостанавливает демонстрацию с объяснением: электрическая нагрузка от столкновения и ток заклинивания здесь не рассчитываются.

### Быстрые проверки

```bash
corepack pnpm test:robotics
corepack pnpm exec playwright install chromium
corepack pnpm test:robotics:browser
```

Последняя команда поднимает временный Vite на каноническом E2E-порту `127.0.0.1:4612`, открывает настоящий экран в Chromium и закрывает собственный сервер после проверки. Занятый порт остаётся ошибкой; чужой процесс не останавливается. Снимки четырёх ширин и структурированный отчёт находятся в `reports/playwright/robotics`.

Focused команда не заменяет общие проверки ASA Lab и проверку существующего редактора электроники. Окончательный статус исполнения и приёмки читается из execution state и фактических CI/review evidence, а не из наличия этих команд.

### Правила изменения модуля

После принятия выбора задачи в canonical main:

```bash
pnpm agent:preflight --scope robotics --check
pnpm validate:electronics-agent-docs --task TASK-ELECTRONICS-ROBOTICS-M0-001
```

Перед записью проверяется полный точный план файлов. Для общей электроники действуют [Electronics START HERE](../electronics/START_HERE.md), существующие component entries и [review protocol](../../agent/review-protocol.md). Эта страница не заменяет `SAFE_TO_START`, проверки shared paths или приёмку результата.
