# ASA Lab Robotics

Робототехника связывает существующую электронику ASA Lab с полем, механикой робота и учебными задачами. Первый результат — управляемая программой двухколёсная тележка на 2D-поле с настоящей схемой из поддерживаемых компонентов.

Это вход в документацию модуля, а не журнал исполнения. Выбранная задача, ветка, checkpoint, ревизии и blockers находятся только в [execution state](../../execution/current.yaml). Граница исходной интеграции задана в [карточке M0](../electronics/tasks/TASK-ELECTRONICS-ROBOTICS-M0-001.md), рабочего редактора — в [карточке M1](../electronics/tasks/TASK-ELECTRONICS-ROBOTICS-M1-001.md) и [плане M1](M1_WORKSPACE_PLAN.md), общего сервиса проектов и публикаций — в [карточке Portal](../electronics/tasks/TASK-ELECTRONICS-ROBOTICS-PORTAL-001.md) и [плане пяти результатов](PORTAL_INTEGRATION_PLAN.md). Последовательность видимых результатов находится в [общем плане](IMPLEMENTATION_PLAN.md). Документы не объявляют этапы выполненными и не запускают следующий этап самостоятельно.

## Что пользователь должен увидеть первым

В одном рабочем пространстве доступны поле с роботом, электрическая схема и существующий редактор Arduino с блоками и текстом. Пользователь запускает программу, наблюдает движение и расстояние до препятствия, меняет программу или соединение и видит соответствующее изменение поведения.

У первого пресета два независимо управляемых колеса, Arduino Uno, два канала низкого ключа на поддерживаемых FET с защитными диодами и один HC-SR04. Источники питания, общая земля, защитные элементы и соединения входят в реальную схему. Пины не заменяются условными командами «ехать» внутри отдельного интерпретатора.

Эта схема допускает движение вперёд, свободный выбег и поворот за счёт разницы скоростей. Реверс, активное электрическое торможение и разворот встречным вращением колёс не заявляются: для них нужен отдельно проверенный драйвер двунаправленного двигателя.

| Реальные компоненты и графика                                             | Существующий каталог/manifest электроники; поддерживаемые элементы выбираются из него                         |
| Геометрия поля, поза робота, колёса и размещение датчика                  | Новый модуль robotics; метры и радианы внутри модели, миллиметры в настройках                                 |
| Связь мира с электроникой                                                 | Явные привязки по стабильным component ID, чтение committed motor observations и штатные timed inputs датчика |
| Проект аккаунта                                                           | Общий Project Core, существующие права, версии и optimistic concurrency; целый документ схемы и мира          |
| Проект в отдельном dev-входе                                              | Ограниченный локальный host для разработки и совместимости; основной портал его хранилище не читает           |

Robot world не вычисляет ток, напряжение, электрический момент двигателя или результат выполнения Arduino. Скорость колёс берётся из наблюдения канонической модели мотора, а положение робота — из кинематики колёс и размеров шасси. Документ схемы хранит исходные параметры; вычисленные токи, RPM и поза не становятся второй электрической истиной.

Общий документ, provider и чистая модель мира находятся в `contexts/robotics`, публичный пакет — `@asa-lab/robotics`. Его используют Web и API; он не зависит от React/DOM и не содержит копии электрического solver или Arduino runtime. UI и совместимые переэкспорты находятся в `apps/web/src/robotics`. Обычный портал загружает `RoboticsEditor` через `ModuleEditorHost` по projectId. Dev-вход `apps/web/robotics-dev.html` сохраняет локальный адаптер для разработки. Оба пути используют существующие Vite, Worker, assets и общие редакторы.

## Рабочие разделы M1

| Раздел          | Действие и видимый результат                                                                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Поле**        | Инструменты «Выбор», «Стена», «Мяч», «Линия», «Зона»; размещение на полотне или в свободном месте, перетаскивание, числовые свойства, удаление и общая история |
| **Робот**       | Настройка размеров в миллиметрах, крепления HC-SR04 и конкретных компонентов схемы; отсутствие детали не заменяется первым похожим компонентом                 |
| **Электроника** | Штатные каталог, провода, свойства и графика ASA Lab; схема сохраняет свой экземпляр при переходах                                                             |
| **Программа**   | Штатный ArduinoCodePanel, настоящие блоки, C++, `.ino`, Serial и примеры; поле и схема остаются доступны для наблюдения                                        |

Навигация меняет основную рабочую область. Компактная схема вне «Электроники» доступна для наблюдения; её указатель и команды клавиатуры не редактируют скрытую схему. На телефоне свойства поля раскрываются кнопкой, а палитра блоков переключается отдельно, освобождая ширину для программы. «Электроника» открывает рабочую схему со свёрнутой библиотекой; кнопка «Компоненты» и явное «Добавить компонент» из сборки открывают её. После касания карточки штатный каталог освобождает поле для размещения. Во время запуска библиотека недоступна, а разрешённые общие runtime-настройки схемы сохраняются. Смена раздела сохраняет экземпляр программного workspace.

Для компактной компоновки общие компоненты получают две узкие необязательные границы. `keyboardShortcutsEnabled` отключает только горячие клавиши схемы вне «Электроники»; по умолчанию прежний редактор сохраняет их включёнными, Worker и его поколение от флага не зависят. `programHandleRef` у Arduino-панели публикует незавершённую правку перед действием и даёт `revealProgramStart()`: штатные `svgResize` и `scroll` возвращают начало программы в видимую область после изменения ширины или закрытия мобильной палитры. Эта команда не меняет блоки, координаты графа, масштаб или историю; обычный переход между разделами не сбрасывает пользовательское панорамирование. Кнопка «К началу» вызывает её явно. Старые вызовы панели без handle сохраняют прежнее поведение. Штатный resize пропускает скрытый host с размером 0×0 и возобновляется при появлении видимого размера: это сохраняет панорамирование между вкладками. Undo изменения поля не пересоздаёт Blockly; новый workspace требуется только при фактическом изменении состояния программы.

Числовое поле фиксирует изменение после завершения ввода. Недопустимые размеры, пересечения и выход за границы показывают ошибку и сохраняют прежнюю сцену. Перетаскивание фиксируется одним шагом истории; отмена жеста не записывает новое положение. Во время запуска и паузы конструкция и сцена защищены от структурного редактирования. «Остановить» возвращает отображение к исходной сцене для редактирования; вычисленные координаты не записываются в неё.

Учебная сцена меняет предметы и старт робота после подтверждения; электрическая схема, программа и назначенные ID остаются прежними. Изменение размера поля никогда не перемещает и не удаляет предметы автоматически. История относится ко всему проекту, включая схему, программу и мир.

### Программы

Три примера создаются существующими ASA-блоками, сериализуются штатным ScratchBlocks и проходят общий `generateArduinoCode`:

- **Движение с датчиком** — команды F/L/R/S, два GPIO и измерение HC-SR04. Питание моторов снимается перед каждым измерением. Общий блок `pulseIn` ждёт до одной секунды; при пропадании эха прежний HIGH поэтому не удерживается всё время ожидания. Новый пример отличается этим от текстового M0 и не обещает ту же траекторию или время остановки.
- **Поворот налево** — один импульс правого мотора в `setup()`, затем свободный выбег. Точный угол зависит от реальной электрической модели и размеров тележки.
- **Толкнуть мяч** — один ограниченный импульс двух моторов в `setup()`, затем LOW. Программа не меняет расположение объектов или датчика и не реализует обработку F/L/R/S.

Перед заменой примера пользователь подтверждает замену текущей программы. Перед Save, Run, Open, сменой примера и переходом между разделами публикуется последняя правка блоков, включая ещё не завершившую 180-мс задержку. Отмена подтверждения сохраняет уже сделанную правку. Открытие другого проекта или подтверждённая замена не позволяет поздней публикации старого workspace восстановить прежний скетч.

Сохранения M0 читаются с неизменённым текстом и режимом программы. Отсутствующие коллекции новых предметов мигрируют в пустые только для версии 1. Новая версия проекта — 2; отсутствие её обязательных коллекций считается повреждением, а не пустой сценой. Ключ `asa-lab:robotics:local-project:v1` относится только к локальному dev-host. Основной редактор открывает серверный проект; его восстановительная копия ограничена projectId и principal identity и не смешивается с глобальным локальным сохранением.

### Опыт с мячом

1. Остановить опыт. В «Роботе» задать для HC-SR04: **вперёд от центра — 0 мм**, **влево от центра — 100 мм**, **направление — 90°**. Это явное боковое крепление, луч направлен наружу.
2. В «Поле» добавить мяч перед корпусом с достаточным зазором и свободным местом за ним. Положение и размеры вводятся в метрах; параметры физики находятся в свойствах мяча.
3. В «Программе» явно выбрать **«Толкнуть мяч»**, запустить и наблюдать движение мяча после контакта и после отключения приводов.
4. Нажать **Сбросить**: робот и мячи возвращаются к исходным координатам, скорости и время обнуляются. Save сохраняет исходную сцену, а не случайный кадр движения.

HC-SR04 по-прежнему принимает только 0,02–4,00 м. Датчик на передней кромке, направленный на близкий мяч, остановит опыт по границе 2 см до контакта корпуса. Поворота на прежнем переднем креплении тоже недостаточно: начало луча может попасть внутрь мяча. Поэтому в опыте крепление переносится вбок явно; вымышленное эхо не создаётся.

Мяч моделируется плоским движущимся диском. Масса влияет на столкновения мячей друг с другом, трение — на **скольжение по полу**, упругость — на отскок. Вращение шара, сопротивление качению, вертикальная динамика и обратная нагрузка на мотор не заявляются. Линия и зона — рисунки на полу: они не сталкиваются и не выдают показаний отсутствующего датчика цвета.

## Категория Arduino и неподдерживаемые элементы

В robotics можно показать собственную категорию **Arduino** с явно отключёнными карточками будущих модулей: двунаправленного драйвера, датчика линии/цвета, энкодера. На карточке указан недостающий контракт или модель. Она не добавляется на схему, не участвует в пресете, не выдаёт показаний и не обещает загрузку рабочего кода для отсутствующей возможности.

Такие карточки принадлежат robotics UI. Они не изменяют общий `component-catalog`, manifest, registry электрических моделей или штатную палитру электроники. Уже поддерживаемые компоненты используются по существующему ID. При последующем добавлении настоящей модели она проходит обычный общий путь электроники; отдельная реализация «только для робота» не создаётся.

## Реальный робот и дальнейшее развитие

Параметры шасси, положение осей и датчика задаются явно. Это позволит связать виртуальный пресет с распечатанными деталями, картоном или другой простой конструкцией. Первый экран сам по себе не доказывает физическую воспроизводимость: для неё нужен отдельный результат с BOM, распиновкой, питанием, сборочным чертежом и проверкой на конкретном роботе.

3D станет другим представлением того же robot document и электрического состояния. До его подключения должны быть определены размеры, крепления, ограничения движения и роль печатной геометрии. Произвольный STL не превращается автоматически в шарнир, датчик или достоверную collision-модель.

## Вход исполнителя

### Основной портал и проект аккаунта

Пользовательский путь: **Создать → Робототехника → изменить поле, конструкцию, схему и программу → Сохранить → вернуться на главную или в «Мои проекты» → снова открыть карточку**. После входа в чистом браузерном контексте исходная работа должна восстанавливаться из API. Локальное сохранение dev-host не является доказательством этого пути.

Project Core хранит whole document с `circuit` и `world`. Серверное имя берётся из `Project.title`; legacy `document.title` не меняется при переименовании. Незавершённая схема может сохраняться: проверка возможности запуска отдельно сообщает о неподключённых компонентах или неподдерживаемой топологии. Future-version и circuit downgrade protection сохраняются.

Save и публикация сначала публикуют ожидающую правку Arduino. Подтверждённая серверная ревизия управляет статусом сохранения и снимком исходной сцены. Поздний ответ прежнего проекта или прежней редакции не подтверждает новые правки. Runtime-поза робота и движение мячей не подменяют авторские начальные положения.

Публикация использует штатную неизменяемую версию и общий каталог. Публичный viewer получает ограниченную геометрию поля и конструкции с provenance; приватная схема, Arduino source, Blockly и bindings в него не входят. Действия просмотра не запускают скрытую симуляцию. Правила копирования, скачивания, StudentSeat и Learning не расширяются этим подключением.

Сквозная проверка основного сайта находится в `e2e/robotics-projects.spec.ts` и штатном workflow `projects-publication.yml`. Она использует построенные Web/API, настоящую изолированную PostgreSQL, автора и второй аккаунт. `gate:projects-publication` и `gate:projects-publication:browser` требуют одну test database с суффиксом `_test` и ограниченную runtime-role `asalab_app`; без этой границы проверка завершается ошибкой. Dev browser suite ниже проверяет другой, локальный вход.

### Запуск локального экрана

Первый запуск из корня свежего checkout подготавливает зависимости и сборки общих workspace-пакетов:

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm nx run-many -t build --projects=module-sdk,contracts,electronics,chess,checkers,three-d,robotics --parallel=2
corepack pnpm dev:robotics
```

Для следующих итераций достаточно `corepack pnpm dev:robotics`; повторять подготовительную сборку после каждой правки интерфейса не нужно.

Открыть `http://127.0.0.1:4610/robotics-dev.html`. Это отдельный вход существующего Vite; API, PostgreSQL и вход в школьный аккаунт для него не нужны. В обычную production-навигацию и production HTML entrypoint он не добавляется.

Нажать **Запустить**: начальная программа подаёт GPIO HIGH на оба FET-ключа, а поле принимает RPM из общего Worker. HC-SR04 измеряет препятствие через настоящий Trig/Echo. Программа снимает питание заранее — при пороге 60 см — потому что низкие ключи дают свободный выбег, а не активный тормоз. Кнопки **Вперёд / Влево / Вправо / Выбег** отправляют F/L/R/S в Serial этой программы. Дистанционный запрет относится к движению вперёд; после автоматической остановки можно повернуть одиночным приводом. Пользовательский скетч сам решает, как реагировать на эти символы.

**Пауза / Продолжить** сохраняют текущую симуляцию; **Сбросить** возвращает исходное положение и время. Поле меняется при остановленной симуляции. **Сохранить / Открыть** используют только локальное хранилище данного браузера. Рабочая схема, программа и блоки сохраняются вместе с полем; скачивание Blockly-проекта не добавляется. Штатная кнопка Arduino позволяет скачать `.ino`.

Учебный запуск ограничен 40 секундами модельного времени и 1000 входными событиями. Эти ограничения не скрывают действующий предел общего ядра. Контакт корпуса с неподвижным препятствием или непреодолимый контакт приостанавливает демонстрацию с объяснением. Толчок мяча не создаёт обратную электрическую нагрузку или ток заклинивания.

### Быстрые проверки

```bash
corepack pnpm test:robotics
corepack pnpm exec playwright install chromium
corepack pnpm test:robotics:browser
```

Последняя команда поднимает временный Vite на каноническом E2E-порту `127.0.0.1:4612`, открывает настоящий экран в Chromium и закрывает собственный сервер после проверки. Занятый порт остаётся ошибкой; чужой процесс не останавливается. Снимки четырёх ширин и структурированный отчёт находятся в `reports/playwright/robotics`.

Focused команда не заменяет общие проверки ASA Lab и проверку существующего редактора электроники. Окончательный статус исполнения и приёмки читается из execution state и фактических CI/review evidence, а не из наличия этих команд.
