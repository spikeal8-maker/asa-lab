# ASAI-01 — контракт реализованного Обзора

Карточка: [ASAI-01](FIRST_TASK_ASAI-01.md), Issue #799, R19/R20/R31 и C17/C20/C28.
Выбранная работа и её приёмка по-прежнему читаются только из
[`docs/execution/current.yaml`](../../execution/current.yaml), направление `ai-assistant`.
Этот файл описывает реализацию и воспроизводимые проверки; он не назначает работу,
не подтверждает deployment и не заменяет приёмку владельца.

## Пользовательский маршрут

В существующей админке `/#/admin/ai` первый визит открывает **Обзор**, второй раздел —
**Настройки**. Остальные разделы и их действия сохранены. Выбор раздела и провайдера
хранится отдельно для каждого административного principal, без данных журнала,
ключей или переписок. Явный адрес, например
`/#/admin/ai?section=connections&provider=openai`, имеет приоритет. Смена владельца
пересоздаёт workspace и отменяет чтение прежнего Обзора.

На Обзоре: количество запросов, входные и выходные токены, семь дневных столбцов и
доступная таблица точных значений. Кнопка «Обновить данные» повторяет только чтение.
Состояния пустого журнала, неполного расхода и ошибки источника различаются.
Загрузка ограничена 15 секундами; поздний ответ отменённого чтения не восстанавливает
старые показатели. Неисправный формат ответа не трактуется как нулевой расход.

## Одна семантика данных

`GET /api/admin/v1/ai/usage-overview` возвращает один снимок существующего
`ai_usage_journal`. Контракт — `packages/contracts/src/ai-usage-overview.ts`.

- Период: текущие сутки UTC и шесть предыдущих. Начало включено, время SQL-запроса
  исключено; последний день ещё идёт. Карточки и график используют одинаковые границы.
- Запрос: одна допущенная операция с существующим составным ключом
  `(owner_principal_id, request_id)`. Повтор чтения/восстановления ответа не создаёт
  строку. Новый вариант ответа — новая операция. Pending и failed не исчезают из учёта.
- Суммы токенов передаются десятичными строками без потери точности JavaScript.
  `known: null` означает, что операции есть, но известных показателей нет. Известный
  ноль остаётся нулём. При частичных данных показана известная сумма и количество
  операций без показателя. Пустой период даёт семь нулевых дневных точек.
- В ответе нет владельцев, идентификаторов запросов, моделей, текстов, ключей и адресов
  подключений. Административная сессия проверяется сервером, затем функция PostgreSQL
  повторно требует действующий `platform_admin`. Ответ имеет `private, no-store`.

Миграция `0268_ai_usage_overview.sql` добавочная: индекс и защищённая агрегатная
функция. Опубликованная `0244` не изменена; RLS и отсутствие прямого доступа
`asalab_app` к журналу сохранены. Модели, квоты, tools и новые таблицы не добавляются.
Внутренний SQL-параметр времени нужен для проверки границ; HTTP не принимает
произвольный период и всегда использует время PostgreSQL.

## Проверки и evidence

Команды зарегистрированы в test catalog и AI surface map:

```bash
pnpm exec vitest run apps/api/src/ai-usage-overview.spec.ts apps/web/src/admin/testing/ai-usage-overview.spec.ts apps/web/src/admin/testing/ai-admin-navigation.spec.ts
pnpm exec vitest run tests/admin/ai-usage-overview.pg.spec.ts
pnpm exec playwright test --config playwright.ai-usage-overview.config.ts
```

Настоящая PostgreSQL нужна для второго и третьего запуска. CI использует отдельные
`*_test` БД, закрытый runtime role, все миграции и существующий `e2e/server.mjs` на
`127.0.0.1:4612`. API и Web собраны из точного candidate SHA, кэш Nx отключён.
Успешные HTTP-ответы в новой E2E-проверке не подменяются. Контрольная сводка:
дневные запросы `[1, 0, 2, 1, 3, 0, 2]`, всего `9`, вход `4500`, выход `450`.
Негативный сценарий временно делает функцию недоступной только в одноразовой БД
и восстанавливает её в `finally`.

Существующий `playwright.ai-chat.config.ts` продолжает запускать свои mock-based
регрессии. Новый настоящий сценарий запускается отдельной конфигурацией; он не
подменён mocked Vite-проверкой и не запускается второй раз против mock-среды.

CI сохраняет безопасные JSON-сводки и снимки 320/390/768/1024/1440/1920 в светлой
и тёмной цветовой схеме, а также состояния empty/partial/error. Снимки исходного
`e9013f86f17e1946857e5b2f4b7c30fd7b28fc82` собираются отдельно из неизменённых
продуктовых файлов с тем же узким harness. Это снимки исходной версии, полученные
во время CI, **не заявление о хронологической съёмке до редактирования**. В исходной
админке отдельной тёмной темы нет. Цветовая адаптация нового Обзора ограничена его
смонтированным маршрутом и использует существующие ASA tokens и палитру AI-чата.

Артефакт CI и временный loopback-адрес runner не являются доступным владельцу
живым стендом. Перед показом по `https://test.asa-lab.ru/#/admin/ai` требуется
сверить `/api/version` и Web metadata с кандидатом. Штатное обновление действующей
установки требует применимого разрешения; код ASAI-01 его сам не предоставляет.
