# Спецификация поведения инструментов и управления ими

[Обоснование и источники](README.md) · [Подробности инструментов](TOOL_CONTRACTS.md) · [Админка](ADMIN_AND_VALIDATION.md) · [Схема](contracts/tool-runtime.schema.json) · [Примеры](contracts/examples.json)

**Редакция проекта 1, 02.11.2026.** Это конкретизация для рассмотрения в PR #946, а не уже внедрённый API. Единственный нормативный вход — [действующее ТЗ](../../../ASA_AI_ASSISTANT_SPEC.md). Существующие R/C, права, сервисы, API и данные сохраняются. Новые внутренние envelopes и события ниже вводятся только вместе с отдельным проверенным продуктовым изменением. Документ не выбирает следующую задачу, не разрешает deployment или изменение базы.

## 1. Что должно получиться у пользователя

Пользователь пишет обычное сообщение. Модель выбирает разрешённые инструменты, получает их результаты и продолжает задачу. Пользователь не обязан открывать плюсик, выбирать технический режим или повторно просить «используй картинку». Плюсик уточняет предпочтение, но не является единственным способом вызова.

Составной результат считается готовым только когда он доступен: изображение видно, файл существует и скачивается, правка создала версию нужного файла. Фраза модели «сделал» не подтверждает выполнение. При частичном результате явно указано, что именно не завершено. Ввод следующего черновика доступен во время ответа; Stop не стирает черновик.

**Сайт с картинками:** сначала найти подходящие изображения, проверить доступность ресурсов и вставить в HTML. Генерация допустима по прямой просьбе либо как явно разрешённый запасной вариант после непригодного поиска. Запрет генерации не отменяется отсутствием результатов. Если ни один путь недоступен, сохранить полезный сайт без выдуманных картинок и честно обозначить недостающие ресурсы.

## 2. Границы компонентов

| Компонент | Отвечает за | Не может |
| --- | --- | --- |
| Модель/проверенный planner | Выбор инструмента, параметры, следующий шаг, пользовательский ответ | Выдавать себе права, подменять успех исполнителя |
| Реестр | Определения, версии, зависимости, эффекты, тексты карточек | Считать наличие записи доказательством готовности сервиса |
| Admission | Сессию, scope, актуальные запреты, лимиты, разрешённые ресурсы | Доверять owner ID из ответа модели |
| Исполнитель | Вызов существующего сервиса, проверку и нормализацию результата | Повторять неизвестную мутацию или обходить блокировку |
| Модельный адаптер | Протокол, call/result IDs, поток и continuation | Удалять необходимые служебные поля или скрыто менять платный маршрут |
| Клиент | Отображение стадий, файлы, предпросмотр, composer и восстановление | Решать права только по скрытым кнопкам |

Используются существующие `AiChatService`, `AiWebSearchService`, определения native tools, `WorkingFileStore`, политики и журналы. Второй чат, второй оркестратор, универсальный shell и новый платный планировщик не создаются.

Способ планирования выбирается по проверенному профилю маршрута:

| Режим | Как получается действие | Что происходит при ограничении |
| --- | --- | --- |
| Native tools | Текущая модель возвращает предусмотренный её API вызов; адаптер собирает части и сохраняет continuation | Не терять IDs/служебный контекст; неверный вызов не исполнять |
| Структурированный fallback | Та же разрешённая модель возвращает закрытую форму следующего действия; исполнитель валидирует её перед запуском | План не показывается как пользовательский текст; ограниченный repair либо уточнение |
| Явная простая команда | Существующий управляющий слой выполняет однозначно запрошенное разрешённое действие | Не обобщать regex-маршрутизацию на произвольный многошаговый запрос |

Fallback не означает скрытую отправку другой модели. Сложная композиция не объявляется поддержанной для маршрута, пока не прошла проверку цикла «план → результат → следующий план». Ограничение Vision не запрещает поиск/показ изображений, но запрещает утверждать анализ пикселей.

## 3. Каталог и режимы доступности

В первый охват входят ровно восемь существующих model-call инструментов: `web_search`, `read_page`, `image_search`, `weather`, `generate_image`, `create_working_file`, `read_working_file`, `edit_working_file`.

Для каждого отображаются независимо:

- **Разрешение:** включён глобально; разрешён текущим классом/заданием/пользователем.
- **Техническая готовность:** настроен; проверен; недоступен; не проверен; проверка устарела.
- **Поддержка маршрута:** native, проверенный fallback или недоступен; Vision — отдельная capability.

Рабочий список модели строится из пересечения этих условий, зависимостей и admission. Отсутствие поля в discovery не равно отсутствию возможности; значение остаётся «не проверено». Запрещённый инструмент не предлагается модели и повторно отклоняется на сервере при поддельном вызове.

В исходном коде `read_page` наследует `web_search`, а три файловых действия не имеют самостоятельных строк `TOOL_IDS`. Целевая гранулярность — отдельные переключатели всех восьми с сохранением зависимостей. Это не означает, что текущие файловые действия лишены авторизации.

При эволюции конфигурации старое выключенное значение поиска не превращается в включённое чтение страниц. Отсутствие новой политики файлов сохраняет прежний разрешённый сервером режим до явной настройки, а не отменяет существующие grants. Предварительный просмотр миграции должен показывать effective policy до/после; окончательные правила совместимости проверяются в выбранном implementation-срезе.

Снимок начала операции нужен для воспроизводимости, но не даёт бессрочное право. Перед новым внешним вызовом, записью версии, выдачей ресурса и recovery-read проверяются актуальные grants/запреты. Отозванный доступ не возвращается из старого snapshot. Утрата права во время внешнего job запрещает выдачу приватного результата и запускает допустимую отмену/сверку; не обещается отозвать байты, уже законно переданные ранее.

## 4. Аргументы: точные формы и ограничения

Машиночитаемые формы находятся в `$defs.call` [схемы](contracts/tool-runtime.schema.json). `kind=call`, `contractVersion=1`, `callId`, `name` и `arguments` обязательны; неизвестные поля отклоняются. Это проект **внутреннего представления**, а не немедленная замена REST или формата API поставщика.

| Инструмент | `arguments` | Дополнительная серверная проверка |
| --- | --- | --- |
| `web_search` | `query`: непустая строка до 400 | Не пробельная; разрешённый поиск; минимизация приватных данных; доменные фильтры |
| `image_search` | Та же форма `query` | SafeSearch/запреты, разрешённые источники, лимиты ресурсов |
| `read_page` | Ровно один вариант: `url` либо непустой массив уникальных `sourceIds` | URL из явного контекста или ID из допущенной выдачи; число страниц; адрес, redirects, MIME, байты |
| `weather` | `city`: 2–100 символов | Место следует из запроса; геокодирование/уточнение; реальный период в результате |
| `generate_image` | `prompt`: 1–3 000; `size`: ID пресета; `model`: ID профиля; необязательный `target` | Только предложенный профиль и разрешённый preset, GPU-квота, immutable job admission, права на target |
| `create_working_file` | Либо `name, content`, либо `name, sourceMessageId, blockIndex` | Разрешённое имя, существующий собственный code block; лимиты содержимого; создание без перезаписи чужой версии |
| `read_working_file` | `name`, необязательная `version` 1–100 | Канонический owner/thread, существующий файл и разрешённая версия |
| `edit_working_file` | `name, expectedVersion, edits` из 1–12 `oldText,newText` | Актуальная версия, каждое совпадение единственно, атомарность всего изменения |

Файловое имя: до 96 символов, без каталогов и `..`, с действующим разрешённым расширением. Для текста сохраняются существующие пределы 96 000 code units и 131 072 UTF-8 байта; JSON Schema не заменяет проверку байтов, NUL и UTF-16 длины. `blockIndex` — 0–19. Эти числа взяты из текущего кода, не новые рекомендуемые бюджеты.

`size` — **идентификатор**, не сторона квадратного изображения: например, 1280 означает 1280×720, а 720 — 720×1280. Новые вызовы используют зарегистрированные preset ID; исторический 512 читается из старых заданий, но не предлагается для новой генерации. Статическая схема знает зарегистрированные пресеты, admission допускает только реально предложенное подмножество. Любая новая модель или размер требует совместимого изменения каталога/адаптера, не редактирования произвольной строки промпта.

`weather(city)` пока не содержит отдельного `period`. Модель выбирает запрошенные интервалы из фактически возвращённого прогноза, сверяя даты и пояс места с запросом. Вне доступного диапазона — честный отказ/уточнение, а не текущая температура вместо завтрашней. Добавление структурированного периода — совместимое развитие отдельного контракта, не функция, уже появившаяся от этой документации.

## 5. Что получает модель в ответ

Общий результат: `kind=result`, `contractVersion`, `operationId`, `callId`, `name`, `state`, `data`. Тип `data` связан со значениями `name/state`; пустая выдача не маскируется под успешный список. Полные формы — `$defs.result` схемы.

В серверных результатах/событиях обязательно `executionSource`: `model_native` (вызов модели), `planner` (проверенный управляющий слой), `user_action` (явная кнопка пользователя), `job_completion` (завершение уже принятого задания), `runtime` (служебный lifecycle) или `unknown` для достоверно не установленного происхождения. Это поле ставит сервер; модель не передаёт его в `call`. В админке видно, кто выбрал действие. Автоматическая вставка готовой картинки не выдаётся за новый вызов инструмента моделью.

| Инструмент | Полезное содержимое результата | Условие, при котором нельзя утверждать больше |
| --- | --- | --- |
| `web_search` | ID, заголовок, URL, сниппет, известная дата и время получения | Это ещё не чтение страницы |
| `read_page` | Запрошенные ID, извлечённые страницы, неудачные ID/причины, время и coverage | Неполнота/ошибка одного чтения не объявляется полным исследованием |
| `image_search` | Asset ID, источник, размеры/вес/MIME, известная лицензия, `selectionBasis` | `metadata` не означает просмотр пикселей; неизвестная лицензия не становится свободной |
| `weather` | Место, известный пояс, актуальность, источник, временные слоты с единицами | Неизвестные величины остаются `null`; прогноз не объявляется наблюдением станции |
| `generate_image` | Job ID, стадии, затем asset, модель, preset, промпт и исход обновления target | Картинка готова — ещё не значит, что сайт обновлён |
| Создание/правка файла | Стабильный file ID, имя, версия, digest | Квитанция записи не означает запуск или визуальную проверку |
| Чтение файла | Та же identity/версия, содержимое и coverage | Нельзя объявлять полный файл после обрезки |

`sourceId` — локальный указатель конкретного допущенного результата. `assetId` — серверный ресурс с проверкой владельца; не открытый вечный URL. `fileId` не меняется при правке, `version` меняется. Название файла из модели разрешается внутри owner/thread в канонический ID. Служебные IDs не выдаются за путь к диску.

В предлагаемой квитанции `digest` — SHA-256 UTF-8 байтов точного содержимого версии, 64 строчных hex-символа. Это новое внутреннее поле; если старый DTO его не содержит, адаптер вычисляет его из разрешённой версии, а не заполняет фиктивным значением. При частичном чтении digest относится к исходной версии, coverage — к возвращённому фрагменту.

Нормализатор сохраняет необходимую provenance и все результаты пакета. Он не придумывает `publishedAt`, timezone, лицензию, пиксельный анализ или успешную проверку. Ошибки HTTP, ошибки в теле ответа и отмены классифицируются раздельно. Полные raw traces и credentials не попадают ни модели, ни пользователю.

**В диалоге провайдера одному call ID соответствует один результат.** Для синхронного действия это итог, для асинхронного задания — принятая квитанция queued/running с job ID. Последующие изменения job обновляют журнал и UI, но не добавляют вторую конфликтующую `tool_result` к уже закрытому вызову. Формы `result` схемы описывают также нормализованные снимки журнала; не каждый такой снимок повторно отправляется модели. На следующем пользовательском ходе актуальный ресурс доступен через разрешённый контекст. Автовставка картинки в target не требует дополнительного модельного запроса.

## 6. Состояния и продолжение

### Пользовательская операция

| Состояние | Допустимый следующий этап | Что видно в чате |
| --- | --- | --- |
| `accepted` | `planning`, отмена, конечный отказ | Сообщение принято, черновик следующего доступен |
| `planning` | `executing`, `responding`, отмена | Краткое ожидание, без выдуманного вызова инструмента |
| `executing` | Следующий вызов, ответ, отмена, сверка | Реальная стадия конкретного действия |
| `responding` | Следующий инструмент либо завершение | Содержательные text deltas по мере получения |
| `cancel_requested` | `cancelled`, `partial`, `reconciling` | Остановка запрошена; нет заявления о возврате расходов |
| `reconciling` | Подтверждённый исход либо `unknown_outcome` | Сверка принятой операции, без повторной отправки |
| `unknown_outcome` | Только `reconciling` или запрос отмены | Исход не установлен; черновик доступен, бесконечного loading нет |
| `succeeded / partial / failed / cancelled` | Терминальное состояние попытки | Индикатор убран, полезные данные и черновик сохранены |

Терминальные события не переигрываются в новое исполнение. `unknown_outcome` — спокойное, но не окончательно разрешённое состояние: при позднем подтверждении оно проходит сверку по тому же ID; нового внешнего задания не возникает. Сверка ограничена профилем и не блокирует ввод бесконечным ожиданием. Если parent уже завершён как `partial`, позднее подтверждение дочернего job меняет его журнал/ресурс отдельным событием, не перезапускает parent и не отменяет запрет перезаписи новой версии. Успешный tool call сам по себе не завершает parent operation.

Полные разрешённые переходы и допустимые/запрещённые последовательности заданы в [state-transitions.json](contracts/state-transitions.json). Переход `unknown_outcome → running` без сверки запрещён: `reconciling → running` означает наблюдение того же уже принятого задания, не повтор dispatch.

### Дочерний вызов

`proposed → admitted → running → result`; генератор после admission может перейти в `queued`. Ошибка прав/аргументов завершается до внешнего исполнения. `queued/running` возвращаются как продолжение задания, но не как итоговая картинка. Для чтений транспортный pending отражается activity, а не фиктивным генерационным job ID.

Неизвестное имя или неразбираемый вызов получает протокольный отказ с исходным call ID, если он есть. В схеме `invalid_arguments` допускает несуществующее имя только для такого отказа (`UNKNOWN_TOOL`); это не добавляет его в каталог и не создаёт исполнителя. Недоверенное имя не используется как заголовок пользовательской activity. Если ID/формат не позволяют безопасно продолжить протокол, попытка завершается без исполнения, с сохранением черновика.

| Исход | Что делает модель/оркестратор |
| --- | --- |
| `succeeded` | Использует данные, выбирает следующий нужный шаг либо отвечает |
| `partial` | Учитывает coverage, при необходимости запрашивает доступный недостающий материал |
| `empty` | Может уточнить запрос в оставшемся бюджете; не повторяет бесконечно то же самое |
| `invalid_arguments` | Возвращается структурированная причина; ограниченный repair согласно профилю, затем конечное уточнение |
| `denied` | Не пытается обходить запрет другим инструментом |
| `unavailable / rate_limited` | Сохраняет полезный результат, не переключает скрыто платный маршрут |
| `conflict` | Перечитывает версию, перепланирует; не перезаписывает старым текстом |
| `unknown_outcome` | Только сверка квитанции/задания; нет автоматического resubmit |
| `cancelled` | Не запускает зависимые шаги |

Бюджет считает отдельно модельные раунды, допущенные tool calls, сетевые попытки, страницы и GPU jobs. Один `read_page` с двумя ID — один tool call и два чтения. Transport retry расходует попытку/время, переформулированный поиск — новый tool call. Все пределы конечны и задаются действующим серверным профилем; новая универсальная цифра здесь не вводится. Параллельно исполняются лишь независимые разрешённые чтения; изменения одного файла сериализуются с CAS. Весь пакет не теряется из-за одного неподдержанного вызова: каждому ID нужен достоверный результат или отказ.

Целевая подпись `pagesLimit` в админке — предел различных публичных страниц за пользовательскую операцию, а не разрешение повторять пакет до бесконечности. Повтор извлечения сохранённого snapshot не создаёт сетевого чтения; новая попытка сети всегда расходует attempts/deadline. Source ID разных поисков, ведущие к одной нормализованной странице, не создают новый лимит. Текущий диапазон конфигурационного валидатора сам по себе не доказывает наличие такого общего счётчика: он проверяется отдельно. Неполный профиль без конечных лимитов/deadline не допускается к внешнему исполнению; подстановка «без ограничений» запрещена.

## 7. Стандартный сценарий сайта с найденными изображениями

1. Принять запрос с новым operation ID, выбранной моделью и снимком политики. Повтор того же request ID сверяет существующее состояние, не создаёт вторую работу.
2. Определить новый файл либо прочитать нужную версию существующего. При двух неоднозначных сайтах — одно понятное уточнение; не выбирать произвольно.
3. Вызвать `image_search` по теме. Показать «Подбираю изображения». Выдача — кандидаты, не доказанные пригодные картинки.
4. Проверить фактический MIME, байты, размеры, источник, отсутствие дубликатов и доступность оригинала. Анализ содержания — только при реальной Vision и передаче пикселей. Иначе критерий отбора — метаданные, без выдуманного просмотра.
5. Создать/изменить HTML с ресурсами выбранных asset ID. Для внешних картинок renderer разрешает только конкретные проверенные материалы этого файла, не произвольную сеть.
6. Получить квитанцию версии и проверить сохранённое содержимое. Показать карточку того же file ID возле ответа, предпросмотр и действия экспорта. Прочтение исходника не подписывать как визуальный тест.
7. Если какие-то ресурсы не получены, итог `partial`: доступны файл и известные рабочие картинки; недостающие не подменяются выдуманными ссылками.

**Повторная просьба «замени картинки»:** читать head того же файла → новый поиск → CAS-правка → новая версия. Старые доступные версии остаются в истории. Модель не печатает заново весь сайт только ради правки и не сообщает «в рабочем файле», если карточка результата не привязана к ответу.

## 8. Генерация как запасной путь и асинхронная вставка

Сохраняется существующий `AI-IMAGE-JOB-001`, а не вводится произвольная автозамена HTML:

1. Убедиться, что генерация явно разрешена намерением и политикой. Поиск недоступен сам по себе не снимает запрет генерации.
2. Сначала сохранить HTML с **единственным** `ASA_GENERATED_IMAGE_PENDING` в `img src`. Получить фактическую версию.
3. Вызвать `generate_image` с `target={name,expectedVersion,placeholder}`. Связь target фиксируется вместе с admission. `size` преобразуется в реальные width/height; промпт, публичное имя модели и разрешение видны пользователю.
4. На queued/running показывать действительную стадию и неопределённый индикатор, если backend не отдаёт проценты/превью. Эти величины нельзя выдумывать. Копирование промпта доступно.
5. Подтверждённый owned asset и новая версия HTML публикуются атомарно в пределах существующего контракта, без второго запроса модели/пользователя. Если потерян ответ commit, сначала прочитать квитанцию того же действия.
6. Конфликт версии, новый пользовательский turn, отмена или ошибка **не перезаписывают** файл. Картинка может быть готова с `targetUpdate=conflict/newer_turn/cancelled`; это не успешная вставка на сайт. `pending_reconciliation` требует сверки.

Несколько картинок — отдельные jobs и квитанции; текущий target-протокол с уникальным placeholder не расширяется молча на многослотовый граф. Последовательная вставка возможна только после чтения фактической версии и при сохранении ограничений. Произвольные ComfyUI graphs, новые платные генераторы и обещание совместимости «со всеми версиями» исключены.

## 9. Предпросмотр, ресурсы и скачивание

Уровни проверки подписываются раздельно: **записан → структурно проверен → запущен → визуально проверен**. Последний требует реального изображения результата и оценки viewport; он не получается из успешного парсинга или слов модели.

Предпросмотр HTML работает в изолированном контексте с разрешёнными скриптами и без доступа к DOM, cookies/storage и полномочиям родителя. Parent не предоставляет универсальную команду fetch/execute. Сообщения ограничены ожидаемым iframe, operation и схемой. Sandbox не считается гарантированной изоляцией CPU/памяти; зависание/ресурсные ограничения требуют отдельной проверки.

Разрешение JavaScript для игры не переносится на загрузку/просмотр пользовательского SVG. В нём запрещены скрипты, обработчики событий, `foreignObject`, опасные URL и внешние ресурсы; требуется фактическая санитизация или безопасное растровое представление. До реализации такой защиты недоверенный SVG не принимается/не отображается соответствующим путём. Прямая вставка недоверенного SVG через `innerHTML` запрещена.

Для картинок parent получает только принадлежащие разрешённой версии asset ID через существующую авторизацию, проверяет формат/пределы и передаёт безопасное растровое представление. Конкретный transport, CSP и отзыв ресурсов должны пройти браузерный прототип до включения. Пока он не проверен, это проект технического решения, не доказанная работоспособность. Внешняя ссылка, ресурс preview и ресурс автономного экспорта не смешиваются.

| Действие пользователя | Ожидаемое поведение |
| --- | --- |
| «Скачать HTML» с внешними ссылками | Явно обозначено, что изображения требуют доступной сети; защищённые внутренние URL не выдаются за переносимые |
| Автономный экспорт | Только реально включённые разрешённые ресурсы; без cookies/ключей, соблюдены ограничения и права использования |
| Открыть SVG | Изоляция/санитизация недоверенного содержимого, fit в область, не прямой `innerHTML` |
| Открыть игру | Кнопки/скрипты работают в sandbox без отдельного доступа к данным ASA |
| Следующий вопрос | Preview остаётся частью истории; не закрепляется поверх переписки, может компактно сворачиваться |
| Изменить существующую работу | Обновляется тот же file ID, доступна новая версия; прежняя не уничтожена |

Нельзя принимать export за работающий только потому, что появился файл: ресурсные ссылки проверяются после открытия скачанного результата в подходящей изолированной среде.

## 10. Поток, восстановление и сообщения об ошибках

Проект событий — `$defs.event` схемы: `text.delta`, `tool.state.changed`, `artifact.version.created`, `image.ready`, `operation.state.changed`. У каждого operation ID, монотонный sequence и серверное время. При повторной доставке sequence не дублирует текст или карточку. Аргументы функции и внутренние рассуждения не попадают в `text.delta`.

Содержательный текст передаётся сразу после получения, даже если tools были предложены, но не вызваны. Результат после инструмента тоже потоковый при поддержке маршрута. Нельзя имитировать streaming постепенным показом заранее целиком полученного текста.

При потере SSE клиент восстанавливает снимок/события существующей операции. При недоступном event history получает актуальный snapshot, а не запускает новую генерацию. Endpoint/курсор реализуется совместимо с существующим API в отдельном срезе; эта схема не означает, что recovery endpoint уже появился.

Смена модели убирает **текущую** ошибку недоступного маршрута, сохраняя исторический исход попытки и черновик. Не отменяет существующий job сама по себе и не отправляет заново сообщение без действия пользователя. Новая явная попытка получает новый request ID и может иметь новый расход; «продолжить сверку» использует старый. Во время исполнения отправка нового сообщения следует существующему режиму admission/очереди, но composer не блокирует набор текста.

| Причина | Сообщение пользователю | Что остаётся администратору |
| --- | --- | --- |
| Сбой текстового маршрута | «Извините, текстовая модель сейчас недоступна. Можно выбрать другую» | Диагностический ID, маршрут, стадия, безопасный класс ошибки |
| Недоступен генератор | «Генератор изображений сейчас недоступен» | Профиль, readiness, исход job и возможность сверки |
| Политика задания запрещает tool | «Этот инструмент недоступен в задании» | Effective policy и причина deny |
| Нет поддержки Vision | «Выбранная модель не поддерживает чтение изображений» | Основание capability; `unknown` не объявляется `unsupported` |
| Ошибка ввода/формата | Понятное ограничение файла/поля | Точная нарушенная проверка без содержимого приватного документа |

Никаких трассировок, балансов, ключей и внутренних IP в пользовательском сообщении. При неизвестной поддержке: «Для этой модели чтение изображений пока не проверено». Ошибка одного инструмента не называется автоматически поломкой текстовой модели.

## 11. Админка: конкретные поверхности

Сохраняется порядок: **Обзор → Настройки → Подключения → Системный промпт → Интернет-поиск → Изображения**. В Настройках есть заметный подраздел «Инструменты», а не второй скрытый список под промптом.

| Экран | Что редактируется | Что видно без раскрытия технических деталей |
| --- | --- | --- |
| Настройки → Инструменты | Восемь отдельных разрешений, категории/scope, конечные ограничения, инструкции выбора | Название, переключатель, готовность, inherited/deny, последняя проверка |
| Системный промпт | Поведение, язык, краткость, зарегистрированные переменные | Реальный preview текущего администратора; доступные tools и причины отсутствия |
| Интернет-поиск | Выдача 1–12, чтение 0–2, текст 500–8 000; фильтры/инструкции и реальные существующие квоты | Значения, единицы, диагностическое поле запроса и результат |
| Изображения | Разрешённый профиль/модель, пресеты, очередь/квоты, инструкция | Готовность, проверенные размеры, тестовое задание; основные поля не спрятаны |
| Подключения | Ключи, адреса, discovery и профиль оборудования | Сохранён/включён/проверен/готов — независимые статусы |
| Обзор | Период, модели, инструменты, исходы | Parent requests отдельно от calls/jobs; unknown отдельно от нуля |

Пример компактной строки каталога: `Чтение страниц | [вкл] | Готов | Наследуется для класса | Ограничения · Проверить`. По нажатию — назначение, аргументы/результат, ограничения, пример и диагностика. Toggle меняет разрешение, а не readiness. «Проверить» вызывает тот же исполнитель и policy; потенциальная стоимость показывается до вызова. Сохранение само не расходует API/GPU.

Отдельные teacher-настройки находятся в области конкретного класса/задания, а не дают преподавателю глобальный admin UI. Преподаватель только сужает верхнюю политику; чужой класс, ключи, URL и global model catalog недоступны. StudentSeat не требует создания фиктивного Account. Все изменения защищены серверными grants, CAS и аудитом; старый таб не затирает новую конфигурацию.

Поиск и чтение — разные переключатели: при разрешённом чтении можно анализировать явную публичную ссылку без обязательного поиска, если этот режим явно допущен политикой. Пользовательский режим «Интернет выключен» запрещает оба внешних действия на запросе. Наследование старой web policy сохраняется при переходе к отдельным полям; lower scope не может его обойти.

## 12. Системный промпт и переменные

Слои запроса: неизменяемые серверные ограничения → редактируемое поведение администратора → разрешённый runtime-контекст → фактические tool definitions → история/вопрос → результаты вызовов. Адаптер размещает эти части в предусмотренных полях API. Вложение/страница/summary не становятся доверенной инструкцией, а текст `{{tools}}` не заменяет `tools` в запросе API.

Краткая основа: «Отвечай по существу и на языке пользователя. Для задачи с файлом создай законченный доступный результат. Пользуйся доступными инструментами. Свежие утверждения подтверждай источниками. Не сообщай о выполнении, просмотре картинки или запуске кода без соответствующего результата. Уважай запреты; при ошибке сохрани полезную работу». Конкретные правила выбора находятся в карточках, а критические ограничения — в сервере независимо от редактора.

Используются зарегистрированные ключи существующего `AI_PROMPT_VARIABLES`:

| Переменная | Реальное значение/источник в исследованном коде | Требование к отображению |
| --- | --- | --- |
| `{{current_datetime}}` | Серверный момент в поясе собственного профиля; fallback UTC | Показать источник и момент снимка; не называть временем ПК |
| `{{current_date}}` | Та же временная основа | Дата соответствует тому же snapshot |
| `{{timezone}}` | Собственный Account; для Seat текущий fallback UTC | Известное значение и причина fallback |
| `{{display_name}}` | Собственный Account либо свой Seat | Реальное имя/«Не указано», не демо-человек |
| `{{gender}}` | Сейчас «Не указано»: канонического поля нет | Не выводить из имени |
| `{{location}}` | Сейчас «Не предоставлено» | Не угадывать по IP или стране регистрации |
| `{{capabilities}}` | Runtime-возможности текущего запроса | Устранить устаревшие фразы, builder должен соответствовать offered tools |
| `{{tools}}` | Серверное описание вызываемых/выполненных действий | Название, назначение, форма вызова, результат и причина недоступности |
| `{{materials}}` | Реально переданные сообщения/вложения/evidence | Не объявлять доступ ко всей CRM или репозиторию |

`{{name}}` из примеров обозначает синтаксис переменной, а не автоматически существующий ключ: для имени зарегистрирован `display_name`. Неизвестные ключи и варианты с пробелами обрабатываются единым parser/builder по R24. UI не придумывает подстановку, которой нет в runtime. Preview не делает inference и равен request snapshot при фиксированном времени/контексте.

Возле каждой строки — информационная иконка, доступная hover/focus/touch: назначение, источник, момент/область, пример фактического значения и передаётся ли модели. Под редактором — полная информационная панель со связями «выбор → допуск → исполнение → результат», без второй редактируемой копии реестра. Расширение персонального/учебного контекста следует R33 и существующим grants; весь профиль, IP и CRM автоматически не подставляются.

## 13. Файлы, Vision и будущие возможности

PDF/DOCX/XLSX и сжатие изображений остаются существующими input pipelines. Для них обязательно явное покрытие, адресуемый оригинал и поддерживаемая модальность; скан не считается прочитанным по имени. Микрофон — вход, не постоянное прослушивание и не фиктивный tool call. Ресурсы имеют те же owner/scope и участвуют в отзыве доступа.

Канонические файлы/версии остаются на сервере; IndexedDB может быть только отдельно согласованным черновиком/кэшем. Закрытие браузера не должно разрушать принятую серверную работу. Чтение репозитория, OCR-инструмент, отдельный inspect-preview, презентации и 3D не рекламируются модели до появления их исполнителя и приёмки. Будущая карточка «Скоро» не расходует API и не попадает в offered tools.

## 14. Приёмка и совместимость

| Свойство | Существующие требования/задачи | Проверяемый результат |
| --- | --- | --- |
| Все маршруты/continuation | R01–R02; ASAI-21–24 | Одинаковый сценарий через реальный допустимый маршрут; Polza отдельно от прямого API |
| Поток и действия | R03–R05; ASAI-15–16; C03–C05 | Первый delta до done, виден реальный tool stage, cancel/replay без дубля |
| Поиск/картинки | R06–R08; ASAI-19–20; C02/C06–C09 | Прочитаны выбранные источники; пригодная картинка после восьмого результата не потеряна |
| Погода | R09; ASAI-41 | Другой пояс/завтра/одноимённый город, нет подмены периода |
| Рабочие файлы/preview | R02/R16; C13/C15/C16 | Новая версия того же ID, реальные ресурсы, открытие/скачивание, уровни проверки различены |
| Админка/контекст | R19/R22/R24; ASAI-04–05/13–14; C17/C19/C21 | Отдельные переключатели, реальный preview, серверный deny, CAS без потери draft |
| Утечки/неизвестные исходы | R02/R05/R28 | Private URL/owner подмена отклонены; мутация после timeout не повторена |

Fixture-сценарии исходов фиксируются до live-запуска, а не оцениваются по словам модели. Для критической композиции проверяются четыре ветки: найденные картинки; разрешённый fallback; запрет генерации; конфликт файла после принятого job. Дополнительно два таба, переключение модели после ошибки, потеря SSE, двойной request ID и отозванный scope. Сохраняются точный SHA, route/model, policy revision и связь operation/call/file/job.

Для документации запускается из корня:

```bash
node docs/product/ai/research/2026-11-02/contracts/verify.mjs
```

Команда проверяет Draft 2020-12 schema, положительные/отрицательные примеры и покрытие восьми имён. Она **не проверяет** серверные права, DNS, семантику dates/digests, работу провайдеров или браузера. Структурная HTTPS-строка может вести на приватный адрес: admission обязателен отдельно. Публичная схема не является защитой сама по себе.

До реализации адаптер переводит существующие DTO в новое представление без смены endpoint и потери старых данных. Старые журналы с отсутствующим полем получают `unknown`, а не выдуманное значение. Введение нового wire API требует отдельной версии и compatibility tests. Документирование этих форм не требует миграции рабочих данных.

### Нерешённые доказательством вопросы

Работоспособность конкретного ресурсного transport/CSP, получение реального screenshot из sandbox и UX одинаковых задач в четырёх конкурирующих продуктах остаются не проверены. Они не мешают описать требуемое поведение, но запрещают объявлять соответствующую реализацию или сравнительное превосходство доказанными. Этот документ не заменяет такие проверки утверждением «всё работает».
