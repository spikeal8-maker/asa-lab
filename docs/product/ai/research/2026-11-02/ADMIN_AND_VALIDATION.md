# Проект админки, полномочий и приёмки инструментов

[Исследование](README.md) · [Контракты](TOOL_CONTRACTS.md) · [Действующее ТЗ](../../../ASA_AI_ASSISTANT_SPEC.md)

**Проект для рассмотрения, не внедрённый интерфейс.** Порядок разделов, существующие R/C и каталог ASAI сохраняются. Эта записка не создаёт второе состояние задач и не даёт разрешения исполнять все перечисленные изменения подряд.

Конкретные поля переключателей, происхождение вызова, зарегистрированные переменные и переходы описаны в [RUNTIME_SPEC.md](RUNTIME_SPEC.md), разделы 3 и 10–12. Эта записка дополняет их UX-обоснованием и матрицей отказов; не вводит другую версию протокола.

## 1. Компоновка админки

Верхний уровень по уточнению владельца: **Обзор → Настройки → Подключения → Системный промпт → Инструменты → Изображения**. «Инструменты» заменяет «Интернет-поиск»; старые ссылки `section=internet` открывают новый раздел. Внутри — восемь вкладок канонического каталога. В «Настройках» находятся компактные главные переключатели восьми инструментов, модели, бюджеты и доступ сетевых сервисов. Во вкладке «Инструменты» — состояние, инструкция и точные параметры выбранного инструмента, без повторного выключателя. «Изображения» сохраняет подключение генератора и тестовый запуск.

У сетевых инструментов пока общие доступ в интернет, часовой лимит, доменные фильтры и инструкция по найденным источникам. Форма явно сообщает об общей области действия; интерфейс не обещает независимые значения. Черновики сохраняются при переключении вкладок инструментов; уход из раздела с изменениями требует подтверждения. Отсутствующие серверные параметры не имитируются редактируемыми полями. Численные настройки файлов остаются отдельной работой. Область «Проверить» выполняет настоящий запрос через выбранную модель, обычные admission, лимиты и исполнитель чата; это проверка всей цепочки, а не детерминированный прямой вызов в обход модели. Отсутствие события выбранного инструмента не считается успешной проверкой. Пустая выдача, неизвестный исход и готовое изображение различаются. Работа генератора считается завершённой только по терминальному состоянию его квитанции. Проверки используют собственный диагностический диалог администратора, поэтому созданный файл можно затем прочитать или изменить. После потери потока производится только чтение сохранённого результата; автоматической повторной отправки нет. Облачная стоимость обозначается до запуска; сохранение конфигурации не запускает проверку.

| Раздел | Главная задача | Что не помещать сюда |
| --- | --- | --- |
| Обзор | Использование, реальные модели/инструменты, готовность, ошибки | Редактирование секретов или длинную инструкцию |
| Настройки | Порядок моделей, default, доступ, бюджеты, главные переключатели инструментов | Объявление не подключённых моделей рабочими |
| Подключения | Адреса, ключи, профили, обнаружение и тест связи | Дублирующий выбор доступа всем ученикам |
| Системный промпт | Поведение, язык, стиль, переменные и просмотр контекста | Сырые ключи, ручной список несуществующих функций |
| Инструменты | Точные параметры, инструкции, фильтры и проверка работы через чат | Ключи текстовых провайдеров и неработающие настройки |
| Изображения | Генератор, разрешённые модели/размеры и тестовое задание | Автоматическое подключение новой платной услуги |

Формы не прячут базовые параметры в цепочки «открой → ещё открой». Поля сгруппированы по действиям пользователя. Сложная техническая диагностика отделена от настройки, но её статус виден сразу. Сохранение не обязано выполнять платный probe; запись конфигурации и результат проверки отображаются независимо.

## 2. Каталог инструментов

Одна строка/карточка на инструмент:

```text
[вкл] Чтение страниц                  Работает · проверено 14:32
Модель выбирает страницы из выдачи или открывает ссылку пользователя.
Доступ: Ученики, преподаватели       [Ограничения] [Проверить]
```

Состояния: **Выключено / Готов / Нужна настройка / Недоступен / Не проверен / Проверка устарела**. «Включено» не означает «проверено и готово». Рядом показывается конкретная зависимость: например, генератор не готов или выбранный маршрут не поддерживает Vision. Успешное сохранение — отдельное короткое уведомление, а не переименование readiness.

Открытая карточка содержит:

1. Что делает и когда модель выбирает инструмент; 2–3 человеческих примера.
2. Что получает на входе и возвращает; пример успеха, пустого и частичного результата.
3. Разрешённые роли/scope и наследование.
4. Ограничения, повторы, отмену и зависимости.
5. Короткую дополнительную инструкцию для модели и её предварительный просмотр.
6. Безопасный диагностический запуск и результат с проверенными фактами.

Системные ограничения не становятся редактируемой строкой промпта. Администратор может изменить совет по выбору источников, но не отключить через текст SSRF-проверку, чужую область доступа, фильтрацию исполняемого SVG или контроль идемпотентности.

Кнопка «Проверить» должна заранее показывать, будет ли внешний/потенциально платный вызов. Отладочные примеры не содержат персональные данные. Результат показывает маршрут, время, проверенные возможности и обезличенный код диагностики; секреты и полный сырой ответ не раскрываются.

## 3. Администратор и преподаватель

| Уровень | Разрешённое управление | Ограничение |
| --- | --- | --- |
| Платформа/уполномоченный администратор | Глобальные tools, зависимости, максимумы, категории, маршруты | Только в пределах своих существующих grants |
| Организация | Допустимое подмножество и квоты своей области | Не расширяет глобальный deny |
| Преподаватель класса | Разрешить/запретить инструменты своего класса/задания, сузить лимиты | Не меняет ключи, чужие классы и глобальные профили |
| Индивидуальная учебная область | Дополнительное ограничение для конкретного Seat при наличии полномочия | Не требует искусственного создания Account или смены глобальной роли |
| Пользователь | Выбор доступной модели, выключение интернет-поиска для своего запроса | Не включает запрещённый сверху инструмент |

Эффективный доступ — пересечение применимых политик, grants и технической готовности. Отсутствующая настройка наследует явно определённое значение; недействительная область запрещается. Не следует превращать отсутствие capability-метаданных в утверждение «не поддерживает»: возможен статус «не проверено».

В UI преподавателя — простой список переключателей и причина заблокированного значения: «Отключено администратором», «Недоступно для этого задания». Один инструмент не получает отдельную копию настроек с другой семантикой в каждом классе. Endpoint проверяет scope на сервере, а не доверяет скрытой кнопке.

Изменение политики во время операции: новый ещё не начатый вызов проходит актуальную проверку. Уже принятое внешнее задание сверяется и по возможности отменяется; нельзя обещать возврат затрат. Версия политики при допуске сохраняется для аудита. Утрата прав блокирует чтение результата независимо от старого снимка интерфейса.

## 4. Системный промпт

Основной редактор содержит поведение: краткость, язык, оформление, честность, правила работы с материалами. Длинный изменяемый список инструментов вручную сюда не вставляется. Под редактором — спокойная информационная панель с четырьмя небольшими блоками:

- **Как действует бот:** выбирает инструмент → система проверяет → возвращает результат → бот продолжает.
- **Доступные сейчас действия:** вычисленный список для выбранной роли/scope/модели, со ссылкой на полную карточку каждого.
- **Переменные:** значение, источник, актуальность, видимость и пример подстановки.
- **Предпросмотр контекста:** текст, который реально сформируется при запросе, с версиями промпта/политики и причинами недоступности.

Переменные перечислены компактными строками с информационной иконкой; описание доступно по наведению, клавиатурному фокусу и нажатию на телефоне. Полное описание есть и в информационной панели, а не только в недоступном tooltip.

| Группа переменных | Что объяснять рядом | Правило |
| --- | --- | --- |
| Дата/время сервера | Источник UTC, пример, время вычисления | Не называть временем компьютера пользователя |
| Часовой пояс пользователя | Значение, получено из профиля/браузера или неизвестно | Не выводить геопозицию из одного timezone |
| Локальная дата/время | Преобразование серверного момента в известный пояс | Явный fallback, без выдуманного пояса |
| Имя/язык профиля | Конкретное значение текущей тестовой персоны | Не отправлять всю CRM автоматически |
| Учебный контекст | Класс, роль/Seat, курс, доступные результаты | Только необходимый и разрешённый scope |
| Геопозиция | Указанный город или предоставленные координаты, источник/согласие | Не обещать точность и не делать скрытую IP-геолокацию |
| Доступные инструменты | Вычисленный manifest текущего запроса | Только допущенные схемы и реальные зависимости |
| Активный файл | ID/название/версия выбранной работы | Не все приватные файлы пользователя сразу |

Пол, аватар, IP, устройство и полная история проектов/курсов не включаются «потому что известны». Для каждого поля отдельно определяются полезность, полномочие и минимальный объём. Технические данные IP/device по умолчанию остаются диагностикой, а не персонализацией промпта. Просмотр от лица ученика требует действующего права; нельзя произвольно выбирать чужую личность.

Дополнительные инструкции конкретного инструмента хранятся в его карточке. Реестр отдаёт их вместе с описанием, а исполнитель сохраняет критические проверки независимо от текста. В preview явно видно: основной промпт, runtime-контекст, определения tools и недоверенные материалы — разные части запроса.

### Пример короткой поведенческой основы

> Отвечай по существу, на языке пользователя. Короткий вопрос обычно требует короткого ответа; для задачи с кодом или файлом создай законченный результат. Пользуйся доступными инструментами, когда нужны свежие данные или действие. Проверяй существенные утверждения по полученным материалам. Не сообщай о выполнении без успешного результата инструмента. Не выдумывай просмотр пикселей или запуск кода. Уважай выключенные функции. При сбое сохрани полезную работу и предложи продолжение доступным способом.

Это проект текста, не новая опубликованная конфигурация. Краткость не должна означать жёсткое обрезание кода. Предел ответа, предел контекста, thinking budget и месячная квота — разные параметры.

## 5. Интернет-поиск: настройки качества

Первая видимая группа — **Как ищет бот**: количество результатов, максимум поисковых обращений, максимум читаемых страниц, текст с одной страницы. Ниже — источники/фильтры и отдельное диагностическое окно. Единицы и влияние объясняются одной строкой, без большого текста над каждым полем.

Фактические пределы исследованного кода, а не новые рекомендации:

| Поле | Допустимый диапазон | Значение при отсутствии настройки |
| --- | --- | --- |
| Результатов поиска | 1–12 | 8 |
| Читаемых страниц | 0–2 | 2 |
| Текста страницы, символов | 500–8 000 | 4 500 |

Основание: [валидация конфигурации в AiWebSearchService](https://github.com/spikeal8-maker/asa-lab/blob/6e6a6e603d7c630f967dd66c20262e3d75e35b0a/apps/api/src/ai-web-search.ts#L316). Это ограничения кода, не подтверждённые значения базы test.asa-lab.ru и не гарантия полного расходования всех границ каждым запросом.

Предложенные в первой редакции профили «Быстро / Обычно / Подробно» сняты: они выходили за текущие пределы, не опирались на замеры и не были согласованы с общим бюджетом шагов. Сначала измеряются действующие настройки; увеличение границ — отдельное решение. Число символов не называется числом токенов. Повторы чтения также должны ограничиваться числом попыток, иначе лимит «различных страниц» легко обходится.

Для изображений действуют отдельные R08: до 8 текстовых источников, 6 миниатюр, просмотр до 32 результатов. Настройка длины текстовой выдачи не должна уменьшать пространство отбора картинок. Составной запрос с изображениями расходует общий бюджет, но возвращает разные типы результатов.

Дополнительные поля: язык/регион, свежесть, предпочтительные/разрешённые/исключённые домены, SafeSearch, timeout, поведение при пустом результате. Эти поля фильтруют, но не обещают абсолютной достоверности и безопасности внешнего интернета. Цены и списки платных поисковых продуктов в настройку не добавляются.

Диагностика содержит поле запроса и переключение «Поиск / Чтение ссылки / Картинки / Погода». Она показывает фактические кандидаты, выбранные страницы, время, неполноту и количество вызовов. Отдельно видны «найдено поисковиком», «прочитано» и «проверены пиксели». Тест использует тот же исполнитель и политику, что чат, а не специальную всегда успешную заглушку.

## 6. Подключения, модели и бюджеты

В Подключениях выбирается допущенный в ASA каталог провайдера; в Настройках — доступ пользователям, default и порядок. Отключённый/не настроенный провайдер не занимает рабочую строку списка моделей. Историческая модель не исчезает из старых сообщений. Ошибка discovery показывает последний успешный snapshot как устаревший, а не свежий выдуманный список.

Провайдер — компактная горизонтальная группа; внутри модели и их порядок, переключатели доступа и краткие capability-метки. Для перестановки нужны drag handle и доступные стрелки/клавиатура. В чате показывается имя модели, а не обязательный бренд посредника. «Vision», «tools», streaming, контекст и thinking относятся к конкретному model/route, а не к провайдеру целиком.

Месячные бюджеты помещаются в собственную компактную секцию: общий бюджет модели и отдельный на пользователя, период и часовой пояс, использовано/остаток или «неизвестно». Требование владельца сохраняется: начатый ответ завершается, затем новые запросы блокируются. Это мягкая граница, возможен перерасход на уже принятые операции; строгий финансовый потолок — отдельная семантика. Учёт параллельных admission и незавершённых запросов проектируется явно, без ложного обещания точного остатка.

В пользовательском composer нет постоянно занимающей место полосы токенов. Исчерпанная/недоступная модель даёт короткое сообщение; выбор доступной модели убирает текущую ошибку без перезагрузки. Черновик, файлы и уже выполненные результаты сохраняются.

## 7. Обзор и пользовательская активность

Обзор показывает пользовательские запросы отдельно от дочерних вызовов, модельные токены отдельно от tool usage, реальные success/failed/cancelled/pending и неизвестные величины. Фильтры периода, timezone, модели и инструмента согласованы для графика и таблицы.

Поисковые вызовы, чтение страниц, погода, image search и генерация изображений учитываются отдельно. Легенда графика позволяет включать/выключать модели цветом, но значения доступны и в таблице. Инфраструктурная readiness отображается рядом с последней проверкой, не вычисляется из одного флага enabled.

В чате — короткие серые строки активности с небольшим отступом: «Ищу в интернете», «Читаю страницу», «Подбираю изображения», «Обновляю файл». Строка появляется из фактического события. Аргументы с приватными данными не светятся в activity; подробная безопасная трасса доступна только уполномоченному администратору. Генерация картинки показывает место будущего изображения, модель/размер/промпт и живой индикатор согласно возможностям backend. `prefers-reduced-motion` обязателен.

Ошибки пользователю: «Извините, текстовая модель сейчас недоступна. Можно выбрать другую»; «Генератор изображений сейчас недоступен». Никаких ключей, балансов, traceback и внутренних адресов. Однако ошибки ввода и отказ прав не надо ложно называть поломкой модели: «Этот файл пока не поддерживается» и «Инструмент недоступен в этом задании» точнее. Полезный частичный результат остаётся видимым.

## 8. Решение о временных файлах

**Baseline — существующие приватные серверные файлы, owner, версии и ссылки сообщений по R11/R16.** Их перенос в браузер не выбран. Перед любым изменением сравнить три варианта: серверное хранение; сервер плюс локальный кэш; явно локальная временная работа. Проверить восстановление, две вкладки, другое устройство, закрытие браузера, удаление и экспорт. Только после этого возможно отдельное ADR. Для браузерного варианта предстоит решить:

- Байты временной работы и версии — локальный workspace IndexedDB с изоляцией владельца.
- В запрос передаётся только выбранная версия/диапазон и необходимые ресурсы.
- Сервер хранит минимальные квитанции операций, права, расход и сведения для сверки неизвестного исхода, с документированным TTL.
- Явное «Сохранить в аккаунт» сохраняет результат по существующей модели доступа; старые серверные файлы продолжают читаться.
- Экспорт доступен до очистки; logout/смена владельца закрывает доступ и очищает приватные данные в памяти. Политика удаления IndexedDB должна быть явной и не уничтожать несохранённую работу молча.
- Закрытый/недоступный браузер не изображает доступный workspace. Вторая вкладка проверяет версии и лидерство изменения, а не перезаписывает файл.

Без такого решения нельзя одновременно обещать «ничего не хранится на сервере», долговечную историю и автоматическое продолжение работы на другом устройстве. Серверный журнал ID не должен становиться скрытой бессрочной копией текста. Неизвестный срок хранения — открытый вопрос, а не уже установленный default.

## 9. Проверки: что означает качество

### 9.1. Уровни доказательств

| Уровень | Проверяемый факт | Недостаточное доказательство |
| --- | --- | --- |
| Контракт | Схема, policy, ограничения, состояние, replay | Только красивое описание |
| Adapter | Реальная последовательность сообщений конкретного маршрута | Один парсер JSON без продолжения после tools |
| Integration | Составная операция с реальными ресурсами/версиями | Возвращённый текст «готово» |
| Browser | Видимый результат, действия, доступность, восстановление | API 200 или screenshot заглушки |
| Live provider | Реальный настроенный маршрут и зафиксированный расход | Тест другого провайдера под тем же названием |
| Owner acceptance | Владелец проверил конкретную версию | Зелёный CI без просмотра |

### 9.2. Матрица обязательных сценариев

| Сценарий | Ожидаемый результат |
| --- | --- |
| Tools предложены, но не нужны | Ответ идёт настоящими дельтами, без ожидания полного текста |
| Несколько readonly calls в одном ответе | Все допустимые вызовы получают результаты с правильными ID; порядок не теряется |
| Поиск → выбранная страница → ответ | Сниппет и чтение различимы, ссылки соответствуют использованным материалам |
| Пустой поиск → уточнение запроса | Ограниченное осмысленное изменение запроса; конечный исход при исчерпании |
| Ссылка пользователя на страницу с картинками | Получены текст и image-кандидаты; Vision-вывод только после пикселей |
| Страница отдаёт 403/CAPTCHA | Никакого обхода или фиктивного прочтения; можно выбрать иной публичный источник |
| Redirect/DNS на приватный адрес, подмена MIME, zip bomb | Отказ до доступа/распаковки сверх предела |
| Инструкция внешней страницы требует секрет/вызов tools | Не меняет полномочия и системные инструкции |
| Картинка найдена после восьмого результата | Не теряется из-за текстового лимита, галерея показывает декодированные пиксели |
| Миниатюра доступна, оригинал сломан | Нет подмены оригинала; остальные изображения работают |
| Модель без Vision + изображения | Галерея доступна, анализа пикселей не заявлено, выбор другой модели без reload |
| Погода завтра в другом поясе | Правильный период/место/единицы; отсутствие периода честно обозначено |
| Сайт с найденными картинками | Поиск первым; реальные ресурсы в HTML, предпросмотр и скачиваемый файл |
| Поиск пуст и генерация разрешена | Генерация как fallback, затем ресурс привязан к текущей версии сайта |
| «Не генерируй» при пустом поиске | Новое задание не запускается |
| Два изображения подряд | Раздельные квитанции/стадии/результаты; нет дублей или вечного ожидания |
| Timeout после принятия внешнего задания | Сверка job ID; без повторной оплаты/запуска |
| «Добавь эту картинку в тот сайт» | Прочитан нужный файл, новая версия того же ID, видимый обновлённый результат |
| Две вкладки изменяют одну версию | CAS-конфликт без потери чужого изменения |
| Stop между инструментами | Следующий вызов не начинается; черновик остаётся доступен |
| Обрыв SSE/reload во время операции | Сверка состояния, нет повторного внешнего действия и дублирования текста |
| Провайдер вернул malformed call, rate limit или 500 | Ограниченный repair/retry; безопасное сообщение, ввод не зависает |
| DeepSeek thinking + несколько tool rounds | Служебное продолжение сохранено; не показано пользователю |
| Отключённый инструмент/смена scope/чужой file ID | Серверный отказ независимо от клиентского списка |
| PDF-скан, DOCX-таблица, XLSX с несколькими листами | Реальные данные/покрытие; OCR и отсутствие значений не маскируются |
| HTML пытается прочитать cookies/storage родителя | Изоляция сохранена; игра/кнопки при этом работают в разрешённых пределах |
| Preview сообщает успех без runtime/screenshot | Не получает отметку визуальной проверки |
| Исчерпана квота, затем выбрана другая модель | Завершённый ответ не обрезан; текущая ошибка исчезает, файлы сохранены |
| Микрофон: deny/cancel/stop/send | Правильный lifecycle, реальная waveform, никаких лишних диалогов продукта |

Одна функциональность проходит одинаковые сценарии на всех реально подключённых маршрутах, где она применима. Возможность Vision, выбор инструмента, продолжение после вызова и streaming — отдельные столбцы. Падение одной облачной модели не выдаётся за отсутствие инструмента у всех. Неизвестные capabilities остаются неизвестными до проверки.

Адаптеры получают общий набор записанных обезличенных fixtures: аргументы по частям, два вызова с разными индексами, text плюс call, неизвестное имя, незакрытый JSON на конце потока, ошибка после уже показанного текста, повтор результата и служебный контекст продолжения. Отдельно проверяются native route и fallback planner: последний принимает только закрытую схему разрешённого плана и не исполняет команды из обычного текста ответа. Успех fixture не заменяет короткий live smoke test конкретного провайдера.

Матрица маршрута хранит поля `discovered / configured / allowed / probed / stale`, а capability — `supported / unsupported / unknown` с основанием и датой. Поддержка инструментов без проверенного многотурового продолжения не получает отметку полной совместимости. Новое имя модели в list API не означает автоматического разрешения пользователям.

### 9.3. Измерения и сравнение

Сначала воспроизводятся критические сценарии владельца: сайт с найденными картинками, правка того же файла, генерация как допустимый fallback и продолжение после ошибки без reload. Затем добавляется детерминированная fault suite и остальные строки матрицы. Для каждой задачи заданы необходимые/запрещённые действия, артефакт, допустимый расход и критерии результата. Сохраняются модель/route revision, версия политики/реестра, SHA, время, сеть и аппаратный профиль. Live-проверки требуют отдельного бюджета; исследование его не расходует.

Предписание «100 задач × 3 прогона на маршрут» из первой редакции снято: объём и стоимость выборки не оценены. Число повторов и порог качества выбираются после пилота по изменчивости исходов и цене ошибки, а не из круглых чисел.

Предлагаемые критерии для будущего согласования:

- **Ноль нарушений** доступа, утечек секретов и повторных внешних мутаций при replay в определённом fault-наборе. Это критерий набора, не доказательство невозможности всех ошибок.
- Доля успешных составных задач, ложных «готово» и неверного выбора инструмента измеряются отдельно. Новый порог процентов здесь не установлен: прежние 95% не имели экспериментального обоснования. Результат публикуется с размером выборки и интервалами неопределённости; действующие критерии R/C сохраняются.
- **Ноль необходимых reload** для восстановления проверенных отказов при живой сессии; ни один черновик не потерян в заданных сценариях.
- Streaming проверяется барьерами событий: первый содержательный фрагмент виден до конца генерации. Существующая проектная граница накладной задержки R03 сохраняется, а не заменяется произвольным TTFT.
- TTFT, p50/p95 полного времени, количество поисков/чтений, токены и расходы измеряются отдельно. Неизвестный расход не считается нулевым.
- UI: 1440/390 px, светлая/тёмная тема; меню/composer также 320 px. Клавиатура, touch, reduced motion, работа с длинными именами и повторной отправкой.

Сравнение с конкурентами требует одинаковых задач и условий, учёта разных лимитов/моделей/стоимости и проверки результата человеком или независимым валидатором. Продуктовые UI и API framework нельзя объединять в один рейтинг. Пока таких запусков нет, допустима формулировка «спроектировано по результатам исследования», но не «работает лучше ChatGPT/Claude».

Трассы для анализа обезличиваются: ID/стадия/время/класс ошибки, по необходимости редактированные вход/выход. Студенческие документы не отправляются стороннему LLM-судье автоматически. Для оценки указывать критерии, а не просить модель произвольно поставить себе оценку.

## 10. Порядок дальнейшей работы

Это зависимости проектных изменений, **не новая executable очередь и не обещание начать её сейчас**. Контролёр сопоставляет их с существующими ASAI/R и отдельно выбирает один срез.

| Зависимость | Результат ограниченного среза | До следующего шага |
| --- | --- | --- |
| Контракт реестра и inventory | Все реальные функции, версии, зависимости, полномочия, generated docs | Тест соответствия схем, admin inventory и runtime |
| Adapter/loop/recovery | Смешанные допустимые вызовы, continuation, конечные исходы и replay | Fault-набор и настоящая streaming-проверка |
| Каталог и prompt preview | Понятное включение/отключение, эффективный контекст, scope | Браузерная приёмка администратора и преподавателя |
| Поиск и составные артефакты | Поиск → выбранное чтение → ресурсы → файл → проверка | Реальные сайты/картинки, источники, скачивание |
| Preview и локальные workspace | Изоляция, проверка заявленного уровня, ADR хранения/миграции | Negatives, две вкладки, сохранность старых файлов |
| Визуальная доводка и измерения | Компактные activity/weather/image states, сопоставимые результаты | Owner acceptance точного SHA |

Презентации, 3D и доступ к репозиторию не включаются в этот цикл автоматически. Исправление чужих модулей ради зелёного общего CI также не разрешается этим планом.

Публикация документации, реализация, успешный CI, попадание в main, выпуск образов, обновление test и приёмка владельца — отдельные факты. Документация должна быть отправлена в GitHub; локальный файл или Docker preview не заменяет публикацию. Этот исследовательский срез не обновляет серверы и не меняет рабочую базу.
