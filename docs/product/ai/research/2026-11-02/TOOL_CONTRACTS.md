# Проект контрактов инструментов ASA

[Исследование и первоисточники](README.md) · [Админка и приёмка](ADMIN_AND_VALIDATION.md) · [Действующее ТЗ](../../../ASA_AI_ASSISTANT_SPEC.md)

Все новые контракты и пределы ниже — **предложения для согласования и испытаний**, а не описание уже работающего API. Существующие имена сохраняются, если нет необходимости в совместимом версионировании. Документ развивает R01–R16 и R24, не отменяя их.

Этот документ объясняет назначение и развитие инструментов. Точные формы проекта, переходы состояний и границы совместимости вынесены в [RUNTIME_SPEC.md](RUNTIME_SPEC.md), [JSON Schema](contracts/tool-runtime.schema.json) и [примеры](contracts/examples.json). Дополнительные параметры вроде диапазонов, языка поиска и числа изображений ниже описывают направление развития/серверную конфигурацию, а не автоматически существующие поля model-call v1. К runtime эти схемы пока не подключены.

## 1. Полный каталог и границы

| Группа | Инструмент | Что делает | Чего не обещает |
| --- | --- | --- | --- |
| Внешние сведения | `web_search` | Находит кандидатов по запросу | Что каждый источник прочитан и сведения верны |
| Внешние сведения | `read_page` | Извлекает разрешённую публичную страницу | Вход в аккаунты, обход блокировки, полноценный браузер |
| Изображения | `image_search` | Находит и проверяет доступность изображений | Что текстовая модель увидела пиксели или разрешено любое использование |
| Данные | `weather` | Возвращает реальные погодные данные для места и периода | Собственный метеопрогноз или глобальное покрытие без исключений |
| Создание | `generate_image` | Создаёт новое изображение выбранным разрешённым генератором | Редактирование прежних пикселей, если профиль этого не умеет |
| Рабочие файлы | `create_working_file` | Создаёт файл и первую версию | Что код безопасен и визуально проверен |
| Рабочие файлы | `read_working_file` | Читает определённую версию/диапазон | Доступ к файловой системе пользователя или сервера |
| Рабочие файлы | `edit_working_file` | Применяет проверенное изменение к ожидаемой версии | Успех при конфликте или не найденном участке |

Эти восемь имён присутствуют в исследованном коде. Следующие возможности требуют отдельного решения о форме API; их нельзя рекламировать модели как готовые:

| Кандидат | Назначение | Условие появления в каталоге |
| --- | --- | --- |
| `read_attachment` | Выбор страниц PDF, разделов DOCX, листов/диапазонов XLSX после извлечения | Выбранные пользователем файлы, корректные индексы и явная информация о неполноте |
| `inspect_image` | Отправка проверенного изображения модели с Vision | Поддерживаемая модальность выбранного маршрута, бюджет и право на ресурс |
| `inspect_preview` | Проверка HTML/SVG по структуре, runtime или скриншоту | Реальный изолированный исполнитель соответствующего уровня, а не одна декларация |
| Инструмент презентаций | Структура слайдов, ресурсы, экспорт PPTX | Отдельная продуктовая карточка, редактор/рендер и тест экспорта |
| Инструмент 3D | Создание и проверка модели GLB/STL | Изолированный процесс, проверка геометрии и предпросмотр |
| Чтение репозитория | Поиск/чтение разрешённой версии исходного кода | Отдельный read-only scope, исключение секретов, лицензий и закрытых данных |

Микрофон/транскрибация, клиентское сжатие, загрузка, просмотр, скачивание, копирование и выбор версии — связанные возможности интерфейса. Они тоже управляются политиками, но не получают фиктивные tool calls только ради увеличения списка.

## 2. Общий контракт

### Определение

Для каждого инструмента хранить: `id`, `schemaVersion`, публичное название, назначение, когда использовать/не использовать, типизированные аргументы и результат, примеры, необходимые grants, модальности, зависимости, лимиты, timeout, тип эффекта и правила повтора/отмены. Описание для модели короткое; полное описание доступно администратору.

Три класса эффектов:

- **Чтение:** поиск, страница, погода, чтение файла. Может расходовать бюджет, хотя не меняет файл.
- **Локальное/облачное изменение:** создание и редактирование версии. Требует identity, CAS и квитанции результата.
- **Внешнее задание:** генерация изображения. Принятие, завершение и фактический расход могут происходить отдельно.

### Результат

Полная форма с привязкой типа к инструменту/исходу находится в `$defs.result` [схемы](contracts/tool-runtime.schema.json). Используется один набор имён `contractVersion/name/state/data`; устаревшая иллюстрация с другими именами удалена, чтобы не поддерживать две конкурирующие формы. Положительные и отрицательные примеры находятся в [examples.json](contracts/examples.json).

`success`, `empty`, `partial`, `unavailable`, `denied`, `invalid_arguments`, `rate_limited`, `conflict`, `unknown_outcome`, `cancel_requested`, `cancelled` различаются. Сетевой HTTP 200 сам по себе не означает успех инструмента. Для результата фиксируются provenance, актуальность, неполнота, artifact/version ID и безопасная причина, понятная модели. Секреты и сырые трассы провайдера не возвращаются.

Общие ID owner/scope устанавливает приложение из сессии. Аргумент модели с чужим owner ID не может расширить доступ. `callId` и idempotency key — разные понятия: новый вызов модели не даёт права повторно оплатить ту же внешнюю операцию.

### Повторы и завершение

| Ситуация | Действие | Недопустимое поведение |
| --- | --- | --- |
| Синтаксически неверные аргументы | Один ограниченный шанс модели исправить схему; затем уточнение/конечный отказ | Неограниченный цикл исправлений |
| Пустой поиск | Уточнить формулировку в пределах бюджета, сохранив предмет запроса | Повторять тот же запрос до лимита |
| Временный сетевой сбой чтения | Ограниченный transport retry с общей deadline; учитывать Retry-After | Обходить ограничения другим адресом или скрыто менять сервис |
| Страница не извлеклась | Допустимая альтернативная обработка того же публичного документа либо другой источник | Обход CAPTCHA, авторизации, robots/access policy |
| Неизвестно, принял ли генератор задание | Сверить сохранённый job ID/квитанцию | Автоматически отправить ещё одно платное/GPU-задание |
| Конфликт версии файла | Перечитать актуальную версию и перепланировать изменение | Перезаписать её старым текстом |
| Stop или закрытый браузер | Отменить очередные шаги, запросить остановку начатых, сверить исход | Считать любой Stop подтверждённой отменой внешнего задания |

Единый новый численный бюджет раундов/вызовов в исследовании **не обоснован и не установлен**. Действующие ограничения сохраняются; их инвентаризация должна различать размер пакета, повтор планирования, внешнее чтение, transport retry и долгоживущее задание. Новый бюджет выбирается по измеренным составным сценариям и нагрузке, затем проверяется на согласованность: разрешённый профиль поиска не может обещать больше действий, чем допускает общий предел. Пользователь видит конечную стадию, даже если бюджет шагов исчерпан.

## 3. `web_search`

**Выбор:** актуальные сведения, внешние источники, явно запрошенный поиск. Не нужен для «найди ошибку» в приложенном коде. В режиме пользователя «Выключено» наружу не обращается.

**Вход:** короткий предметный запрос, язык/регион при необходимости, желательная свежесть. Модель не задаёт произвольный URL внутреннего поискового сервера и не отправляет всю историю чата. Административные доменные и возрастные фильтры добавляет исполнитель.

**Результат:** упорядоченные `sourceId`, URL, заголовок, сниппет, известные даты публикации/получения, тип результата. Неизвестная дата остаётся неизвестной. Дубликаты объединяются; рекламный сниппет не объявляется фактом. Модель получает достаточно контекста для выбора страниц, но не автоматически полные тексты всей выдачи.

**Уточнение поиска:** после `empty` допустима переформулировка; после слабой выдачи — уточнение термина или региона; после противоречий — ещё один независимый источник. Каждый новый запрос учитывается отдельно. Нельзя повторно искать секретный фрагмент документа наружу без разрешённого основания.

**Админка:** число возвращаемых результатов, число поисковых обращений на запрос, язык/регион, свежесть, строгий режим безопасного поиска, разрешённые/исключённые домены, время ожидания. «Разрешённые» ограничивают поиск; «предпочтительные» только меняют ранжирование и не являются гарантией проверки фактов. Совпавший deny имеет приоритет. Настройки транспилируются с учётом ограничений конкретного backend.

## 4. `read_page`

**Выбор:** пользователь дал публичную ссылку, либо модель выбрала результат поиска для проверки деталей. Поисковый сниппет не требует автоматически скачивать страницу.

**Вход:** source ID или разрешённый URL, цель чтения/раздел. URL из сообщения не считается доверенным. Проверять схему, DNS/адрес при соединении и redirects, запрет внутренних/служебных сетей, порты, фактический MIME, размер сжатого и распакованного ответа, время и число переходов. Настройка ComfyUI в локальной сети не выдаёт `read_page` доступ в эту сеть.

**Результат:** финальный URL, заголовок, основной текст, идентификаторы фрагментов, ссылки/кандидаты изображений, время получения, статус извлечения и границы покрытия. `partial` сообщает, какие разделы не попали. HTML-инструкции страницы — недоверенные данные, а не системный промпт.

**Повтор:** альтернативный extractor при ошибке формата не превращается в другой внешний адрес; повтор не отменяет сетевую политику. Динамическая страница без извлечённого содержимого даёт «материал не получен», не «страница проанализирована». Браузерный renderer с JavaScript — отдельная возможность и отдельная граница безопасности, не скрытый fallback.

**Админка:** максимум различных страниц и всех попыток чтения на запрос, текст с одной страницы в символах, общий объём извлечения, timeout. Повторная обработка того же сохранённого snapshot не расходует новое сетевое чтение, но занимает шаг и контекст. Хранить digest, чтобы не перечитывать бесконечно один документ.

## 5. `image_search` и проверка пикселей

**Выбор:** найти фотографии/картинки/иллюстрации, подобрать ресурсы к сайту. Поиск не заменяется генерацией, если пользователь просит найти. Изображения на странице и отдельный image search — разные источники кандидатов.

**Результат:** image ID, thumbnail и original URL, страница источника, фактически проверенные MIME/байты/размеры, известная лицензия либо «не установлена». Превью не выдаётся за оригинал. Недоступный оригинал не скачивается молча как миниатюра под тем же обещанием.

**Качество выбора:** сначала релевантность заголовка/окружения и техническая пригодность. Затем, если разрешена Vision выбранной модели, получить пиксели разрешённых кандидатов и проверить соответствие. Без Vision честно сообщать уровень отбора «по метаданным»; текстовая модель всё равно может показать и использовать изображения. Это не абсолютная защита от нежелательного контента.

**Фильтры:** SafeSearch, доменные запреты, тип/соотношение сторон, минимальный полезный размер, отбраковка битых/дублирующихся ресурсов; для учебного scope — дополнительные ограничения. Лицензионная пригодность отдельна от тематической: «найдено в интернете» не означает свободного права перепубликации.

**Действующие границы R08 сохраняются:** исходно до 8 текстовых источников, 6 миниатюр, просмотр до 32 результатов. Эти величины независимы. Нельзя прекращать подбор после восьмого кандидата, если пригодный ресурс находится дальше. Изменение границ требует оценки нагрузки.

**UI:** крупная адаптивная галерея, увеличение, аккуратные действия «копировать», «скачать оригинал», «использовать в чате» с подсказками. Метаданные при наведении/фокусе, доступный способ открыть их на телефоне. Размер и вес в подсказке соответствуют реальному выбранному ресурсу. Ошибка одного элемента не скрывает остальные.

## 6. `weather`

**Вход:** место или подтверждённые координаты, период, единицы. Если указан однозначный город, разрешение геопозиции не требуется. Одноимённые населённые пункты уточняются; дубликаты одной географической сущности не создают искусственный выбор.

**Результат:** место и timezone, диапазон доступного прогноза, время данных/получения, текущие и запрошенные значения с единицами и источник. Значения с отсутствующими данными не превращаются в нули. Уточняется, прогноз это или наблюдение; «завтра» вычисляется в поясе места.

**Композиция:** «сравни погоду в двух городах завтра и выбери одежду» допускает два чтения и сравнение. Недоступный период не подменяется текущим. При ошибке модель не выдумывает температуру из памяти.

**UI:** компактная светло-голубая карточка: город/период, погодная пиктограмма, температура, осадки/ветер, строка актуальности и источник. Почасовые подробности по запросу; таблица не раздувает обычный ответ. Иконка/эмодзи дополняет текст и имеет понятное описание. В тёмной теме отдельные токены, без белого меню.

**Админка:** включение, единицы, допустимый горизонт, timeout, квоты, диагностический запрос места. Наличие источника не обещает работу в каждой стране: покрытие и доступность проверяются живыми сценариями. Новый платный погодный API не добавляется.

## 7. `generate_image`

**Выбор:** явная просьба нарисовать/сгенерировать; либо подтверждённая допустимая альтернатива после безрезультатного поиска. Для сайта по умолчанию сначала поиск. Если поиск запрещён или временно недоступен, это не универсальное разрешение автоматически генерировать. Фраза «или сгенерируй» разрешает запасной маршрут, но не меняет приоритет поиска.

**Вход:** промпт на русском для текущего русскоязычного сценария, разрешённый рецепт/model ID, размер, число изображений в пределах политики, роль ресурса в создаваемом файле при наличии. Требования пользователя не теряются при составлении промпта. Внутреннее имя сервера не является публичным именем модели.

**Результат:** сначала квитанция job ID и состояние, после завершения — image ID, разрешение, публичное имя модели, MIME, байты и источник «сгенерировано». Ошибка job возвращается отдельным конечным состоянием. Несколько изображений — несколько учтённых дочерних заданий, а не одна бесконечная анимация.

**Прогресс:** промпт, модель, размер и действительная стадия видны возле будущей картинки. Промпт копируется. Индикатор очереди/исполнения может быть неопределённым; проценты и частичный кадр показываются только при реальных событиях поддерживаемого профиля. Документированная возможность partial images другого API не доказывает её наличие в нашем ComfyUI.

**Граница совместимости:** проверять конкретные recipe/schema/nodes/models и версию backend. Не обещать «все версии ComfyUI». Недоступный профиль имеет объяснимую диагностику в админке; пользователю — краткое сообщение без адресов и финансовых подробностей. Auto выбирает только из доступных, разрешённых и проверенных профилей.

**Админка:** включение, готовность, профиль/модель по умолчанию, разрешённые размеры, число изображений, очередь/параллельность, квоты, prompt-инструкция, тестовое задание с явным учётом расходов. Все ключи и адреса настраиваются в Подключениях, а не дублируются в системном промпте.

## 8. Рабочие файлы: создание → чтение → изменение

### `create_working_file`

Вход: безопасное имя, формат, содержимое, назначение и при необходимости проверенные image ID. Создаётся устойчивая identity файла и версия 1, вычисляется digest. Запрет traversal, размер, owner/scope и разрешённые форматы проверяются до записи. В ответе — реальная ссылка/ID версии и результаты структурной проверки; обещать визуальную проверку нельзя.

HTML с картинками использует ресурсы из проверенного реестра. Для скачивания различать одиночный HTML с доступными ссылками и самодостаточный пакет: защищённая сессионная ссылка не должна выдавать себя за вечный переносимый ресурс. Подготовка автономного пакета требует явной обработки ресурсов и проверки прав использования.

### `read_working_file`

Вход: file ID, версия и диапазон. Ответ: содержимое, язык, версия, digest, фактически прочитанные границы. Большой файл читается частями, а не скрыто обрезается. Перед правкой «добавь это на сайт» модель получает текущую версию выбранного/последнего уместного файла. Если кандидатов несколько и намерение неясно, задаёт уточнение.

### `edit_working_file`

Вход: file ID, ожидаемая версия/digest и ограниченный набор однозначных изменений. Ответ: новая версия, перечень применённых изменений, новый digest и проверки. При отсутствующем/неуникальном участке — никакого частично применённого неопределённого patch. Undo создаёт понятное восстановление версии, не уничтожает историю.

После изменения карточка того же файла обновляется, доступна возле нового ответа и в списке результатов. Фраза «всё добавил» без квитанции новой версии недопустима. Новая версия не обязана печатать весь код повторно. Старый preview не должен закрепляться поверх дальнейшей переписки: обновление и навигация по истории — явные действия.

### Проверка исполнения

Уровни фиксируются отдельно:

1. **Структура:** парсинг, ссылки на ресурсы, допустимый тип, ненулевой результат.
2. **Runtime:** изолированный запуск, ошибки, конкретные проверки событий/элементов.
3. **Визуал:** получен фактический снимок, проверены viewport и видимые требования; для модели без Vision возможна только другая явно разрешённая проверка.

HTML с игрой стартует в разрешённом sandbox автоматически при открытии. Он не получает cookies, storage и DOM родителя, новые привилегированные каналы, произвольные сетевые запросы или скачивания. Parent принимает только ограниченные сообщения от ожидаемого iframe. Код внутри preview считается враждебным, включая ресурсные циклы; iframe не является гарантированной изоляцией CPU/памяти. Для строгих лимитов исполнения требуется отдельное решение, не обещание через один атрибут.

**Картинки сайта при запрете произвольной сети:** предложение должно включать отдельный канал разрешённых ресурсов. Родитель получает байты только для image ID этого артефакта через существующую авторизацию, проверяет формат/размер и передаёт растровые материалы в изолированный документ без cookies и ключей. Сам iframe не получает универсального fetch-моста. Конкретное представление ресурсов и CSP необходимо проверить прототипом; успешность этого механизма пока не установлена. Исходная внешняя ссылка, локальное представление для preview и ресурс автономного экспорта — три разных сущности. Для download отдельно проверяется самодостаточность пакета. Без этого сценарий «сайт с картинками» технически не специфицирован до конца.

Никакого общего shell, исполнения Python/SQL на сервере или доступа к пользовательскому диску этот каталог не предоставляет. SVG отображается с существующей санитизацией/изоляцией, не прямой вставкой недоверенного DOM.

## 9. Связанные входные возможности

PDF/DOCX/XLSX: сохранять имя и оригинал согласно политике, извлекать структуру и предоставлять модели содержание с координатами страниц/листов. Скан без текста требует OCR/Vision, а не ответа по имени файла. Табличные формулы, вычисленные значения и отсутствующий cached value различаются. Макросы, внешние связи и вложенные исполняемые файлы не запускаются.

Изображение: сжатие в браузере перед передачей с ограничением пикселей/байтов и сохранением читабельности. Качество OCR проверяется на скриншотах; уменьшение мегабайтов не гарантирует пропорционального уменьшения модельных токенов. При модели без Vision файл не теряется: показывается краткое ограничение и доступен выбор другой модели без reload.

Транскрибация: пользовательский микрофон включается одним действием после необходимого разрешения браузера; запись визуализируется по реальному уровню сигнала внутри composer. Stop возвращает текст для редактирования, отправка распознаёт и отправляет согласно явному действию. Backend/ключ/цены не выводятся пользователю. Отмена не отправляет накопленное аудио. Это input pipeline, а не доступ текстовой модели к постоянному прослушиванию.

## 10. Эталонная композиция: сайт с изображениями

```text
Запрос пользователя
  → определить создаваемый/редактируемый файл и роли изображений
  → image_search по предметным запросам
  → проверить оригиналы и пригодность, при наличии Vision — пиксели
  → если действительно нет подходящих и разрешена генерация: generate_image
  → create/edit_working_file с реальными resource ID
  → read_working_file + доступные проверки preview
  → показать новую версию, предпросмотр, скачивание и источники
```

Если генерация ещё идёт, HTML может показывать честный placeholder. Связь job/ресурс/file ID и ожидаемой версии позволяет после завершения добавить картинку. Если пользователь уже изменил файл, автозамена не перезаписывает новую версию: сверить место вставки или предложить обновление. Не сообщать о готовом сайте до появления доступного артефакта.

## 11. Будущие инструменты

Презентации: сначала согласовать основной экспорт PPTX, модель слайдов, тему, источники, подбор/генерацию картинок, редактирование и проверку переполнений. HTML-презентация может быть отдельным вариантом, но не называется PowerPoint. Интеграция Google Slides требует отдельного подключения и разрешений. Нехватка картинок не означает, что каждый раз надо спрашивать пользователя: сначала использовать разрешённый поиск и уточнять действительно необходимые личные материалы.

3D: отдельно определить редактируемую сцену, GLB для просмотра и STL для подходящей печатной геометрии, единицы и масштаб, проверки целостности/полигонов. CAD STEP — другой класс геометрии и не обещается экспортом из произвольного mesh. Новые сервисы, загрузки моделей, GPU-маршруты и затраты автоматически не включаются.

Чтение репозитория: только разрешённые пути закреплённого commit SHA, ссылки на конкретные строки, поиск и последующее чтение кода. Документация не заменяет исходники. Нельзя давать боту GitHub token, доступ к `.env`, credentials, приватным журналам и любому репозиторию по имени из запроса. Публикация/изменение кода — отдельный инструмент с другим риском; здесь он не предлагается.
