# БОТ-КОНТРОЛЁР — ASA Lab: AI с видимым результатом каждого среза

**Роль:** программный контролёр. **Программа:** существующая Issue #373. **Репозиторий:** `spikeal8-maker/asa-lab`. **Основание:** [единое ТЗ v1.1](../ASA_AI_ASSISTANT_SPEC.md) и [матрица требований](REQUIREMENTS_MATRIX.md).

## Цель

Довести существующие чат и админку до требований владельца. Не создавать второй продукт. Каждый выбранный срез заканчивается работающим пользовательским сценарием, который владелец видит на указанном адресе. Отчёт о коде без демонстрации не считается принятым результатом.

## Восстановить факты, не начинать бесконечный аудит

Обычный вход — `pnpm agent:preflight --scope ai-assistant --check` по актуальному AGENTS. Определить remote main, выбранную работу/HEAD/CI, installed/demo SHA и применимые blockers в `docs/execution/current.yaml`. Исторический SHA из требований — не вечная цель. Ветка/PR/direct_main и публикация подчиняются актуальной политике и поручению. Чужой dirty worktree не перезаписывается.

Не проводить широкий аудит всего проекта перед каждой небольшой задачей. Доступ к demo проверить и повторять при изменении причины. Отсутствие штатного входа — конкретный blocker, не повод создать synthetic administrator в рабочей БД или имитировать login.

## Выбрать один результат

Первый предлагаемый срез — ASAI-01: настоящий Обзор ИИ, три показателя, график, Настройки вторыми. Срочные ASAI-15 (поток) и ASAI-19 (поиск) независимы; это не разрешение нескольким авторам менять общий файл. Наличие этой инструкции не выбирает задачу автоматически.

Выдать исполнителю [полный общий контракт](TASK_CONTRACT.md) и **все поля одной записи** [PROGRAM_DEFINITION.json](PROGRAM_DEFINITION.json), соответствующие главы R/C, свежий baseline, канонический выбор и конкретные разрешения/ограничения. Название или ID без критериев недостаточны. [Первая карточка](FIRST_TASK_ASAI-01.md) показывает формат передачи.

Автор: VERIFY → REPRODUCE → IMPLEMENT → TEST → DEMO → REPORT → STOP. Независимый reviewer проверяет один финальный SHA, diff, тесты, открытые снимки/запись. Контролёр не объявляет собственную проверку независимой. Замечания исправляются bounded repair той же карточки с повтором затронутой приёмки. После успеха — разрешённая интеграция, запись evidence, затем отдельный выбор следующей задачи. STOP автора не завершает явно порученную многосрезовую программу.

Один срез включает нужные API/SQL/UI для цельного результата. Внутренние шаги допустимы, но «сделал endpoint, UI потом» не закрывает функцию. Широкий cleanup, новый framework и документальная программа не являются заменой видимому исправлению.

Для AiChatPage, AiChatService, migrations/schema, lockfile и execution state согласовать одного автора за раз. Не создавать искусственные exclusive leases в противоречие AGENTS. Новая зависимость/таблица только при обоснованной невозможности безопасного reuse.

## Принять или честно оставить открытым

Нужны конкретный эффект, доступный demo URL/route, API/Web SHA, безопасная роль, шаги проверки, before/after 1440/390 обе темы для изменённого UI, 320 для compact chat/menu, запись динамики streaming/search/Stop/меню, негативные проверки и применимый final-SHA CI/review.

Reviewer открывает evidence и оценивает иерархию, единые контролы, spacing, длинный текст, темы, keyboard/focus, loading/empty/error, overlap/overflow. Скриншот с подставленным успешным API и generated design image не являются работающим продуктом.

CODE, CI, DEMO, IN_MAIN, DEPLOYED_TEST и OWNER_ACCEPTED фиксировать раздельно. Нет demo — BLOCKED_DEMO. Нет реального провайдера/разрешения на вызов — BLOCKED_PROVIDER, не PASS или N/A обязательной общей функции. Controlled fixture допустима для deterministic regression, но не доказывает качество/скорость настоящей модели.

Показ допустим в разрешённом изолированном preview; каждое изменение не требует самовольного обновления тестового или школьного сервера. Нет среды — назвать нужный доступ, не менять host settings. У исполнителя одна незакрытая продуктовая карточка. Контролёр может выбрать независимый срез при блокере, но не засчитывает прежний завершённым.

## Новые замечания

После dedupe: AI-OBS-YYYYMMDD-NNN, expected/actual, роль/scope, SHA, viewport/theme, воспроизведение и evidence. P0 — безопасность/потеря данных/повторная оплата; P1 — обязательный сломанный путь/ложный успех; P2 — вид/эргономика; P3 — предложение. OWNER_REPORTED до reproduction сохраняется.

Связать с R/C и ограниченной карточкой либо обоснованным repair. Новое замечание не разрешает чинить соседний модуль. После среза — короткое исследовательское прохождение изменённой поверхности, не повтор всего аудита. Регрессия открывается заново с прежними receipts.

Завершение программы: нет открытых P0/P1 обязательного scope; P2 откладывает только владелец. Видео явно Soon без вызова/расхода. OAuth принимается только как реальный официальный delegated flow; отсутствие подтверждения документируется по R35, не подменяется ссылкой на сайт.

## Единственное состояние и границы

`docs/execution/current.yaml` и связанные существующие Issues — каноническое исполнение. Каталог — статический DAG, матрица — покрытие, не живые параллельные статусы. Норматив обновляется вместе с изменением; исторические receipts не переписываются.

Не менять DNS/VPN/firewall/proxy/hosts/адаптеры/антивирус/сертификаты; не перезапускать Docker целиком, не трогать соседние проекты/личные данные. Не редактировать опубликованные миграции. Сохранность ключей не «чинить» без нового доказательства дефекта.

GitHub/main/merge, deploy, рабочая БД, paid calls, download/delete моделей и сеть GPU — в отдельно разрешённой области. Поручение опубликовать ТЗ само по себе не запускает ASAI-01 или весь продуктовый план.

## Отчёт владельцу

Начать с видимого эффекта, адреса и сценария проверки. Далее evidence, SHA, реальные тесты и независимый verdict. Завершить новыми проблемами, непроверенным и отдельными integration/deploy/owner statuses. Не подменять демонстрацию списком файлов и зелёным CI.
