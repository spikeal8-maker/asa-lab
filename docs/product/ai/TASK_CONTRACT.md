# Общий контракт одного задания ASAI

Это обязательная общая часть **каждой** записи [PROGRAM_DEFINITION.json](PROGRAM_DEFINITION.json). Полное задание = этот контракт + все поля выбранной записи + связанные R/C из [ТЗ](../ASA_AI_ASSISTANT_SPEC.md) + фактические разрешения/выбор контролёра. Статический каталог не назначает работу.

**Роль:** инженер-исполнитель. **Контролёр:** координатор ASA AI.  
**Режим:** VERIFY → REPRODUCE → IMPLEMENT → TEST → DEMO → REVIEW → REPORT → STOP.

## Вход и ограниченный объём

Прочитать актуальные AGENTS/START_HERE, выполнить обычный scope preflight. Сверить выбранный task/current.yaml, remote main, candidate/CI/dirty paths и параллельные изменения. При сбое восстановить факт, не повторять mutation вслепую. Не начинать очередной полный аудит перед уже ограниченным исправлением.

Поля baseline/source_paths — исходные ориентиры, не вечная истина и не право массово менять соседние модули. До записи воспроизвести текущий дефект и снять before. Контролёру согласовать новые необходимые paths/shared contracts. Уже опубликованные migrations только читать; изменения схемы добавочные. Существующие Account/Seat, authz, журнал, storage, история и ключи сохраняются. Не создавать второй чат или учётную систему.

## Реализация и проверки

Сделать ровно заявленный visible_result и implementation. Переиспользовать существующую функцию. API/БД/UI входят в необходимую вертикаль; промежуточный endpoint/миграция не означает завершение задачи. Допустима меньшая согласованная вертикаль, но родительская карточка остаётся открытой до полного результата.

Выполнить verification и связанные C, негативные права, replay/ошибки/отмена, где применимо. Не отключать assertions, не скрывать красный CI, не устранять чужой дефект в этой задаче. Применимые final gates на точном HEAD; старые результаты не переносить. Не запускать лишние тяжёлые тесты после незатронутой правки, но не подменять обязательный gate его частью.

Primary evidence — собранный UI, настоящий API и изолированные PostgreSQL/S3, когда нужны. Controlled LLM/transport fixture полезна для детерминированного времени и ошибок; реальную модель, внешний поиск и качество ответа проверять отдельно в разрешённых сценариях. Mock-success screenshot не является главным доказательством готовности.

## Обязательный показ

Выполнить demo из карточки. Указать URL/route, точные API/Web SHA, безопасную роль и 3–6 шагов проверки. Для изменённого UI before/after 1440/390 в обеих темах; compact chat/menu также 320. Снимки реально открыть и оценить: spacing, иерархия, focus/keyboard, touch, long content, loading/empty/error, отсутствие overlap/overflow. Общая размерная матрица и zoom — R18/R31.

Streaming, поиск, Stop и меню требуют записи/trace последовательности. Не выдавать статичный снимок за доказательство динамики. Демонстрация может быть в разрешённом preview; самовольно обновлять живой сервер запрещено.

Нет адреса/доступа к показу — BLOCKED_DEMO. Нет provider key/разрешения paid call — BLOCKED_PROVIDER. Неточная информация — NOT_VERIFIED. Не называть «готово» ни эти состояния, ни «UI позже», ни только зелёный CI.

## Независимое review и новые дефекты

После self-review передать точный SHA независимому reviewer; не присваивать себе эту роль. Он оценивает фактический diff, тесты и открытое evidence, не только авторский отчёт. Repair замечаний ограничен этой карточкой; повторить затронутую приёмку.

Новые проблемы регистрировать по R32 с постоянным ID, ожидаемым/фактическим, воспроизведением и доказательством. Не терять их в свободном тексте и не расширять scope автоматически. При опасности данных/оплаты остановить соответствующее действие и сообщить контролёру.

## Запреты и разрешения

Не менять host settings: VPN/DNS/firewall/proxy/routes/hosts/adapters/антивирус/сертификаты. Не перезапускать Docker целиком, не трогать соседние проекты и volumes, рабочую БД/backup/личные данные. Не получать чужие секреты, не публиковать ключи или приватные промпты.

GitHub publication/merge/deploy, рабочая БД, paid calls, model downloads/deletes и сеть GPU — только конкретное разрешение. Этот контракт не является им. Нельзя создавать обходной login, снимать policy для успешной картинки или автоматически переключать на платную модель.

## Финальный отчёт

1. **Что теперь видно пользователю.**
2. **Где и как проверить:** адрес, роль, версия, последовательность.
3. **Доказательства:** before/after, динамика, реальные действия/файлы, независимое заключение.
4. **Проверки:** точные команды, результаты и SHA; отдельно NOT_RUN/FAIL/BLOCKED.
5. **Новые проблемы и непроверенное.**
6. **Раздельные состояния:** CODE / CI / DEMO / IN_MAIN / DEPLOYED_TEST / OWNER_ACCEPTED.

OWNER_ACCEPTED выставляет владелец. После одного выбранного среза — STOP; следующий назначает контролёр. Не переключаться на следующую feature, чтобы скрыть незавершённый текущий результат.
