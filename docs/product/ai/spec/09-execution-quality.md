# 15. Качество кода, документов и каждого шага

## R30. Поддерживаемая реализация и единая документация

Разделять перегруженные компоненты по функциональным границам: состояние беседы, поток, вложения, orchestration, admin settings, export. Не переписывать чат и не проводить широкий рефакторинг одновременно с первой починкой streaming. Число строк не критерий качества; важны зависимости, отсутствие дублей и регрессий.

Зависимости минимальны, закреплены lockfile, проходят действующие security/license gates. Не добавлять неиспользуемые UI-библиотеки, широкие any, fake success, TODO в критическом пути и рабочие generated assets. После среза проверить затронутые зависимости/bundle/крупные файлы/мёртвый код; перед выпуском — общий аудит AI scope.

Единый продуктовый норматив — основной AI-spec и его главы. Не плодить конкурирующие backlog/master. Краткий паспорт возможностей ссылается на каноническое execution state, provider matrix и последнее доказательство; не становится вторым вручную обновляемым статусом. Датированные отчёты остаются историей SHA, не переписываются под новый успех.

Приёмка: следующий бот без догадок находит активную задачу, код, installed/demo version, подтверждённые возможности и blockers. Сохранены один чат, права и учёт.

## R31. Видимый результат каждого захода

До edits — реальный путь/роль/состояние и before screenshot/trace. После — тот же сценарий на новом точном SHA. Отчёт начинается с эффекта и способа увидеть, не количества файлов. Demo: URL/route, API/Web SHA, безопасная тестовая роль, действия, before/after, фактически проверенные ошибки. Mock-success screenshot и нарисованный макет не заменяют работающий продукт.

На изменённом UI: 1440/390 CSS px и light/dark; compact chat/menu также 320. Финальная матрица 320/390/768/1024/1440/1920, 200% zoom, mobile keyboard. Не повторять тяжёлый suite после каждого неизменённого текста; затронутые проверки на текущем шаге, общий gate на финальном кандидате.

Reviewer действительно открывает evidence: иерархия, spacing/alignment, одинаковые icons/controls, contrast, overflow/overlap, long content, loading/empty/error/pending/disabled, keyboard/focus, touch targets. Использовать ASA tokens, без второго UI-kit, случайных рамок/цветов. Основной текст ориентировочно 16 px; обязательная информация не скрыта secondary copy. Touch target 44×44 при компактной иконке. Не уменьшать страницу transform/zoom ради красивого снимка.

Streaming/search/Stop/menu подтверждаются записью/trace со временем. Charts имеют реальные данные, кнопки реально действуют, изображения декодированы. Нет demo — BLOCKED_DEMO, не разрешение придумать показ.

**C28:** владелец открывает тот же результат по инструкции; независимый reviewer подтвердил затронутые визуальные критерии. Внутренний технический шаг не закрывает пользовательскую карточку.

## R32. Новые дефекты

После dedupe присвоить AI-OBS-YYYYMMDD-NNN. Запись: симптом, expected/actual, роль/scope, browser/viewport/theme, main/candidate/installed SHA, reproduction, screenshot/trace, affected paths, источник и уровень доказанности. Невоспроизведённое остаётся OWNER_REPORTED/NEEDS_REPRO, не стирается и не FIXED.

P0: утечка/потеря данных, опасная запись, повторная оплата. P1: обязательная функция отсутствует/ломается/ложный успех/непригодный файл. P2: визуальный/эргономический дефект без потери операции. P3: предложение. Цвет не заменяет причину. Security/data-loss блокирует соответствующий выпуск немедленно.

Контролёр решает: текущий repair, новая bounded карточка, зависимость или продуктовое решение. Автор не чинит соседний модуль заодно. Каждая находка связана с R/C, видимым результатом и regression; current.yaml/связанная Issue — каноническая запись, матрица лишь трассировка.

После среза коротко исследовать изменённый путь/соседние состояния, не проводить полный повторный аудит без новой гипотезы. Регрессия открывает repair с сохранением прежнего evidence. Финал: 0 открытых P0/P1 обязательного scope; отложить P2 может только владелец с причиной.

**C29:** новая тестовая находка проходит регистрацию → dedupe → приоритет → назначение → reproduction → regression → demo → независимое review. Она не теряется в свободном тексте.

## R33. Полевая матрица контекста

| Поле | Допустимый источник/область | Результат и отсутствие |
| --- | --- | --- |
| Имя | Свой Account profile / Seat label | Реальное значение/source; иначе «Не указано» |
| Дата/время | Сервер + разрешённый профильный timezone | Пояс/время вычисления, не выдавать за часы устройства |
| Пояс | Профиль, Seat по действующей policy | Валидный пояс либо явный UTC fallback |
| Пол | Добровольно указанный поддержанный источник | Источник/разрешение; не выводить из имени/аватара |
| Местоположение | Явно введённое место или добровольное browser permission | Не запрашивать точные координаты автоматически; denied и missing различны |
| Аватар | Собственный разрешённый descriptor | Preview/source; не анализировать и не отправлять фото автоматически |
| Устройство | Грубые нужные для помощи client data | «Сообщено браузером», не trusted identity; без fingerprint/серийников/IP-геолокации |
| Класс | Выбранный разрешённый Seat/class scope | Свой контекст без списка чужих учеников/секретов |
| Курс/прогресс | Выбранный доступный Course/Run + read grants | Название, точная версия/status/time, без права менять оценки |
| Проект | Явно выбранный доступный project/version | Название/версия и bounded read tool, не все проекты |
| Capabilities/tools | Реальные adapters + policy + runtime | Provider support, ASA readiness и permission раздельны; unknown не превращать в false/true |

Каждое поле: значение/причина отсутствия, source, timestamp, scope, «передаётся модели». Revocation/owner switch очищают cache. Нет canonical source — назвать зависимость/решение, не строить вторую profile DB. Постоянный fallback при существующем разрешённом источнике не принимается.

**C30:** filled/empty/denied/revoked поля и выбранный учебный объект, preview/runtime parity, обе identity-kind, без чужих данных/секретов.

## R34. Управляемая загрузка/удаление моделей

Ollama и ComfyUI — отдельные жизненные циклы с единым понятным UI: что/куда загружается, размер/free space, источник/license/hash при наличии, recipe, progress/cancel/result/последствия. Download не открывает модель ученику автоматически.

Запрещены arbitrary shell/URL, установка Python/custom nodes, удаление неучтённых файлов. Allowed sources/directories, server auth, version/idempotency, очередь, cleanup частичной загрузки и защита busy/default. Remote ComfyUI transport должен реально работать на разрешённом узле; проценты не имитируются. Ресурсное разрешение отдельно; рабочие модели не использовать для удаления в тесте.

**C31:** тестовая модель реально скачана/проверена/видна; cancel/no space безопасны; busy не удаляется; свободная удаляется после подтверждения. Для обеих интеграций evidence или отдельный честный blocker.

## R35. Ollama Cloud и официальный вход

Кнопка входа только по подтверждённому официальному протоколу стороннего приложения. Website/App/CLI signin не равен OAuth grant для ASA. API-key остаётся полноценным независимым подключением, секрет только backend.

Нет подтверждения third-party OAuth — проверенное описание и рабочий key UI, не «OAuth реализован». UNCONFIRMED_PROVIDER_PROTOCOL означает недостаток подтверждения, а не доказанное отсутствие. NOT_SUPPORTED_BY_PROVIDER_CONFIRMED — лишь при прямом официальном подтверждении; закрытие пожелания согласует владелец. Сохранить дату/официальные источники/условие пересмотра. Появившийся protocol требует adapter/security tests/отдельного разрешения, без извлечения cookies.

**C32:** UI и документы одинаково описывают работающий способ; key save/probe/errors/revoke верны. OAuth доказан реальной делегацией либо явно UNCONFIRMED с источниками. Это не блокирует key-based чат, но не исчезает из матрицы.
