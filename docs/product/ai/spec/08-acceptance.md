## Провайдеры и роли

Для OpenAI, DeepSeek, Ollama Cloud, Ollama проверить поток, tools, поиск, картинки, файлы, отмену, историю, расход и image-generator request. Vision — на реальной supporting модели и отдельно no-Vision. Нет ключа/paid permission — BLOCKED_PROVIDER, не N/A/PASS. Реальная модальность может быть документированным исключением, но не оправданием отсутствия поиска.

Каждому семейству хотя бы один реальный маршрут, каждой предлагаемой модели — подтверждённый профиль. Paid tests ограничены заранее разрешённым набором, не повторяются без причины после CSS.

Роли: platform_admin, teacher своего/чужого класса, Account, allowed/denied Seat. Проверить изоляцию history/files/images/artifacts, revoked session, stale policy, ID spoof, reuse ID с другим payload.

Негативные сценарии: prompt injection в странице/файле/summary, недоверенные tool args, опасный URL, неподдерживаемый формат, внешние связи документа, формулы. Данные не получают право выполнить произвольный shell/network/foreign object или отключить policy.

## Качество модели и нагрузка

Фиксированный набор минимум 40 проверяемых заданий: учебное объяснение, код, tools/search, документы/Vision, длинный контекст, артефакты. Оценивать правильность, полноту, источники, честность ограничений и пригодность файла, не буквальное совпадение текста.

Жёсткий допуск: 0 межвладельческих утечек, выдуманных успехов, повреждённых контрольных файлов и скрытых повторных списаний. Для рекомендованной учебной модели проектный порог ≥90% применимых заданий. Неприменимость фиксируется заранее по модальностям, не постфактум для неудобных тестов. Все провалы раскрываются.

На разрешённом стенде минимум 30 одновременных пользовательских сессий: история, очередь, отмена, ограниченное исполнение. Это не 30 GPU-inferences одновременно. Параллелизм — по измеренным ресурсам; очередь/ожидание видны. 300 сессий — отдельная приёмка перед таким масштабом. Нагрузку на рабочий сервер без разрешения не запускать.

## Definition of Done

Обязательны исходная проблема, работающий сценарий, точный SHA, применимые final gates, независимое review, доступное владельцу demo в настоящем браузере, открытые/оценённые before-after, обновлённые требования и новые findings. Внешние providers/sources требуют разрешённых живых проверок.

«Миграция готова, UI позже», «endpoint отвечает», «написал документ», «CI зелёный» — промежуточный результат. Исполнитель доводит выбранную вертикаль до показа или называет blocker; не берёт следующую feature для сокрытия недоделанной. PARTIAL/BLOCKED_DEMO можно передать на review, но не назвать принятой функцией.

Внутренние технические шаги/commits разрешены по AGENTS; не нужен декоративный экран для каждого коммита или самовольный production update после CSS. Demo может быть в разрешённом изолированном preview точного SHA. DEPLOYED и OWNER_ACCEPTED — отдельно.
