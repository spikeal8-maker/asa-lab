# 11. История, очистка и контекст

## R25. Лимит диалогов и безопасное удаление

Завершить соответствующую часть #750. Централизованный настраиваемый лимит, проектный default 20 диалогов на владельца. Для существующей установки миграция не включает молча автоудаление: preview последствий и отдельное подтверждение. До него — управляемый отказ/выбор удаления при пределе, не стирание данных.

При разрешённой ротации 21-й диалог удаляет старейший подходящий по last_activity_at, затем created_at и стабильному ID. Защитить открытый/исполняемый, pending-платёж, школьно-удерживаемый и чужой диалог. Архив по умолчанию входит в предел; другой режим задаётся явно. Нет безопасного кандидата — объяснить причину, не удалять новый и не обходить защиту.

Удаление транзакционно убирает допустимые связи и ставит долговечную очистку принадлежащих только беседе файлов/картинок/артефактов. Переиспользовать текущий cleanup. S3 удалять после commit, с retry и повторной проверкой ссылок. Общие необходимые объекты сохраняются. Минимальные quota/audit tombstones — по явной политике, без текста удалённой переписки.

Приёмка: 20→21, равные даты, архив, активная генерация, конкурентное создание, общий файл, S3 failure/retry, чужой Seat. Повтор удаления имеет один видимый эффект. Есть диагностика stuck/orphan; постановка в очередь не выдаётся за уже удалённые байты.

## R26. Сжатие вместо слепого обрезания

Бюджет — токены выбранной модели. Нет точного tokenizer — явно обозначенная консервативная оценка с запасом. Резервировать ответ, system instructions, tool results и новый вопрос.

Проектный порог сжатия 75% проверенного context window, настраиваемый и не объявляемый характеристикой всех моделей. Старые реплики сжимать в отдельный versioned checkpoint; свежие вопросы, решения, источники и оригиналы файлов сохранять. История неизменна. Summary — недоверенные данные, не системная инструкция.

Меньшая модель вызывает безопасный пересчёт. Последний большой ответ не переполняет окно бесконтрольно; код/документы доступны через оригинал, не только пересказ. Summary-расход и replay учитываются; сбой даёт честную деградацию, не выдуманную память.

Приёмка: ниже/на/выше порога, длинный код/файлы, model switch, конкуренция, Stop при summary, reload. Ранние контрольные факты доступны, происхождение резюме проверяемо, нет бесконечного resummarize.

# 12. Вычисления и изображения

## R27. Рабочая ComfyUI-интеграция

Сохранить существующий разрешённый local генератор, подключить общими инструментами всем text providers. Наличие файлов не равно готовности: проверить модель/encoder/VAE/recipe и реальный успешный job. UI показывает модель, размер, stage, Stop, ошибку и сохранённое изображение.

Выбор из разрешённых проверенных recipes/models; Auto только внутри них. Удалённый GPU допускается без снятия SSRF-защит. Адрес задаёт уполномоченный администратор; prompt не превращается в произвольный workflow, file path или endpoint.

Итеративная правка требует подтверждённой способности и точного исходного изображения. Text-to-image не называть редактированием прежнего рисунка. UNKNOWN сначала сверяется с существующим job, не повторяется.

Приёмка: реальная картинка, сохранение/reopen, разные текстовые инициаторы, cancel, offline GPU, replay и foreign owner. Удалённый узел и editing проверяются отдельно на реально поддерживаемом маршруте. Платная генерация не добавляется.

### Управление моделями и отложенные функции

Загрузка/удаление Ollama-моделей и разрешённых комплектов ComfyUI входят в R34, ASAI-37/38, но не блокируют первый Обзор/streaming/search. Каждая реальная операция требует отдельного ресурсного разрешения. Наличие карточки не выдаёт такого разрешения.

Ollama Cloud сохраняет API-key путь. R35/ASAI-42 проверяют официальный delegated flow на дату исполнения. Вход на сайт/App/CLI не равен стороннему OAuth. Не изымать browser session, не имитировать grant. Неподтверждённый протокол — документированное ограничение, не выполненный OAuth.

Видео и голос отложены: «Скоро» не вызывает API и не расходует деньги. Не добавлять платный сервис незаметно. Отложенность не скрывает незавершённые обязательные функции админки и изображений.

# 13. Секреты, настройки и обновление

## R28. Сохранность административных данных

Сохранить server encryption и независимые provider keys. Не выводить секрет в браузер, лог, screenshot, GitHub или отчёт. Пустой key field означает оставить старое; удаление подтверждается отдельно. Замена одного ключа не меняет другие.

Конфигурационные записи versioned/idempotent. Потеря ответа после save — чтение фактического состояния, не слепой reset. Старый browser tab получает конфликт и сохраняет draft, не затирает более новую настройку.

До разрешённого update — безопасный config snapshot и проверенный backup. После — сравнить прежние поля, тот же master key и decrypt внутри сервиса без вывода значений. Валидность у провайдера проверяется отдельно с разрешением на расход. Новое поле без старого аналога не объявляется потерянным.

Сохраняются модели, подключения, prompt, tools policies, budgets, grants, история и file refs. enabled=false/лимит/deny не заменяются новыми defaults. Master-key rotation — отдельная защищённая операция.

Приёмка: save → reload → logout/login → разрешённое пересоздание только ASA containers → test update. Значения и decrypt сохранены, соседние проекты неизменны. Поиск, выключенный пользователем, не включается обновлением.

### Установка и восстановление

Для выпуска закрепить full SHA, OCI digest, миграции, конфигурацию. Проверить backup и restore в изолированной среде до опасного switch. Никакого произвольного DB downgrade. App rollback только при доказанной совместимости; иначе forward-fix или согласованное restore с сохранением новых после backup данных.

После установки: версии API/Web, БД/объекты, штатный login, чат, поток, источники, картинки, файлы и настройки. Container health — только технический шаг. Ошибка входа не разрешает менять пароль владельца без согласования.
