# 10. Полноценное административное управление

## R19. Структура и честные статусы

**Обзор первым, Настройки вторыми.** Отдельно доступны Подключения, Системный промпт, Интернет-поиск, Изображения. В Настройках допускаются небольшие секции моделей/доступа, бюджетов, истории и инструментов. Инструменты находятся по понятной ссылке, не только внизу редактора промпта. Пустые разделы «позже» не являются исполнением.

Первый визит без preference — Обзор. Возврат сохраняет раздел/провайдера, explicit deep link приоритетнее fallback. Preference не секрет; при смене владельца прежние чувствительные данные очищаются.

Различать ключ сохранён, включено, подключение проверено, модель доступна, время/revision проверки. `!!localModel` и enabled сами по себе не readiness. Ошибка чтения даёт конечное состояние/retry, не вечное «Проверяем». Пустое поле существующего ключа не означает удаления.

Сохранение без обязательного платного вызова. «Сохранить и проверить» — отдельное действие с согласием на один потенциально платный запрос. Успешная запись и неудачный probe показываются отдельно. Разделённые формы не затирают несвязанные поля; version/CAS/requestId/reconciliation сохранены. Несохранённый draft защищён при навигации.

Приёмка: первый визит/возврат/deep link/reload/новая сессия, выключенная сохранённая local модель, сеть, пустое поле ключа, конфликт двух администраторов, draft, failed probe после save. ASAI-01/03/04.

## R20. Реальный дашборд

ASAI-01 использует существующий ai_usage_journal: Запросы, Входные токены, Выходные токены и график запросов по дням за семь дней, период/пояс/время обновления. Настоящие API+UI, без зависимости от завершения tools orchestrator, категорий и всех бюджетов. Endpoint без экрана, пустая вкладка и fake график не принимаются.

ASAI-02: уникальные владельцы в scope, succeeded/failed/cancelled/stopped/pending, вход/выход токенов, модели/инструменты; 24 ч/7 дней/30 дней/свой диапазон, provider/model. Графики запросов и токенов по времени; читаемая таблица моделей/инструментов с количеством и ошибками. Категории после серверного контракта, не задерживая первые фильтры.

Parent operation считается одним пользовательским запросом, хотя usage всех дочерних model rounds, планирования и summary суммируется. NULL/UNKNOWN/несобранную историю не превращать в 0. Empty отличается от failed source. TTFT только если измерялся; отсутствие истории не «0 мс». Деньги — только по проверенной версии тарифа/валюты, отдельно от токенов и локальной бесплатной стоимости.

Административные grants обязательны. Private prompts/answers/ключи не раскрываются по умолчанию. Фильтры применяет сервер одинаково к карточкам, графикам и таблице.

Приёмка: контролируемые PG-записи, replay, несколько rounds, zero/unknown, границы суток/пояса, failed/empty. Фильтры согласованно меняют данные в реальном браузере. Подписи и табличная альтернатива графику. Это не маркетинговый макет.

## R21. Живой каталог и профили

Объединить реально обнаруженные модели Ollama и поддерживаемые модели настроенных cloud providers. Поля: стабильный внутренний ID, provider ID, имя, источник/время, состояние, модальности, streaming/tools, context/limits, готовность ASA-адаптера. Отсутствующее поле capability в list API не означает отсутствия способности: документация, проверка или «не проверено».

Сбой обновления виден; последний успешный snapshot помечен stale. Не выдумывать свежий список. Удалённая модель остаётся в истории, но не предлагается рабочим новым вариантом. Default разрешён и фактически подключён.

Несколько установленных локальных моделей — отдельные разрешённые варианты, не один глобальный ollama-local. Выбор пользователя не меняет модель всем. Память, параллелизм и очередь учитывают GPU.

Приёмка: две local модели, disappeared/offline/stale, default change, no-Vision/no-tools, одновременно открытые пользователи. Обнаружение не выдаёт ученикам доступ автоматически.

## R22. Права по категориям, классам и ученикам

Продолжить #725. Администратор задаёт глобально допустимые модели/default по существующим категориям Account/учебных ролей. Преподаватель с действующим доступом к конкретному классу выбирает подмножество/default; индивидуальное ограничение Seat требует полномочий. Название роли директора/администратора школы не даёт чужой класс.

Эффективное разрешение — пересечение применимых глобальных, организационных, классовых, индивидуальных ограничений, admission и технической готовности. Явный верхний deny не отменяется снизу. Отсутствующая policy наследуется по документированным правилам; недействительный scope запрещён. Personal Account и школьный Seat не смешиваются.

Каждый новый вызов, вариант, дочерний инструмент и смена scope проверяются сервером. HTTP model spoof не обходит policy. После отзыва новые вызовы запрещены; начатый upstream отменяется по возможности, результат сохраняется приватно с принятой семантикой. История не стирается из-за запрета новых генераций.

Приёмка: свой/чужой учитель, разрешённый/запрещённый ученик, персональный deny, рейтинг, Account/Seat switch, отзыв во время работы, подмена и гонка. Отказ до сети не списывает бюджет.

## R23. Бюджеты и квоты

Сохранить операционные лимиты, добавить токенные бюджеты платформы, разрешённых категорий и владельцев. Явные период, timezone reset и наследование. Токены, денежный потолок и число операций — разные показатели.

Атомарный резерв до платного/ограниченного этапа учитывает конкуренцию. После — сверка reported usage. UNKNOWN остаётся pending, не освобождает резерв как ноль. Учесть все tool/model rounds, варианты и summary. Local без выдуманной цены, но с ресурсными и пользовательскими лимитами.

Приёмка: конкурентное исчерпание, смена периода, разрыв после dispatch, unknown tokens, replay, разные owners. Показатели совпадают с журналом; отказ объясняет причину/reset без чужих данных.

## R24. Системный промпт и реальный контекст

Сохранить краткий промпт, полные кодовые артефакты, версии и immutable server constraints. `{{name}}` и `{{ name }}` используют общий parser/однозначную нормализацию UI/API/preview. Неизвестная переменная даёт одинаковый понятный отказ до save. Изменение моделей/промпта не сбрасывает несвязанные поля даже при общем storage object.

«Что система знает обо мне»: реальные значения вошедшего администратора, source, timestamp, scope, признак передачи модели. Preview использует тот же builder, что запрос, без inference/расхода. Default-ветка также получает разрешённый профиль, не `{}` до первого custom save.

Имя/пояс/время — реальные собственные источники. Пол/место/аватар/устройство/класс/курс/проект — матрица R33. Отсутствующее не угадывать. Не читать автоматически всю CRM, файлы и проекты. Детали выбранного объекта — owner-bound read tool с grants/версией, не инструкция в промпте вместо доступа.

Приёмка: preview равен request snapshot при контролируемом времени; default/custom, Account/Seat, allowed/missing/revoked/foreign, оба синтаксиса, нет секретов. Видимые ASAI-05/13/14.
