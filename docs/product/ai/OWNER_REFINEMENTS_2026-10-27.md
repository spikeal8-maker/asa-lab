# Уточнения владельца: плотность, последние 10 диалоговых операций, поиск и D2R2

**Основание: замечания владельца 27 октября 2026 года после просмотра PR #800.** Это дополнение к [единому ТЗ](../ASA_AI_ASSISTANT_SPEC.md), а не новый параллельный master. Уточняет R06/R07/R19/R20/R24/R31 и разрешённую среду демонстрации. Действующие защитные инварианты и инженерные gates не снимаются. Текущее execution state по-прежнему в current.yaml; документ хранит требования и датированное разрешение, не оперативный статус.

## 1. Плотность интерфейса — самостоятельный критерий приёмки

Для кандидата `8934e542d767b52b5e0d763c5db4d9835fda916b` владелец не принял плотность desktop/mobile. До нового показа исторический visual APPROVE нельзя считать owner acceptance. [Решение и карточка repair в PR #800](https://github.com/spikeal8-maker/asa-lab/pull/800#issuecomment-6447468485), исходная задача [#799](https://github.com/spikeal8-maker/asa-lab/issues/799).

Снимки и CSS подтверждают три строки мобильных разделов, три высоких KPI, многократные пояснения и чрезмерную вертикальную длину. Ошибка плотности может существовать без overflow. Следующий repair сохраняет реальные SQL/API/права и исправляет только компоновку/представление и их регрессии.

- Одна компактная строка заголовка/действий; период и время обновления без повторных абзацев. Обновление — знакомая иконка с доступным именем.
- На телефоне разделы — одна горизонтально прокручиваемая строка с видимым текущим разделом, без горизонтальной прокрутки всей страницы. Не прятать все разделы в неочевидные три точки.
- Показатели — компактная полоса/короткие строки, не три высокие карточки; большие пустые отступы убрать. Точные значения остаются доступны. Нельзя скрывать факт unknown/partial/error в подсказке.
- График уменьшить по высоте без потери дат, значений, нулевых дней и доступной таблицы. Техническую методику подсчёта — в явное раскрытие «Как считаем», не в постоянный многострочный подвал.

Проектные пределы при 100%, обычных коротких контрольных данных и закрытых раскрытиях:

| Область | Desktop 1440×900 | Mobile 390×844 |
| --- | --- | --- |
| Блок KPI целиком | ≤110 CSS px | ≤140 CSS px |
| График с обязательными подписями | ≤260 CSS px | ≤220 CSS px |
| Обзор от собственного заголовка до конца сводки | ≤560 CSS px | ≤480 CSS px |

Это критерии нормального состояния, **не fixed height с обрезкой**. Для длинных чисел, ошибок, partial/unknown и 200% допускается рост высоты. Body14–16px, secondary не меньше12px, цели касания44px; no transform/zoom trick. После добавления журнала его заголовок и первая строка при обычных данных должны быть видны в первом viewport обоих контрольных размеров. Before/after с одинаковыми данными и масштабом; browser bounding boxes плюс открытые снимки, не оценка только отсутствия overflow.

## 2. Последние 10 запросов с ответами — отдельная рабочая вертикаль

[Карточка #806 / ASAI-01B](https://github.com/spikeal8-maker/asa-lab/issues/806) расширяет R20 и последующий ASAI-02. После density repair под сводкой появляется компактный журнал последних10 разрешённых операций. Это десять пар вопрос→ответ, не десять отдельных сообщений. Последние записи не исчезают из-за семидневного окна карточек; подпись объясняет отдельный период списка.

По умолчанию: время, модель/провайдер, статус, 1–2 строки вопроса и ответа. Полное содержание раскрывается явно. Детали: точная исходная операция/вариант, известная версия промпта и политики, доступный расход, факт tools/search. Unknown/history without version обозначаются честно. Replay не создаёт строку; regeneration связывается с исходным вопросом; pending/error/deleted content не подменяются соседним ответом.

Использовать существующую историю и точные source/request/owner связи. Не копировать все тексты в ai_usage_journal и не создавать скрытое второе хранилище переписок. Последние10 сортируются стабильно, выдача и раскрытие ограничены, без N+1.

**Агрегатный доступ не равен праву читать переписку.** Для контента нужна отдельная явная авторизация анализа качества в существующей системе и политика допустимых personal/school scopes; обычные Account/Seat, учителя и неуполномоченные администраторы доступа не получают. Общий агрегатный API остаётся без приватных текстов; RLS и owner isolation не отключаются. Обещанную приватность личных/учебных переписок не отменять молча. До готовности контентного права проверять на собственных/контрольных разрешённых беседах, не объявляя глобальную аналитическую функцию готовой.

Чтение контента аудитируется метаданными без текста; no-store, безопасный Markdown, предусмотренное маскирование секретов и контактов, никаких реальных переписок/ФИО детей в публичных CI/GitHub evidence. Удалённые сообщения не восстанавливать из невидимого дубля.

Приёмка:0/1/9/10/11 операций, равные timestamps, replay/variants, partial/error/pending, удаление и отзыв grant, чужой owner, HTML injection. Настоящие PG/API/UI, точные пары, разрешённый просмотр и403 лишнему пользователю. Обновление/раскрытие журнала не вызывает модель.

## 3. Поиск — общий, с диагностикой и честным недостатком результатов

[Карточка #807 / ASAI-19A](https://github.com/spikeal8-maker/asa-lab/issues/807) уточняет R06/R07 и существующую очередь поиска. Владелец сообщил об ответе «сервис не существует»; точный запрос и сегодняшняя конфигурация пока не воспроизведены. Исторический enabled=false не является текущим диагнозом.

Проверенный источник e9013f86: ai-web-search-provider задаёт `categories=general`, engines Bing/DDG/Wikipedia, язык ru-RU и safesearch2; deployment doc подтверждает закрытый список. Это ограничение источников, не доказанный запрет тем, кроме программирования.

Требования: общие темы и все разрешённые модели; конфигурируемые проверенные бесплатные engines; видимые enabled/permissions/domain policies, engine availability и upstream errors; ограниченные осмысленные fallback. Проверять цепочку от фактического query через upstream/post-filter counts до контекста модели. Точный публичный URL читать безопасным bounded tool независимо от индекса; не писать «прочитал», если fetch не реализован. Private/reserved/link-local/metadata IP, dangerous redirects и утечки credentials запрещены.

**Пустая выдача не доказывает несуществование сервиса.** Различать no matches, policy blocked, unavailable и insufficient evidence. Контроль: ASA Lab, asa-lab.ru, site:asa-lab.ru и нетехнические темы. Не зашивать успех для одного сайта; не обходить CAPTCHA и не менять SEO/robots/DNS сайта в этой задаче. Доступность любого сайта в индексе не гарантируется.

Тематические/стилевые инструкции управляются администратором в промптах. Права, квоты, сетевые защиты и проверки источников остаются программными. Domain rules и SafeSearch — явная авторизованная настройка, не тайная тематическая узость и не только инструкция модели.

## 4. Системный промпт — проверяемое изменение, не автоматическое обучение

ASAI-04/05 и R24 остаются обязательными: удобный компактный редактор, сохранение без потерь, единый синтаксис переменных, реальный preview и версия применённого шаблона. Основной промпт и отдельные tool/search instructions не должны противоречить друг другу. Журнал последних10 нужен для разбирательства конкретного ответа: какой model/prompt и какой поиск реально использовались.

Новая версия не переписывает историю. Старому ответу без receipt не приписывается текущий prompt. Никакого автоматического перезаписывания промпта по десяти ответам, массовой повторной генерации или paid test при save. Короткие контрольные примеры используются по явному действию.

## 5. Разрешение на D2R2 и экономия работы

Владелец прямо разрешил использовать **D2R2 как тестовый компьютер: обновлять существующую установку ASA Lab и показывать новый результат**. Это снимает необходимость снова просить то же самое общее разрешение на тестовый показ; конкретная проверенная версия и безопасный update plan всё равно фиксируются.

Перед обновлением определить фактические каталог/Compose/ports/volumes из текущих контейнеров, особенно working_dir PostgreSQL. Не переносить Linux `/srv/asa-lab` или старый порт на D2R2 догадкой. Сохранить БД, объекты, ключи и пользовательские данные; использовать штатный updater, проверяемый backup и согласованные version/digest checks. PR-кандидат допустим для тестового показа, когда поддержанным способом закреплён exact tested SHA. Если штатный инструмент не допускает candidate, сообщить конкретный blocker, не обходить guards.

Разрешение **не** означает merge #800, acceptance дизайна, обновление test.asa-lab.ru/школьного production, очистку данных, второй постоянный stack, платные APIs или загрузку моделей. VPN/DNS/firewall/proxy/hosts/сертификаты/ОС и соседние IZO/Publikator не менять.

Исполнение короткими срезами: density repair → bounded последние10; поисковый repair отдельно, системный промпт — существующие ASAI-04/05. Каждому — работающий экран/сценарий на D2R2, точные API/Web SHA, адрес, before/after и REPORT→STOP. Параллельные авторы общих файлов исключены. Новая карточка получает canonical выбор контролёра до product edits.

Экономия: один целевой preflight, повторное использование действующего кода и artifacts; targeted tests в цикле, один необходимый final gate; никаких live LLM-вызовов для проверки CSS или простого чтения журнала, нет бесконечных poll/full-audit/main-sync циклов. Реальные поисковые/модельные проверки — минимальный заранее ограниченный набор. Эти правила не разрешают пропустить безопасность или назвать старый CI проверкой нового SHA.
