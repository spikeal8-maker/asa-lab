# ASA Lab — визуальная приёмка входа (D2-R2)

Только тестовый браузер Playwright и отдельная рабочая копия ASA Lab на D2-R2. **Это настоящие скриншоты работающего React-интерфейса**, а не изображения, сгенерированные по описанию. Ответы внешних мессенджеров в данном браузерном наборе синтетические. Скриншоты **не доказывают** вход через реальные токены MAX или Telegram.

На компьютере показана двухколоночная композиция с направлениями ASA Lab, на телефоне — компактная форма без дополнительного рекламного блока. Пустые окна не открываются: ссылка на бота доступна только после создания запроса на авторизацию.

## Воспроизведение

На точной версии проекта с изменениями входа:

```bash
corepack pnpm exec nx build web --skip-nx-cache
corepack pnpm exec vitest run apps/web/src/auth-providers.spec.ts
corepack pnpm exec playwright test --config=playwright.auth-confirmation.config.ts --grep "auth surfaces and long account data fit at|starts without a blank browser popup|an unknown social identity"
```

Playwright проверяет ширины 1440, 1024, 390 и 320 px, отсутствие горизонтального переполнения, размещение входа через мессенджер выше пароля, отсутствие пустого popup, правильную ссылку MAX/Telegram и возврат к существующему аккаунту без регистрации нового.

Результат на D2-R2 от 22 октября 2026 года: **13/13 unit**, **7/7 focused browser**, **Web build PASS**, **TypeScript PASS**.

## Реальная проверка тестовых ботов

Создана отдельная read-only утилита `tools/auth-provider-live-probe.mjs`. Она получает тестовые секреты **только** из переменных среды `ASA_TEST_MAX_BOT_TOKEN`, `ASA_TEST_TELEGRAM_BOT_TOKEN` и путь к проверенному корневому сертификату через `ASA_TEST_MAX_CA_FILE`. При отсутствии секретов утилита безопасно возвращает `not_checked` и код завершения 2. После ввода тестовых ключей выполняет только `GET /me`, `GET /subscriptions` для MAX и `getMe`, `getWebhookInfo` для Telegram. Никаких изменений webhook или чтения личных переписок не делает.

Для MAX выполняется отдельный DNS-over-HTTPS lookup внутри процесса (без изменения системного DNS) и строгая проверка TLS с официальным корневым сертификатом, SHA-256 `D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31`. Путь к сертификату задаётся локально. В отчётах выводятся только статусы, ID и имена тестовых ботов и минимальная информация о подписке, без самих токенов, cookies и внешних payload.

На D2-R2: **5/5 проверок утилиты PASS**; с намеренно неверным тестовым токеном MAX сервер вернул **HTTP 401**, как и ожидалось. Реальные ключи пока не переданы.

```bash
node --test tools/auth-provider-live-probe.test.mjs
node tools/auth-provider-live-probe.mjs
```

## Что ещё не проверено

- Настоящий Bot API с *действительными* тестовыми токенами и регистрация webhook для конкретного локального окружения.
- Живое подтверждение пользователем в MAX и Telegram и успешная выдача сессии ASA Lab.
- Сохранение существующего Account ID, проектов и роли администратора после живой привязки.
- Полная приёмка шрифтов и админки при масштабе текста 150%: в предыдущем полном наборе был независимый сбой подписи на 1440 px.
- Публикация результата в `main` и production.

Не сохранять токены, cookie, инициирующие payload или личные переписки в директории с доказательствами. Для живых испытаний использовать изолированные тестовые аккаунты и отдельный HTTPS webhook на D2-R2.
