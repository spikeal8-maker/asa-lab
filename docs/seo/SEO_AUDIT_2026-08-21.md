## 1. Итог

На момент аудита продукт уже был доступен пользователям, но поисковые системы получали почти пустую оболочку одностраничного приложения. Для ASA Lab это критическое ограничение: содержимое, которое видит учитель после выполнения JavaScript, почти не было представлено в исходном HTML, а отдельные направления продукта не имели собственных индексируемых адресов.

В локальных исходниках подготовлен новый SEO-фундамент:

- содержательная публичная главная страница;
- двенадцать индексируемых URL с уникальными `title`, `description`, H1 и canonical;
- отдельные страницы блочного программирования, рисования, 3D-моделирования, виртуальной электроники, шахмат и русских шашек;
- страница для преподавателей;
- schema.org JSON-LD для организации, сайта, приложения и страниц;
- настоящий `sitemap.xml`, управляемый `robots.txt` и вспомогательный `llms.txt`;
- обычные HTML-ссылки между публичными страницами;
- корректный ответ 404 для неизвестных путей вместо массовых soft-404;
- автоматическая SEO-проверка, включённая в кодовый gate проекта.

Эти изменения пока являются **локально проверенными исходниками**. Они не закоммичены, не отправлены в GitHub и не развёрнуты на рабочем сайте. Действующий `asa-lab.ru` до публикации продолжает отдавать прежнюю SEO-версию.

## 2. Что обнаружено на рабочем сайте

### Критические проблемы

| Область | Фактическое состояние 21.08.2026 | Влияние |
| --- | --- | --- |
| Исходный HTML главной | Только Vite-контейнер `<div id="root"></div>` и короткий `title` | Поисковому роботу почти нечего классифицировать без выполнения JavaScript |
| Meta description | Отсутствовал | Поисковик сам выбирал бы фрагмент сниппета или не показывал содержательное описание |
| Canonical и языковые ссылки | Отсутствовали | Не было явного основного URL документа |
| Open Graph и Twitter Card | Отсутствовали | Ссылка на продукт не имела управляемого социального превью |
| Структурированные данные | Отсутствовали | Не были явно описаны организация, сайт и программный продукт |
| Индексируемая архитектура | Основная навигация работала кнопками и hash-маршрутами | Функции продукта не имели самостоятельных поисковых страниц |
| `sitemap.xml` | Возвращал HTML приложения с кодом 200 | Поисковые системы не получали карту сайта |
| Неизвестные URL | Возвращали оболочку приложения с кодом 200 | Массовые soft-404 расходуют краулинговый ресурс и размывают качество сайта |
| `robots.txt` | После правил Cloudflare содержал HTML приложения | Файл был технически загрязнён и не управлялся из репозитория |
| AI-краулеры | Managed robots Cloudflare запрещал ряд краулеров, включая GPTBot; отдельного разрешения OAI-SearchBot не было | Видимость в AI-поиске не была управляемой и проверяемой |
| Поисковая видимость | В тестовых запросах `site:asa-lab.ru` и по названию продукта страницы сайта не найдены | На дату проверки подтверждённой индексации домена не видно |

Отсутствие результата в операторе `site:` — диагностический сигнал, а не точный счётчик индекса. После публикации нужно подтверждать состояние в Google Search Console и Яндекс Вебмастере.

### Положительные факторы

- рабочий HTTPS и HSTS;
- русская локаль документа (`lang="ru"`);
- адаптивный viewport;
- действующий бренд и favicon;
- публичный GitHub-репозиторий уже индексируется;
- продукт содержит реальные, отличимые друг от друга образовательные среды;
- есть понятная целевая аудитория: учителя, школьники, кружки и классы;
- публичный edge-слой Cloudflare может централизованно контролировать ботов после настройки;
- транспортный туннель не является Cloudflare Tunnel и должен проверяться как отдельный слой доставки.

## 5. Техническая реализация

### Индексация и рендеринг

- В `index.html` добавлен полноценный статический слой содержимого. Он виден роботу даже до загрузки React, а React заменяет его интерактивным приложением для пользователя.
- Для функций созданы настоящие HTML-страницы, не зависящие от JavaScript и авторизации.
- Публичная навигация использует crawlable-ссылки `<a href>`.
- Неизвестные пути на Caddy больше не должны переписываться на главную. Исключение оставлено только для реального SPA-маршрута редактора `/projects/*`.

### Метаданные

- уникальные `title` и `meta description`;
- canonical на HTTPS-адреса `asa-lab.ru`;
- `robots: index,follow`;
- Open Graph;
- Twitter Card без изображения;
- `hreflang="ru"` и `x-default` на главной;
- JSON-LD: `Organization`, `WebSite`, `SoftwareApplication`, `WebPage` и `CollectionPage` там, где применимо.

Не добавлены вымышленные рейтинг, отзывы, цена или награды. Такие свойства следует публиковать только при наличии проверяемых данных.

### Файлы для роботов

- `sitemap.xml` содержит двенадцать канонических страниц и дату обновления;
- `robots.txt` разрешает публичные страницы, закрывает API, health-endpoints и пользовательские проекты;
- OAI-SearchBot и ChatGPT-User явно разрешены на публичной части;
- GPTBot закрыт, чтобы отделить поисковую доступность от разрешения на обучение моделей;
- `llms.txt` даёт AI-системам краткую фактическую карту продукта и ссылки на первичные страницы.

`llms.txt` является вспомогательным машиночитаемым документом, а не заменой HTML, sitemap, robots или поисковых панелей.

## 6. Что остаётся сделать вне исходного кода

### Приоритет P0 — публикация и проверка

1. Закоммитить и отправить изменения в GitHub.
2. Развернуть именно эту ревизию на рабочем сервере.
3. После развёртывания проверить каждый URL, content type, canonical, sitemap, robots и настоящий 404 с внешней сети.
4. Убедиться, что авторизация, классы, редакторы и маршрут `/projects/*` не регрессировали.

### Приоритет P0 — цепочка публикации, edge и Cloudflare

По подтверждению владельца транспортный туннель настроен не через Cloudflare. Репозиторий описывает контейнерный origin на Docker/Caddy, опубликованный через операторский TLS reverse proxy/туннель. Одновременно авторитетные NS домена находятся в Cloudflare, а публичные ответы содержат `Server: cloudflare`, `CF-RAY` и Managed Content Signals в `robots.txt`. Это означает, что Cloudflare используется как отдельный DNS/proxy edge, но не как транспортный туннель к origin.

Слои нужно проверять независимо:

1. **Туннель/доставка:** какой процесс публикует локальный или серверный порт Caddy, как он запускается и восстанавливается.
2. **Origin:** Docker/Caddy, статические SEO-файлы, SPA-маршрут `/projects/*`, API и реальные 404.
3. **Cloudflare DNS/proxy edge:** DNS-записи, TLS, caching, WAF/Bot rules и Managed robots.

Cloudflare Managed robots сейчас добавляет собственные директивы перед origin-файлом. Поэтому новый `robots.txt` из репозитория сам по себе не отменит внешние запреты.

Нужно в панели Cloudflare:

1. проверить режим Managed robots и AI Crawl Control;
2. разрешить OAI-SearchBot для публичного контента, если цель — появление в ChatGPT Search;
3. сохранить запрет GPTBot, если обучение на материалах сайта не разрешается;
4. разрешить только выбранные reference/search crawlers, а не все AI-боты без разбора;
5. проверить события WAF/Bot Management, чтобы разрешённый робот не получал challenge или блокировку;
6. повторно запросить рабочий `robots.txt` и сохранить результат проверки.

Изменение этих параметров — внешняя публичная операция, поэтому в рамках аудита оно не выполнялось.

### Приоритет P1 — поисковые панели

1. Подключить домен в Google Search Console через DNS-подтверждение.
2. Отправить `https://asa-lab.ru/sitemap.xml`.
3. Проверить главную и все одиннадцать разделов инструментом URL Inspection, затем запросить индексацию.
4. Подключить Яндекс Вебмастер, отправить ту же карту сайта и проверить отрисовку JavaScript.
5. Подключить Bing Webmaster Tools или импортировать подтверждение из Google.
6. После стабильного деплоя рассмотреть IndexNow для оперативного уведомления об изменениях.

### Приоритет P1 — сущность бренда

- заполнить поле Website/Homepage репозитория GitHub адресом `https://asa-lab.ru/`;
- дать ссылку на рабочий сайт в верхней части README;
- использовать одинаковое написание `ASA Lab` и краткое описание на GitHub, в социальных профилях и публикациях;
- завести публичные страницы «О проекте», «Контакты», «Политика конфиденциальности» и «Условия использования», когда юридические тексты будут утверждены;
- указывать реального владельца/оператора продукта, не выдумывая юридическое лицо.
