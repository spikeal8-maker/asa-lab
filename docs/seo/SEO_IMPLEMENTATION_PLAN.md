# План внедрения SEO для ASA Lab

Версия: 1.0
Дата: 21 августа 2026 года
Канонический домен: <https://asa-lab.ru/>
Публичный репозиторий: <https://github.com/spikeal8-maker/asa-lab>

## 1. Цель и границы результата

Цель SEO — сделать ASA Lab однозначно распознаваемым продуктом для четырёх типов систем:

1. поисковых роботов Google, Яндекса и Bing;
2. AI-поиска и систем, которые дают ссылки на первоисточники;
3. учителей и руководителей школ, сравнивающих цифровые образовательные инструменты;
4. разработчиков и технических специалистов, которые находят продукт через публичный GitHub.

SEO считается внедрённым не в момент написания метатегов, а после прохождения всей цепочки:

```text
исходники → проверенный коммит → GitHub/CI → production → внешний crawl
→ поисковые кабинеты → индекс → показы → полезное действие в продукте
```

Статусы не смешиваются:

- **LOCAL:** изменение существует и проверено локально;
- **PUBLISHED:** коммит находится в публичном GitHub;
- **CI VERIFIED:** обязательные GitHub Actions завершились успешно на этом SHA;
- **DEPLOYED:** production сообщает или иным способом подтверждает этот SHA;
- **RUNTIME VERIFIED:** рабочий домен прошёл внешний SEO- и продуктовый smoke;
- **INDEXED:** URL подтверждён в поисковой панели, а не только доступен по HTTP;
- **PERFORMING:** появились показы, переходы и продуктовые конверсии.

## 2. Фактическая схема публикации

Нельзя называть всю публикацию «туннелем Cloudflare».

| Слой | Фактическая роль | Что проверяется |
| --- | --- | --- |
| Приложение | React/Vite + API + PostgreSQL | продуктовые маршруты, данные, авторизация |
| Origin | Docker/Caddy | HTML, статические страницы, headers, 404, `/projects/*` |
| Транспортный туннель | Не Cloudflare Tunnel; операторский механизм публикации | целевой порт, процесс, автозапуск, восстановление |
| DNS/proxy edge | Cloudflare NS и публичный proxy response | DNS, TLS, WAF, cache, bot rules, Managed robots |
| Поисковые системы | Google, Яндекс, Bing | crawl, render, canonical, индекс и сниппеты |

Перед каждым production-релизом нужно фиксировать, какой origin обслуживает домен и какой commit на нём работает. DNS/edge и туннель тестируются отдельно.

## 5. Пакет 1 — технический SEO-фундамент

### Результаты

- содержательный HTML до выполнения JavaScript;
- отдельные публичные URL без авторизации;
- уникальные `title`, `description`, H1 и canonical;
- `lang="ru"`, robots meta, Open Graph и Twitter Card;
- JSON-LD Organization, WebSite, SoftwareApplication, WebPage/AboutPage/FAQPage;
- crawlable `<a href>` между публичными страницами;
- `sitemap.xml` только с каноническими 200-страницами;
- чистый origin `robots.txt` и дополнительный `llms.txt`;
- настоящий 404 для неизвестных URL;
- сохранение реального SPA-маршрута `/projects/*`;
- автоматический `seo:check` в общем code gate.

### Критерии приёмки

- 12/12 страниц проходят автоматическую SEO-валидацию;
- каждая страница возвращает `200 text/html` и содержит собственный H1;
- случайный URL возвращает 404 после прохождения всей публичной цепочки;
- sitemap возвращает XML, robots и llms — plain text, ни один не содержит оболочку приложения;
- ссылки на CSS, favicon и будущие изображения не возвращают 404;
- мобильный viewport 390 px не имеет горизонтального скролла;
- вход, регистрация, код класса и `/projects/*` не регрессировали.

## 7. Пакет 3 — GitHub как внешний источник сущности

### About

- description перечисляет категорию и все ключевые направления;
- homepage указывает на `https://asa-lab.ru/`;
- topics включают брендовые категории продукта без keyword stuffing.

### README

В первой видимой области должны находиться:

- ссылка на рабочий продукт;
- краткое продуктовое описание;
- полный набор доступных направлений;
- аудитория и польза учителю;
- статус пилотного использования;
- ссылки на безопасность, школы, FAQ и сайт;
- только затем — инженерные детали и локальный запуск.

### Критерии приёмки

- GitHub About и README используют одно и то же каноническое описание;
- Homepage кликабелен и ведёт на HTTPS-домен;
- README не представляет доступные функции как будущие;
- GitHub Search находит репозиторий по `ASA Lab`, `STEM education`, `block programming`, `electronics simulation` и смежным категориям;
- описание не превышает лимит GitHub и не превращается в список ключевых слов.

## 8. Пакет 4 — изображения и социальные карточки

Обязательные файлы и промпты вынесены в [`SEO_IMAGE_BRIEF.md`](SEO_IMAGE_BRIEF.md).

До получения файлов нельзя добавлять несуществующий `og:image`. После готовности изображений:

- основной social card подключается ко всем страницам как fallback;
- страницы направлений получают собственные карточки;
- Twitter Card переключается на `summary_large_image`;

## 9. Пакет 5 — edge, robots и AI discovery

### Origin robots

- публичные страницы разрешены;
- API, health и пользовательские проекты закрыты;
- OAI-SearchBot разрешён для публичных материалов;
- GPTBot закрыт, если обучение не разрешено;
- sitemap указан абсолютным URL.

### Cloudflare DNS/proxy edge

Cloudflare здесь не является транспортным туннелем. Проверяются только его реальные функции на публичном edge:

- DNS-записи и proxy status;
- TLS и принудительный HTTPS;
- Managed robots/Content Signals;
- AI Crawl Control;
- WAF/Bot правила без challenge для разрешённых поисковых роботов;
- cache rules: HTML и robots не должны застывать после релиза;
- отсутствие альтернативного edge-ответа по IPv4/IPv6.

### AI discovery

- `llms.txt` содержит краткие факты и канонические страницы;
- публичный HTML остаётся первичным источником;
- GitHub и сайт ссылаются друг на друга;
- факты о продукте совпадают между JSON-LD, HTML, README и About;
- серверные/edge-логи позволяют отличить OAI-SearchBot, Googlebot, YandexBot и Bingbot.

## 10. Пакет 6 — поисковые кабинеты

### Google Search Console

- подтверждение Domain property через DNS;
- отправка `/sitemap.xml`;
- URL Inspection всех 12 страниц;
- проверка rendered HTML;
- отчёт Pages: indexed/not indexed;
- Core Web Vitals после появления полевых данных.

### Яндекс Вебмастер

- подтверждение домена;
- sitemap;
- проверка ответа сервера и JavaScript rendering;
- мониторинг исключённых страниц и зеркал;
- переобход ключевых URL после деплоя.

### Bing Webmaster Tools

- подтверждение или импорт из Search Console;
- sitemap;
- IndexNow только после стабилизации canonical URL и релизного процесса.

Доступы к кабинетам и DNS — внешние права владельца; их наличие не подменяется кодовым коммитом.

- переход ко входу по коду класса;

Не собирать в SEO-аналитику содержимое детских проектов, имена учеников или открытые идентификаторы. Отчёт строится на агрегатах.

## 12. Пакет 8 — выпуск

### Перед публикацией

1. обновить `main` fast-forward;
2. убедиться, что рабочее дерево содержит только SEO-пакет;
3. запустить `control-plane:check`;
4. запустить `seo:check`;
5. запустить focused unit test публичной страницы;
6. запустить `gate:code` без Nx cache;
7. отдельно отметить, если Docker-dependent compose validation была пропущена;
8. просмотреть итоговый diff и список новых файлов;
9. создать один понятный коммит;
10. опубликовать в соответствии с действующей политикой репозитория.

### После публикации в GitHub

1. дождаться всех обязательных CI checks;
2. не называть код deployed до фактического обновления origin;
3. сделать backup перед изменением production containers;
4. развернуть точный SHA;
5. проверить health и версию приложения;
6. выполнить внешний SEO-smoke через домен;
7. проверить tunnel recovery и edge behavior;
8. отправить sitemap в поисковые панели;
9. сохранить release receipt: SHA, время, результаты, URL и ответ 404.

### Rollback

- не удалять предыдущие образы и backup базы до runtime-проверки;
- при регрессии приложения возвращается предыдущий рабочий SHA;
- Git-откат не заменяет восстановление данных, если миграция изменила схему;
- SEO-страницы можно откатить отдельно только если сохранены совместимые Caddy routes;
- настройки DNS/edge меняются независимо и должны иметь собственный журнал.

## 14. KPI на 30, 60 и 90 дней

### 30 дней после индексации

- sitemap принят без ошибок;
- 12 основных URL обнаружены;
- брендовый запрос связывается с доменом и GitHub;
- нет soft-404 и случайно индексируемых API/project URL;
- сниппеты используют управляемые title/description.

### 60 дней

- появляются показы по функциональным небрендовым запросам;
- страницы направлений получают отдельные impression/click данные;
- известен CTR и переход к регистрации по каждой посадочной;
- видны первые referral-переходы с AI-поиска, если они возникли.

### 90 дней

- опубликованы реальные методические сценарии;
- известна доля органических посетителей, дошедших до первого полезного действия;
- определены страницы с высоким показом и низким CTR для переписывания сниппетов;
- определены запросы, по которым нужен новый полезный материал, а не дополнительное повторение ключевых слов.

## 15. Definition of Done

SEO-релиз ASA Lab завершён, когда:

- код опубликован и CI подтверждён на точном SHA;
- production обслуживает этот SHA;
- внешний домен отдаёт 12 страниц, корректные robot-файлы и настоящий 404;
- туннель, origin и Cloudflare edge проверены как разные слои;
- GitHub About, Homepage, topics и README обновлены;
- Open Graph изображения существуют и подключены либо явно записаны как следующий P1;
- Search Console, Яндекс Вебмастер и Bing приняли sitemap;
- индексация подтверждается кабинетами;
- настроен еженедельный отчёт по crawl, visibility и conversion;
- факты о продукте не расходятся между сайтом, GitHub и структурированными данными.
