# Регистрация по почте без обязательного псевдонима, 24 октября 2026

## Реализованный срез

- В обычной регистрации, регистрации из MAX mini app и регистрации после
  подтверждения MAX / Telegram убрано обязательное поле username.
  Подсказка объясняет: «Почта будет вашим логином».
- Вход называется «Почта или логин»: старые пользовательские логины сохраняются.
  API и PostgreSQL не менялись; сервер уже поддерживает вход по почте.
- Требуемый существующим API публичный handle генерируется один раз на форму:
  `u_` + 32 hex-символа UUID v4. Используется существующий `newClientId`
  (`crypto.randomUUID`, иначе `crypto.getRandomValues`); email в handle не входит.
  Валидация и неоднозначные ошибки сохраняют значение. Только определённый
  `409 username_taken` заменяет ещё не зарегистрированный handle, после чего
  требуется новая явная отправка. Автоматического повтора регистрации нет.
- Отображаемое имя остаётся необязательным. Имя, полученное от провайдера,
  сохраняется; пустое значение отправляется как «Пользователь». Ни случайный
  идентификатор, ни email не становятся отображаемым именем по умолчанию.
- Нормативная спецификация входа уточнена согласно решению владельца.

## Проверки

- 27 focused unit tests PASS: выбор аккаунта, отказ link, expiry, fallback имени,
  реальные формы ordinary / legacy MAX / social MAX, неизменность handle после
  503 и ручная повторная отправка после определённого конфликта.
- ESLint шести основных изменённых файлов — без ошибок; локальная проверка
  границ Nx пропущена из-за отсутствия cached ProjectGraph.
- Браузерные сценарии добавлены в существующий auth confirmation gate:
  обычная регистрация и MAX без username на 1440/390, вход с email и старым логином;
  снимки входа/регистрации/MAX на 1440/1024/390/320.
- В восьми существующих e2e-файлах обновлены только помощники регистрации и
  повторного входа созданного ими аккаунта. Поля редактирования username в
  существующем Account profile не удалялись.

Браузерная и визуальная приёмка ожидает exact-SHA GitHub CI. Локальный прогон
Docker/сервера и обновление рабочего сайта не выполнялись. Проверки production
бота, почтовой доставки или новой политики подтверждения email этим срезом
не заявляются.
