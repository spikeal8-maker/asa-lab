# Нативная регистрация MAX без почты и пароля — browser contract

Дата: 24 октября 2026. Срез проверок интерфейса, без обновления рабочего сайта.

## Принятый маршрут

- Уже связанный подтверждённый MAX входит в свой существующий Account напрямую.
- Неизвестный подтверждённый MAX сразу открывает минимальную форму: дата рождения,
  страна, необязательное редактируемое имя из MAX. Промежуточного выбора
  «существующий / новый аккаунт», обязательных почты и пароля нет.
- Условие 18+ сохранено. Публичный handle остаётся совместимым полем API,
  пользователь не вводит его вручную.
- Telegram сохраняет прежний выбор и регистрацию с почтой/паролем. Отдельный
  legacy raw MAX mini-app endpoint не объявляется изменённым этим browser-срезом.

## Добавленные / обновлённые проверки

- На 1440/1024/390/320: неизвестный MAX, отсутствие choice/email/password,
  обязательная дата, предзаполненное имя, одна явная отправка и успешный вход,
  снимок формы и отсутствие горизонтального overflow.
- На тех же размерах: уже связанный MAX входит без формы и без нового register.
- После ответа проверяется настоящий экран «Главная», в том числе с `email: null`,
  а не только флаг синтетического сервера.
- Точное тело MAX pairing/register не содержит email/password; signup не требует
  отдельного password login или повторного pairing. Fixture моделирует новый
  отдельный Account без настроенного пароля.
- Проверка отображения серверного отказа для возраста младше 18 лет.
- При удержанном ответе повторные события submit не создают второй запрос;
  неполученное подтверждение не объявляется успешной регистрацией.
- Существующие Telegram registration/password-return/stale-response проверки
  сохранены; старый MAX choice-сценарий заменён новым согласованным маршрутом.

## Границы доказательств

HTTP-ответы браузерного набора синтетические. Они проверяют shipping UI и shape
запросов, но не доказывают серверную проверку подписи MAX, 18+, отсутствие
объединения Account или атомарность создания. Эти инварианты требуют отдельных
backend unit / real PostgreSQL проверок продуктового среза.

Браузерные результаты, responsive-снимки и итоговая приёмка ожидают exact-SHA
GitHub Actions. Локальный браузер / Docker / production build не запускались.
Один локальный ESLint завершился без ошибок; правило границ Nx было пропущено
из-за отсутствия cached ProjectGraph. Форматирование и diff check пройдены.
