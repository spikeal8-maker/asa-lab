# School NAT mutation admission — bounded repair, 24 October 2026

## Causal evidence

The previous isolated soak (`1dda05fc`, Actions run `40028790314`) recorded one
HTTP 429 during a save at the 60-session stage. It did **not** retain the failed
route template, error code or limiter classification. Its exact historical
limiter cannot be recovered from that aggregate alone.

A deterministic replay on unchanged Main baseline `1c426cbe` isolated a concrete
false-rejection mechanism in `MutationAbuseProtection`:

1. Exhaust the anonymous address budget (900 mutations / five minutes).
2. Admit 60 distinct valid pupil credentials. All authoritative lookups succeed.
3. Advance 30,001 ms, expiring their positive admission proofs.
4. Repeat those 60 pupils' requests: **all 60 are rejected without another
   authoritative lookup**, because the same source's 60 new-proof checks/minute
   are exhausted. Each session has sent only two requests (<600); the aggregate
   is 1,020 (<9,000). The database and individual mutation ceilings are not the
   cause of this replay failure.

The successful baseline-defect replay ran locally before the production change
(one test, 18 ms). The committed regression expects all refreshed pupils to be
admitted instead. It is deliberately not a claim that the missing historical
limiter field has been reconstructed.

## Change

- Successful authoritative project context resolution records server-owned,
  credential/policy-specific budget evidence. Ordinary project reads can warm
  100 pupils even after the source has reached its anonymous mutation ceiling.
  This performs no extra session query. Cookies, response status and client
  headers cannot supply this evidence.
- Positive proofs still last 30 seconds. A bounded record of a previously
  verified proof allows a new **authoritative recheck** for five minutes without
  competing for the unknown-cookie onboarding budget. Revoked credentials are
  not trusted by this record. Any successful recheck renews the bounded record.
- Proof state stays at 1,024 entries and in-flight work at 1,024 entries, with
  in-flight coalescing. Negative proofs retain their separate five-second TTL.
- Unknown credentials still allow at most 60 new lookups/source/minute. The
  anonymous 900/5 min, session 600/5 min and aggregate 9,000/5 min limits remain.
- Account, legacy Seat and AI existing-only Seat proofs remain separate. A
  project Seat lookup cannot seed the AI existing-only policy or initialize
  an AI owner via that policy.
- Terminal HTTP logs gain the server-owned `mutationAdmission.blockedBudget`
  enum (session/shared_address/anonymous_address/new_proof_work/pending_proofs/
  invalid_proof). No token, hash, IP, bucket key or identity is added. Proof-work
  rejections now use that limiter's own Retry-After instead of the unrelated
  five-minute anonymous window.

Every protected route still performs its original authentication, authorization,
revision and write checks. Admission evidence is never permission to read/write.

## Focused acceptance

- Existing 41 mutation/AI proof-policy tests plus the initial five new replay
  tests passed locally (46 total). Two additional bounded-state/expiry tests
  and the final source are included in the exact-SHA GitHub gate.
- New fake-clock replay covers 30, 60 and 100 pupils for ten virtual minutes
  per stage, with Electronics drafts every ten seconds and Scratch capability
  renewals every minute. Runtime Scratch saves retain their separate budget.
  This is **not** a throughput or latency measurement.
- Manual `school-nat` CI profile builds API and runs focused security tests,
  then migrates a disposable `*_test` PostgreSQL database. Its real loopback
  HTTP scenario creates 100 distinct Seat sessions/projects, exhausts the
  anonymous source budget, warms authenticated project reads, saves and reads
  back 200 drafts across a proof expiry, and verifies revocation/anonymous-read
  rejection. Only bounded aggregate evidence is retained in `school-nat.json`.
- No production URL, object store or installed Docker stack is used. Existing
  `_test` connection guards and an ephemeral loopback HTTP listener enforce
  isolation.

The first CI integration attempt (`40033274778`) completed 100 saves, then its
fixture incorrectly compared a legacy schema-1 input with the correctly migrated
schema-4 readback. Its duplicate runtime-pool shutdown masked that assertion.
The repaired fixture uses the existing canonical version-4 capacity document,
retains exact full-document/revision equality, drains all concurrent operations,
preserves the first failing phase, and closes the runtime pool through its API
owner once. It waits a real 31 seconds between waves: replacing `Date.now` after
limiter construction would not expire its captured clock. Product code is
unchanged by this fixture repair; the final exact-SHA CI is the acceptance gate.

## Limits

This change removes a proven admission-accounting defect. It does not prove
3,000–5,000-user capacity or relax every proxy/route limit. Cold unverified
cookies presented after exhaustion without any successful project read still
share the protected 60/min onboarding budget. A hard aggregate ceiling remains;
its tuning requires a separate capacity decision rather than unlimited traffic.
No production update or production load test is part of this slice.
