# Сохранение: сокращение работы основного пула, 24 октября 2026

## Основание

[Предыдущий прогон](POINT8-CLASSROOM-20261024.md) обнаружил p95 сохранения
750,32 мс при цели 700 мс и максимальную очередь 20 при пуле 10.
Одновременный старт 30 запросов сам по себе может дать такую очередь;
это не доказательство нехватки соединений или необходимости увеличить пул.

## Изменение

Раньше SaveDraftUseCase загружал предыдущий документ только ради moduleKey,
а затем PgProjectRepository повторно запрашивал project_context_for_principal
через отдельное обращение к пулу. Теперь репозиторий готовит только
авторизованную метаинформацию и writer, привязанный к проекту и копии identity.
В нормальном успешном пути это 3 обращения к пулу вместо 4; старый документ,
preview и история при подготовке не передаются. Счетчик проверен на обеих
реализациях одинаковым тестовым пулом, а не вычислен из p95.

Writer не является сохранённым разрешением. При выполнении CAS/replay заново
проверяется текущий context и его userId; MATERIALIZED CTE вычисляет его один
раз на SQL statement. Сохранены tenant RLS, ACCESS/EDIT predicates, текущий
transaction guard, publication/origin lock order, CAS, mutation receipt,
классная активность, подтверждение только после COMMIT. Во время проверки
документа и объектного хранилища соединение не удерживается.
