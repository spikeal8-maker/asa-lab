# Вход с публичной страницы, 24 октября 2026

## Изменено

- «Войти» остаётся в шапке на desktop, tablet и mobile, без открытия меню.
  На узких экранах шапка содержит бренд, вход и меню; регистрация доступна
  отдельной явной кнопкой в hero и в меню. Повтор входа внутри раскрытого меню убран.
- Основная кнопка hero называется «Создать аккаунт» вместо «Начать создавать».
  «Смотреть проекты» остаётся отдельным вторичным переходом к сообществу.
- В статическом fallback ссылка «Войти» вынесена из скрываемой мобильной навигации.
  Она ведёт на тот же `/#/sign-in`; signup также имеет явную подпись.
  Изменения SEO CSS ограничены `.seo-fallback`, другие SEO-страницы не перестраиваются.

## Проверка

- PublicEntryPage unit: 3 PASS. ESLint изменённых JSX/test файлов — без ошибок;
  локальное правило границ Nx пропущено из-за отсутствующего cached ProjectGraph.
- В существующий auth confirmation browser gate добавлены проверки 1440/1024/390/320:
  прямой видимый вход на первом экране, клавиатурный Enter и маршрут, target ≥44 px,
  отсутствие пересечения с брендом/меню и горизонтального overflow, явный signup,
  navigation/signup в меню, снимки первого экрана.
- На тех же размерах отдельный JS-disabled context проверяет видимую нативную
  ссылку fallback, размер target, маршрут и снимок. Это не доказательство работы
  SPA-аутентификации без JavaScript.
- Этот же e2e-файл остаётся единственной точкой browser-проверок согласованного
  auth-среза: видимые связанные подсказки, клавиатурная необязательная справка,
  provider-check error/retry с сохранением полей и различение ready-empty/error.

Браузерные результаты и визуальная приёмка ожидают exact-SHA GitHub CI.
Рабочий сайт не обновлялся. Глобальная boot mask и protected-route bootstrap
сохранены: при медленном запуске JavaScript fallback ещё закрыт прежней маской;
гарантия видимости статической ссылки относится к JS-disabled fallback.
