## 1. Причина и существующее исправление

Очередь настоящего CLIENT доставляет посещение перед модульной сессией. Прежний браузерный mock отвечал только на module-session: неподтверждённый visit задерживал последующие start/touch/close. Это дефект тестового окружения; историческая причина школьного сбоя этим не доказана.

При предыдущем объединении исправление уже вошло в main: [3ab6693e](https://github.com/spikeal8-maker/asa-lab/commit/3ab6693eb3bf52d7ba73c5f6679bbac83c656efb) добавил acknowledgeVisitsAndQuality в оба сценария, перенёс запись наблюдаемого module-session после await route.fulfill и добавил ожидание close. Последующие ограниченные исправления тестовых часов и загрузки протокольных helper довели выбранные сценарии до реально выполненных PASS на [0e904550](https://github.com/spikeal8-maker/asa-lab/commit/0e9045500fd2c069b35e6c51d9dcaad039258be2).

На входе текущей работы main и чистая авторская копия совпадали: **b5bf8a3c250cb8bd84665dee1639014fb0eae840**. Preflight: SAFE_TO_START, execution blockers и пересечения с чужими грязными worktree отсутствуют. Незавершённые чужие файлы сохранены.

## 2. Проверенные критерии

| Требование | Подтверждение |
|---|---|
| Visit и качество получают действительное подтверждение | acknowledgeVisitsAndQuality возвращает analytics HTTP 200/persisted с идентичностью события; diagnostics quality — HTTP 202/intake_acknowledged. Поля потока, sequence, pipeline и acknowledgementStage коррелированы с запросом. |
| Настоящий module-session достигает обработчика | Используется shipping CLIENT и настоящий браузер с закреплённым Scratch. Очередь посещения не обходится. После доверенного ввода наблюдается start с полным телом и требуемым actor. |
| Закрытие проверяется после ответа | Наблюдение telemetry.push выполняется после await route.fulfill. Close ожидается через polling; сохраняются точные количества, сравнение sessionId и различных eventId. Нет дедупликации или замены точного ожидания приблизительным. |
| Heartbeat, idle и синтетический ввод не выдумывают работу | Исходные отрицательные проверки сохранены. Настоящий ввод, закрытие по idle и новая сессия после следующего ввода различаются. |
| Минутное сохранение и 401 остаются рабочими | Отдельный module-session handler возвращает 401. Проверяются реальное минутное сохранение, последняя правка при controlled exit, рост серверной revision и отсутствие auth refresh. Разрешённая console-ошибка сопоставляется с фактически наблюдаемым 401 того же POST и origin. |
| Виртуальные часы не создают ложный delivery timeout | Тест ожидает чтения JSON настоящего ответа перед продвижением часов. Продуктовые таймеры и deadline не изменялись. |

Пользовательское поведение в этом запуске не менялось: пункт исправляет достоверность браузерной проверки уже существующего поведения Scratch. Новые возможности редактора, авторизации и API не добавлялись.
