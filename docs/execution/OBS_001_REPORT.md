# Отчёт по пункту 1: связь Scratch при смене рабочего пространства

**Дата:** 2026-10-13  
**ТЗ:** [OBSERVABILITY-REPAIR-SPEC, пункт 1](../product/ASA_OBSERVABILITY_REPAIR_SPEC.md#5-подробное-тз-пункта-1--obs-001)  
**Задача:** TASK-OBSERVABILITY-001 / OBS-001, Issue #551  
**Результат:** реализация пункта 1 и целевые проверки приняты. Весь пакет CLIENT и выпуск остаются непринятыми. Следующий пункт не начат.

## Что было неисправно

В подготовленной версии CLIENT смена только рабочего пространства у того же Account и проекта очищала связь приложения со Scratch, но оставляла прежний iframe загруженным. Новый обработчик ожидал повторной загрузки, которая не происходила. Причина — различающиеся ключи владения эффекта связи и iframe.

Дефект воспроизведён на настоящем смонтированном компоненте. Он относится к подготовленной версии; причина школьного происшествия и наличие такого сбоя на опубликованном сайте этим не установлены.

## Что изменено

Продуктовое изменение — одна строка в `apps/web/src/blocks/BlocksEditor.tsx`: React key iframe теперь включает `actorKey(telemetryActor)`, как и существующий эффект связи.

При смене Account/workspace или StudentSeat/class прежнее окно заменяется, старый bridge очищается, новое окно проходит существующее подключение со свежей capability и nonce. Эквивалентный контекст сохраняет прежнее окно. Происхождение сообщений, полномочия проекта и правила сохранения проверяются прежними механизмами.

Добавлен файл `apps/web/src/blocks/testing/workspace-bridge-lifecycle.spec.ts` с пятью проверками настоящего компонента и bridge. Других продуктовых файлов в коммите пункта 1 нет. Вёрстка, тексты и CSS не менялись; React key не является DOM-атрибутом.

```text

```
