# Отчёт OBS-013 — безопасное чтение и выгрузка старых журналов

Дата: 2026-10-14. TASK-OBSERVABILITY-001 / #551. ТЗ 1.11, раздел 18. Второй пункт серии 12 → 13 → 14; OBS-012 принят ранее.

## 1. Причина и исправление

Старые диагностические записи БД могли содержать личные значения и произвольные внешние поля. Очистка новых записей не защищала чтение прежней истории и быстрый экспорт целого сегмента. Запись без корректного source также вызывала ошибку reader. Обе проблемы воспроизведены на временных обычных и gzip-сегментах.

Первоначальный продуктовый SHA: 10491503082b9229670c146e635031c6682d0caa; после независимого замечания исправлен до a5f4aca80fe469885b716e06dde822e478e489b6, ветка codex/observability-item-13. Исходный и канонически выбранный main: 7e31490e7c25811ac53b81756a8ca758cf57e329. Изменены ровно четыре файла: apps/api/src/database-diagnostics.ts, admin-logs.worker.ts, admin-logs.worker.spec.ts и apps/api/tsconfig.json.

Новый reader использует единый JSON-контракт OBS-012. Узнаваемые записи БД очищаются до поиска, фильтрации, ответа worker и ZIP. Заново формируется разрешённая внешняя оболочка, сохраняются действительные идентификатор и время. Обработаны старые обычные/gzip, вложенные и дважды закодированные сообщения, импортированное происхождение, ошибочные и подменённые поля. Неизвестное происхождение не даёт права пропускать диагностические значения. Общие сообщения API/системы без признаков записи БД сохраняют доступность; произвольный текст без таких признаков не восстанавливается в предполагаемый источник БД.

Целостность исходного сегмента проверяется до очистки: SHA256, размер, gzip CRC и идентификаторы. Быстрое копирование deflate допустимо только для проверенных неизменившихся строк, соответствующих фильтру, и единственного полного потока. Составной gzip импортированной истории проходит обычную безопасную упаковку.

Метаданные ZIP описывают фактически экспортированные JSONL-части и их контрольные суммы. Исходный текст поиска не отражается в архиве: сохранён только searchApplied. Подробности исходных статусов источников не копируются, это явно отмечено sourceStatusIncluded:false. Архив не обещает полное покрытие источников. Исходные сегменты, каталог и индекс не переписываются.

JSON подключён настоящим import; resolveJsonModule обеспечивает его включение в собранный API. Целевая проверка компилятора использует действительные параметры API и исполняет настоящий собранный Worker.

## 3. Ограничения и публикация

Пропущены прежние 256 MiB и 200000-строчные benchmark-тесты, полный API build/repository gate, авторизованный HTTP-сеанс и работающая установка. Python-код и контракт не менялись; 45 PASS коллектора из OBS-012 не повторялись и не объявляются новым прогоном. Проверка компиляции изолированная, не полная сборка API. Обработка ограничена одним сегментом до 4 MiB и примерно 1 MiB выходной порцией; весь рабочий архив в память не загружается.

Подробные статусы источников в ZIP сознательно исключены ради недопущения отражения старых произвольных данных. Для анализа полноты используются существующие защищённые сведения коллектора; безопасная сводка покрытия в архиве остаётся ограничением для дальнейших пунктов. Этот отчёт не утверждает очистку любых произвольных личных строк во всех неструктурированных системных сообщениях.

После независимого review и документальных проверок результат направляется обычным fast-forward в main. Новый CI проверяется по точному опубликованному SHA; незавершённый запуск не считается PASS. SHA push, чистота checkout и публикация фиксируются отдельно.

Работающий сайт не обновлялся. Docker, рабочая БД, настоящие журналы, резервные копии и расписания не изменялись. Классификация Linux/Docker — отдельный следующий OBS-014, остальные модули — OBS-015. Прежние blockers и результаты не закрываются.
