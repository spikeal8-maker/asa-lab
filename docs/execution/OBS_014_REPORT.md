## 1. Причина и результат

Python уже распознавал Linux и Docker lifecycle как host, но API распознавал только Windows, Docker Desktop и метрики. Дополнительно сохранённые корректные по форме, но ошибочные subsystem/module могли переживать импорт и читаться как достоверные. Системные события попадали в фильтр приложения, а старые подсказки каталога расходились с фактическими строками.

Продуктовый SHA: 3a3497e31194880a191fa3b63bdef4decc546c69, ветка codex/observability-item-14; исходный main и канонический выбор — 3e762aebf0529cf0141e7ddc951ad430b8e28c82. Автор и независимый рецензент разделены.

В каждом языке введено общее правило источников host. Linux linux:* и docker-lifecycle получают системную область (значение API scope=host), подсистему host и внешний module=system. Подсистема метрик остаётся metrics, область — host. Контрольные Windows и Docker Desktop сохраняют обычное поведение. Ошибочный host у api/web/scratch исправляется по источнику и маршруту; законные модули приложения сохраняются.

Коллектор, добавление/импорт, каталог, reader, поиск и ZIP используют согласованную классификацию. Старые неизменяемые сегменты не переписываются: исправляются выдача и метаданные каталога. Для смешанных старых подсказок используется ограниченное чтение до 4 MiB на сегмент; результат кэшируется в private по итоговому digest метаданных. Кэш ограничен активными сегментами и не требует повторного чтения уже исправленных данных. Существующие правила квитанций, идентификаторов, целостности, приватности и прав не ослаблены. Проекция БД из OBS-013 применяется до системной классификации: поддельный Linux-source не обходит очистку БД.

Изменены пять файлов: tools/collect_logs.py, tools/test_collect_logs.py, apps/api/src/log-subsystems.ts, admin-logs.worker.ts и admin-logs.worker.spec.ts. Нового формата каталога, миграции или общего классификатора всех модулей нет; OBS-015 не выполнялся.

## 3. Ограничения

Все данные искусственные, каталоги временные. Не выполнялись полная сборка, весь pnpm test:admin-logs/repository gate, настоящий Linux journal или Docker daemon, авторизованный браузерный сеанс, замер большого рабочего архива и два больших benchmark-теста. Два платформенных пропуска контрактных тестов также отмечены отдельно, а не выданы за PASS. Классификация Linux проверена на фикстурах; это не подтверждение фактического доступа к журналу Linux на другом компьютере.

Новый GitHub CI оценивается только по опубликованному SHA; незавершённый запуск не объявляется зелёным. Доказательства независимого просмотра не являются повторным выполнением авторских тестов. Прежние ограничения полноты источников Windows и приёмки Scratch остаются открытыми.
