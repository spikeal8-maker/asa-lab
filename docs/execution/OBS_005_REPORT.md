## Причина и исправление

Сама очередь событий имела предел, но каждое повторное обращение к одной ожидающей операции создавало отдельный Promise и добавляло обработчик в массив. При задержке сети или сервера этот массив мог расти без ограничения; при каждом добавлении он также копировался.

Теперь у каждого ожидающего eventId одна запись с общим Promise и завершающим обработчиком. Повторный `open`, объединяемый `touch` и повторный `close` возвращают тот же Promise. Поддерживаемые вызывающие получают одинаковый итог. При завершении запись удаляется до разрешения Promise; повторное завершение отсутствующей записи ничего не делает.

Ожидание освобождается при подтверждении, окончательном отказе, истечении срока, замене ещё не отправленного touch закрытием и retirement. Поздний ответ остановленной очереди не меняет итог и не завершает ожидание новой очереди. Обработчик результата может безопасно создать следующее допустимое действие с отдельным Promise и eventId.

Ожидания, которыми владеет очередь, ограничены числом допущенных операций: не более 96 для 32 сессий по три операции. Посещения не создают таких ожиданий. Самостоятельные подписки вызывающего кода на возвращённый Promise в этот предел не входят.

Сетевой повтор сохраняет общий Promise, исходные eventId, actor и тело события. Правила HTTP 200 и receipt, порядок сессии, TTL, счётчики, авторизация и достоверность хранения из пунктов 1–4 сохранены. Телеметрия не вмешивается в вход пользователей и сохранение проектов.
