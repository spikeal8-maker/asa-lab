## Наблюдения и исправления

- В журналах: 155 ответов `401 expired_token` при загрузке ресурсов одного
  Scratch-проекта, 12:06:11–12:14:48. В коде родительского окна после временного
  сбоя обновления runtime capability терялся таймер следующей попытки.
  Добавлено восстановление после сетевой ошибки, 429 и 5xx с паузой,
  экспоненциальным увеличением до 30 секунд и учётом числового Retry-After.
- Начальная выдача разрешения допускает две дополнительные попытки при
  временном сбое. Ошибки доступа, повреждённый ответ и неверный origin
  не повторяются автоматически. Существующий предел ожидания запуска сохранён.
- При 401 чтение ресурса, загрузка ресурса и сохранение черновика запрашивают
  новое разрешение через существующий протокол. Одновременные обращения
  объединяются; ожидание ограничено 15 секундами. Повтор разрешён один раз,
  только после смены токена. Черновик сохраняет исходные тело, mutationId и
  baseRevision. Повторный отказ не подтверждает сохранение.
- В 12:15:02 запрос `a5307cc4-dcc6-4422-8755-1f265b0ab7bd` получил 503;
  непосредственно перед ним PostgreSQL сообщил конфликт
  `blocks_blobs_tenant_id_object_key_key`. Вставка метаданных теперь учитывает
  оба ограничения уникальности. Последующая точная проверка hash, размера,
  object key и alias сохранена: несовместимые данные отвергаются.

Связь всех ошибок запуска и 429 с этими дефектами не доказана. Источник
браузерных 429 в исходных журналах не локализован. Исправление не означает
подтверждённую готовность к 5000 одновременным пользователям.

## Проверки

- Локальные проверки протокола/хранилища воспроизводят 401, смену разрешения,
  повторный отказ, неизменный токен, сохранность mutation, неверные source,
  origin, project/nonce, ограничение времени и завершение редактора.
- Проверки родительского окна: восстановление после 503 без перемонтирования,
  старт после 429 с паузой, окончательный отказ после исчерпания попыток,
  прежние проверки доступа и остановки.
- Проверки типов, линтер и unit-проверки API выполняются по существующему
  focused gate. Локальный общий node-прогон встретил два инфраструктурных
  ограничения installation-identity: путь Git Bash и Windows execution policy.
  Эти проверки не объявляются локально пройденными; настройки Windows не меняются.
- Добавлена PostgreSQL-регрессия: 24 параллельные записи одного ресурса
  создают один blob/alias; конфликт object key с другим hash не создаёт alias.
  Запуск разрешён только в изолированной базе с окончанием `_test`, в GitHub CI.
- Добавлена браузерная регрессия настоящего закреплённого Scratch: 401 при
  PUT ресурса и черновика, новое разрешение, тот же черновик, одна подтверждённая
  ревизия без перезагрузки. Выполняется GitHub Scratch runtime-image workflow.

Полные Docker/browser/PostgreSQL проверки относятся к конкретному SHA GitHub
Actions. Этот документ не объявляет их заранее пройденными.

## POST_STEP_REVIEW

STEP: восстановление ограниченного Scratch runtime-доступа и конкурентной записи.
CHANGE_CLASS: L3_CRITICAL (storage/protocol).
USER_RESULT: временный сбой обновления доступа больше не обрывает цикл обновления;
редактор может завершить операцию после получения нового разрешения.
INVARIANTS_TOUCHED: runtime binding, negative authorization, immutable asset
integrity, exact draft acknowledgement. TTL и серверные проверки прав сохранены.
LAYOUT_IMPACT: none; текст, CSS и структура интерфейса не изменены.
VIEWPORTS / VISUAL_EVIDENCE: n/a для этого изменения поведения.
SELF_REVIEW: отсутствие повторов после окончательного отказа в одной операции,
защита от позднего bootstrap после ошибки, очистка таймеров и AbortController.
INDEPENDENT_CHALLENGE: требуется по Scratch AGENT_GUIDE; результат отдельного
read-only review финального SHA сообщается вместе с публикацией.
DEPLOYMENT: не выполнялся. Проверка поведения на работающем сайте после
отдельного развёртывания остаётся необходимой.
