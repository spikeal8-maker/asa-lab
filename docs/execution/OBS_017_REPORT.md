## Причина и исправление

Прежний свежий запрос включал целые последние 30 минут через OR без ограничения числа строк. Уменьшение старого интервала не сокращало эту часть: превышение лимита ответа могло повторяться без продвижения. Исторический запрос также не имел постраничного ограничения.

Новый database_batch читает до 128 строк с суммарным пределом SQL CSV 4 MiB, PostgreSQL statement timeout 15 секунд и process timeout 25 секунд. Устойчивый порядок time/native PK сохраняет строки с одинаковым временем. Границы окна фиксируются до завершения его порций; история имеет отдельное состояние и прежний шестичасовой период. Обязательный trailer проверяет целостность ответа, число строк и наличие продолжения. Обрезанный/повреждённый/слишком большой ответ, включая единственную чрезмерную строку, явно останавливает порцию без ложного продвижения.

События, fingerprints и курсор сохраняются одной SAVEPOINT-транзакцией, с восстановлением внутренних счётчиков при ошибке. Следующий свежий цикл сохраняет перечитывание последних 30 минут для законных mutable наблюдений. Незавершённые порции явно обозначаются pending, coverageComplete=false; курсор внутри одинакового timestamp не объявляется полным покрытием времени. Используется существующий поддержанный API/UI статус, новая разметка не добавлялась. Приватность OBS012/013, identity/default compatibility OBS016, старые ID и неизменяемые сегменты сохранены.
