## Причина и исправление

Тест зависания Scratch возвращал HTTP 200 с телом runtime-session на каждый запрос. Диагностическая очередь требует HTTP 202 и accepted=true. Первое событие editor_ready оставалось без подтверждения и повторялось; последующие editor_unresponsive и editor_recovered не доходили до проверяемого запроса.

Существующий общий helper теперь различает endpoint. `/api/diagnostics/client` получает HTTP 202 с accepted=true, `/api/diagnostics/quality` — HTTP 202 с полной коррелированной квитанцией intake_acknowledged. Ответы analytics v2 и runtime-session сохраняют прежние собственные контракты. Проверка heartbeat использует этот helper.

Изменения только выбранного сценария оказались недостаточны: три предыдущих выполняемых сценария через тот же singleton outbox также отправляли editor_ready с неверным ответом. После очистки тестовых таймеров оставался признак ожидающего повтора. Поэтому исправлен общий helper для этих трёх сценариев и самого heartbeat — четырёх случаев, без сброса очереди или обхода её проверки.

Все содержательные утверждения и таймеры сохранены: пропущенные heartbeat, сообщение editor_unresponsive, восстановление editor_recovered и игнорирование скрытой вкладки. Продуктовый heartbeat, авторизация, доставка, API и схема не менялись. Исправление теста не устанавливает причину исторических школьных вылетов.
