# Идея синхронизации локальных школьных установок

## Статус

Это архитектурная идея для отдельной будущей задачи. Она не является текущей
реализацией, не меняет схему PostgreSQL и не разрешает автоматическое
объединение рабочих баз.

## Зачем это может понадобиться

Школа может временно работать без интернета на нескольких локальных
установках. После восстановления связи изменения должны безопасно передаваться
в центральную установку без потери проектов, результатов обучения и аудита.

## Безопасный минимальный протокол

1. Каждая установка получает постоянный `installation_id`, а создаваемые записи
   — глобально уникальные идентификаторы.
2. Локальные изменения записываются в transactional outbox вместе с tenant,
   автором, временем, версией сущности и идентификатором операции.
3. Передача идёт идемпотентными подписанными пакетами: повтор одного пакета не
   создаёт дубликаты.
4. Центральный API повторно проверяет tenant/RLS и права автора; доверять
   присланному клиентом tenant нельзя.
5. Для каждой сущности заранее задаётся правило конфликта. Проекты могут хранить
   версии, а роли, блокировки, платежи и безопасность требуют ручного решения и
   никогда не используют слепое `last write wins`.
6. Удаления передаются tombstone-событиями, а не физическим исчезновением строки.
7. Каждая попытка импорта попадает в неизменяемый аудит с результатом, причиной
   отказа и исходным `installation_id`.
8. Очередь поддерживает retry с backoff, контроль порядка и карантин пакетов,
   которые невозможно применить автоматически.

## Что запрещено

- multi-master PostgreSQL без формальной модели конфликтов;
- копирование volume между работающими установками;
- слияние SQL/custom-format dumps;
- импорт, обходящий API, RLS, аудит или проверку версии схемы;
- включение синхронизации до тестов потери связи, повторов, конфликтов,
  частичного пакета и восстановления из backup.

## Условия отдельной реализации

Нужны отдельные модель угроз, миграции, протокол версий, API-контракт, метрики,
проверка восстановления и пилот на тестовых данных. До этого локальные базы
остаются независимыми, а перенос выполняется только проверенным backup/restore
с участием владельца.
