# ТЗ: синхронизация часов и сетевых ответов в браузерном тесте Scratch

**Идентификатор:** RELEASE-SCRATCH-CLOCK-SPEC

**Редакция:** 1.0

**Задача:** TASK-RELEASE-SCRATCH-CLOCK-001

## Причина и границы

Scratch Focused 38480278103 на интеграционном коммите 3ab6693e остановился в classroom-scratch-time.spec.ts:129: ожидался один сырой запрос close, получено два. Лог не содержит eventId/sessionId и не доказывает двойного логического закрытия. CLIENT добавляет 12-секундный deadline отправки; существующий непрерывный скачок виртуальных часов на 66 секунд может истечь до обработки реального ответа Playwright и вызвать повтор того же события. Это непосредственная несовместимость интеграционного diff и тестового времени, категория B.

## Требования

1. Изменяется только e2e/classroom-scratch-time.spec.ts. Продуктовые сроки, доставка, лимиты, сохранение и общая fixture не меняются.
2. Виртуальное время продвигается шагами не более одной секунды. Между шагами тест ждёт реального завершения обработки телеметрических ответов клиентом, включая чтение JSON или ошибку. Наблюдатель сохраняет native fetch, исходные аргументы, response и результаты; не создаёт подтверждений, не подавляет ошибки и не отключает AbortSignal.
3. Отсутствие подтверждения остаётся ограниченным провалом теста. Нельзя заменять ожидание слепой паузой, увеличивать рабочий deadline или дедуплицировать запросы для успешного утверждения.
4. Сохраняются строгие исходные количества сырых запросов, trusted-input граница, отсутствие активности от heartbeat/синтетического ввода, завершение по простою, отсутствие последующих запросов, новый sessionId при возобновлении, минутное сохранение и контролируемый выход при HTTP 401 без refresh.
5. Диагностика на ошибке содержит operation/eventId/sessionId, позволяя отличать повтор доставки от двух сессий. Успешная проверка должна подтверждать один close первого sessionId, затем отдельный start/close нового sessionId.
6. Локально достаточно форматирования, diff-check, независимого просмотра и обнаружения сценариев при наличии исходных build artifacts. Тяжёлые build/browser/DB выполняются в GitHub. Сохранённый реальный CI FAIL является доказательством до исправления.
7. Перед обновлением требуется успешное реальное исполнение исправленного сценария Scratch на точном финальном коде, полный General окончательного main и проверенный Portable Release. Исторические независимые blockers других задач не закрываются этой правкой; их приёмка не заявляется.

Исполнитель реализует один срез, отчитывается и останавливается. Контроллер продолжает прямо разрешённый выпуск и обновление существующего сайта.
