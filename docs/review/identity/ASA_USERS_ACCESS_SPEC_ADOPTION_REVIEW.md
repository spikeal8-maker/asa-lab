# ASA-USERS-ACCESS — проверка и принятие канонического документа

**Дата:** 8 сентября 2026 года.  
**Область:** документация пользователей, доступа, интерфейсов и правила адресного чтения для агентов. Это исторический отчёт о документационном изменении, не источник активной задачи.  
**Baseline:** `703ce0107a849489f5e4ab5fe0c1bdd6df8d3a52`.  
**Основной результат:** [ASA_USERS_ACCESS_AND_SETTINGS_SPEC.md](../../product/ASA_USERS_ACCESS_AND_SETTINGS_SPEC.md), редакция 2.0, `NORMATIVE / TARGET`.

## 1. Основание и граница разрешения

Владелец попросил опубликовать подготовленный V1.2 на GitHub, сделать его основой
и устранить логические проблемы. Разрешение относится к документации. Оно не
активирует новые Learning/Admin-задачи, не принимает их реализацию, не разрешает
миграции, изменение tenant/RLS, deployment или работу с production-данными.

Исходный файл из переписки: `ASA_USERS_ACCESS_AND_SETTINGS_SPEC_V1_2.md`.
Его SHA-256 проверен локально:
`1d648f50875622a23b05611a8345c89c1526841a99bb99dddf0f57a25001eda4`.
Новая редакция объединяет повторяющиеся разделы накопленных V1–V1.2, сохраняет
модель и идентификаторы сценариев, но не является побайтной копией вложения.

## 2. Найденные коллизии и исправления

| Проблема | Исправление |
|---|---|
| Seat issued/active смешивалось с meaningful learning activation | Отдельно profile lifecycle, credential/session и Enrollment/Participation; login не доказывает Attempt |
| Revoked membership могло читаться как общий запрет на все роли аккаунта | Проверка зависимости каждой grant-chain; независимые personal/другие org права сохраняются |
| Owner без detail grant одновременно может выдать его себе | Уточнено: нет текущего скрытого чтения, но есть отдельная явная audited management-команда в ceiling |
| Distinct LearnerIdentity нескольких школ назывался количеством людей | Cross-context counts подписываются как scoped учебные профили без выдуманной глобальной дедупликации |
| Linking отзывает Seat credential; не был явно отделён отзыв участия | Credential revoke не removed/suspended learner и не withdrawn Enrollment/Participation |
| Lost response выдачи секрета допускал неоднозначный retry | Сначала безопасный статус; без чтения старого секрета; при утрате — явный новый reset, не автоматический цикл |
| Меню объединяло возможности контекстов без ясной границы данных | Навигация указывает доступную область, но страницы/actions проверяются по точному ресурсу после server switch |
| TARGET personal self-study мог восприниматься как разрешение менять school-scoped модель | Сохранены ADR и запреты AGENTS; отдельное разрешённое архитектурное изменение до affected реализации |
| Auth MD/YAML всё ещё допускали class code + handle с optional PIN | Целевой контракт синхронизирован: индивидуальный секрет либо защищённый browser-bound approval, без внезапной смены действующих credentials |
| Learning START HERE указывал начинать с M0 и автоматически идти по микрозадачам | Постоянный вход читает актуальный state/scope, не запускает исторический аудит и не активирует следующий этап |

Исправления относятся к смыслу документа. Они не означают, что соответствующие
runtime-регрессии уже исправлены или исполнены. Дополнительные проверки LC-01…08
включены как обязательства будущей затронутой реализации.

## 3. Как документ становится основой

- В `AGENTS.md` добавлен постоянный адресный маршрут чтения пользовательского контракта.
- В `START_HERE_FOR_AI.md` он включён в чтение задач о пользователях/доступах/экранах.
- Learning entry связывает его с Master Spec и ADR без подмены их академической и физической области.
- Auth MD и YAML согласованы по code-entry, optional organization, linking и историческому статусу PR59-инструкций.
- Admin spec ссылается на единую модель ролей, не делает организационное право универсальным учебным доступом.

Основной путь постоянный, без суффикса версии. Версия находится внутри документа
и в Git history. Исходные вложения V1/V1.1/V1.2 — история обсуждения, не ещё три
действующие очереди. `current.yaml`, Master Spec, migration ledger, runtime и
проектные результаты этой публикацией не изменяются.

## 4. Фактическая проверка и ограничения

Выполнены адресное чтение исходного V1.2 и связанных документов, ручная проверка
модели/приоритетов/путей, локальная проверка fingerprint исходного файла и сверка
смыслов существующих AC-64…70 и PERSONA-AC-20…28 после консолидации.

Локальный clone репозитория в этой среде недоступен из-за DNS. Поэтому
`pnpm control-plane:check`, `pnpm gate:governance`, `pnpm gate:repository`,
PostgreSQL/RLS и browser tests здесь **не запускались**. Нельзя обозначать их
PASS. Проверку удалённого CI после публикации следует читать из GitHub Actions
для фактического commit SHA; этот файл не записывает предсказанный результат.

Источник V1.2 содержит исторические UI-наблюдения, а не полную проверку текущего
backend. Применимость providers, возрастных/consent policy, numerical security
параметров и personal learning context остаётся явно ограничена §28 основной
спецификации. В этой редакции не проводилась новая правовая экспертиза или
внешнее исследование OWASP-источников, унаследованных от V1.

## 5. Что не заявляется

Не заявляются отсутствие всех возможных логических ошибок, готовность 19
кабинетов, реализация permissions, наличие новых API, принятие пользователями
интерфейса, применение миграций или deployment. Опубликована целевая основа,
согласованная по обнаруженным противоречиям; реализация подтверждается только
отдельными проверяемыми пользовательскими результатами.
