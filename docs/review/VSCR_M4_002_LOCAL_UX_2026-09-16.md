# Scratch: local loading and ASA home repair — 2026-09-16

This is bounded evidence for VSCR-M4-002, not a source of task selection or a
claim that all Scratch persistence/security milestones are accepted.
The owner reported working public access but slow startup/library and an inert
ASA wordmark. Per instruction, this investigation made no ASA domain, DNS, TLS
or FRP probes/changes. GitHub remains the source/CI delivery channel.

## Baseline and method

Baseline: `1d6b62e41ccedd991579c4c5960f8e7e0af812f2`. Actual primary port 4613
served its 17,162,296-byte GUI script without gzip. A temporary diagnostic used
the same deployed image on 127.0.0.2:4613, changing only its configured parent
origin to 127.0.0.1:4612. The parent bundled the shipping BlocksEditor; the account
response was synthetic. No working database/account data was read or changed.
The candidate reused identical pinned GUI/media bytes with the changed Nginx
configuration and the same precompression function used by both delivery paths.
This is not a complete authenticated production-home journey.

Chromium used no request interception for timing, so its HTTP cache was real.
Each series had one fresh-context cold load and two warm reloads. All 346 sprite
preview images completed without broken images; no external resource URL or
browser error was recorded. These are local observations, not a statistical
benchmark or an attribution of the owner's delay to their internet connection.

## Measurements

| Measurement                      |         Baseline | Static-gzip candidate |
| -------------------------------- | ---------------: | --------------------: |
| Cold editor ready                |          1.891 s |               1.890 s |
| First visible sprite             |          0.208 s |               0.200 s |
| All 346 sprite previews complete |          1.103 s |               1.334 s |
| Warm editor ready (two samples)  |    0.598–0.671 s |         0.650–0.814 s |
| Warm complete sprite library     |    0.318–0.322 s |         0.342–0.399 s |
| Cold runtime resource transfer   | 21,723,369 bytes |       7,876,554 bytes |
| Cold stock-media transfer        |  4,229,087 bytes |       1,995,455 bytes |
| GUI script response body         | 17,162,296 bytes |       5,754,956 bytes |

Compressed/uncompressed GUI content matches SHA-256
`5d00a74b8acf72e05f25765c59627c0033d753fcf73a8d12f25e6df9922c292f`.
The script transfer is 66.47% smaller. Do not call this a threefold local startup
speed-up: loopback startup did not improve materially, and the measured complete
library was slightly slower in this small sample. The demonstrated gain is less
transfer, not less Scratch parsing/rendering work. Initial dynamic-only gzip was
replaced by build-time static gzip to avoid recompressing the large bundle per user.

## Repair and checks

ASA home is parent-owned, with hover/focus feedback and a confirmation explaining
local .sb3 saving. Cancel preserves the editor; keyboard confirmation invokes the
home callback. The native Scratch Home remains non-navigating; avatar/account and
exact-origin protocol checks are unchanged. The hit target is checked at
1440/1024/390/320 without covering the native Settings menu button. The button's
label text hides at smaller breakpoints; tests use its observed accessible name,
not the hidden decorative span.

Both new regression scenarios failed before the fix: absent ASA home action and
absent gzip encoding. After the fix, all nine local product-integration browser
scenarios passed, including native file/media restoration, timeout/retry and
ready/error footer geometry. Source-focused and final exact-SHA CI results belong
in the GitHub delivery receipt, not inferred from the local browser run.

Two pre-existing JSX shell tests were not matched by the repository's .spec.ts
include. They were converted to createElement and renamed to .spec.ts, without
changing global test discovery. Compression tests check preserved original bytes,
deterministic output, nested static text and exclusion of HTML/binary/small files.
The HTTP regression checks gzip/plain equality, actual compressed Content-Length,
Vary, immutable stock caching, mutable-file revalidation and genuine missing-media 404.

An initial temporary Docker client stalled while adding a bind-mounted config;
no candidate container was created. Only the verified diagnostic clients were
stopped, and a tiny image layer using the same base/helper replaced that diagnostic.
No Docker daemon, production process or transport restart was used for testing.

Local logs/metrics/screenshots are under reports/blocks/local-ux-20260916 and
reports/blocks/product-integration. Preserve them as evidence; do not confuse their
synthetic account or local parent configuration with an authenticated production run.
The owner-observed public access, code tests, deployment and full roadmap acceptance
remain separate. No runtime token, database contract, school/class restriction or
server-save function was added.

## Recovery, impact and acceptance boundary

After the interrupted response, the same 17 changed/untracked paths and existing
local browser/gate logs were inspected before any retry. A local ZIP preserves the
pre-recovery diff. Remote changes since the baseline were only Electronics task
bookkeeping, disjoint from this repair; they were inherited without modifying
that lane or `current.yaml`. No finished build or live deployment was repeated.

Layout impact is L1: only `.blocks-editor-home` is new; the fullscreen geometry,
status footer and account overlay retain their existing styles. Direct consumers
are `BlocksEditor`, its real `ModuleEditorHost` adapter and the product test entry.
No shared generic button, other editor, portal menu or account screen was restyled.
The full product browser suite covers ready/error/loading-retry and account states;
the home test checks logo/Settings hit areas on 1440/1024/390/320, cancel/confirm,
keyboard activation, no child navigation or popup, and the existing account action.
The no-save confirmation is deliberate: returning home discards current local VM
work unless the user first downloads it. It does not promise automatic saving.

This is a navigation/transport repair. The owner reported public access working;
that observation is not a substitute for unperformed deployment or full B/E,
server-save, learning, backup/restore or load-test acceptance. Exact-candidate CI,
independent review limits and any subsequent rollout must be recorded separately.
