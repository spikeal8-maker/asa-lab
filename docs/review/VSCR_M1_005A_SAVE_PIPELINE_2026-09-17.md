# VSCR-M1-005A — связанный путь сохранения Scratch

Выбор задачи опубликован в main отдельным коммитом `3a54a9edf58633331fd466b5f46cb2a8c4f5d390`, issue #285.
Активное состояние определяется только `docs/execution/current.yaml`.
Это Draft-пакет разработки; независимая приёмка перед слиянием/выпуском не отменена.

## Что реализовано

`BlocksProjectPersistence.save`: снимок JSON и mutation identity → проверка существующего
проекта → настоящий закреплённый parser → уникальные костюмы/звуки → проверка байтов
и их MD5 → сохранение ресурсов обязательным adapter → SHA256/размеры → общий
`SaveDraftUseCase` с durability guard. Только затем записывается новая ревизия.
Нет отдельного Blocks draft repository, таблицы проектов или счётчика версий.

`open`: существующий `OpenProjectUseCase` → сохранённый документ → точное множество
ссылок и метаданные → чтение всех ресурсов с проверкой байтов → повторная проверка
доступности проекта. Пропавший или повреждённый ресурс не заменяется пустышкой.
Сохранённый документ не содержит objectKey, физические пути или inline/base64 файлов.

Малое дополнение Project Core — optional generic `ProjectDraftPersistenceGuardPort`.
Существующие вызовы без guard сохраняют прежнее поведение. С guard порядок остаётся:
baseRevision/mutationId → snapshot → доступ → module parse → async guard → единственная
repository.saveDraft. Документ и actor отделены от async-изменений вызывающей стороны.
Новые реализации не зарегистрированы в AppModule и не выставляют HTTP endpoint.

## Проверка содержимого

Официальный `scratch-parser` 6.0.1 расположен только в API, не в Web или Project Core.
Вход — только ограниченный JSON, не пользовательский ZIP. Дополнительно проверяются
точные assetId/dataFormat/md5ext, отсутствие пропусков/лишних/дублированных canonical refs,
совпадение tenant/digest/size/format и committed metadata. Дубликаты в графе допустимы:
два спрайта с одним костюмом используют одну каноническую ссылку.

Пределы: JSON 16 MiB, отдельное изображение 10 MiB, звук 25 MiB, сумма уникальных
ресурсов 250 MiB. Ограничения JSON/суммы можно только снижать при создании guard.
Parser-repaired JSON не выдаётся за побайтно прежний документ: такой вход отклоняется.

## Исполняемое доказательство

Интеграционные тесты используют настоящие SaveDraftUseCase/OpenProjectUseCase,
настоящий parser и файловые TEST adapters во временном каталоге. Записываются блоки,
координаты спрайта, переменная, PNG-костюм и WAV-звук. Новый экземпляр reader читает
данные с диска и восстанавливает JSON и те же байты без исходного VM source.
Это не доказательство HTTP/браузерного сохранения или production PostgreSQL/S3.

Проверяются повтор потерянного ответа с прежними mutationId/baseRevision,
конфликт двух писателей вместо перезаписи последним, отзыв доступа и удаление проекта,
ошибки/искажения ресурсов, metadata и parser, snapshot во время async-записи.
Общий SaveDraftUseCase тоже проверяется напрямую: validator нельзя обойти его вызовом
в правильно собранной композиции. Соседние модули используют прежнюю семантику.

его AGPL-3.0-only лицензия; для `jszip@3.10.2` выбран MIT из выражения
`(MIT OR GPL-3.0-or-later)`. Проверяется точное имя/версия/выражение лицензии.
Другой пакет, версия, несколько версий или GPL-only не проходят это исключение.
Общий allowlist лицензий и запрет high/critical advisories не расширены.
Парсер не используется как основание заявлять безопасный импорт произвольных ZIP.

Первоначальный interrupted-срез восстановлен из существующего dirty checkout без
удаления файлов или повторного создания задачи. Исправлены типы тестового Project,
clone/validation order, проверки trashed при open и отсутствующая проверка лицензий.

## Граница результата и следующая интеграция

На сайте новая функция ещё не включена. В A нет реального S3/blob metadata adapter,
HTTP-контроллера, VM-save hook, Account/StudentSeat adapter, autosave и кнопки сохранения.
Файловые TEST adapters не поставляются как рабочее хранилище. Код намеренно не
импортирует неподключённый capability helper из PR278 и не меняет его приёмку.

Перед следующим выпуском нужны настоящие adapter с проверкой содержимого файлов,
квот/прав, неизменяемости alias и blob-before-metadata. После загрузки некоторых
файлов и сбоя документа эти файлы могут остаться orphaned; предыдущий draft цел.
Это не одна атомарная транзакция между объектным хранилищем и PostgreSQL.
Удаление orphaned blobs и backup consistency остаются отдельными обязанностями.

В будущей production composition один и тот же guard обязателен для всех путей
записи, включая общий PUT draft. Нельзя включить только Blocks-контроллер и оставить
обычный SaveDraftUseCase без guard: это будет обход проверки. Optional constructor
оставлен только для обратной совместимости до интеграции; он не означает готовую
защиту уже работающего generic API. Нет новых claims о server save в интерфейсе.

## Исправление прямого HTTP-потребителя после CI

Общий CI выявил неполную таблицу HTTP-статусов в существующем ProjectsController:
новый ProjectErrorCode `dependency_unavailable` отсутствовал в Record. Добавлено
точное отображение в 503. Это исправление прямого потребителя нового результата,
не включение нового контроллера/маршрута или production persistence guard.
Добавлены шесть unit-регрессий всех ProjectErrorCode через существующий saveDraft-метод: 400/503/409/404
не превращаются в успешный ответ и не переходят к повторному открытию/анализу.
Они не являются проверкой реального HTTP-сервера или действующих аккаунтов.
