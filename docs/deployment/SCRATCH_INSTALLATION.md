# Scratch: штатная установка и обновление

## Обязательный маршрут для оператора и бота

Scratch — встроенный модуль `blocks` одной ASA Lab, а `scratch` — имя его
сервиса в общем `compose.yaml`. Директория `infra/scratch-editor`, отдельный
Dockerfile/образ, слово `standalone`, runtime-origin или внутренний порт 8080
не обозначают новую систему для установки. Аккаунты, навигация и Project Core
принадлежат ASA; отдельные пользователи, БД и backend Scratch не создаются.

| Запрос                                           | Действие                                                                                                    | Недопустимая подмена                                                                        |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Первый запуск на действительно новом компьютере  | [Quick Start](QUICK_START.md): один clone/ZIP и общий startup ASA                                           | Отдельно устанавливать Scratch после ASA                                                    |
| Обновить работающую ASA или исправить её Scratch | [Guarded update](GUARDED_UPDATE.md) из каталога работающей PostgreSQL, с прежним Compose project и overlays | Новый clone как новая установка, `docker run` для рабочего Scratch, новый project name      |
| Порт занят или редактор не открывается           | Установить владельца порта, origin и причину ошибки в той же установке                                      | Перебирать свободные порты/loopback-адреса, клонировать runtime или выключать origin-защиту |
| Проверить код                                    | Изолированный CI; локальный отдельный стенд только по явному разрешению                                     | Оставить диагностический контейнер как постоянный сервис или выдать TEST за production      |

Новая версия проекта не требует нового порта, домена, базы или контейнерного
Compose-проекта. Updater может заменить контейнеры сервисов внутри прежней установки.
Отдельная сборка образа не равна отдельному развёртыванию продукта.

### Сначала найти установку, не выбирать первый контейнер

До команд изменения собрать read-only snapshot работающих PostgreSQL и их
Compose metadata. Эти команды не печатают environment или секреты:

```powershell
$ids = @(docker ps -q --filter "label=com.docker.compose.service=postgres")
if ($LASTEXITCODE -ne 0) { throw "Не удалось прочитать Docker." }
foreach ($id in $ids) {
    $record = @(docker inspect $id | ConvertFrom-Json)[0]
    if ($LASTEXITCODE -ne 0) { throw "Не удалось проверить контейнер $id." }
    [pscustomobject]@{
        Container = $record.Name
        Project = $record.Config.Labels."com.docker.compose.project"
        Directory = $record.Config.Labels."com.docker.compose.project.working_dir"
        ComposeFiles = $record.Config.Labels."com.docker.compose.project.config_files"
    }
}
```

Сопоставить выбранную владельцем основную установку с каталогом PostgreSQL,
приватным `.env`, Compose files и томом БД. При нескольких кандидатах, пустом
working_dir или конфликтующих метках — STOP, не создавать новую установку.
Далее проверить Web/API/Scratch той же установки, их revision и опубликованные
порты. Не считать одиночную метку `project=asa-lab-dev` достаточным доказательством:
диагностический образ/контейнер может содержать старые service/project labels.

Старые TEST-стенды и одиночные проверочные контейнеры — отдельные объекты аудита.
Их не нужно обновлять, переименовывать, подключать к порталу или удалять вместе
с основной установкой. Очистка требует точного списка объектов и разрешения;
`down --volumes`, глобальный prune и остановка Docker/WSL не являются ремонтом Scratch.

## Один переносимый состав

`compose.yaml` содержит PostgreSQL, миграции, API, Web и Scratch. Scratch всегда
активен в реестре; `ASA_BLOCKS_PREVIEW` не управляет доступом. Стандартные
`tools/asa-lab.ps1 up` и `tools/asa-lab.sh up` включают редактор автоматически.
`compose.blocks-preview.yaml` оставлен только как совместимый overlay: он не создаёт
второй обязательный runtime и не нужен для штатного первого запуска или обновления.

Сборка Scratch использует закреплённый upstream SHA из `infra/scratch-editor/upstream.env`,
проверяет версию и контрольные суммы ресурсов, применяет принятую ASA-настройку,
готовит сжатые файлы. Она не читает каталоги D2-R2-X, backups, временные скриншоты
или истекающие Actions artifacts. Нужны Docker и доступ к источникам зависимостей
при первой сборке; отсутствие сети или памяти не может гарантированно компенсироваться
инсталлятором. Ошибка сборки останавливает запуск до замены рабочих контейнеров.

Первичный локальный запуск поддерживается из Git clone и распакованного исходного ZIP.
Для ZIP без `.git` ревизия будет `unknown`; это не доказательство exact-SHA сборки.
Для обновляемого сервера используйте clone. Не переносите чужие `.env`, дампы и токены.

## Локальные адреса

По умолчанию основной вход — `http://127.0.0.1:4610`, runtime —
`http://localhost:4613`. Оба порта слушают только loopback. Это разные origin и
разные имена узла; runtime не разделяет cookies с порталом по `127.0.0.1`.
Открывайте основной вход именно по указанному адресу. Нестандартные порты (`ASA_WEB_PORT`, `ASA_BLOCKS_PORT`) задаются только по
явно согласованной топологии до сборки, не выбираются ботом при каждой версии.
У существующей установки сохраняются прежние значения.

`4610` — вход в ASA; `4613` — уже предусмотренный endpoint её сервиса Scratch;
`8080` — порт внутри контейнера, его не открывают на хосте дополнительно.
Пользователь открывает портал, создаёт/выбирает программу и работает в редакторе
внутри ASA. Переход пользователя прямо на runtime не является штатным входом.
Порт — часть origin, но сам по себе не изолирует cookies: не заменять разные
имена узла одним именем только с разными портами.

Для собственного домена или школьной сети задаются два точных адреса до сборки:
`ASA_BLOCKS_PARENT_ORIGIN` — портал, `ASA_BLOCKS_RUNTIME_ORIGIN` — отдельный runtime.
Origin не содержит путь или завершающий `/`. Для HTTPS-портала нужен HTTPS-runtime.
Автоматическое создание DNS/TLS/туннеля не является частью локального `up`.

## Обновление существующей установки

Используйте guarded updater из каталога, определённого работающей PostgreSQL.
Он сохраняет БД и rollback-образы, проверяет exact-SHA общий CI, собирает сервисы
последовательно и после запуска проверяет также Scratch. Пароли и origin не
переопределяются. Движение main после проверки CI останавливает обновление.

Старый локальный `compose.frp.yaml` мог содержать `services.scratch.build.context`
с абсолютным путём в `backups/.../runtime-context` и `Dockerfile.artifact`.
Перед переходом сохраните этот файл и уберите **только** его `services.scratch`
секцию: новый основной Compose уже содержит сервис. Остальные настройки транспорта,
Web и секреты не переносите и не удаляйте. Не используйте старую временную папку
для будущих сборок. Наличие такого legacy override требует явной миграции оператором.

Штатное обновление всегда собирает весь состав из текущих исходников.
Ни режим пропуска сборки, ни ручная подстановка артефакта для этого не нужны.

## Что означает успешная проверка

`up`/`health` завершаются успешно только при готовых Web/API и Scratch одной ревизии.
Содержимое проектов Scratch пока сохраняется локально в `.sb3`, не в аккаунте ASA.
В рабочем редакторе постоянная нижняя полоса отсутствует; ошибка подключения и
кнопка повтора показываются только при проблеме. При возврате через ASA Lab
сохраняется предупреждение о потере несохранённой работы.

## Контейнер healthy, но порт Scratch недоступен

У runtime отдельная bridge-сеть без API и PostgreSQL, но не `internal: true`: в
проверенной конфигурации Docker сеть только internal не публиковала порт на хост.
Временный тест подтвердил `docker exec ... healthz = ok`, но отказ соединения с
loopback-портом; подключение отдельной обычной bridge-сети восстановило HTTP 200.
Не решайте это общим network_mode=host, публикацией API/БД или снятием origin-защиты.
Проверяйте `/healthz` через опубликованный порт, а не только внутри контейнера.
Новый CI проверяет оба локальных имени до входа и открытия редактора.

Сгенерированный dev-педагог связан со школьным workspace. Для его API-входа нужны
`workspace`, `email`, `password` из сгенерированной конфигурации; вызов личного
входа без workspace не является проверкой школьного seed. Рабочие пароли не
копируются в тесты и не отключается проверка авторизации.
