# Админ → Логи: критический разбор и контракт

## Разбор до реализации

1. Docker stdout принадлежит контейнеру, а не установке. При замене контейнера
   исчезает история. Сохранение должно выполняться независимо от Web/API и до
   следующего обновления. Повторный сбор не может восстановить уже удалённые записи.
2. История администраторов и аналитика в PostgreSQL не содержат всех технических
   ошибок. Ошибки вкладки/iframe/worker необходимо сообщать отдельно. Отсутствие
   сообщения о сбое не доказывает отсутствие сбоя: браузер может аварийно закрыться
   или потерять сеть до отправки.
3. Доступ API к Docker socket, произвольным путям и shell создал бы возможность
   управления сервером через страницу журналов. API читает только подготовленные
   сегменты; источники собирает отдельный host runner с существующим доступом
   оператора к Docker. Публичных портов и второго Compose project нет.
4. Чтение недельных файлов и упаковка на основном потоке API мешали бы ученикам.
   Поиск и экспорт выполняются в worker с ограничением времени, объёма и числа
   одновременных операций. Экспорт — фоновая задача с повторной проверкой доступа.
5. Технический журнал может раскрыть секреты, документы и сведения о других
   школах. Общие журналы доступны только существующему platform permission
   `administration.operations.read`; учебные payload и cookies не принимаются
   клиентской диагностикой, известные секреты очищаются перед сохранением.
6. «Все журналы» не означает гарантированную полноту. Для каждого источника
   показываются время последнего успешного сбора, границы сохранившихся записей,
   ошибки/ограничения доступа. Windows Security без прав остаётся недоступным.
7. Бесконечное хранение заполнит диск. Срок хранения — 30 дней по умолчанию;
   размер и рабочие архивы ограничены. При очистке удаляются только записи
   диагностического хранилища. Пользовательские данные и backup dumps не затрагиваются.

## Выбранная архитектура

Host collector (Python standard library) → собственный SQLite индекс →
атомарно опубликованные сегменты JSONL и catalog → read-only mount API →
worker поиска/ZIP → защищённая страница «Логи».

SQLite используется только host collector; общий Windows/Linux WAL не передаётся
в контейнер. API читает завершённые сегменты. Идентификатор записи обеспечивает
повторяемый сбор без дубликатов. Настройки источников хранятся вне исходников.

Источники: все контейнеры канонической установки; системные события Windows;
Docker Desktop; зарегистрированные файлы туннеля, обновлений и backup; таблицы
событий PostgreSQL. Недоступный источник имеет отдельный статус, а не пустой PASS.

Клиент сообщает ограниченные коды ошибки, модуль и версию. Текст исключения,
содержимое проектов, URL query, browser storage и авторизационные данные не
отправляются. Повторения ограничены на клиенте и на сервере; недоступная
диагностика не меняет вход и сохранение проекта.

## Приёмка

- Anonymous, StudentSeat и organization admin получают отказ на просмотр,
  экспорт, статус задачи и скачивание; отозванный доступ проверяется повторно.
- Потерянный ответ, повторный сбор и замена контейнера сохраняют историю.
- Проверяются очистка секретов, недоступный/устаревший collector, неправильные
  даты/cursor/source, выход за каталог, повреждённый сегмент, большие архивы.
- Поиск по источнику, модулю, уровню и периоду; время отображается по Москве.
- Архив содержит выбранные записи и сведения о полноте; ZIP проверяется.
- Страница проверяется на 1440/1024/390/320, включая загрузку, пустые записи,
  длинные сообщения, ошибку и готовность скачивания.
- Не выполняется очистка production logs, БД, volumes или существующих архивов.

## Эксплуатация

### Установка сборщика

После публикации и обычного обновления канонической установки:

```powershell
.\tools\install-log-collector.ps1
```

Windows: задача `ASA-Lab-Logs-<project>` запускается от текущего пользователя
Docker Desktop; при закрытой пользовательской сессии сбор недоступен. Права
не повышаются автоматически. Недоступные каналы, включая Security, видны отдельно.

Linux: `sudo sh tools/install-log-collector.sh` создаёт systemd службу.
Каталог опубликованных сегментов доступен группе 1000 контейнера API;
закрытый SQLite индекс остаётся доступен только сборщику. Пользователь службы
должен уже иметь доступ к Docker канонической установки.

Настройки: `.asa/log-collector.json`. `project` берётся из
`.asa/installation.json`; `retentionDays=30`, `maxBytes=1073741824`,
`intervalSeconds=20`. Дополнительные каталоги задаются оператором через
`fileSources: [{"source":"backup","path":"абсолютный каталог"}]`.
Windows installer находит журналы резервных копий рядом с установкой и
`logs/service-logs` рядом с ASAFrpc. Каталог журнала может содержать `.log`
или ротации `.log.*`/`.out.*`; конфигурационные и credential файлы не собираются.

SQLite, сегменты и каталог находятся в `.asa/diagnostics`. При достижении лимита
удаляется самая старая сохранённая история. Временные пики во время чтения,
SQLite VACUUM и публикации требуют свободного места сверх лимита хранения.
Первое заполнение выполняется частями; `обработано по` показывает ход обработки.
Docker/Windows стартуют с последних семи дней; таблицы событий сверяются за
весь срок хранения, свежие события дополнительно перечитываются с перекрытием.
Старые удалённые контейнеры, журналы и сообщения, не отправленные браузером,
не восстанавливаются автоматически. Существующие ZIP и backups сохраняются.

Резервная копия приложения включает БД, объекты и конфигурацию. Независимый
каталог журналов сохраняется на хосте и не входит в этот снимок; это явно
отмечается в manifest как `externalDiagnostics`. Его отдельная копия создаётся
через **Скачать все журналы**. Backup допускает только точный каталог
`.asa/diagnostics/store`, подключённый API для чтения; произвольные новые
каталоги и тома по-прежнему блокируют неполную резервную копию.

### Пользование

Открыть **Админ → Логи**. По умолчанию показаны ошибки за семь календарных
дней. Выбрать даты, источник, модуль, уровень или текст; нажать **Показать**.
**Скачать все журналы** включает все сохранившиеся источники за выбранные даты;
**Скачать ошибки** — ошибки за те же даты. Остальные экранные фильтры на эти
две кнопки не влияют. Дождаться готовности и нажать **Скачать ZIP**.

Архив содержит JSONL записи, manifest со статусами источников и README.
Размер исходных записей ограничен 256 MiB, ZIP — 64 MiB; при превышении нужно
сократить период. Одновременно создаётся один архив, сохраняется не больше
трёх архивов на API; они удаляются через час при следующем обращении к странице.
После перезапуска API нужно собрать архив снова. Скачанные файлы остаются у
пользователя. Эти лимиты не затрагивают собственные проекты и резервные копии.

Проверки: `corepack pnpm test:admin-logs`; после сборки Web —
`corepack pnpm e2e:admin-logs`. CI запускает Python regression и browser gate;
общий Vitest suite также включает серверные тесты. Windows adapter отдельно
проверяется на Windows с синтетическими каналами и на живой установке.

Добавление страницы в исходники и запуск службы не равны публикации Web/API:
для канонической установки применяется обычный проверенный выпуск и менеджер.
