# Универсальные команды ASA Lab после проверенной установки

Зависимое изменение к [ASA Unified Setup #845](https://github.com/spikeal8-maker/asa-lab/pull/845),
[программа #792](https://github.com/spikeal8-maker/asa-lab/issues/792).

После подтверждённой штатной установки ASA Lab регистрация предоставляет три команды:

| Команда | Результат |
| --- | --- |
| `asa status` | Краткая информация об установленном выпуске, схеме, Docker и последней операции; только чтение. |
| `asa check` | Официальная проверка релиза и окружения; без миграции или переключения контейнеров. |
| `asa update` | Только штатный транзакционный update с сохранением PostgreSQL/MinIO и проверкой источника. |

## Linux / Ubuntu 24.04 amd64 / 1Panel

После **успешной принятой** операции из неизменяемого аттестованного
ASA Setup в `/opt/asa-setup/<40SHA>` регистрируется root-owned
`/usr/local/bin/asa` и реестр `/etc/asa-lab/commands.json`.
В интерфейсе 1Panel выполняйте те же команды. Под sudo пакет запускается
как корень, но сам setup запускает Git, Docker и приложенческий менеджер
от подтверждённого владельца установленного checkout.
Root SSH из внешней сети разрешать не требуется.

`asa check` вызывает проверку в закреплённом setup bundle,
а `asa update` — его существующий `auto` **только при наличии
валидного installed-release.json и .asa/setup.json**.
Отсутствующая/другая установка не превращается в новую пустую установку.
Состояние Docker и база никогда не удаляются командой-обёрткой.

## Windows / Docker Desktop

После принятого `tools/asa-setup.ps1 -Apply` создаётся
`%LOCALAPPDATA%\ASA-Lab\cli\asa.cmd` и пользовательский реестр установок.
В пользовательский PATH добавляется только этот каталог; откройте новое окно
PowerShell/CMD после установки. Системный PATH, VPN, firewall, Docker
Desktop, чужие контейнеры и другие учётные записи не меняются.
Проверка вызывает существующий Python manager, обновление —
`tools/asa-setup.ps1 -Mode update -Apply` с исходными guard/backup.
Windows bootstrap проверяет SHA256 добавленного asa_cli.py.

## Неоднозначность установки и восстановление

На одном Docker Engine могут существовать независимые проекты.
В реестре фиксируются действительные каталоги, project и profile.
Если зарегистрировано несколько, команда без `--root` останавливается.
Для выбора применяйте `asa status --root /srv/asa-lab` или
`asa update --root C:\ASA-Lab`.
Иностранный корень, symlink/junction, несовпадение project/profile,
повреждённый реестр, отсутствие точного published-release receipt,
занятое чужой программой имя `asa` и неполная операция — причины отказа.

## Проверки перед объединением

- Ubuntu: Python unit+negative, сборка подписываемого immutable setup bundle,
  реальная чистая установка и обновление независимого QA Docker project
  с no-change, проверкой данных и выводом CLI.
- Windows: Parser PowerShell 5.1/7, CLI unit+negative, verified bootstrap,
  отдельная Docker QA установка и update со сохранением project/ports/volumes.
- CI запускается на точном SHA зависимого PR; требуется независимый review.

**Текущее состояние:** новая CLI-реализация находится в отдельном PR от
Linux Unified Setup #845. Ни #845, ни настоящая публикация подписанного
setup-release пока не подтверждены. Утверждать возможность установки
на любой сервер до прохождения реального Ubuntu/Windows испытания нельзя.
Прототип `/usr/local/bin/asa` на H03 не использовался как канонический код.
Существующий чужой исполняемый файл не будет перезаписан автоматически.
