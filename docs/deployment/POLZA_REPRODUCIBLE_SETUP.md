# Polza AI — переносимая настройка после установки ASA Lab

**Цель:** один и тот же официальный Docker-релиз из GitHub должен давать одинаковые
возможности Polza AI на D2R2, тестовом сервере и следующей установке. Работающий
API не означает, что модели доступны пользователю: нужны отдельный сохранённый
ключ, действующий каталог, выбранная модель и разрешение в политике генерации.

Эта операция **не переносит** .env, зашифрованные API-ключи, пользовательские данные,
PostgreSQL/MinIO volumes и историю чатов на другой сервер. Секреты в GitHub не
сохраняются. Обновление приложения выполняется штатным tools/asa_manager.py update
с проверенным релизом. Оператор ниже запускается **отдельно, после развёртывания**.

## Одинаковая процедура на Linux/Compose-сервере

1. Установить официальный релиз ASA Lab через защищённый менеджер из GitHub,
   подтвердить готовность API/Web и соответствие SHA образов.
2. Войти под администратором платформы и открыть
   **Админ → ИИ → Подключения → Polza AI**. Сохранить свой API-ключ через
   форму и включить провайдера. Не копировать тестовую БД ради каталога.
   Если база восстановлена из архива, сохранённый зашифрованный ключ можно
   использовать **только с исходным ключом ASA_SETTINGS_ENCRYPTION_KEY**.
3. Запустить безопасную проверку (без обновления данных):

       cd /srv/asa-lab
       docker compose -f compose.yaml -f compose.production.yaml exec -T api \
         node tools/polza-reconcile.mjs --check \
           --model polza/deepseek/deepseek-v4.1-flash

   Если модель ещё не выбрана, код возврата — 2, поле chatReady=false.
4. На сервере с **единственным** администратором платформы получить
   идентификатор для записи с аудитом:

       export ASA_POLZA_ACTOR="$(
         docker compose -f compose.yaml -f compose.production.yaml exec -T postgres \
           sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -At -c "SELECT p.id FROM public.principals p WHERE public.admin_authorized_role(p.id, '"'"'platform'"'"', NULL) = '"'"'platform_admin'"'"';"'
       )"

   При нескольких администраторах необходимо указать конкретный
   авторизованный ID. Скрипт проверяет роль platform_admin в БД.
5. Применить только необходимые изменения:

       docker compose -f compose.yaml -f compose.production.yaml exec -T api \
         node tools/polza-reconcile.mjs --apply \
           --model polza/deepseek/deepseek-v4.1-flash \
           --actor "$ASA_POLZA_ACTOR"

   Если каталог отсутствует или неактуален, выполняется ограниченный
   запрос метаданных GET /models. Если указанной модели нет,
   операция прекращается **до изменения разрешений**.
   Выбранные ранее модели, системный промпт, модель по умолчанию, квоты
   и другие провайдеры не изменяются. Используются существующие
   серверные функции Polza и политики генерации с проверкой
   ревизии, роли и аудитом. Платной генерации текста, речи и изображений нет.
6. Если подтверждены необходимые условия обработки школьной речи внешним
   провайдером и оператор **явно** решил разрешить STT, выполнить отдельно:

       docker compose -f compose.yaml -f compose.production.yaml exec -T api \
         node tools/polza-reconcile.mjs --apply --enable-stt \
           --model polza/deepseek/deepseek-v4.1-flash \
           --actor "$ASA_POLZA_ACTOR"

   Это использует действующие суточные лимиты. Без --enable-stt
   состояние распознавания речи **не меняется**, аудио не отправляется.
   Пользовательское подтверждение передачи записи остаётся обязательным.
7. Повторить --check. Ожидаются catalogCurrent=true, selected=true,
   allowed=true, modelAvailable=true, chatReady=true. Повторный --apply
   должен вернуть applied=[]; ненужных повторных записей нет.

## Ошибки и безопасный повтор

- **CREDENTIAL_NOT_READY:** ключ не настроен, шифрование недоступно
  или провайдер выключен. Исправить в административной панели.
- **REQUESTED_MODEL_UNAVAILABLE:** каталог не содержит указанную
  текстовую модель. Проверить актуальный ID и доступность у провайдера.
- **PROVISIONING_OPERATION_FAILED:** ошибка подключения, доступа
  или конфликт конкурентных изменений. Проверять серверные журналы
  без раскрытия секретов. Повторить --check перед --apply;
  успешные предыдущие шаги сохраняются.
- Скрипт не создаёт администратора, не правит аккаунты, не запускает
  миграции, не отправляет платные запросы и не обходит квоты.
- Реальный тест аудиотранскрибации и пользовательского интерфейса
  выполняется отдельно по HTTPS под авторизованной учётной записью.

## Технический контракт

- Dockerfile.api содержит две утилиты из GitHub в официальном API-образе:
  tools/polza-reconcile.mjs и tools/polza-reconcile-core.mjs.
- APP_DATABASE_URL и ASA_SETTINGS_ENCRYPTION_KEY читаются только из
  окружения действующего API; значения ключей не принимаются в аргументах.
- --check строго read-only; --apply требует UUID администратора.
- Каталог Polza, выбор модели и политика генерации проверяются независимо.
- Повторная настройка не удаляет уже разрешённые модели, промпт или ключи.
- Контрактные тесты: node --test tools/test-polza-reconcile.mjs.
- Production H-04 не обновляется при прохождении CI тестового сервера.
