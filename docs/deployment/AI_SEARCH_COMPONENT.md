# Внутренний бесплатный поиск ASA

Поиск — компонент `search` той же установки Compose, а не отдельный проект,
публичный сайт или дополнительный порт. API обращается к `http://search:8080`.
Недоступность компонента не мешает запуску обычного чата/API: режим интернета
возвращает понятное состояние недоступности. Состояние `healthy` само по себе
не доказывает успешный поиск во внешнем интернете.

## Что запускается

ASA-образ оборачивает официальный SearXNG `2026.10.25-54ca1d9cf`, upstream commit
`54ca1d9cfb08674f66261d7f351b063558dfcc62`. Индекс образа закреплён SHA256
`23482d8ecf7ddf66029479468ea04c1bb11d2b65785a17a7e629e2ffd13296ca`.
OCI revision ASA-образа и файл `asa-commit.txt` содержат SHA выпуска ASA.

Зарегистрирован закрытый список бесплатных движков: Bing, DuckDuckGo,
Wikipedia и поиск картинок Bing/DuckDuckGo. Платные API не подключаются,
учётные записи и внешние API-ключи не нужны. Все плагины отключены;
autocomplete, внешний image proxy и HTTP access log отключены. Запросы
обрабатываются в JSON, русский язык и SafeSearch включены по умолчанию.
Блокировки, CAPTCHA и лимиты внешних поисковиков не обходятся. Бесплатный
метапоиск не имеет SLA и не гарантирует доступность каждого источника.

Погодный адаптер использует бесплатные MET Norway и ограниченный поиск города
Nominatim, без погодного API-ключа. Доверенная настройка
`ASA_AI_GEOCODER_ENDPOINT` в закрытом `.env` позволяет заменить геокодер без
редактирования исходников; по умолчанию это `https://nominatim.openstreetmap.org`.
Она не принимается от браузера. Публичный Nominatim — только для явно
запрошенного города: общий лимит 1 запрос/с, ограниченный объём и кэш,
без autocomplete или массового поиска адресов. См.
[обязательную политику Nominatim](https://operations.osmfoundation.org/policies/nominatim/).

Сервис работает без root, на read-only filesystem и tmpfs, только в сети
`application`; он не подключён к БД. Host-порты и новые volumes отсутствуют.
Лимиты: 512 MiB RAM, резерв 128 MiB, 1 CPU, 128 процессов/потоков. Это
изоляционные ограничения, а не доказательство пропускной способности. Новая
возможность поддерживается в обычном Docker Linux/amd64 сценарии ASA, включая
Docker Desktop/WSL2 на Windows; для других CPU-архитектур готовность не заявлена.

## Секрет и обновление

`ASA_SEARCH_SECRET` — локальный ключ подписи SearXNG, **не ключ платного API**.
Он генерируется однократно в существующем закрытом `.env` при разрешённой
установке/обновлении. Он не переиспользует ключи моделей, сессий или БД.
Проверки `doctor`, `--check` и `-CheckOnly` секрет не создают.
Пустой, некорректный или дублированный уже заданный ключ не заменяется молча.

Нормальное обновление сохраняет значение. Компонент получает только свой ключ,
создаёт временный private settings-файл в tmpfs и не пишет запросы в логи.
Полный экспорт ASA уже включает закрытый `.env` как `private.env`, поэтому
ключ перемещается вместе с установкой. Нового отдельного хранилища данных нет.
Ротация — отдельное действие владельца: разрешённая остановка компонента,
защищённое изменение единственного поля и штатное обновление. Она инвалидирует
внутренние подписи, но не меняет историю чата, БД или ключи моделей.

Новый portable manifest `asa-deployment-v2` требует все пять ASA-образов:
API/Web/Scratch/MinIO/Search. Исторический `asa-deployment-v1` остаётся строго
четырёхкомпонентным и не объявляется имеющим поиск. Проверки SHA и образов
старых компонентов не ослабляются. Установка нового выпуска проходит через
существующий защищённый updater/менеджер; ручной второй Compose stack не нужен.

## Проверки

Локальный source-only gate:

```text
python -m unittest discover -s tools/deployment -p test_search_component.py -v
```

Он проверяет закрытые engines, настройки безопасности, immutable pin,
совместимость manifest v1/v2, однократную генерацию в синтетическом файле,
сохранение байтов и read-only check. Он не обращается к Docker, рабочему `.env`
или внешним поисковикам. Portable delivery CI дополнительно запускает настоящий
контейнер, проверяет его SHA, health и фактически зарегистрированные engines и HTTP 200/JSON для запроса на ru-RU.
Количество реальных upstream-результатов выводится отдельно: пустой успешный
JSON не объявляется качественным ответом внешних поисковиков.
Реальный поиск, погода и пользовательский browser journey подтверждаются
отдельно; контейнерный smoke не заменяет эту приёмку.
