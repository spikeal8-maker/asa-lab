# Изоляция аналитики от входа и сохранений

## Граница пункта 3

Основание: диагностика работы 23 октября 2026 года, 09:00–16:00 МСК.
В интервале 14:49–14:51 наблюдались ошибки API/базы, очередь основного пула
и таймауты аналитики. Это подтверждает необходимость ограничения нагрузки,
но не доказывает, что аналитика была единственным инициатором происшествия.

До изменения запись ProductAnalytics уже использовала отдельный пул PostgreSQL,
но контроллеры v1/v2 проверяли Account/Seat cookie через основной пул до допуска
в ограниченную очередь. Таким образом, поток телеметрии всё ещё мог занимать
соединения, нужные входу и сохранению проектов.

## Контракт

- Допуск в существующую очередь выполняется **до SQL проверки cookie**.
  Максимум 256 операций вместе с выполняющейся; одновременно работает одна.
- Проверка текущих Account и Seat сессий и запись выполняются одним заданием
  на существующем выделенном пуле аналитики: максимум одно соединение.
  Дополнительный пул и увеличение бюджета соединений не нужны.
- Account/Seat проверки последовательны; лишний поток запросов не создаёт
  неограниченную очередь ожидания соединения PostgreSQL.
- Используются существующие авторитетные резолверы: отзыв, срок действия,
  актуальные реквизиты Seat и конфликт двух активных cookie сохраняются.
  Кэша разрешений нет. Первичная материализация principal Seat сохраняется,
  но выполняется на пуле аналитики.
- Переполнение возвращает `429 telemetry_capacity`; отказ БД или истечение
  ожидания — `503 telemetry_unavailable`. Они не превращаются в `401`.
  Действительно недействительная сессия по-прежнему возвращает `401`.
- V2 подтверждает только проверенную квитанцию `persisted`; механизм UUID
  повтора и проверки совпадения actorExpectation сохраняется.
- V1 сохраняет успешные HTTP/JSON контракты. Его инфраструктурный отказ теперь
  явно возвращает 429/503, а не маскируется ответом об успешном приёме.
- Внутренний контекст допуска принадлежит конкретному экземпляру сервиса,
  запрещает повторное вложенное задание и вторую/параллельную запись.
  Он инвалидируется в `finally`, поэтому отложенная работа не наследует
  разрешение обходить очередь после завершения задания.
- Задание без успешной записи не увеличивает `persisted`. Фоновые наблюдения
  входа остаются неблокирующими и используют прежнюю очередь/повторы.

## Проверка

Focused gate: `pnpm test:session-database` — 81 тест, 11 файлов.
Сборка API и зависимостей, затем итоговая проверка типов API — PASS.

Новый PostgreSQL regression в `test:session-database:pg` запускается только
на изолированной базе `*_test` через GitHub workflow Session Context Database:
занимает единственное соединение аналитики, подаёт 16 запросов телеметрии,
проверяет ограниченную очередь и одновременно выполняет настоящие SQL создания
сессии/проверки входа, сохранение и чтение черновика проекта через основной пул.
После освобождения соединения проверяет квитанции; после отзыва сессии
следующее событие должно получить отказ. Результат PostgreSQL-прогона следует
оценивать по точному SHA GitHub Actions, а не по наличию этого описания.

## Ограничения эксплуатации

Это изоляция соединений приложения. PostgreSQL, CPU, диск и общие блокировки
остаются общими; неисправная база может повлиять на все операции.
Одна последовательная очередь ограничивает пропускную способность аналитики;
при перегрузке часть событий отклоняется/истекает, а не считается сохранённой.
Очередь в памяти не является долговечной. Результат с поздней квитанцией после
таймаута ответа остаётся неоднозначным до повтора с тем же UUID.

Изменение не подтверждает нагрузочную ёмкость 5000 пользователей, не исправляет
Arduino/конфликты сохранений/IP, не изменяет рабочую БД и не обновляет сайт.
Внедрение требует отдельного выпуска API; новой миграции для пункта 3 нет.

## POST_STEP_REVIEW

- STEP: изолировать авторизацию и запись фоновой аналитики от основного пула.
- CHANGE_CLASS: L3_CRITICAL.
- USER_RESULT: поток телеметрии ограничен до проверки cookie и не занимает
  основной пул производственной фабрики API.
- INVARIANTS_TOUCHED: текущая серверная авторизация, truthful ACK, bounded queue.
- LAYOUT_IMPACT / VIEWPORTS / VISUAL_EVIDENCE: none / n/a / n/a.
- NEGATIVE_CHECKS: capacity до SQL; ошибка БД не 401; mixed/mismatched actor;
  отсутствие записи не persisted; nested/stale/cross-instance admission.
- DOC_DRIFT: none.
- UNVERIFIED: фактическая ёмкость 5000 пользователей; эксплуатация на сайте;
  PostgreSQL evidence ожидается в GitHub на итоговом SHA.
- AUTHOR_VERDICT: PASS для реализации и локальных focused checks;
  независимый challenge review и GitHub PostgreSQL gate выполняет контроллер.
