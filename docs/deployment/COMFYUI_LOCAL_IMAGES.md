# ComfyUI: локальные изображения, RTX 3060 12 ГБ и подключение по сети

Поисковые названия: **ComfyUI**, «Config UI», Flux 2 / FLUX.2 Klein 4B,
12 GB VRAM, видеокарта 3060, энкодер Qwen3 4B, изображения по IP.

Это единая эксплуатационная инструкция для оператора и бота. Профиль ниже
зафиксирован 28 октября 2026 года. Он не устанавливает модели, не обновляет
рабочий сервер и не означает приёмку ASA Lab на другом компьютере.

## Быстрый маршрут для бота

1. Прочитать эту страницу, затем [профиль](comfyui/rtx3060-12gb-profile.json)
   и [измерения](comfyui/rtx3060-12gb-measurements.json).
2. Определить, какой workflow нужен: проверенный ИЗО FP8 или закрытый recipe ASA.
   Они различаются; не подменять один другим по совпадению имени модели.
3. Прочитать текущие `/system_stats`, `/queue`, каталоги `/models/*`, параметры
   службы и UUID GPU. Проверка каталога не запускает генерацию.
4. В админке ASA → ИИ → Изображения указать адрес ComfyUI, проверить и сохранить.
   Адрес применяется к обнаружению, dispatch и восстановлению заданий.
5. Проверить один холодный и несколько повторных запросов с разными seed,
   затем простой. Нельзя выдавать CPU offload или shared memory за полное
   размещение в VRAM. Записывать физическую RAM, commit, dedicated/shared VRAM,
   время, ошибки и используемый workflow.

Не менять Ollama, другие GPU, службы, firewall, модели или рабочую БД только
ради диагностики. До изменения работающего узла нужны backup настроек и проверка
очереди. Не выполнять глобальные `/interrupt` или `/free`: ComfyUI может быть
общим для ИЗО и ASA Lab. Не повторять неизвестно отправленное задание.

## Два разных профиля

| | Измеренный профиль ИЗО | Recipe ASA Lab в исходниках |
| --- | --- | --- |
| Workflow | [Нейтральный API graph](comfyui/izo-fp8-diagnostic-workflow.json) | `apps/api/src/ai-image-comfyui.ts`, `flux2-klein-4b-v1` |
| Диффузия | `flux-2-klein-4b-fp8.safetensors` | То же имя |
| Энкодер | **локальный FP8** под именем `qwen_3_4b.safetensors` | `qwen_3_4b_fp4_flux2.safetensors` |
| VAE | `flux2-vae.safetensors` | То же имя |
| Sampling | AuraFlow shift 3, KSampler `er_sde`, `simple`, 4 шага, CFG 1 | BasicGuider, Flux2Scheduler, `euler`, 4 шага |
| Версия | Измерено на ComfyUI 0.19.3 | Текущий guard требует 0.42.1+ и точные native inputs |
| Доказательство | Реальные тесты RTX 3060 ниже | Наличие файлов и связь не доказывают успешную генерацию ASA |

На проверенном узле **нет FP4-файла, который требует recipe ASA**, и версия
ComfyUI не проходит его текущий version guard. Поэтому обнаружение FLUX нельзя
называть готовностью ASA. Эта инструкция не меняет guard и recipe задним числом:
это нарушило бы проверку digest старых заданий. В админке связь и совместимость
recipe показываются отдельно. Перед развёртыванием ASA нужна совместимая сборка
и точный комплект её recipe либо отдельная проверенная миграция recipe.

## Модели и перенос файлов

Файлы лежат относительно каталога `ComfyUI/models/`:

| Файл | Байт | SHA-256 измеренного файла |
| --- | ---: | --- |
| `diffusion_models/flux-2-klein-4b-fp8.safetensors` | 4070624520 | `97ed34fe0567e436200f2faee3939b88f2b5d99f8af2a4dc16532c4245c0ccb6` |
| `text_encoders/qwen_3_4b.safetensors` (локальный FP8) | 4022515168 | `33607b140dc891e31c36360ecdc95b6fb69ec4f37d658fa2a11b41f5957e002d` |
| `vae/flux2-vae.safetensors` | 336213556 | `d64f3a68e1cc4f9f4e29b6e0da38a0204fe9a49f2d4053f0ec1fa1ca02f9c4b5` |

Копировать именно проверенный FP8-энкодер и сверять размер/hash. Официальный
BF16-файл `qwen_3_4b.safetensors` имеет размер 8044982048 байт: одинаковое имя
**не означает одинаковые веса или расход памяти**. FP4 — ещё один отдельный
формат; его нельзя имитировать переименованием FP8.

Алгоритм исходной CPU-конвертации сохранён в
[`tools/comfyui/prepare-fp8-encoder.py`](../../tools/comfyui/prepare-fp8-encoder.py).
Если проверенного FP8-файла нет, его можно получить из оригинального BF16 в
**новый** файл, используя Python той же ComfyUI-сборки:

```powershell
& 'D:\AI\ComfyUI_windows_portable\python_embeded\python.exe' `
  tools/comfyui/prepare-fp8-encoder.py `
  --source 'D:\model-source\qwen_3_4b.safetensors' `
  --output 'D:\AI\ComfyUI_windows_portable\ComfyUI\models\text_encoders\qwen_3_4b.safetensors'
```

Это отдельная ресурсоёмкая подготовка: требуется запас RAM/commit, GPU не
используется, существующие веса не перезаписываются. FP8-конвертация с потерями;
она не обещает побитово одинаковое качество с BF16. Различия библиотек/метаданных
могут изменить hash; если он отличается, это другой артефакт и требуется новая
проверка, а не подмена эталона. В исходной подготовке было 398 tensors и не было
clipping. Самый точный перенос измеренного профиля — копия проверенных весов.

Источники: [официальный комплект Comfy-Org](https://huggingface.co/Comfy-Org/Flux-2-Klein-4B),
[каталог энкодеров](https://huggingface.co/Comfy-Org/Flux-2-Klein-4B/tree/main/split_files/text_encoders),
[официальный workflow](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_flux2_klein_text_to_image.json).
Проверять лицензию и ревизию конкретного файла перед загрузкой. Данная инструкция
не скачивает веса; они не хранятся в GitHub репозитории ASA.

Для сверки перенесённого комплекта из корня репозитория:

```powershell
node tools/comfyui/verify-models.mjs --models-root "D:\AI\ComfyUI\models"
```

Проверка читает только три указанных файла. Она не загружает модели в GPU,
не удаляет и не исправляет чужие файлы. Другая версия весов требует отдельного
профиля и теста, а не изменения контрольных сумм ради зелёной проверки.

## Проверенная система и запуск

Измерено: Windows x64, RTX 3060 **12 ГБ**, 32 ГБ RAM, Python 3.12.10,
PyTorch 2.11.0+cu126, ComfyUI 0.19.3 portable. RTX 3090 используется отдельно
для текста. Это не гарантия для всех карт с 12 ГБ: другая архитектура, драйвер,
dtype, ОС или workflow требуют повторной проверки. Linux/CUDA и другие GPU
в этом профиле не проходили такой же нагрузочный тест.

Перед переносом сохранить версию/ревизию ComfyUI, зависимости, custom nodes,
службу, workflow, три файла весов, manifest и исходный BF16 отдельно. Для новой
установки закладывать не менее 20 ГБ свободного места под комплект, оригинал
энкодера и временные файлы, плюс место под Python/PyTorch, output и backup.
Не отключать файл подкачки; ограничение commit проверять отдельно от свободной RAM.

Выбрать UUID видеокарты командой `nvidia-smi -L` на **новом** компьютере.
Не копировать физический индекс CUDA или UUID старого компьютера. После маски
`CUDA_VISIBLE_DEVICES` нужная физическая карта обычно называется `cuda:0`.

Пример PowerShell для portable-сборки, пути задаются под новый компьютер:

```powershell
$comfyHome = 'D:\AI\ComfyUI_windows_portable'
$env:CUDA_VISIBLE_DEVICES = '<UUID целевой GPU из nvidia-smi -L>'
$env:PYTHONUTF8 = '1'
$env:PYTHONIOENCODING = 'utf-8'
& "$comfyHome\python_embeded\python.exe" -s "$comfyHome\ComfyUI\main.py" `
  --windows-standalone-build --listen 127.0.0.1 --port 8188 `
  --disable-auto-launch --gpu-only --fp8_e4m3fn-unet --fp8_e4m3fn-text-enc `
  --reserve-vram 1 --disable-async-offload --disable-pinned-memory
```

Параметры относятся к измеренному FP8-комплекту. `--gpu-only` не оставляет
сознательный CPU offload как способ вместить увеличенный workflow; при нехватке
VRAM возможен OOM. Резерв 1 ГБ не является гарантией для любого размера.
Не добавлять `--cache-none`. Загрузка после перезапуска процесса/Windows всё равно
холодная: постоянство весов относится к работающему процессу, а не к перезагрузке.

Если уже установлен локальный `ComfyUI-AutoFreeMemory20s`, его forced unload
отключён переменной **`IZO_COMFY_KEEP_MODELS_HOT=1` в окружении службы**.
Это переключатель нашего расширения, не стандартная функция ComfyUI.
На чистом ComfyUI это расширение устанавливать не требуется. Проверять отсутствие
других таймеров выгрузки и клиентских вызовов `/free`; флаги запуска не отменяют
явную внешнюю команду выгрузить модель.

Видео: отдельный экземпляр/планировщик LTX остановлен и отключён. Файлы видео
могут оставаться на диске — это не означает загрузку в RAM/VRAM. Для изображений
должен быть один согласованный процесс и порт. Не запускать второй ComfyUI при
занятом порте и не удалять видеофайлы как способ освободить оперативную память.

## Размеры и измерения на RTX 3060

Исторические тесты 28 октября, batch=1, четыре шага, FP8-комплект ИЗО:

| Размер | Результат | Время | Пиковая dedicated VRAM по замеру |
| --- | --- | --- | --- |
| 1024×1024 | холодный / повторный успешно | 15,76 / 10,26 с | Последний cold sample: 10837 МиБ |
| 1536×864 и 864×1536 | успешно, ровно 16:9 / 9:16 | 10,35 / 9,90 с | 11605 МиБ |
| 1632×928 и обратно | несколько успешных повторов; близко к пределу, не ровно 16:9 | около 11–12 с | до 12085 МиБ |
| 1664×960 | остановка по защитному пределу shared memory | 12,95 с | 12085 МиБ |

Для запаса начинать с 1024×1024 либо 1536×864/864×1536, один job за раз.
Full HD 1920×1080 здесь не считается принятой конфигурацией. Нельзя делать вывод
«максимум для любой 12-ГБ карты» из одного удачного изображения. 11605 МиБ из
12288 оставляет около 683 МиБ по этому счётчику; это небольшой запас.
В wide/portrait тестах shared memory около 80 МиБ — измеренный фон, а не доказательство
абсолютного нулевого использования общей памяти.

Cold physical working set достигал 4,391 ГиБ, warm около 1,89 ГиБ; private/commit
около 13,9 ГиБ не равен физически занятой RAM. Следить за обоими показателями и
системным commit headroom, особенно при параллельной текстовой генерации.
Raw summary без пользовательских промптов: [измерения](comfyui/rtx3060-12gb-measurements.json).
Эти размеры не добавляются автоматически в разрешённые размеры ASA: её UI и SQL
recipe имеют собственный список и должны изменяться согласованно.

## ComfyUI на другом компьютере

В ASA → ИИ → Изображения → Подключение ComfyUI указать, например,
`http://192.168.1.20:8188`, нажать «Проверить», затем «Сохранить».
Адрес хранится в БД ASA и сохраняется с backup. При смене IP внешнего GPU-узла
меняется эта настройка, а не исходники. Для устойчивости использовать reservation
DHCP или адрес VPN; обнаруженный IP не становится идентичностью всей ASA-установки.

| Где ComfyUI | Что означает адрес для API ASA |
| --- | --- |
| В том же host, ASA внутри Docker Desktop | Обычно `http://host.docker.internal:8188`; проверить доступность из API-контейнера |
| В том же host, ASA без контейнера | `http://127.0.0.1:8188` |
| Другой компьютер в LAN/VPN | Его частный IPv4 и порт, например `http://192.168.1.20:8188` |
| `localhost` в браузере пользователя | Не адрес сервера ASA; браузер напрямую в ComfyUI не обращается |

На GPU-узле loopback `--listen 127.0.0.1` не обслуживает другой компьютер.
Для LAN выбрать адрес соответствующего сетевого интерфейса в `--listen`, либо
ограниченный private ingress. Firewall разрешает порт только серверу ASA или
доверенной VPN. Не открывать ComfyUI всему Интернету; CORS `*` не нужен.
Эта инструкция не меняет firewall или текущую службу автоматически.

Разрешены HTTP, private IPv4 (в том числе VPN 100.64/10), localhost и
host.docker.internal с явным портом. Публичные IP, произвольные DNS, пути,
URL credentials, query/fragment и redirects запрещены. HTTPS/authenticated ingress
требует отдельного поддерживаемого transport; защиту для этого не отключать.

Источник по умолчанию: `ASA_COMFYUI_BASE_URL`, затем `http://host.docker.internal:8188`.
Сохранённый администратором адрес имеет приоритет. Пока есть admitted/submitting/
unknown/running/storing задания, смена адреса отклоняется: иначе восстановление
могло бы уйти на другой сервер. UNKNOWN сначала сверяется на прежнем узле.
Проверка и сохранение используют только GET к ComfyUI, генерацию не запускают.

## Приёмка и восстановление

На новом узле проверить identity GPU, три hash, версии, native nodes и очередь;
затем связь **из API ASA**, точный recipe, один cold job, три warm job с другими
seed, сохранение/скачивание результата и простой 60 секунд. Проверить offline,
повтор UUID и отмену только собственного job. Сохранять результаты и ошибки.
Успешный `/system_stats` — это связь, не качество/готовность полного graph.

Перед обновлением backup включает конфигурацию ASA/БД/объекты, настройки службы,
workflow и manifest; веса копируются отдельно с hash. Перенос БД без моделей,
объектов и конфигурации GPU-сервера неполон. При OOM сначала уменьшить размер и
проверить другие процессы на нужной GPU; не менять dtype/recipe или выключать
защиты вслепую. Службу перезапускать только после согласования очереди.
