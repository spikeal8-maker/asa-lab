# Ошибки браузера: как найти исходную строку

Пункт7 аудита занятий добавляет локализацию новых исключений. В «Админ → Логи»
ищите `client_diagnostic` с кодом `window_error`, `unhandled_rejection` или
`render_failed`. В JSON сообщения есть revision и exception: стандартный kind,
capture, handling и максимум5 кадров script/line/column. Это недоверенное
сообщение браузера, не доказательство падения всего редактора.

- `unhandled`: ошибка не перехвачена границей React; состояние проекта неизвестно.
- `boundary_fallback`: граница React перехватила исключение и показала прежний
  экран выхода/перезагрузки. Успешное восстановление/сохранение этим не доказано.
- Сообщения исключений, function names, componentStack, параметры URL и данные
  проекта не передаются. Ошибки пользовательской электрической схемы сохраняют
  прежние `simulation_failed/category/failureCode` и не превращаются в JS-crash.

## Приватные карты конкретной сборки

Каждая web-сборка создаёт `apps/web/private-symbols/web-symbols-REVISION.json` и
digest manifest рядом. Архив содержит карты и точные сжатые JS-байты, зашифрован
AES-256-GCM; ключ завёрнут RSA-OAEP-SHA256 на `tools/web-symbols-public.pem`.
Содержимое карт и исходников не публикуется в открытом виде. Public key не секрет.

Docker хранит тот же зашифрованный архив в `/usr/share/asa-web-symbols`, вне корня
сайта `/srv`. Это работает и при установке из исходников: не требуется Windows
или внешний сервис. При необходимости архив можно извлечь обычным read-only
`docker cp` из web-контейнера выбранной канонической установки. Нельзя брать
архив от другого checkout или заново собирать тот же SHA вместо исходного образа:
параметры сборки могут изменить JS-хеши.

GitHub `ASA Portable Release` экспортирует архив из того же Docker build,
сверяет JS-digests с собранным runtime до публикации образа и хранит зашифрованные файлы
в артефакте `web-symbols-REVISION`90 дней. Обрабатываются и обычные Rollup chunks,
и Worker JS/maps, которые Vite выдаёт как assets. Отдельный Browser Error Diagnostics CI
тоже проверяет реальный web-образ. Публичный GitHub-артефакт содержит только
шифротекст и manifest хешей. В `/srv` нет `.map` и sourceMappingURL.

## Разбор ошибки

1. Сохраните JSON самого `client_diagnostic` сообщения в `event.json`.
2. Возьмите архив именно той сборки/образа, чей40-символьный revision указан
   в событии. При нескольких сборках одного SHA сверяйте script с manifest.
3. На доверенном компьютере с Node22 выполните:

```text
node tools/browser-error-symbols.mjs symbolize web-symbols-REVISION.json PATH-TO-OWNER-PRIVATE.pem event.json
```

Команда расшифрует архив в памяти, проверит точный revision и SHA-256 сохранённых
JS-байтов, границы координат, затем выведет repo-relative файл/строку/колонку.
Строки исходного текста/сообщение исключения не выводятся. Просматривайте файл
именно на указанном Git SHA. Это локализация места, а не автоматическое
объяснение причины. При unknown/development, чужом revision/asset, повреждённом
архиве или отсутствии кадров команда отказывает; карта другого выпуска не
подставляется. Старые карты до введения механизма этим не восстанавливаются.

## Ключ владельца

Закрытый ключ хранится только у владельца, вне Git и Docker context. Он необходим
для чтения архивов, его нужно сохранять при переносе на другой компьютер.
Потеря ключа делает существующие архивы недоступными. Текущее местоположение
указывается в личном отчёте реализации, а не в публичной документации.
Установка/сбор/работа сайта не требуют закрытого ключа; он нужен для разбора.
Новый владелец может создать собственную пару через `keygen PRIVATE.pem PUBLIC.pem`
и явно заменить public key перед своим выпуском. Не перезаписывайте старый
закрытый ключ: старые архивы по-прежнему зашифрованы для него.

После публикации исходников всё это начнёт работать на сайте при отдельном
штатном обновлении Web и API. Новые nested поля пока отклоняются старым API;
поэтому обновляются оба сервиса одним согласованным выпуском.
