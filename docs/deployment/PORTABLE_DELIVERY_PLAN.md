# Переносимая доставка и обслуживание ASA Lab

Этот документ фиксирует границы инфраструктурного изменения, а не состояние
продуктовых задач. Принятое окно обслуживания: воскресенье 03:00–05:00 МСК
(UTC+03:00). Поддерживаются Windows с Docker Desktop и Linux с Docker Compose.

## Результат

1. Docker-кэш зависимостей отделён от исходников; API не строит Web повторно.
2. GitHub публикует готовые образы только после общего CI точного main SHA.
   Установщик проверяет манифест, SHA и digest каждого образа. Изменение main
   не заменяет уже выбранный релиз во время операции.
3. Один переносимый менеджер (Python 3.11+, только стандартная библиотека)
   выполняет проверку, установку, обновление, полный backup и проверку backup.
   Shell/PowerShell — тонкие точки входа. Node/pnpm на сервере не требуются.
4. Планировщики Windows Task Scheduler / Linux systemd вызывают тот же менеджер.
   Проверка окна выполняется внутри процесса; пропущенное окно не означает
   немедленное обновление при включении. Параллельные операции исключаются.
5. Backup содержит PostgreSQL с правами, MinIO, необходимые приватные настройки,
   версии и контрольные суммы. Во время согласованного снимка писатели остановлены.
   Частичный backup не выдаётся за готовый. Копирование в облако требует
   отдельной настройки шифрования и назначения; Яндекс Диск не подключается молча.
6. Восстановление сначала проверяется на одноразовой БД `*_test`; live restore
   остаётся отдельной явно выбранной аварийной операцией. Данные старого
   компьютера не перезаписываются.

## Границы

Сохраняются единственный Compose project, канонический каталог PostgreSQL,
порты, origin-изоляция Scratch, tenant/RLS и существующие тома. GitHub push не
перезапускает сервер. Еженедельное разрешение действует только для настроенного
окна, установки и проверенных релизов. При отсутствии зелёного релиза остаётся
текущая версия. Откат БД автоматически не выполняется.

Для универсальных образов адреса портала/редактора задаются при запуске и
проверяются как точные HTTP(S) origins, без ослабления проверки postMessage.

## Проверки

- unit/negative tests менеджера на Windows и Linux: окно, lock, manifest,
  повтор без изменений, неправильный каталог, повреждённый backup, пути и ошибки;
- готовые образы: Linux CI, чистая установка, HTTP и совпадение Web/API/Scratch;
- тест изменения исходника: зависимости используют прежний кэш;
- тест backup/restore в изолированном CI с синтетическими данными и объектами;
- проверка ботов: короткий маршрут и однозначные коды ошибок/безопасные действия;
- независимый review финального SHA для границ rollout/данных.

Текущий чужой сбой общего Electronics CI не исправляется внутри этой задачи.
Он запрещает продвижение релиза, но не подменяется отключением проверки.
