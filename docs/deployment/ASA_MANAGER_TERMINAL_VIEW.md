# Ручное обновление ASA Lab — вывод в терминале

Область этого изменения — только отображение стадий существующей команды `tools/asa_manager.py`.
Само переключение, Docker, PostgreSQL/MinIO, backup, релизные проверки и сроки обновлений не меняются.

## Команды владельца

Проверка, доступен ли новый опубликованный стабильный релиз:

```bash
sudo -u admins -H python3 /srv/asa-lab/tools/asa_manager.py check --root /srv/asa-lab
```

Ручная установка опубликованного проверенного релиза:

```bash
sudo -u admins -H python3 /srv/asa-lab/tools/asa_manager.py update --root /srv/asa-lab
```

`update` — только по инициативе владельца. `check` не устанавливает новую версию и не перезапускает рабочие контейнеры; при чтении опубликованного manifest допускается скачивание образа метаданных.
Менеджер использует только опубликованный `deployment:stable` с проверенным точным CI, не произвольный `main`.

В интерактивном терминале зелёный означает подтверждённую проверку, жёлтый — наличие обновления/предупреждение, красный — ошибку. Если терминал не поддерживает Unicode, выводятся обычные ASCII-маркеры. При записи в файл, `NO_COLOR`, `CLICOLOR=0` или `TERM=dumb` ANSI-коды отсутствуют.

## Точные значения результата

- `NO_CHANGE`: текущий verified stable уже установлен; новая резервная копия и перезапуск сервисов не требуются.
- `AVAILABLE`: только при `check` — обновление опубликовано, но не устанавливалось.
- `UPDATED`: техническая готовность и HTTP проверены; вход в аккаунт, действия ученика/преподавателя и сохранение проекта остаются `NOT_RUN`.
- `BLOCKED`: исходный код ошибки и `SAFE_ACTION` сохраняются. Если ошибка произошла после начала switch, статус прежней версии и автоматический rollback не считаются подтверждёнными.
- `RETRY_NEW_MANAGER`: после безопасной замены исходников менеджера нужно сверить runtime/checkout и повторить ту же команду. Контейнеры не менялись на этом шаге.

Локальный backup в данном менеджере проверяется на завершённость перед переключением. Облачный Yandex/AGE readback этой командой отдельно не подтверждается. Нельзя считать красивый вывод доказательством recoverability или браузерной owner acceptance.

Параллельные программы: PR #845 — новый единый установщик со своим отчётом, PR #846 — Windows no-op. Эта правка не интегрирует и не подменяет их.
